# 交付目标

别人clone或pull已发布代码，用自己的EN凭证，从EN私有File获取批准的业务资产后，能在项目主电脑停止运行时，自行刷新数据、运行已有预测/净额并解释结果。范围覆盖三分公司全部批准商品，查询时按授权选择分公司及SKU。

单SKU固定回放仅是回归测试。不能代替三分公司数据、历史预测重算、全量规则和后续刷新；不得将“能读到过去建议”称作“拥有预测能力”。

## 代码与资产分工

公共main：Skill、Agent手册、CLI、模型实现/依赖锁、schema、测试、只读EN客户端、输出解释模板。私有File：旧GS/补充历史、批准的A/B政策与C映射、D侧车及必要模型参数、版本化交期/生产日历、需要的供应快照。结果快照可用于验收，但不能替代原始输入与计算代码。

每类资产要说明来源、时间、范围、版本、SHA256、更新机制和负责方。不能因拥有Key就推断附件权限，发布方需实测匿名、非授权与合法用户。数据不进公共仓库，下载失败不回落到作者D盘。

## 能力验收矩阵

| 能力 | 交付要求 | 独立验收 |
|---|---|---|
| 历史读取 | EN采集与旧GS/外部历史入口、去重、取消改量、未发货 | 缺旧历史时明确覆盖不足；增量不冒充全历史 |
| A/B规则 | 批准范围、归属/身份/形态/UOM与用途 | 不能从Item.disabled、仓库出现、客户名称重新猜 |
| C库存 | 最新完整run及库存映射、占用/CG口径 | 同run完整分页，陈旧和未知可见 |
| E供应 | SO/生产/DN/Shipment/通途PO事实和日期 | 跨阶段去重、未关联行不丢、partial不能当完整 |
| D预测 | 冻结可重跑版本、全部必要输入和依赖 | 外部机器真运行，不只是下载D5表；周期/样本一致 |
| 净额 | 需求×可售日期供应、单位/形态/池一致 | CG只抵一次，采购SO不是终端需求 |
| 解释 | 商品/分公司/期间、候选数量、证据及缺口 | 非技术人员可读，未知不叫无需补货 |
| 刷新 | 增量取数、规则/包版本更新、失败重跑 | 不依赖项目主手动跑包；保留上版但标陈旧 |

每一能力报告代码可得、数据可得、权限通过、执行通过、业务通过五个维度。所有标志均有证据，不能从前一个维度自动推断下一个。

## 可复现验收顺序

1. 从冻结提交创建干净目录；不得靠旧worktree源码、D盘资料或作者环境默认值补齐。
2. 用锁文件安装；构建wheel并检查所有声明模块/静态资源，隔离目录导入。
3. 同事Claude Desktop与老板Codex使用各自凭证；Agent安装与项目信任分开验证。
4. 校验私有资产包，验证范围包含三分公司全部批准商品；明确哪些是重算输入、哪些是参考输出。
5. 相同冻结版本/日期先复现；选取多个普通与异常样本，保留全体去向。
6. 在独立机器主动刷新订单、库存、供应，再运行预测和净额。历史覆盖/政策缺失必须阻断相应结论。
7. 模拟403/分页中断/损坏包/更新失败，确认不假报成功、不产生“0库存”或“无需补货”。
