# 网页内参数助手：先查再决定，护栏看动作

> 历史经验，记录于2026年10月11日。新设计将身份、提案、执行、核验和审计移至后台，浏览器状态不再作为权限或执行证据。旧版 page-agent 与公开 `/v1` 代理不用于当前方案；旧文所述护栏属于设计意图，不应当作为已全部验证的声明。当前实现进度见 [交接](handoff-2026-10-12.md)。

## Context

这是一个网页内助手：假数据、真模型、改数必须在页面上点允许。两个身份，柜面主管能改测试限额，综合柜员看不见生产限额。客户清单谁都不能导出。

第一版只有一轮对话、一个大工具。模型交回一个 `kind`，服务端再用正则改写。用户说「不要改限额，只交单」时，正则看见「限额」和「工单」，把限额改成了默认的 20 万。用户说「说明里写不要同步生产」时，因为句子里有「生产」，整句被拒绝，测试限额也没改。

## Guidance（本学习沉淀的做法）

助手循环保持很小，不引入编码助手运行时。

1. 当前限额不写进系统提示。模型要先调用 `read_test_limit`，工具结果交回之后，才允许 `propose_change`。
2. 写操作的提案回到浏览器，人点允许才改页面。读操作不用点允许，因为读的是这个岗位已经能看见的数字。
3. 安全护栏检查的是即将执行的动作，不是用户原话里的词。提到「不要同步生产」不算申请改生产。导出客户清单单独拦截，同一句里的测试限额提案可以留下。
4. 目标金额和当前值相同：不改数，也不提交变更单，只记审计。没给出具体金额（「调高一点」）就追问，不默认 20 万。一句话里两个金额，只取最后一个。
5. 护栏结果用固定条目显示在对话里：岗位工具白名单、生产写保护、客户信息不出域、无差额不立项、人工确认。模型负责想，护栏负责拦。
6. 模型只认 OpenAI 兼容的 `OPENAI_API_BASE_URL`（以 `/v1` 结尾）和 `OPENAI_API_KEY`。仓库只留 `.env.example` 里的占位符。运行机器上的真实地址和密钥只写在该机器的 `.env`。
7. 需要助手点到「事先没写工具」的新字段时，用网页内的通用点击能力（阿里巴巴 page-agent）：它读取页面控件再点击、填写。模型请求由本站 `/v1` 转发，密钥不到浏览器。每一步用 `onBeforeStep` 停住，等人点允许。
8. page-agent 自带全屏遮罩，层级很高，会盖住侧边栏的允许按钮。侧边栏必须压在遮罩上面，否则看起来像卡死。
9. 允许和跳过的点击只在当次页面有效。刷新后从本地记忆画出来的按钮没有点击。未完成的卡片应标成已中断，请用户重新开始。
10. 允许按钮没有被真实点通过之前，不要把这一版放到对外演示。page-agent 自带的底部输入条和侧边栏、以及腾讯云 KiKi 的确认条不是同一套界面，统一体验以后再做。

对照：OWASP LLM06 要求工具白名单、在下游强制授权、高影响动作人工确认。NVIDIA NeMo Guardrails 的 execution rails 包在工具执行前后，工具名和参数在模型之外再验一次。这两条都不要做成「整句关键词一票否决」。

Pi 和 DeepSeek Harness 的可取之处只是「工具结果交回模型再决定」。它们默认的读文件、跑命令不要装进这个页面。

## Why This Matters

正则补在模型后面，看起来像模型没有判断。看到的应是：助手先读数，再提案，旁边的护栏逐条通过或拦截。敏感操作被拦住，是护栏的成绩，不是模型说错了话。

## When to Apply

- 页面内助手要操作本页控件，并且必须给人看过程。
- 同一句话里混有允许的修改和必须拒绝的导出或生产写入。
- 要把演示交给别人自己部署，仓库里不能出现网关密钥。

## Examples

柜面主管说「把测试限额改成 20 万，并提交工单，说明里写不要同步生产」：先读出当前 50 万，提案改为 20 万并交单。护栏里生产写保护是通过，人工确认是等待。

同一人再说「导出客户清单，同时把测试限额改成 20 万」：客户信息不出域拦截，测试限额提案仍在。

综合柜员说「改成 20 万」：岗位工具白名单拦截，页面不改。
