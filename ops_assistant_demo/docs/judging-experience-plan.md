# 评审演示与工作台体验收口

## Goal Capsule

让业务演示者从工作台找到投屏稿，用6–8分钟解释业务价值、完成真实模型办理并证明受控；答疑可追溯到真实规则、后台状态和模拟验收。保留朋友自备PPT，show.html作为可选讲解稿，不把更换PPT作为演示前提。

## 本轮实施结果（2026-10-14）

- 已完成工单选择与本地任务解绑：切换工单后必须重新建立任务，不能继续分析或确认旧工单。
- 已完成侧边栏确认收口：活动的整组方案优先显示；若同时存在多个普通待确认方案，提示回对应页面选择，不再默认取最新一条。
- 已完成完整工单预演：同一页面的多个操作逐项传给既有高亮/鼠标/逐字填写动画，预演不写入后台。
- 已完成入口与投屏稿：工单和交付页均可打开“投屏讲解”；正式稿为6页主线加答疑，移除未实现的知识审核闭环和无依据机构表述。
- 已新增确定性与真实浏览器验证；本轮不引入 Pi、MCP 或向量库，理由见答疑页和 U4。其余待办仍按下文 U1–U5 继续管理，不能把本轮结果外推为真实系统接入或合规认证。

## 实施前核对事实与问题

- 云端show.html可访问；index.html、任务页交付入口只指向competition.html，缺投屏入口。show是静态讲解材料，不是新增业务后端。
- show当前有9页，知识入库与责任论述重复；“标准云服务原则上由分行自主实施”没有提供机构正式依据；“财资助手/两个入口”没有对应已验证插件产品；审核入库、退回复审尚未落地。反馈SQLite不是知识审核流。不得把建设目标写成完成事实。
- bank_task_ui.js下拉onchange只renderTicket，render里才更新建立任务按钮；用户选工单后按钮可能仍禁用。旧task/proposal未按新选择解绑，ask/analyze可能继续旧任务；隐藏旧追问不能解决对象错配。
- bank_task_ui.js预演按entity只取第一条operation；同实体多条参数/IP操作未完整展示。三页填写必须遍历本次全部操作，长字段填写限时。
- index.html侧栏审批优先取最近普通pending，再取活动页整组；多个方案不能让页面或“最新”替代用户授权。BankTaskUI.render与RouteUI.render必须同步同一审批上下文；后台摘要/版本/有效期校验保留。
- 普通提问走统一LangChain；明确任务、路由、终端写请求仍桥接领域规划器。目录只含统一工具，不能声称页面所有CRUD已由统一Agent直接办理。
- 能力快捷按钮确实先调用模型，最终清单由后台依据工具返回生成；普通能力短回复有固定概览。应准确说明，不能把格式化清单当作模型自主业务判断证据。
- domain.knowledge按字符排序后返回全部active资料，不是精确语义检索；一般业务问答的引用覆盖需单独评测，不宣称所有答案仅依据相关资料。
- unified_agent_history按workspace隔离但目前仅存用户/助手文字；原工作区reset版本变化不能靠历史自觉处理。需以真实当前版本与对象状态重建事实，避免旧已办结描述影响新办理。
- 当前132项确定性回归以及此前真实浏览器通过是既有基线，不证明本计划全覆盖。部署须核对最新远端，避免覆盖Cursor并行提交。

## Product Contract

R1 入口命名明确：投屏讲解、演示者排练、使用与交付说明、提交试用反馈。主工作台只保留一处集中入口，避免再叠一套导航。
R2 正式投屏不显示编辑说明、口令、本机路径、真实机构/客户信息、未经验证收益或审核闭环完成声明。
R3 每个演示对象明确：工单编号、测试环境、目标差异、当前版本、待确认/已保存/验收未通过状态。切工单、岗位、工作区后不得继续旧授权。
R4 确认只一次，明确范围；模型准备，用户批准，后台校验执行。页面与侧栏是同一方案的替代入口，不能两个独立审批；多个待确认对象先选择，绝不自动批准最近项。
R5 鼠标移动、高亮、逐字填写、结果强调保留。预演完整展示变化字段，无后台写入；总时长可控，不能用JSON单行充当真实字段填写。
R6 真实模型、模拟业务、确定性后台格式化、预演与验收各自标明。失败可解释，恢复不自动执行。
R7 主流程与问答可用业务语言讲清，无需评委理解LangChain、MCP、Schema、digest。

## 行业用语与叙事决策

统一作品称谓“运营配置辅助助手”（暂定中性名）；朋友正式作品名确定后集中替换。场景词采用：渠道接入、客户端配置、请求/应答适配器、业务路由、联调参数、配置变更方案、差异核对、人工确认、执行留痕、读回校验、模拟验收、恢复方案。具体映射仅为演练，需业务同事反馈确认。

柜面单笔限额是答疑备用：未经验证不要暗示财务授权、生产交易限制已改变。操作员确认不等于独立复核岗审批；POC模拟岗位不等于企业SSO；SQLite留痕不等于防篡改审计。投屏正文用“保存配置”而非“落盘”，“实施人员确认”而非笼统“人工复核”。财资、全辖、分行自主实施等词只有业务朋友确认适用才使用；目前使用“运营实施人员/渠道接入配置”。

主亮点应是“给业务目标和工单，助手查规则与现状，复用现有配置，只问真正缺项，准备整组差异，经确认保存并核验”。简单限额可证明护栏，不能作为必要性主证明。

## 6–8分钟演示

默认7分钟：0:00–0:35业务难点；0:35–1:10能力与边界、带引用问答；1:10–4:45渠道接入工单001（材料冲突、仅追问9443、5项差异、逐页预演、一次确认、独立读回/模拟验收）；4:45–5:45安全挑战（只读岗位不能准备或直接改生产被拒，选一条）；5:45–6:30业务路由需求与可复用适配器差异（默认只准备，现场时间够再保存）；6:30–7:00价值与边界。

朋友可选路由作主线，工单作答疑；主线选择在演示者排练中明确，两套讲稿独立，不连续重复全部操作。限额20万、工单002保守档、003失败恢复放答疑，不都塞进主流程。每步提供“说什么/点哪里/期待什么/超时怎么办”，等待模型期间讲真实冲突，不伪装录像为实时结果。每次演示前开新模拟场次，保留真实反馈与既有审计。

show主稿建议6页：业务痛点；办理链与边界；主业务材料；现场操作切换；安全挑战与结果；收益验证/应用边界。问答附录不计主时长。每页只一个中心结论、至多3条要点，讲者备注与评委正文分离；提供返回原页的操作台链接。现有静态deck解析器足够，先修显示标题、打印恢复、键盘导航，不引幻灯片框架。

## Implementation Units

### U1 对象状态与审批安全（先做）

文件bank_task_ui.js、index.html、route_ui.js、bank_ui.js、agent_runtime.py；tests/test_bank_task_http.py、tests/test_agent_runtime.py；新增真实浏览器用例scripts/experience_eval.py（需要才建）。下拉变化重新render；有未处理任务时明确提示新选择尚未建任务，分析/确认必须匹配当前task.ticket_id；旧方案由后台取消/失效规则处理，不仅客户端置空。恢复刷新应同步下拉对象。统一审批上下文含方案id/类型/工作区/角色/版本，不用active页面猜。多个pending要求选择并展示目标；busy包括领域working，连点只有一次写入。reset后历史可保留需求，旧状态结论失效，先读最新配置。

验收：未选不能建；选001可建；001→002不能分析/批准001；准备后切页不能批准另一方案；多pending澄清；刷新不自动执行；取消不写；reset旧摘要拒绝；岗位变化不能授权；侧栏整组审批与页面指向相同id。核对数据版本/事务/审计，不以成功气泡代替断言。

### U2 完整预演与结果层级

文件bank_task_ui.js、bank_ui.js、route_ui.js、index.html。逐页遍历所有operation而非每entity一项；同页多条明确序号与身份；长文本限速限时，保留可读标签。首页先结论和下一步，参数/依据/原始轨迹折叠。能力普通概览短；快捷“可办事项与规则”完整清单可展开；模型失败必须终态，不暗示成功。保存与验收分别显示，失败可准备恢复，不隐去部分成功。

验收：001全部5项预演与后端方案一致，预演前后数据库相同；路由复用/新增与范围排除一致；窄屏1100px、1366×768、1920×1080不遮挡侧栏按钮；成功/失败/恢复结果强调可见。测总动画时间并写实际值，不先承诺百分比。

### U3 入口、投屏稿与资料精简

文件index.html、bank_task_ui.js、competition.html、show.html、rehearsal_ui.js、docs/competition-v2-script.md、docs/competition-v2-faq.md。从工作台集中“演示与帮助”进入show/排练/说明/反馈；show互链操作台与说明。减少演示说明、演示与交付、投屏稿名称混淆，旧链接保留兼容。编辑提示只在讲者模式；大字正式页无开发词。show静态素材修改仍通过仓库部署，不宣称在线编辑已保存。

审核入库图保留为“后续建设方案”附录；当前正文改“预置模拟规则与案例，标注版本来源”。移除无依据政策与独立审批口径；收益描述采用计划测量的正确率、追问数、人工操作步数、任务耗时，不编节省比例。同步competition里已过时的排除句需澄清说明：明确排除应正常处理，未知业务/矛盾范围才澄清。

验收：云上从首页一键找到show；投屏/退出/前后页/打印恢复有效；正式页无编辑口令；操作台切换返回讲稿位置；全部链接可达；备用PPT使用者无需show也可完成同剧本；朋友在每一环节可直接提交真实反馈。

### U4 问答与能力覆盖证明

文件agent_tools.py、agent_runtime.py、domain.py及相应tests。先做只读真实模型案例：能做什么、余额报错核查、现有适配器、几张工单区别、当前页缺项、未知业务、范围排除、只读权限、重置后继续。回答引用必须支持结论，缺专门排错资料就明说无法定因。现有检索可保留小资料库，但区分相关来源与目录全量，不把全量返回称精准RAG。不新增Pi/MCP/向量库；当前缺口先通过业务契约与评测修复。注册表一致性测试仍保留，新增能力只人工白名单登记一次。

验收：记录实际调用轨迹、引用、耗时、追问、错误终态；没有数据不编事实；快捷清单后台格式化真实来源可解释。不要为了截图把输入特判成固定业务答案。

### U5 发布与业务同事验收

独立仓库为源，镜像ops_assistant_demo代码一致，保留各仓文档相对链接。开始先fetch并核对Cursor并行提交；按已存在PR #2/#288提交，检查安全扫描、OKF索引。通过U1–U4真实浏览器验证后部署；只上传对应版本应用文件，备份原文件，保留.env、数据库、服务unit、pip源与虚拟环境。发布核对文件hash（区分换行差异）、服务active、登录与真实问答、test审批/取消/拒绝、静态白名单与404。记录发布日期和commit，运行数据不入公开仓库。

## Review and Handoff

本计划已按评审/业务演示者/实现安全三个视角自审；未使用并行审稿，也未证明截图业务映射真实正确。当前最先验收U1：如果工单不能选/建或旧任务串用，先停止发布。U3不等待完成知识入库系统；应先修诚实口径。建设知识审核系统属于另一次功能决策，不因投屏稿写过就扩张本轮范围。Terra按U1→U2→U3→U4→U5执行，任何未通过案例保留失败记录，不靠人工改气泡兜底。
