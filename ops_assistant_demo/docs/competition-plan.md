# 竞赛实施与验收规格

本文记录竞赛验收口径。当前页保留原蓝色柜面壳，另加联调配置、知识依据、安全实测和演示说明。真实模型只规划和解释，执行权在后台。柜面限额页保留。实际核验范围见 [交接](handoff-2026-10-12.md)。

以下合同已完成本轮39项自动化与真实模型主线核验，具体覆盖与仍存在的边界见 [审计](cursor-audit-2026-10-12.md)。部署信息保留在私有运维记录，公开文档不列地址。

## 场景与单位

主场景：合作方联调接口超时。联调及生产初始 `timeout=30` 秒、`retries=2` 次；建议联调改为 60 秒、1 次，检索依据需说明减少重试如何避免扩大请求压力。执行后读取新值及模拟验证，生成生产申请。生产始终保持 30 秒、2 次。

柜面场景：测试与生产初始 `limit=500000` 元。演示测试调为 150000 元（15 万元），生产不变。1.5 万元应为 15000 元；未给金额应追问，不默认 20 万元。

经办可以在授权范围办理；只读不能写；复核可以处理申请，不能通过复核修改生产。独立浏览器工作区隔离模拟状态，同一浏览器切换岗位保留数据，以便展示职责分离。

## HTTP 合同

登录以外的读取要求后台会话；POST 要求 `X-Demo-Request: 1`，若有 Origin 则须与当前站点一致。角色字段不能覆盖登录身份。

| 路由 | 输入 / 作用 |
|---|---|
| POST /api/login | username、password，可选 access_code；账号 operator/reader/reviewer，演示口令 demo2026 |
| GET /api/state | 当前工作区的可见配置及状态 |
| POST /api/chat | text、scenario（integration/counter）；真实模型规划 |
| POST /api/propose | scenario、changes（field/value 列表）、reason、submit；生成提案 |
| POST /api/execute | proposal_id、digest；确认后检查并执行 |
| POST /api/cancel | proposal_id；取消等待提案 |
| POST /api/rollback | proposal_id；受控恢复 |
| POST /api/review | ticket_id、approve 布尔值；处理申请，不写生产 |
| POST /api/reset | 空对象；重置模拟工作区用于演练 |
| GET /api/knowledge?q= | 检索当前身份可见的模拟资料 |
| GET /api/audit | 当前工作区审计 |
| POST /api/safety-test | case；明确标记的安全测试 |

安全测试 case：unauthorized、tamper、stale、repeat、injection、production、unknown、failure。配置及工单由 domain.py 事务持久化；摘要、有效期、版本、幂等性在执行时复查，失败测试应使用真实 SQLite 事务中止。

## 文件职责与验收步骤

1. server.py：先验证未登录访问、异源 POST、静态敏感文件和公开 /v1 均拒绝，再实现会话与调用限制。模型调用受 IP、会话、全局预算及并发限制。
2. domain.py：先验证读写权限、提案篡改与失效、重复执行、事务回滚和生产写保护，再实现受控办理及重新读取。
3. 界面：显示资料引用、旧值新值、生产范围、确认等待、真实核验和后台拒绝理由。切换身份通过登录完成。
4. 演练：执行自动化，随后跑真实模型主场景、复述与改值场景。安全测试必须说明输入和后台结果，不能替代真实对话验证。
5. 部署：备份运行文件和数据；更新代码与必要配置，保留 Key；重启并检查敏感路径、身份、模型与写入核验。测试失败时恢复备份，不发布成功声明。

## 验收目标（不是测试通过声明）

合法办理经确认完成；确认前无写入；生产始终不写；越权、未知动作、篡改、失效、重复与污染输入不能扩大执行范围；事务失败无部分提交。模型不可用时停止新办理并允许查已有结果。执行证据来自后台，不由模型编造。效果数字来自本 POC 对照实验，不引用厂商案例收益作自己的成绩。
