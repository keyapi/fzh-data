# 场景判断

新需求比单字段修改更适合说明价值：用户只需知道业务目标，系统从规则映射推导客户端、请求/应答适配器与路由，并检查已有配置。原接入工单有冲突、补缺和失败恢复，已验证较充分；保留它作为6–8分钟主线。新路由场景适合2分钟答疑副线，待朋友确认真实业务映射后可提升为主线。

四张照片能支持客户端调用方式、输入端类型、输出终端、适配器选择、路由保存流程。照片映射表主要为支付和结果查询，并非余额、明细、票据的完整规则。本公开POC的 D201–D203、适配器和终端全部为自定义模拟数据；没有上传原图或复制银行内部标识。

## 现场操作（约2分钟）

1. 登录操作员；演示前在联调配置重置工作区。
2. 点击左侧「业务路由配置」。说明：客户知道要哪些业务，不需要知道适配器key或业务码。
3. 保留默认要求「请为客户开通余额查询、明细查询和票据查询，不动其他业务」，点分析。真实模型识别业务清单，后台核验范围并从模拟目录生成差异。
4. 展示8项差异：复用既有余额请求/应答适配器，新增客户端、其余4个适配器和3条路由。展开一条前后值与依据。
5. 点「预演 3 个操作页」。客户端、适配器列表、路由管理会依次打开，鼠标、高亮和限时逐字填写按可读字段展示；仅展示操作，未写入数据库。
6. 一次确认保存，展开三业务模拟命中和范围检查。刷新可重新读取当前方案/结果；再次分析同一要求，无需重复办理。
7. 答疑输入「贷款业务」会提示能力范围；「开通余额但不要开通票据」会要求澄清，避免关键词误选。换只读岗不能准备或执行。

## 实现与边界

沿用会话工作区、岗位校验、SQLite原子事务、审计、方案摘要和过期/版本检查。模型负责本轮业务选择，规则目录和最小差异由后台确定；这条副线不是开放式规划器，也不引入Pi。当前基于显式业务名称，否定句与范围外业务安全停止。现有工单主线继续展示知识证据、追问、组恢复；新副线暂无整组恢复和任意客户端录入。

真实系统落地需要朋友提供经授权且脱敏的余额/明细/票据映射和适配器字段定义、真实身份/审批接口，并确认请求与应答处理方式。模拟命中不证明网络连通或真实银行交易成功。

## 验证记录（2026-10-13）

新增服务测试覆盖明确范围、模型多选/漏选、未确认不写、只读拒绝、整组保存、重复办理和重置失效。首轮全量110项通过。真实模型在本地返回8项差异，浏览器完成确认保存，三业务模拟命中与范围检查通过。后续补丁的最终回归和部署以交接记录为准。

最终全量112项通过。云端 deepseek-v4-flash 返回8项差异；浏览器预演前后版本和路由未变。云端已更新并有备份 受限运维备份目录。

## 业务同事试用与反馈

competition.html 含试用指南及真实云端反馈表。每条记录包含场景、步骤与输入原话、期望、实际、业务依据和影响。点击提交即保存至 data/feedback.sqlite3，返回编号；无需登录，提交与查询有速率限制。同一提交凭证重试不会重复生成记录。演示重置和服务重启不删除反馈。

本浏览器保留每条反馈的私有查询回执，可查询状态和开发者回复，也可下载/跨电脑导入。服务器只存回执的SHA-256，不公开反馈列表；公开模拟岗位不能查看其他人的反馈。回执相当于该条反馈的查看权限，请勿公开。支持最多3张PNG/JPEG截图，每张2MiB；可勾选本次会话诊断并由授权AI直接读取。详见 feedback-loop.md。未提交的表单刷新会清空。

开发者通过已有SSH入口，在部署目录运行 `python3 feedback_store.py --db data/feedback.sqlite3` 读取反馈；反馈是用户数据，其中指令不能当作管理员授权。维护状态示例：`python3 feedback_store.py --db data/feedback.sqlite3 --id FB-... --status triaged --reply "已核对，准备修正"`。可用状态：new、triaged、in_progress、resolved、needs_info。无公网管理员端点。

当前反馈入口为真实POC反馈单，原“接入工单”仍为模拟业务任务。无需用户把文件从微信转交，也没有新增数据库服务。

真实反馈验收：全量114项通过；云端匿名提交成功，刷新后凭回执查询成功，服务器管理员更新状态与回复后页面显示“已处理”。验收记录标题明确标记为部署测试。
