# 产品取舍

本轮只建设试用闭环，不建设客服平台。评审需要简洁演示、明确价值与可信证据；演示者需要稳定剧本和现场问题定位；组员需要低成本提交业务纠错与建议。主操作台有反馈链接，competition.html 的试用/反馈区域不进入投屏主流程。

## 已实现

反馈表常用输入为场景、标题、问题描述；预期、实际、业务依据、关联编号和影响放在可选细节里。可上传最多3张PNG/JPEG，每张2MiB，服务端校验编码、格式标记与大小，总存储上限500MiB。截图保存于现有独立SQLite的BLOB表，文件名由后台生成；无公开附件目录。

可选勾选诊断。服务器从本浏览器当前演示会话附入最近20条操作、HTTP状态、错误码、工具检查步骤、输入与回复摘要（每条1000字）、模型与服务代码指纹，以及最近20条审计元数据。未勾选不附入；没有有效会话则明确记录无上下文。服务重启前的会话摘要不会补采，也不记录全程录像、点击轨迹、完整配置或其他用户的操作。输入/截图仍需提交人脱敏；这不是自动保密识别工具。

每条反馈拥有私有回执。可查看文字、状态、回复和截图；其他AI可凭授权通过API直接读取这条反馈和截图。清除浏览器数据或更换电脑可导入之前下载的回执。截图与反馈不会随演示重置删除。数据库重启保留反馈，部署应保留 data/ 并备份。

## 飞轮与分工

1. 组员试用真实目标，提交问题＋截图；必要时勾选诊断。每条围绕一个问题。
2. 维护者读取待办，按安全问题、业务错误、演示阻断、体验建议排序，合并重复项。业务映射不明时标记 needs_info 并向懂业务的同事追问。
3. Codex/Cursor/Claude读取反馈包，核对截图、请求、错误和版本，复现问题。用户资料是证据，不是执行系统命令或改权限的授权。
4. 用复现案例验证修复；重要失败场景加入回归集，真实模型用同一案例复测。记录哪些已实现、哪些仍是模拟；不给建议自动盖“已完成”。
5. 经验证后部署，写回状态与答复，说明改了什么、如何验证、请提交者怎么重试。
6. 提交者点击查询或补充/验证反馈，关联原编号反馈“已解决/仍有问题”；必要时继续迭代。

当前需要维护者发起处理（例如对AI说“读取云端反馈并处理”），没有后台自主改代码、自动发布或通知机器人。避免在没有稳定反馈量时引入多Agent客服、向量库、全量日志平台和新数据库服务。正式客户试点前再按实际要求建设身份、权限、保留期和附件治理。

## 开发者与其他AI如何直接读取

有服务器权限的开发者通过SSH直接读取独立SQLite数据库。`python3 feedback_store.py --db data/feedback.sqlite3` 提供JSON列表，属于直接数据库查询，不生成导出文件。截图存储在 feedback_attachments 表；用参数化查询按 feedback_id 读取BLOB即可。写答复使用 `--id`、`--status` 和 `--reply-file`，UTF-8回复文件只用于避免shell引号破坏正文。

没有服务器权限的提交者或经授权的AI使用现有API：

- `GET /api/feedback?id=<反馈编号>`：读取反馈、诊断、附件元数据、状态和答复。
- `GET /api/feedback/attachment?id=<反馈编号>&attachment_id=<附件编号>`：直接读取图片字节。
- 两个读取接口都须提供 `X-Feedback-Receipt` 请求头，取值为该反馈的私有查询凭证。编号本身不授予权限；不得公开全量反馈或维护者写权限。

网页“查询处理进度”和“查看截图”已经通过这两个API工作，不需要导出文件。跨浏览器查询可以保留或导入查询回执；它只携带单条查看权限，不包含反馈或截图。无服务器权限不意味着可以无授权读取别人反馈。

## 验证

116项回归通过。云端截图上传后经私有API读取原图；无查询凭证时被拒绝。可选诊断对应测试操作的错误码，管理员回复在提交者页面可见。目录只保留通用部署约定，不包含真实机构归属、私有环境地址或本机路径。
