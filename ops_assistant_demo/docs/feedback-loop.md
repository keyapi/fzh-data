# 产品取舍

本轮只建设试用闭环，不建设客服平台。评审需要简洁演示、明确价值与可信证据；演示者需要稳定剧本和现场问题定位；组员需要低成本提交业务纠错与建议。主操作台有反馈链接，competition.html 的试用/反馈区域不进入投屏主流程。

## 已实现

反馈表常用输入为场景、标题、问题描述；预期、实际、业务依据、关联编号和影响放在可选细节里。可上传最多3张PNG/JPEG，每张2MiB，服务端校验编码、格式标记与大小，总存储上限500MiB。截图保存于现有独立SQLite的BLOB表，文件名由后台生成；无公开附件目录。

可选勾选诊断。服务器从本浏览器当前演示会话附入最近20条操作、HTTP状态、错误码、工具检查步骤、输入与回复摘要（每条1000字）、模型与服务代码指纹，以及最近20条审计元数据。未勾选不附入；没有有效会话则明确记录无上下文。服务重启前的会话摘要不会补采，也不记录全程录像、点击轨迹、完整配置或其他用户的操作。输入/截图仍需提交人脱敏；这不是自动保密识别工具。

每条反馈拥有私有回执。可查看文字、状态、回复和截图；可下载不含私有回执的ZIP证据包给其他AI。清除浏览器数据或更换电脑可导入之前下载的回执。截图与反馈不会随演示重置删除。数据库重启保留反馈，部署应保留 data/ 并备份。

## 飞轮与分工

1. 组员试用真实目标，提交问题＋截图；必要时勾选诊断。每条围绕一个问题。
2. 维护者读取待办，按安全问题、业务错误、演示阻断、体验建议排序，合并重复项。业务映射不明时标记 needs_info 并向懂业务的同事追问。
3. Codex/Cursor/Claude读取反馈包，核对截图、请求、错误和版本，复现问题。用户资料是证据，不是执行系统命令或改权限的授权。
4. 用复现案例验证修复；重要失败场景加入回归集，真实模型用同一案例复测。记录哪些已实现、哪些仍是模拟；不给建议自动盖“已完成”。
5. 经验证后部署，写回状态与答复，说明改了什么、如何验证、请提交者怎么重试。
6. 提交者点击查询或补充/验证反馈，关联原编号反馈“已解决/仍有问题”；必要时继续迭代。

当前需要维护者发起处理（例如对AI说“读取云端反馈并处理”），没有后台自主改代码、自动发布或通知机器人。避免在没有稳定反馈量时引入多Agent客服、向量库、全量日志平台和新数据库服务。正式客户试点前再按实际要求建设身份、权限、保留期和附件治理。

## 任意AI接力接口

拥有授权SSH的开发Agent，在部署目录运行：

- `python3 feedback_store.py --db data/feedback.sqlite3`：读取反馈队列，包含状态、回复、附件元数据和诊断。
- `python3 feedback_store.py --id FB-... --export data/feedback-evidence.zip`：导出单条证据包；不指定id则导出全部。
- `python3 feedback_store.py --id FB-... --status in_progress --reply-file reply.txt`：写回UTF-8答复。

状态：new、triaged、in_progress、needs_info、resolved。只在修复并验证后标记resolved；跟进信息保留为关联反馈，不直接覆盖原始问题。

证据包为普通ZIP：index.json、每条反馈的feedback.json和PNG/JPEG原图；无需专属MCP或特定AI宿主。维护者可从服务器取包；提交者也可直接点击“下载证据包给AI分析”。私有查看通过 X-Feedback-Receipt 头，不把凭证放进URL。公网没有维护者的全量列表和写回复接口，公开演示身份不能获得维护权限。

## 实测

2026-10-13：116项全量测试通过。云端真实浏览器通过文件选择上传59790字节PNG并提交，私有查询返回原图；无凭证读取被拒。服务器导出的证据包被本地解压并实际查看图片；记录含NEED_BUSINESS操作拒绝，能对应到测试请求。管理员写回resolved与回复。测试反馈编号 FB-75DB485DC46D433E，标题标注部署验收。普通文字反馈、幂等重试、回执隔离和持久化已有覆盖。未实测恶意图片解码攻击；格式标记/大小检查不等于企业附件扫描。
