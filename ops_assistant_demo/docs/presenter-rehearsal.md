# 目标与已落地设计

让演示者在系统内学会“说什么、按什么、看什么、有疑问在哪里反馈”，业务同事的校准直接发生在相关操作环节。评审看到正式演示；组员看到排练提示与反馈，使用同一套真实模拟执行能力，不另造预录脚本或客服系统。

入口：操作台左侧“演示者排练”，说明页也有直接进入链接。需要先选择模拟操作员；培训可不限时，正式主线约7分钟，路由副线约2分钟。

## 两条培训剧本

接入工单共7步：准备工作区→建立工单→模型分析→补唯一端口缺项→核对差异与预演→明确确认并验收→复盘。

业务路由共6步：准备工作区→提出三项业务目标→模型准备最小差异→逐页预演→明确确认并验收→复盘。

每一步提供讲稿、实际操作按钮、预期观察点和业务校准问题。可以把本步操作指令放入助手输入框，但不会自动发送。进入业务页面后，底部提示条继续显示当前环节、操作、下一步和反馈；正式模式隐藏提示条。可以收起提示条，查看完整页面。

动作复用原工单/路由UI与服务。模型分析仍依赖真实模型；保存仍由演示者明确点击确认，后台仍检查权限、版本、范围。培训“已检查”不替代数据库验收：失败显示暂停，复盘无后台通过报告时不能宣称成功。跳步只切换培训提示，前置任务缺失时动作安全停止；重复完整演练应从准备工作区开始。

## 五类业务校准融入环节

- 材料与角色：真实办理材料有哪些必要事实，谁操作、谁复核？
- 规则：如何认定现行版本，哪些模板不能沿用？
- 缺项：哪些值应由业务人提供，哪些能根据规则推导？
- 页面依赖：适配器新增还是选择已有定义，实际配置顺序/必填项是否一致？
- 验收与价值：实际完成标准是什么，最费时或容易出错的步骤在哪里？

问题作为各步提示，不强制填调查问卷。可先写排练笔记，再点击“就本步提交问题/截图”，窗口就在操作台里，自动填场景、环节和预期观察点；允许修改，诊断由提交者勾选。反馈复用真实云端提交、截图、私有回执API与开发者SSH读取，提交后本步保留编号。

提交者可以查询答复、补充或验证；维护者复现、修复、回归后写回答复，业务同事再排练校准。反馈是待验证材料，不授予工具或系统权限。

## 清理边界

| 按钮 | 对模拟业务/聊天的影响 | 对已提交反馈的影响 |
|---|---|---|
| 开始全新排练 | 确认后切换至新的模拟工作区，清聊天/旧任务/待确认页面；保留旧工作区审计 | 保留 |
| 一键准备正式演示 | 新模拟工作区、空聊天、无待确认内容；打开所选场景，隐藏培训提示，不自动分析/保存 | 保留 |
| 清理排练笔记与进度 | 只清当前浏览器的笔记与步骤勾选，不改业务、不清聊天 | 保留 |
| 原“重置工作区” | 恢复当前模拟业务并使旧任务/确认失效，保留审计 | 保留 |

每种清理显示具体范围并确认，执行中禁止切场次。正式准备不删除反馈、原场次数据库或其他用户数据；同一浏览器登录会话的多个标签页共享工作区切换，应现场只保留一个操作台。权限和API凭证不因培训改变。浏览器排练笔记与进度按工作区保存；已提交反馈独立持久化。

## 演示前最后检查

确认模拟操作员身份、选择剧本、点击一键准备正式演示，检查聊天为空且无旧方案。打开说明页或正式讲稿，确认联网、模型和投屏尺寸。主线先建立新工单，副线从客户业务目标开始。试用未确认的真实业务映射不能在台上宣称已验证。

## 实测与边界

本地真实模型与浏览器跑通两条培训剧本：工单形成5项差异，路由形成8项差异；两次预演均未改变后台版本，明确确认后验收通过。本步反馈自动带入环节并提交，编号返回培训页。一键正式准备后工作区变化、聊天0条、原任务为空、路由无待确认方案、提示条隐藏。HTTP测试覆盖只读拒绝、新工作区拒绝旧提案、原审计与反馈保留。

修复首轮浏览器验收发现的工单目录加载时序问题。培训提示与笔记不是服务器任务状态；刷新后应重新读取真实任务。没有录音识别、自动播放旁白或自动发送反馈；这些能力不影响本轮闭环，不纳入本轮范围。

最终118项全量测试通过。云端真实模型主线同样完成5项差异→预演不写→确认后completed/验收通过；云端本步反馈提交后，一键正式准备切换工作区，聊天0条、任务为空、提示条隐藏，反馈仍可通过私有API查询。

## 收尾确认

原联调配置“重置工作区”未移除；正式上场推荐使用“一键准备正式演示”，培训开始使用“开始全新排练”。说明页已改为同一推荐顺序，文字备用步骤不再把原重置当作唯一准备入口。当前两仓库各118项通过；云端主线、反馈保留及清理边界已实测。当前覆盖限定模拟场景；真实映射仍需业务同事校准。
