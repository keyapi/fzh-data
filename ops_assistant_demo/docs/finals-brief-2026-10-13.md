# 决赛 6–8 分钟总说明

面向工银科技第四届创新大赛·价值创造赛，赛道是智能办公效率。成果名称用申报口径：**资金管理系统实施智能体——基于「工单驱动 + 知识自沉淀」的配置与排障助手**。

书面材料已经交过四维表和约 1800 字申报正文。台上这 6–8 分钟不要再念材料。评委要看到的是：分行实施时先问得着，再在测试环境改得了，而且改之前必须有人点头。

## 最终要证明的一件事

司库全面推广之后，分行要自己做实施，工银科技不能靠群聊逐条答同一类报错。这个成果把两件事接成一条：

1. **财资助手**负责「这报错、这配置，手册和既往案例怎么说」，回答必须带出处。
2. **操作助手**负责「按这个口径，在测试环境准备改哪几项」。人在页面上确认之后，系统才写入测试并读回；生产只形成申请，不能直接改。

台上用一句话收口：**问答解决“还得问人”，确认式办理解决“问完仍不敢改、改了说不清”。智能体只出建议方案，人是决定者和实施者。**

这和行内材料里的分工同向，但不要说成已经替代了运营中心或专家团队：常见咨询和操作指导走助手；标准化排障和复杂转接仍由人；重大故障仍由专家处理。我们演示的是助手把前一段做完，并把改配置停在确认之前。

## 现在各自能演示什么

| 部分 | 现场能做 | 不要说成已经完成 |
|---|---|---|
| 财资助手 Web | 问答、知识库（已发布 / 草稿 / 已废弃）、上传素材、候选审核（待审、通过、驳回、疑似重复）、踩赞 | 不要打开含具体客户环境、系统版本排查的草稿条目当主线 |
| 浏览器插件 | 申报口径是嵌在工单、日志、配置页里选中即问 | 若现场没装好插件，不要临时安装，改口说 Web 是同一套问答 |
| 操作助手网页 | 演练工单三张差异、缺一项就追问、确认后只写测试并读回；或按点名准备余额 / 明细 / 票据的路由整组方案 | 自助提单、生产工单对接、全行铺开都是规划，不计入本段已交付 |
| 朋友的 10 页答辩稿 | 开场痛点和知识进库五步可用。人名、赛事、部门已从公开页去掉 | 不要照念「已上线」「数据不出域」「任务自主执行」。操作助手这场要现场做，不再说成只放 25 秒规划录屏 |

知识库里适合上台的干净问题是「什么是银企直连」和「余额查询报错先查什么」。带具体客户环境的排查留在审核或答疑，不放进计时主线。

## 评委口味：必须落到嘴上的话

行内材料的口径是：总行统筹，分行主导，工银科技支持；司库业务要分行自己具备实施和运营能力，工银科技做平台化、集约化的技术支持。标准云服务项目原则上分行自主实施。

所以台上优先说这些，不必展开文件：

- 痛点是银企直联参数相互依赖，证书、验签、报文、授权一类报错反复出现在群里，经验带不走。一个实施群的重复求助，放到多家分行就是支持量接不住。
- 创新不是再造一个大模型，而是三件事：嵌在作业现场问、聊天人审入库而手册免审入库、回答带引用并可踩赞回炉。不合格不进库。
- 算力和模型的目标是复用行内底座、处理留在行内。今天这场是模拟，不说已经不出域。
- 智能体只出建议方案。人确认之后，系统才把这一次变更写入测试并读回。人是决定者，也是实施者。不要说「任务自主执行」或「代操作已经替人做完」。
- 制度口径对齐国家金融监督管理总局金发〔2026〕8号，只背边界、不宣称已满足：谁使用谁负责；资金交易等生成式场景按高风险，关键环节要人工监督和干预；解释不足时只做辅助，关键决定要人工复核并留下依据。本演示没有走过风险管理委员会准入。
- 时长、工时那些数是立项时的保守估算。说「预期把约 30 分钟的共性排查压到 10–15 分钟」，马上补「试点后用命中率、有用率和前后对照替换这个估算」。

不要说：已经满足监管、所有攻击都能拦住、助手可以代替审批人、已经全行上线、无人值守改生产、把估算说成已经省下的工时、数据已经不出域。

## 6–8 分钟怎么排

知识库画面短，口播加长，把人审入库、强制引用、回炉说清楚。赢面仍在两次可操作，但每次操作页面上都要看见同一句：只出建议，人确认才落盘，人是决定者和实施者。不要在同一段里换岗、做安全测试、再开路由。

模型若超过约 20 秒没有结果，口播往下走，屏幕停在已打开的引用或已填好的方案上，不要干等。投屏用 `/show.html`，版式对齐答辩稿：红条、深色页脚、微软雅黑。朋友用记事本打开该文件，只改「演示正文从这里开始」和「演示正文到此结束」之间的中文；每一页用单独一行 `---` 隔开。保存后的文件要换到演示地址上，网上那一页才会变。公开页面不写单位、赛事、人名和具体分行数量。投屏会藏起「口播」，打分句写在「底栏」。

投屏上的每一句都是给评审读的。计时和现场取舍放在「口播」，打印讲稿才看得到。限额、接入工单、业务路由三页都在投屏里。现场三选二：限额建议保留，工单与路由按是否直观、现场有没有工单来定。

| 时间 | 页面标题 | 评审读到的结论 |
|---|---|---|
| 0:00–0:50 | 分行自主实施，经验沉淀为可复用能力 | 问询有出处，配置变更经人工确认后实施 |
| 0:50–1:15 | 一个助手，两个入口 | 判断与实施由人工完成 |
| 1:15–3:05 | 知识入库规则 | 群聊经验经人工审核后入库，回答只引用已审核知识 |
| 3:05–3:45 | 建议由助手生成，落盘须经人工复核 | 本次为模拟；正式使用另行履行准入和数据管理 |
| 3:45–5:15 | 测试环境限额调整 | 确认前原值不变；确认后测试为 20 万，生产仍为 50 万 |
| 5:15–7:15 | 接入工单，或按业务需要配置路由 | 两项里现场讲一项；都讲则压缩知识库 |
| 7:15–8:00 | 共性报错一次沉淀 | 助手不替代在岗支持与专家处置 |
| 提问 | 常见问题 | 生产不写入、责任在实施人员、效率数为立项预期 |

路由页的输入是：只开通余额查询，不要明细，不要票据。安全测试和换岗不进这 8 分钟。

## 两段之间怎么接

预热结束后不要说「下面换一个系统」。说：

「刚才它告诉实施同事先查证书和密钥，依据是已经人审过的知识。真正改配置时，它只能起草方案，不能自己落盘。下一段是同一类事情进了演练工单：缺端口就只问端口，人确认后系统才实施这一次测试变更，生产不动。决定的人和实施的人是同一位实施人员。」

若有人问为什么不一开始就改配置：因为评委要先看见「答得有据」，再看见「动得有界」。先改配置，前两分钟像在看一个参数后台。

## 书面材料和上台各占什么

申报正文和汇总表给评委读，台上不复述 200 字。朋友的演示稿还在改，不能当成计时主线。我们的网页承担后半段可操作演示；财资助手承担前半段问答。两边不要互相登录到对方系统里现场拼。

知识库站点的账号只用于准备，不写进口播，不投到屏幕上。
