# 助手面板、刷新记忆与删除语义修复

## Problem

同一岗位手动能删除IP，助手却要求输入数值。原因是模型删除工具有时附带旧端口，运行层对所有动作检查新数值；另外模型可能只问“确认删除吗”，没有创建可批准记录。固定侧栏不能收起或调宽，刷新则丢失可见聊天与页面上下文。

## Solution

- 删除只识别记录，不要求新目标数值。模型回传与已读记录一致的冗余字段可归一为空；删除不允许夹带修改。修改只把变化字段送后台，避免旧值回显覆盖并发变更。
- 读取工具提供当前终端记录及`latest_record_id`。最新指后台当前列表最后一条，新增或更新排在末尾；不是根据编号猜创建时间。确认区展示具体前置/客户端地址与端口。
- 用户明确要求删除时，模型应准备真实待确认操作，由页面负责一次批准。仅文字询问批准时允许一次工具纠偏，不能假装已生成确认单。
- 顶部“AI助手”开关右侧栏；收起后右下悬浮入口显示待确认数量。分割线支持鼠标拖动、左右键及Home/End，默认360px，范围320–640px，并在窄窗口为业务区保留空间。
- 银行三页显示当前页面提示与自然语言示例，隐藏不相关的柜面/联调快捷按钮。页面“让助手…”按钮仍是同一模型入口的示例快捷方式，不是另一套权限或执行路径。

## Refresh and authorization

`assistant_panel.js`将开合/宽度保存至localStorage；当前标签页的最近60条展示消息、输入草稿、页面及终端上下文保存至sessionStorage，按后台工作区和岗位隔离，大小限90KB。超过限制的旧消息/深层证据会裁剪；存储被禁用时界面仍可运行。

恢复的是界面展示，不恢复可执行提案、摘要、口令或访问码。确认按钮始终从后台最新状态构建。客户端旧聊天不送模型冒充当前状态；同一有效后台会话内的模型上下文本来就保留，刷新继续使用。服务重启、会话过期或不同设备不属于跨会话记忆能力，本轮未实现持久化后台长记忆。

重置计数变化清理旧展示及草稿；岗位切换保存原岗位展示，读回新岗位自己的记录。普通加载不反复恢复缓存。POST前后推进请求代次，旧GET不能在登录、重置或写入之后覆盖新岗位/新配置；银行页面的加载也检查相同代次。

## Verification

- 三个新增回归先失败：删除旧端口回显、修改未变端口回显、只有确认文字而无确认单；修复后通过。补充并发变更回归，旧客户端端口不会覆盖后来保存的新值。
- 80项自动化通过、0跳过，包含脚本静态白名单；Python编译与两个外部JS语法检查通过。
- 真实Flash模型“删除最新ip”约3.3秒准备IP-DEMO-002，确认前仍2条；对话“确认删除”后剩1条，独立读回`passed=true`。
- 在待确认时收起、填写草稿、调至380px并刷新：聊天、草稿、IP页面、关闭状态、宽度和后台待确认记录均保留，没有自动执行。
- 实际鼠标拖动至524px；1100px视口限制504px，业务区400px，无重叠。关闭侧栏会释放业务区，恢复后可继续输入。
- 只读岗位不显示操作员聊天，模型删除被后台拒绝；切回操作员恢复其展示记录。重置后展示与草稿清空。
- 人为延迟旧岗位的普通状态与银行状态响应，切换到只读岗再释放旧响应，当前岗位仍为reader，写按钮仍禁用。

以上是指定模拟用例，不能替代正式银行身份、安全认证或全部自然语言能力评测。
