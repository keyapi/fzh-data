# 数据源匹配规则

目标：内部 100% 可追溯，给 PB 的清单能对上她们付款记录和 Diane 后台拉取。xlsx 在仓库外。

## 三套文件，三种角色

| 源 | 路径（仓库外） | 用来干什么 | 不能用来干什么 |
|----|----------------|------------|----------------|
| A. SPS 日发票 CSV | `D:\Work\美国\Tracy Miller\PB orders\YYYYMM\YYYYMMDD\invoice\` | **我方开了什么**：INV#、PO#、PO Date、单价、数量 | 当「PB 付款用的发票号」的唯一来源 |
| B. `来自Email` | `...\payment advice\来自Email Payment Remittance Advice_PaymentDate …_CheckDate ….xlsx` | **PB 付了哪张号**：脚本解析原始对账邮件，**给 PB 看的 INV# 以这里为准** | 覆盖我方全部开票日（UPS 日期滞后） |
| C. 给财务 / To Tracy Miller | `...\payment advice\给财务\` 与 `...\To Tracy Miller\` | 我方财务与佣金结算 | **不能当 PB 号来源**——为方便对钉钉 CSV，个别行可能已改成我们本地 INV# |

A 是「我们账上是哪张票」。B 是「对方系统认哪张票」。C 是 A/B 冲突时的人工加工层。

## A. 发票 CSV 怎么取

日文件夹 `\invoice\` 经常有多份。

**只认**：文件名以 `invoice x` 开头（钉钉提交那份），且路径不含 `NotUsed`。

**不算**：中文前缀「再次下载核对」「作废」「合并」、`Invoice_From_ASN`、`payment advice\` / `batch download\` 里的大包历史 CSV。

同一 INV# 只留一行。把「核对/作废」副本算进去会把同一张票加两次——发给 Tracy 的 ~$28k 就是这样来的，**不要再当索赔额**。

2026-08-27 又操作过发货：重跑时把该日及之后的 `invoice x*` 扫进去，不要停在 08-24。

## B. `来自Email` 怎么用

这是 PB 原始付款邮件的解析结果。列里的 Invoice Number = 对方付款键。

- 能匹配上 A 的：PB 列填 B 的号；本地列填 A 的号。
- 对不上、我方已开票：标「尚未在来自Email」（黄）。常见原因是 UPS 收货日晚于我方开票日，下一账期才出现。
- 两个日期：B 的 Invoice Date ≈ UPS "We Have Your Package"；A 的 Invoice Date = SPS 点发货开票。B 只可能等于或晚于 A。

例：`PaymentDate 20260720-20260825` 付款日到 8/25，对账单 Invoice Date 大约到 7/28，**盖不到** 8 月发货。

## C. 给财务 / Tracy 表的陷阱

为匹配钉钉 CSV，人工可能把 B 的号改成 A 的号（或给占位号补上 INV#）。对 PB 索赔时**必须回到 B**。内部对照列可以同时保留 A 和 C 的号。

## 边界情况与处理

### 1. 索赔窗口：PO Date，不是开票日

约定窗 11/07–12/02。索赔 **PO Date ≥ 2025-12-03**。

窗口内 PO、12/02 之后才开票：单价本来就该是活动价，**不要向 PB 要**。用开票日过滤会多算（08-24 粗算大约多 $1,044 / 63 行）。

### 2. 分批发货（多张真发票）

一单部分有货先发 → 一张 INV#，PB 先付；其余后发 → 另一张 INV#，PB 再付。两张都是真发票，都留。给 PB 不必解释「为什么一个 PO 两张票」。本窗口三角枕集合里截至 08-24 扫描为 **0 单**；规则仍要保留。

### 3. 双号（一张货两个 INV#）

SPS 偶发同一货两张号。我们钉钉留一个，PB 可能付另一个。

- 给 PB：**用 B 上的号**。
- 内部：本地号对照。不要在邮件里写「我们有两个号」。
- 已知一对（与 `pb_reconciliation.REMAP` 相同）：PB `INV0580626000011541` ↔ 本地 `INV0580626000011530`。

月度对账脚本把付款号 **映射成本地号**（方便财务表对 CSV）。本 true-up **方向相反**：对外映射成 PB 付款号。

### 4. 占位号（补付、无 INV#）

PB 偶发漏付后补上，对账单不用 INV# 而用一串含年份的数字（例 **`20230216`**，2026-02-12 付款出现 17 行）。

- 给 PB：仍写占位号（她们付款记录上是这个）。
- Tracy/财务表：Key 常手动改成本地 INV#。
- 本窗口进索赔的：其中 1 张（PO `135393330` / 本地 `INV0580625000010023`）。其余 16 行 PO 在 10/20–11/30，有的是合同价或 23.5"，不进本次。

重跑时扫全部 `来自Email`，找非 `INV` 开头的 Invoice Number。

### 5. SKU 过滤

只收 28 个三角枕、单价仍为 51.7 / 57.6 / 60.5 / 70.4。排除 23.5"、Gap Filler。Coffee 4 个 Diane 无订单 → 改价可改、差额清单排除。SkyBlue Twin `3167719` 无货但仍在改价列表。

### 6. 给 PB vs 给自己的列

| 列 | 给 Diane | 内部 |
|----|----------|------|
| Invoice # | `来自Email` 的号（未付则暂用本地号） | 同上 + 本地号 + 财务表号（若不同） |
| Invoice Date | 可选：两边都列，对方优先看 PO Date / 她们的日期 | SPS 日 + UPS 日 |
| 佣金 | 禁止 | Tracy 5% 另表 |
| $28k | 禁止 | 注明是重复 CSV 粗算 |

### 7. 双侧对账（我方账 vs PB 账）

同一批票，两边对得上，但列不同。不要合成一张「混用双方发票号」的表发给 Diane。

| | 我方（内部） | PB（给 Diane / AP） |
|--|-------------|---------------------|
| 发票号 | `invoice x*` 本地 INV#；另列财务表号（若已改） | `来自Email` 付款号；未付暂用本地号并标黄 |
| 窗口 | **PO Date ≥ 2025-12-03** | 同一 PO Date；Diane 后台 pull 也按这个，不要从 1/1 |
| 已付 | B 命中（含双号/占位号） | 对账单已出；用 B 的号做 debit memo |
| 未付 | 已开票、尚未在来自Email | 下一张 remittance 前改应付；UPS 日滞后是正常的 |
| SKU | 28 个改价；差额按实开 | Diane 24 色 order report（无 Coffee）应对上内部实开 |
| 佣金 | Tracy 5% 另表 | 禁止 |

对账完应能回答：开了 N 张 → 给 PB 认 M 张；N−M 里多少是滞后、多少是双号、多少是占位、多少是排除 SKU。差数必须可追溯。

### 8. 对账顺序（建议）

1. 扫 A（`invoice x*`）→ 候选行（PO≥12/03 + SKU + 活动单价）。
2. 按 INV# 去重。
3. 左连 B（所有 `来自Email`）。命中 → 已付；PB 号取 B。
4. 双号：B 有号、A 是另一个 → 用已知 REMAP 或同 PO+金额配对；PB 列用 B。
5. 占位号：B 非 INV* → 用 PO+金额+日期对 A；PB 列用占位号。
6. 未命中 B → 未付/滞后。
7. 报告：总行、去重后张数、已付/双号/占位/未付、差额；N−M 去哪必须可追溯。
