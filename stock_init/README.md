# stock_init — 赛狐库存初始值导入

从通途多仓库存 + EN BOM 成本 → 赛狐库存初始值导入文件（含库存数量和采购成本）。

## 背景

- 公司从通途切换赛狐，需导入自发货仓的库存数量与成本
- 通途有 6 个自发货仓，赛狐建了 3 个（CENTRADE / DANEEY / POLAND）
- EN 产品 BOM 中有按仓库+发货方式的尾程前成本
- 赛狐库存初始值导入支持同时写入数量 + 成本（最多 5000 条/次）
- 使用共享库存（不指定店铺/FNSKU）以支持后续成本补录单的仓库+SKU 简单操作

## 管道

```
通途库存(6仓) ──仓库映射(3仓)──┐
                              ├── left merge ──→ 赛狐SKU过滤 ──→ 聚合 ──→ 输出
EN BOM成本(产品编号+成本列) ──┘      SKU→客户物料号      产品编号=赛狐SKU    按(仓库+SKU)
```

## 成本选取规则

| 绍兴发货方式 | CENTRADE (美东) | DANEEY (美中) | POLAND (波兰) |
|------------|----------------|--------------|--------------|
| 皮壳 | `发皮壳尾程前成本, 美东USNJ` | `发皮壳尾程前成本, 美中USTX` | `发皮壳尾程前成本, 波兰PL` |
| 半成品 | 同上（皮壳成本） | 同上 | 同上 |
| 成品 | `发成品尾程前成本, 美东USNJ` | `发成品尾程前成本, 美中USTX` | `发成品尾程前成本, 波兰PL` |

## 仓库映射

| 通途仓库 | 赛狐仓库 |
|---------|---------|
| CENTRADE | CENTRADE |
| FZHPoland-covers | POLAND |
| FZH-DANEEY-* (5个) | DANEEY |

## 使用方法

```bash
cd stock_init
uv run python build_saihu_stock_init.py

# 或指定对比基准
uv run python build_saihu_stock_init.py --compare-to "out/赛狐库存初始值_导入_20260514_160622.xlsx"
```

脚本自动选取 `./数据源/` 下最新的数据文件。

### 递增导入工作流

1. 放新数据到 `数据源/` → 运行脚本
2. 查看 `新增条目_导入_*.xlsx` → 上传赛狐
3. **更新锚点**：把本次全量导入文件复制到 `out/上次导入_基准.xlsx`
4. 下次运行自动对比锚点

## 数据源与输出

| 角色 | 默认查找规则 | 说明 |
|------|-------------|------|
| 通途库存 | 含「通途合并库存结存清单」的最新 xlsx | 运营从通途导出 |
| EN BOM 成本 | 含「EN产品BOM成本列表」的最新 xlsx | 开发者从 ERPNext 导出 |
| 赛狐商品 | 含「商品导出」的最新 xlsx | 运营从赛狐导出（SKU 白名单） |
| 输出 | `out/` | 主结果 + 问题报告 |

## 输出文件

- `赛狐库存初始值_YYYYMMDD_HHMMSS.xlsx` — 可直接上传赛狐，工作表名 `商品`
- `stock_init_问题报告_YYYYMMDD_HHMMSS.xlsx` — 7 个 sheet 详细分析

## 问题报告 sheet 说明

| Sheet | 内容 |
|-------|------|
| `汇总` | 单行多列总览（匹配数、排除数、各仓统计等） |
| `通途SKU_未匹配EN客户物料号` | 通途 SKU 在 EN 找不到客户物料号映射 |
| `不在赛狐商品列表的SKU` | EN 产品编号在赛狐商品列表中不存在 |
| `采购成本为0` | 成本=0 的 SKU-仓库组合（赛狐可能忽略） |
| `可用库存为0` | 库存=0 的记录（含在途/待发参考） |
| `EN数据清洗排除` | 绍兴发货方式/客户物料号为空的 EN 行 |
| `每仓统计` | 按仓库维度汇总（SKU数、库存、成本） |

## 关键业务规则

- 使用**共享库存**（店铺/FNSKU 留空），便于后续成本补录单修正
- 半成品按皮壳成本核算
- 绍兴发货方式为空的行排除（无法确定用皮壳还是成品成本）
- 客户物料号=通途主 SKU，用于关联 EN 物料
- **成本借用**：同「重量模板」的产品（仅颜色不同）互相借用填充 0 成本。详见 AGENT_HANDOFF.md §9
