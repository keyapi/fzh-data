# stock_init — Agent 交接说明

---

## 1. 业务背景

赛狐「库存初始值导入」：从通途多仓库存 + EN BOM 成本列表，生成赛狐库存初始值导入文件。一次写入库存数量（可用/次品）和采购成本。使用共享库存策略（不指定店铺/FNSKU），便于后续通过成本补录单按"仓库+SKU"修正成本。

---

## 2. 管道步骤

```
./数据源/*.xlsx
  → 读取 通途库存(4771行) + EN BOM成本(3566行) + 赛狐商品导出(2214行)
  → 通途仓库映射 (6→3赛狐仓)
  → EN 数据清洗 (去发货方式空 + 客户物料号空)
  → Left merge: 通途SKU → EN客户物料号
  → 按(绍兴发货方式 + 赛狐仓库)选取成本列
  → 赛狐SKU白名单过滤 (产品编号 ∈ 赛狐商品导出)
  → 聚合: 按(赛狐仓库, 产品编号) sum数量, first成本
  → 输出: 赛狐库存初始值_*.xlsx (模板格式)
  → _write_issues: stock_init_问题报告_*.xlsx (7 sheet)
```

## 9. 成本借用策略（✅ 已实现）

### 原理

EN BOM 成本列表中，有些产品在特定仓库的成本列为 0（或缺失）。但这些产品与有成本的产品共享同一个「重量模板, 编号」：
- 列 `重量模板, 编号`，如 `ZLMB#KS0001-CMGDTH-100`
- 去除 `ZLMB#` 前缀得键 → `KS0001-CMGDTH-100`（即 SKU 的前 3 段：款式-面料-尺寸）
- 同键的产品仅颜色不同，理论上发货成本（尾程运费等）应一致

### 借用规则

当某产品在目标成本列的值 = 0 时：
1. 提取 `重量模板, 编号` → 去除 `ZLMB#` 前缀 → 得匹配键
2. 在同一 EN BOM 中查找同键、**同成本列**内值 > 0 的其他产品
3. 借用第一个有值的成本填充（纯列内操作，不跨列、不限制发货方式）
4. 在问题报告中记录到 sheet `成本借用记录`

### ⚠️ 注意

- **不精确借用**：颜色变体可能因包装体积不同导致物流成本略有差异
- **借用范围**：每列独立借用，同键同列 0→非零

### 实现位置

应在 df3 预处理阶段（Left merge 之前）完成借用，即在 EN BOM 内部补齐缺失成本后再参与后续流程。

## 10. 边界条件与已知限制

1. **共享库存策略**：输出中店铺、FNSKU 留空。若赛狐后续产生店铺/FNSKU 专属库存，成本补录需匹配相应字段
2. **成本=0**：EN 中部分产品的目标仓库成本列为 0（可能是产品不发往该仓库，或成本未填写），需人工确认。导入文件中已过滤掉
3. **半成品按皮壳成本**：半成品仅 164 行，目前无独立的尾程前成本列，暂用皮壳成本
4. **聚合时成本取 first**：同一(仓库, SKU)下多条 客户物料号记录的成本可能不同（当前已确认同一产品编号下绍兴发货方式一致，成本通常一致）
5. **赛狐白名单过滤**：EN 中有产品编号但赛狐未建档的 SKU 被排除（145 条），需先在赛狐建立商品
6. **通途 SKU 未匹配**：1073 个通途 SKU 在 EN 客户物料号中找不到（可能是 EN 未登记或格式不同）
7. **Excel 输出**：使用 `pd.ExcelWriter(engine='openpyxl')` 直接写，不复制模板（无隐藏 sheet 需求）
8. **赛狐导入实测**：可用库存=0 的行可以导入赛狐（去掉"隐藏0数据记录"可见）；采购成本=0 的行在生成时即过滤掉（赛狐将 0 视为空，不导入）
9. **输出文件拆分**：生成两个文件——导入用（成本>0）和参考用（全量），文件名明确区分以防用错
10. **可选列不自动填**：次品库存等非必填列留空，不要擅自填 0
11. **报告含产品名称**：问题报告的各 sheet 中 SKU 右侧放产品名称列，方便人工审核

## 11. 实现过程中的踩坑记录

### 成本借用：必须是纯列内操作
- **坑**：曾错误添加"同发货方式限定"，导致皮壳产品无法借用同组内成品列的值，借用数从 726 降到 363
- **正确的逻辑**：每列独立借用，同重量模板键、同列内 0→非零。不跨列，不限制发货方式。皮壳产品借用成品列的值虽不会被用于输出（它只用皮壳列），但借用本身是列内操作，不应排斥
- **教训**：用户说的是纯列内，没有提跨列，不要擅自加约束

### 成本补录单：全字段匹配
- **坑**：POLAND 仓测试 SKU 在入库时填了店铺「北京如森-Rucener-FR」，Amazon 同步后又带 FNSKU。成本补录导入时需仓库+SKU+店铺+FNSKU 全部匹配才能找到
- **结论**：开局导入一律用共享库存（店铺/FNSKU 留空），后续成本补录只需仓库+SKU

### 借用来源产品编号取错
- **坑**：`need_borrow.index[0]` 取的是第一个待借用行的索引而非 donor 行，借用来源产品编号会写错行自身
- **修复**：单独记录 `donor_product`，不依赖 `need_borrow` 的索引

## 11. 与赛狐操作流程的关系

### 递增导入工作流

赛狐库存初始值导入限制：同一 SKU+FNSKU 已有库存时，再导入会失败。
因此采用**锚点递增**策略：

```
第1次：全量 = A → 导入A → 锚点 ← A
第2次：全量 = A+B → 对比锚点A → 新增 = B → 导入B → 锚点 ← A+B
第N次：全量 = P+C → 对比锚点P → 新增 = C → 导入C → 锚点 ← P+C
```

每次只导入新增条目，已导入的不会被重复导入（赛狐自动拒绝）。

### 操作步骤

1. 放新数据文件到 `数据源/`
2. 运行 `python build_saihu_stock_init.py`（自动读取 `out/上次导入_基准.xlsx`）
3. 查看差异报告 `差异报告_*_vs_*.xlsx`，确认新增条目
4. 将 `新增条目_导入_*.xlsx` 上传赛狐
5. **将本次全量导入文件复制到锚点**：
   ```
   cp out/{stamp}/赛狐库存初始值_导入_*.xlsx out/上次导入_基准.xlsx
   ```

### 实测验证（2026-05-15）

- A 导入 → 成功
- B 新增导入 → 成功
- B 中已存在行再次导入 → **失败**（「当前仓库该SKU已存在」），验证了不可重复导入

### 赛狐操作矩阵

| 赛狐操作 | 生成工具 | 频率 |
|---------|---------|------|
| **库存初始值导入** | 本脚本（全量）+ 新增条目文件 | 每次数据更新 |
| 每日数量修正 | 待开发（调整单导入） | 每天 |
| 成本批量修正 | 成本补录单（仓库+SKU） | 按需 |
