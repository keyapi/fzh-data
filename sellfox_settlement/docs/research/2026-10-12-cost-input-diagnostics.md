# 分类完成，财务 hold 保持

本轮复用 2026-10-10 私有 EN 订单快照、2026-10-09 BOM、仓库配置、生产函数 AST 的已验证组件重放。没有刷新生产、修改物料／仓库映射或调用公共 API；不能把本报告日期当作订单／BOM 新快照日期。

`cost_ledger.diagnose_cost_inputs()` 只读取已绑定订单源 SHA-256 的组件账本，以原生账号、EN 名称及组件位置保留全部证据。总入口没有因此选择历史成本、退款或财务分摊口径。

342 个 `no_item` 不等于 342 个待修发货物料：274 个实际发货组件中188个有通途SKU、86个没有；另68个是非发货占位。141 个 `no_warehouse_config` 的更精确原因都是输入仓库名称空，不能描述成141个仓库配置缺失。分类仅区分证据角色，不静默删除占位；成功9,340＋明确占位68＋未解决415＝输入9,823。

274 个实际发货缺映射组件中6个在当前 BOM 客户物料号上有唯一完全精确候选，全部来自平台 SKU，通途 SKU 输入仍空；268个没有完全精确候选。候选只是当前 BOM 的对照建议，未赋值 ERP 物料、没有回填成本。当前客户码不足以证明历史订单映射；未剥离 SKU 后缀、进行兄弟颜色借用或均分成本。

## 23 组产品成本差异的输入对照

保留原单＋拆单全部组件时，当前重放12组产品金额相等；11组不完整，缺失项全是拆单的明确非发货占位。额外给出仅对 `is_deliver_good=1` 组件的诊断对照后，23组当前重放产品金额均相等。这个对照没有改原账本选择、历史快照金额或 `hold_parent_children_difference`。

23组中的观测输入变化计数如下，类别可重叠：仓库名称集合不同6组；ERP物料集合不同11组（包含空物料占位）；quantity／split_factor原始输入列表不同20组；持久化和当前发货方式集合各有11组不同（包含占位空值）。因此不能把23组全部称为已证实的“仓库货流差异”。仓库、数量和组件列表变化不证明实际货物流转；需历史同步来源、包裹实际发货组件、仓库字段生成过程及当时 BOM 版本才能解释历史持久化值。

## 尚未证实的订单关系

原有5月至9月零售FBA探针内仍有4个独立目标未找到：3个带 `S01-` 的不透明订单标识和1个加拿大目标。账单对应5行（加拿大目标2行）；按行保留，没有因为订单去重丢掉退款或交易。只凭标识前缀不能改名、剥前缀或猜成其他零售订单。

缺的技术证据是原始 Amazon 交易中的订单／reference 命名域、原生账号对应的引用字段、通途支持的订单类型/API范围或历史导入来源。加拿大目标还需确认该原生账号在已查询零售FBA端点的可见性；没有结果不等于平台不存在订单。相关私有目标及所需输入列于 `cost/diagnosis20261012/unproven_order_relationships.json`。

## 复跑与验收

```powershell
uv run python -m sellfox_settlement.cost_ledger --cost-root PRIVATE_COST --out PRIVATE_COST/diagnosis20261012 --diagnose-inputs
uv run python -m pytest tests/sellfox_settlement/test_cost_ledger.py -q
```

`PRIVATE_COST` 是仓库外既有成本快照目录；输出 `cost_input_diagnosis.json` 与组件账本，源 BOM、配置、订单、组件探针及账单引用 hash 均写入报告。业务订单标识、SKU和金额只留私有报告。20项测试通过，新增用例先红后绿覆盖：缺物料候选不赋值、占位与空仓库分开、非发货占位对照不能释放产品 hold。9,823组件、11,580账单引用守恒，23组产品 hold 不变。
