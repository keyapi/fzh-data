# 非V2月度技术验证完成计划

**Goal:** 财务未确认时，交付可复跑的月度候选收入、订单成本技术分量、结算桥和全量异常证据，不能将候选称为最终报税结果。

**Architecture:** 复用现有CSV/PDF解析、账号快照、真实EN与通途只读快照及当前BOM探针。新增纯函数成本ledger、尾程选路诊断、账号成本证据桥；总入口统一调用并产生私有报告。原始数据、真实订单、金额、源码副本和工作簿均留仓库外。

## 任务与验收

- [x] 成本ledger：`cost_ledger.py` 与合成测试；订单键包含原生账号，原单/拆单与组件关系完整保留。产品、头程、加工分开，父子单只取拆单；仓库差异hold，退款不自动冲成本。真实私有报告对账输入/可用/hold/排除数量。
- [x] 尾程诊断：`tail_validation.py` 与合成测试；真实源码上传实际/分摊实际/设置第三优先，FBA排除、历史预估零无通途fallback；115行未采用费用保留。无法证明包裹分摊单位时hold，不直接按金额相等去重。
- [x] 账号成本桥：`account_cost_bridge.py` 与合成测试；标准账号到原生账号须证据唯一，冲突与缺证据fail closed。加拿大、S01、跨月购买日期、NBSP案例分别保留，不能将商品存在当订单存在。
- [x] 总入口：`run_technical_month.py` 与测试；快照月与目标月相容、空输入和fatal停止、全量状态数量可对账；JSON-only验证模式与Excel输出分开。集成新增报告，不把全局候选数量写成严格账号覆盖。
- [x] 工作簿：`workbook_tables.py` 与测试；去掉硬编码行数，所有未匹配/hold及诊断可追溯，收入候选按币种/状态分开；私有实数复跑与源hash核对。
- [x] 复审提交：模块测试、git diff检查、凭证扫描、OKF索引/solutions体检；阶段性checkpoint及最终ce-okf提交推到PR286。

## 已知外部输入关口

ZJ口径、申报主体、汇率、银行实际流水、历史成本版本仍需要外部证据。用户已允许用当前成本做技术尝试；当前BOM技术数必须标注版本，不冒称8月历史。账号登记、EN同步、费用选路设置和生产写入不在本轮授权范围。

## 额度与恢复

账户5小时额度为共享窗口，约剩余25%时停止扩展任务，约15%前完成ce-okf提交/推送并核实远端。没有取得的证据写成缺输入/未完成，不能为了收尾改为通过。恢复入口为本计划、AGENT_HANDOFF第11节、PR286最新提交及私有technical报告。

## 实际收口

147项模块测试通过。八表工作簿逐单元格与JSON核对一致，无公式或错误单元格。额外完成89个FBA缺口只读候选及9,823组件精确重放；缺完整导入字段、同步日志、历史成本及银行流水仍显式hold。提交推送与远端SHA在PR286核实，不能把离线验收替代生产同步验收。

## 继续完善的收口

按用户继续指令追加：原币V2完整分页与第9表、探针源hash和全组件覆盖、quantity门禁、尾程缺值证据、独立CLI范围、失败重跑run_status。银行403文件定向复查仍缺Amazon实际实收。FBA获取完整源和实时缺口／日志；源字段完备仍不等于导入通过，生产修复需在所属应用分支另作验收。

本轮继续验收：161项模块测试通过，真实8月JSON重跑成功；9表交付加入原币证据。完整FBA89目标已取，56源字段键覆盖未验导入／1账号碰撞／31字段不全／1零数量hold；89源运费为null不得填0。实时只读确认缺口仍存在，93原始证据hash、请求月与目标身份集合纳入入口核验；历史具体漏单根因仍未证实。当前Daily回溯7天及9月超时不等于8月原因。后续技术修复位于生产tongtool_integration应用，须用所属应用测试和独立分支，不在数据仓库擅自部署。
