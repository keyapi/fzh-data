# 预估与补货方法说明（给 Agent 与老板）

> 目标：让高琪/老板的 Agent 不仅会跑命令，还能解释“为什么这样算”。
> 一句话：**需求看两档（中位/保守90%），每 SKU 按历史形态选模型，供给按单据日期和阶段去重，最后才得出补/催/不补。**

## 1. 需求从哪里来

- 用最新订单（Tongtool Order/Item）按 **SKU×仓×日** 聚合成件数；
- 排除 FBA/第三方仓；EN 不维护 UOM，统一按“个”，套件按订单件数换算；
- 缺近期销量/只在其他分公司卖/订单无行 → 不硬编预测，标“未覆盖”，退回 D6 并需人工复核。
- “近期”当前定义为**最近 3 个完整月（2026-08~10）无销量份额**；USNJ 68 行构成：54 个 8–10 月无份额、11 个只在其他分公司卖、3 个订单无行。

## 2. 为什么按 SKU 分型、选不同模型

需求形态不同，不能一个模型通吃：

| 形态 | 特征 | 常用方法 |
|---|---|---|
| smooth 平稳 | 每周都有销量、波动小 | AutoETS / 季节 naive |
| intermittent 间歇 | 有零销量、但偶发 | SBA（Croston 偏差修正） |
| lumpy 块状 | 零销量多、单次量大 | TSB（更新“是否发生”的概率） |
| new/short 新/短史 | 历史不足 | naive / MA3 |
| obsolescent 退市 | 销量下滑 | TSB / 人工 |

分型依据是 **ADI（平均需求间隔）和 CV²（非零需求波动）**；这是业界对间歇需求的标准做法。Croston 原版有偏，SBA 是修正版；TSB 更适合会衰减/断续的需求。

## 3. p50 / p90 / p95 是什么

- **p50（中位）**：一半概率需求低于它；
- **p90（保守）**：约 90% 情形需求不超过它；业务默认用它；
- **p95**：更高保障，但需要更多回测校准；目前**不承诺**。
- **p90 ≠ 90% 订单满足率**，也不是“90% 不缺货”；它只是需求分位。
- 90 和 95 的库存差取决于 SKU 波动，不是固定比例；不要对外说“95% 库存翻倍”。
- 目前**没有 90 vs 95 的成本/服务权衡数据和 p90 实测覆盖率**；预测区间 `calibrated=false`，p90 只是经验分位。因此默认 90 的理由是“保守、可解释、不过度承诺”，不是“90 已被证明最优”。

## 4. 回测怎么做、现在的结果

- 用滚动原点、按保护期累计需求评估，而不是只看一步误差；
- 指标用 WAPE（加权绝对百分比误差），越小越好；
- 同一批 USNJ key 的 WAPE 中位：
  - 旧 11/13 D3b/D5：**0.782**
  - 简化 AutoETS：**0.700**
  - 当前 classified（逐 SKU 选型）：**0.677**
- 分型：间歇类明显更好（0.808 vs 1.001/0.924）；**lumpy 仍略差**（0.981 vs 0.863），所以不能宣称全面更好。

## 5. 周计划怎么来

- 先有 90 天总量，再分到 13 周；
- 历史 ≥52 周：周度模型（按分型的 ETS/SBA/TSB）；
- 不足：4–8 周均值或等分；
- 最近 12 周占比只作最后回退；
- 首尾周不是完整 7 天：按 covered_days 折算，标 partial_week；
- 周合计必须等于 90 天窗口；但“合计对”不代表周形状一定准，需回测。

## 6. 供给怎么算

- C：当前可发（不含在途）；
- EN：在途/待发；
- PO：开放采购；**只有 ETA ≤ 需要日才抵缺口**；
- SO：分公司生产/交付单，**不加进消费需求**；按时到仓才抵供给，否则只作条件；
- CG：下游共享仓 on-hand，按 **B SKU 归属**计入对应分公司，不算在途；
  - 风险：如果同一 SKU 同时出现在多个分公司池、或 B 归属不唯一，当前按“行所属 pool”计入，可能在不同分公司决策里重复使用同一共享库存；需靠 B 唯一归属或后续批次额度约束。
- 阶段没有批次键时，取“最大单阶段”避免同批重复；另给独立供给情景。

## 7. ETA/交期来源（重要）

- **SO→DN**：实测 2026 最近 6 个月 p90 约 34 天；
- **DN 出库→到仓**（项目已有 ZMT/Shipment 快照）：
  - 普船：中位 44 / p90 61 天
  - 快船：中位 27 / p90 32 天
  - 空运：中位 13 / p90 14 天
- 通途采购单本身没有 ETA，且采购日期可能漏建/晚建，**不能作为规划基准**；
- 正确口径应以 **EN 的下单日期 / DN 创建日期 + 运输方式分段** 计算；
- 当前手动 PO 的 ETA 已改为 **EN DN 创建日期 + 海运普船 p90 61 天** 估算（不再用通途采购日期）：141 行中 130 行可估、USNJ 62 行；DN 关联/运输方式仍不完整，只是近似，接口恢复后替换。

## 8. 决策怎么落地

- 需求（p90） − 已知供给 = 缺口；
- 补/催已有/不补/待核；
- 下单日 = 需要日 − SO→DN p90；过期标 past_due；
- 未覆盖、过期、PO 未映射等会写“可执行性=否”原因；
- 只是候选，人工审核后才下单。

## 9. 老板版 FAQ

- **问：为什么要有“中位/保守”两档？** 中位用于产能/销售讨论，保守用于补货；不承诺 95%。
- **问：为什么有的 SKU 没建议？** 缺近期销量，系统不硬编，列出来人工看。
- **问：为什么数字和上次不同？** 订单更新、模型/供给变化都会变；看 bundle_id 和 as_of。
- **问：能不能直接下单？** 不能；`可执行性=否` 时只能当候选。
- **问：PO 什么时候到？** 看 EN 下单/DN 日期 + 运输方式；通途采购日期不作为基准。

## 10. Agent 回答要求

被问“为什么”时：
1. 先说结论/动作；
2. 说需求分位（中位/保守）和模型/分型；
3. 说供给各阶段和日期来源；
4. 说未覆盖/未知/过期；
5. 引用 bundle_id、as_of、包版本；不知道就写“未提供/未知”，不补 0。
