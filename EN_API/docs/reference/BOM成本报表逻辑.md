# BOM Cost List V2 报表 —— 逐列说明（业务版）

> 本文写给业务同事看，解释报表里**每一列是什么、数字怎么来的**，全篇不含代码。
> 表格里写的列名，就是界面上看到的列标题；需要和 IT 沟通时，直接报列名即可。

## 一、这张报表是干什么的

把「产品」大类下的所有成品列成一张表，横向展示这个成品的：

- **成本构成** —— 皮壳、绍兴包装（半成品/成品）、海外加工
- **重量与体积** —— 单重、包装体积、计费重量
- **各目的地的物流成本** —— 头程运费，以及"发到目的地之后、尾程之前"的总成本

一行 = 一个产品（如果开启了"显示客户物料号"，则一行 = 一个客户物料号）。

## 二、过滤器怎么用

| 过滤器 | 默认 | 说明 |
|---|---|---|
| 物料组 | 产品 | **必填**。选一个组，报表会包含它下面所有子组 |
| 显示停用物料 | 否 | 默认只列在用物料 |
| 精简列视图 | 否 | 只有"生产经理"角色能用；勾上后只显示常用列 |
| 累加成本列排到最后 | 是 | 把"尾程前成本"这类累加列排到表格最右边 |
| 显示客户物料号 | 否 | 打开后多一列；**一个产品有多个客户物料号时会拆成多行** |
| 半成品运费缺失时用皮壳运费 | 否 | 半成品运费为 0 时，用皮壳运费近似顶上 |
| 缺重尺 | 显示全部 | 可只看「缺重尺」或只看「不缺重尺」的产品 |

## 三、逐列说明

### 3.1 产品基础信息

| 列 | 含义 | 怎么来的 |
|---|---|---|
| 产品编号 | 产品的物料编码，报表的行标识 | 直接取物料编码 |
| 客户物料号 | 该产品对应的客户物料号 | 开启"显示客户物料号"后才出现；多个客户物料号会拆成多行 |
| 产品图片 | 产品缩略图 | 优先用**物料自己的图片**，没有则用**所属物料组的图片** |
| 物料组链接 | 可点击，跳到该产品的物料组 | 按产品所属物料组生成 |
| 产品名称 | 产品全名 | 取物料名称 |
| 绍兴发货方式 | 这个型号按哪种方式发（皮壳 / 半成品 / 成品） | 从产品编码里取出**型号（KS 号）**，再用型号去找对应物料组上维护的「发货方式」 |
| 产品BOM | 该产品的默认 BOM，可点击 | 见下方「取数规则」第 1 条 |
| **皮壳成本** | ⚠️ **列名有误导** —— 它取的是**产品 BOM 的总成本**，等于「皮壳 + 内胆」的合计，不是单指皮壳 | 见下方「取数规则」第 2 条 |

### 3.2 绍兴包装

| 列 | 含义 | 怎么来的 |
|---|---|---|
| 绍兴包装半成品-编号 / 名称 / BOM | 该产品对应的"绍兴包装半成品" | 按物料组规则推导（见「取数规则」第 4 条） |
| 绍兴包装半成品成本 | 它的默认 BOM 成本 | 同「成本」口径 |
| 绍兴包装成品-编号 / 名称 / BOM | 该产品对应的"绍兴包装成品" | 同上 |
| 绍兴包装成品成本 | 它的默认 BOM 成本 | 同上 |
| **绍兴总成本** | 绍兴这一段的合计成本 | 见下方「取数规则」第 5 条 |
| 成品参考采购价 | 该产品的参考采购价 | 取「供应链参考采购」价目表上的价格 |

### 3.3 填充物与工序

| 列 | 含义 | 怎么来的 |
|---|---|---|
| 填充物N名称 / 数量 | 该产品用到的填充物及用量 | 从**绍兴包装成品 BOM 的「展开物料」**里，挑出属于 **PP 棉**类的物料；数量表示"每做 1 个成品需要多少"。数量最多有几个，列就有几组 |
| 工序N名称 / 时间(分钟) | 每道工序及其工时 | 取自绍兴包装成品 BOM 的工序行，按顺序排列 |

### 3.4 海外加工成本

| 列 | 含义 | 怎么来的 |
|---|---|---|
| 美东包装成品-USNJ 编号 / 名称 / **加工成本** | 发往美东的包装成品及其加工成本 | 加工成本取**该物料的估值价**（系统里的成本价）。若该物料已停用，此列留空 |
| 美中包装成品-USTX 编号 / 名称 / **加工成本** | 发往美中的同上 | 同上 |
| 波兰包装成品-PL 编号 / 名称 / **加工成本** | 发往波兰的同上 | 同上 |

### 3.5 重量与体积

| 列 | 含义 | 怎么来的 |
|---|---|---|
| 重量模板-编号 / 名称 | 该产品对应的重量模板 | 按产品编码的三段（型号 / 面料 / 尺寸）拼出 |
| 皮壳单重-(g) | 皮壳单个重量 | 取重量模板上的"皮壳单重" |
| 成品单重-(g) | 成品单个重量 | 取重量模板上的"成品单重" |
| 单个包装体积-(cm³) | 一个成品的包装体积 | 取重量模板上的"包装体积" |
| 半成品包装体积-(cm³) | 半成品的包装体积 | 取重量模板上的"半成品包装体积" |
| **成品实际重量-(kg)** | 按单重换算 | 成品单重 ÷ 1000，**向上保留 1 位小数** |
| **成品体积重量-(kg)** | 按体积折算的"体积重" | 单个包装体积 ÷ 6000，**向上保留 1 位小数** |
| **成品计费重量-(kg)** | 最终用于算运费的重量 | 取「成品实际重量」与「成品体积重量」中**较大的那个** |
| **半成品计费重量-(kg)** | 半成品用于算运费的重量 | 有"半成品包装体积"→ 体积 ÷ 6000 向上保留 1 位；没有 → 用半成品单重 ÷ 1000 向上保留 1 位 |

> **向上保留 1 位小数** = 1.21 记作 1.3，1.20 记作 1.2（只要有小数就进位）。

### 3.6 物流列（每个目的地一组）

系统里每个**生效中的物流价**会产生一组列（美东 USNJ、美中 USTX、波兰 PL、以及各 FBA 目的地）。
价格取"当前生效、且最近维护的那一条"。

| 列 | 含义 | 怎么算 |
|---|---|---|
| 头程单价 | 该目的地按重量计的单价 | 直接取物流价 |
| 皮壳运费 | 发皮壳到该目的地的头程运费 | 单价 × 皮壳重量(kg) |
| 半成品运费 | 发半成品到该目的地的头程运费 | 单价 × 半成品计费重量(kg) |
| 成品运费 | 发成品到该目的地的头程运费 | 单价 × 成品计费重量(kg) |
| 发皮壳尾程前成本 | ⚠️ 列名写着"皮壳"，但**口径会随该行的「绍兴发货方式」切换**（半成品行显示的是发半成品口径） | 见「取数规则」第 6 条 |
| 发成品尾程前成本 | 按"发成品"形态算的成本（固定口径，不切换） | 见「取数规则」第 6 条 |

> **列的分组规则**：FBA 类目的地**没有**「皮壳运费」「半成品运费」「发皮壳尾程前成本」，只有「单价 / 成品运费 / 发成品尾程前成本」。
> 非 FBA 目的地（USNJ / USTX / PL）才有完整的皮壳、半成品、成品三套。

### 3.7 管理员专有列（表格最右侧 3 列）

| 列 | 含义 |
|---|---|
| BOM皮壳-编号 | 该产品对应的**皮壳物料**（产品编号加 `PK#` 前缀） |
| BOM皮壳成本 | 该皮壳物料默认 BOM 的成本 |
| BOM内胆成本 | 该产品**内胆物料**默认 BOM 的成本（内胆按"同尺寸"匹配） |

> 只有**系统管理员**角色能看到这 3 列。

## 四、取数规则（关键，看数前请先读）

**1. 什么算"默认 BOM"**
必须同时满足两个条件：**已启用** + **已设为默认**。
两者缺任何一个，系统都当成"没有 BOM"，相应成本直接显示 **0**。

> 实际例子：`KS0464-FHXYR-60x45x42-RED` 的皮壳成本显示 0，就是因为它的两张皮壳 BOM 都处于**停用**状态，且物料的默认 BOM 绑定被清空了。

**2. BOM 成本 = 材料成本 + 工序成本 + 废料成本**

- 材料成本：BOM 里所有物料的金额之和
- 工序成本：各道工序的工时费之和
- 废料成本：BOM 里的废料项金额
- 这三项都是**记录在 BOM 单据上的数字**，不是打开报表时现算的

> ⚠️ 提醒：ERPNext 标准算法是"**减去**废料成本"，而这张报表是"**加上**"。目前系统里没有任何废料项，两种算法结果一样；将来若启用了废料项，两边会对不上。

**3. 报表不会自动"重算成本"**
报表只读取 BOM 上已有的成本数字。
如果 BOM 内容变了（比如换了面料、改了用量）但没有在 BOM 上点过「更新成本」，**报表显示的就是旧数字**。

> 另外：点「更新成本」**不会改变 BOM 的"最后修改时间"**，所以不能靠看修改时间判断成本有没有更新过，只能看数字。

**4. 关联物料（皮壳 / 内胆 / 各类包装）怎么找**

这些不是靠 BOM 的上下级关系找的，而是**按编码和物料组规则推算**：

- **皮壳**：产品编号前面加 `PK#`
- **内胆**：先看产品属于哪个物料组，去对应的「内胆#…」组里，找**尺寸相同**的物料
- **绍兴包装成品 / 半成品、美东 / 美中 / 波兰包装成品**：去对应的「…包装成品#…」组，取该组上维护的**型号**，再拼上**尺寸**凑出物料编号
- **重量模板**：按产品编号的三段（型号 / 面料 / 尺寸）拼出
- **绍兴发货方式**：从产品编号取型号，去物料组上取"发货方式"字段

> 因此：**物料组上的型号、发货方式等字段维护错了，报表这一行就会串或空**。

**5. 绍兴总成本 `绍兴总成本` 的两种算法**

- **自采购情形**：当"绍兴发货方式 = 成品"、皮壳成本不为 0、绍兴包装成品成本为 0，
  且该产品 BOM 的用料里出现了它自己 → 绍兴总成本 = **皮壳成本**
- **其他情形**：产品 BOM 和绍兴包装成品 BOM 都存在 → 绍兴总成本 = **皮壳成本 + 绍兴包装成品成本**

**6. 尾程前成本怎么算**

**先理解"尾程前"**：货从绍兴出发，一路算到**海外仓**为止。最后一段"从海外仓送到客户手上"的配送费**还没算进去**，所以叫"尾程前成本"。

**为什么要两列**：同一批货可以用不同形态出海，成本结构不一样，报表把两条路都算出来供比较。

| 出货形态 | 绍兴要做的 | 到海外仓之后要做的 |
|---|---|---|
| 发皮壳 | 只把皮壳做好 | 在海外加工成成品 |
| 发半成品 | 皮壳 + 绍兴包装半成品 | 在海外加工成成品 |
| 发成品 | 全部做完 | 不用再加工，直接配送 |

**三个公式**：

| 形态 | 成本构成 |
|---|---|
| 发皮壳 | 皮壳成本 + 皮壳头程运费 + 目的地加工成本 |
| 发半成品 | 皮壳成本 + 绍兴包装半成品成本 + 半成品头程运费 + 目的地加工成本 |
| 发成品 | 绍兴总成本 + 成品头程运费 |

> 头程运费 = 该目的地单价 × 对应重量（皮壳用皮壳重量、半成品用半成品计费重量、成品用成品计费重量）
> 目的地加工成本 = 报表里「美东加工成本-USNJ / 美中加工成本-USTX / 波兰加工成本-PL」那三列

**⚠️ 哪一列套哪个公式（最容易看错的地方）**

「**发皮壳尾程前成本**」这一列会**随该行的「绍兴发货方式」自动切换**：

- 发货方式 = **半成品** → 用**发半成品**公式
- 其他（皮壳 / 成品 / 未填） → 用**发皮壳**公式

所以列名写着"皮壳"，但在半成品行里显示的其实是半成品口径，**不要只看列名**。
「**发成品尾程前成本**」固定用发成品公式，不切换。

**真实算例**

产品 `KS0001-CMM-153-WHITE`，发货方式 = 皮壳，目的地 = 美东 USNJ。这一行上的数字：

| 项 | 值 |
|---|---|
| 皮壳成本 | 62.999 |
| 绍兴包装成品成本 | 61.05425 |
| 绍兴总成本 | 124.05325 |
| 皮壳单重 | 1050 g = 1.05 kg |
| 成品计费重量 | 5.0 kg |
| 美东头程单价 | 8.2 元/kg |
| 美东加工成本 | 204.686615 |

**第一步，先算两种头程运费：**

- 皮壳运费 = 8.2 × 1.05 = **8.61** 元
- 成品运费 = 8.2 × 5.0 = **41.00** 元

**第二步，套各自的公式：**

- **发皮壳尾程前成本** = 62.999 + 8.61 + 204.686615 = **276.295615**
- **发成品尾程前成本** = 124.05325 + 41.00 = **165.05325**

（两个数与报表完全一致）

**怎么读这两个数**：这个产品"在绍兴做成成品再发美国"要 **165.05**；"只发皮壳出去、到美国再加工"要 **276.30** —— 贵 111 元。两列并排就是为了让你做这个比较。

> ⚠️ **"缺一即 0"**：上面每个公式里的必要项只要有一项为 0，整个尾程前成本就记 **0**。
> 这是"宁可留空也不给错数"的设计 —— 所以看到 0 要先判断：是**真的算出来是 0**，还是**有项缺失被清零**（BOM 成本没维护 / 重量没维护 / 加工成本没维护）。

## 五、看数时要注意的 6 件事

1. **列名「皮壳成本」不等于皮壳的成本** —— 它实际是**产品 BOM 的总成本**（皮壳 + 内胆）。
   要单独看皮壳，用管理员的「BOM皮壳成本」列。
2. **列名「发皮壳尾程前成本」口径会变** —— 半成品行上显示的是"发半成品"口径，不看列名会读错。
3. **0 有两种含义** —— 真为 0，或"缺 BOM / 缺必要项"被置 0。看 0 时先查产品是否**有启用且默认的 BOM**。
4. **BOM 必须"启用且默认"** —— 只启用未设默认、或只设默认但已停用，都会让成本显示 0。
5. **成本要先在 BOM 上更新** —— BOM 改过了但没点「更新成本」，报表就是旧数（反复出现的问题）。
6. **报表比较慢** —— 全量跑一次约 1 分半，查的时候耐心等一下。

## 六、常见疑问

**Q：「皮壳成本」这一列是不是只看皮壳？**
不是。它取的是**产品 BOM 的总成本**，等于「皮壳 + 内胆」的合计。
实测：`62.999 = 53.43136（皮壳）+ 9.568（内胆）`。
要单独看皮壳成本，用只有管理员能看到的「**BOM皮壳成本**」列；内胆用「**BOM内胆成本**」列。

**Q：「发皮壳尾程前成本」为什么在半成品单上数字不一样？**
因为这一列的口径会随该行的「绍兴发货方式」切换 —— 半成品行用的是"发半成品"公式。
详见「取数规则」第 6 条。

**Q：为什么这一行皮壳成本是 0？**
先查该皮壳物料是否有**同时启用且设为默认**的 BOM。多数情况是 BOM 被停用，或物料的默认 BOM 绑定被清掉。

**Q：为什么换了面料，报表数字没变？**
因为报表读的是 BOM 上已存的成本。需要在 BOM 上点一次「更新成本」。

**Q：为什么尾程前成本整列是 0？**
该公式要求皮壳成本、运费、目的地加工成本**都非 0**，任意一项缺失就全部记 0。

**Q：同一个产品为什么出现好几行？**
开启了"显示客户物料号"过滤，且该产品对应多个客户物料号。

**Q：有些目的地没有"皮壳运费 / 半成品运费"列？**
FBA 类目的地不显示这两列，只有"单价 / 成品运费 / 发成品尾程前成本"。
