## 一、项目概述

`EN_API` 是 `saihu-data-pipeline`（赛狐/ERPNext/通途数据一致性维护工具集）的一个模块，位于 `fzh-data/EN_API/`。

**核心职责**: 通过 ERPNext REST API 管理**物料组（Item Group）**数据，包括备份、对比、同步、重构、图片上传等操作，维护**生产系统**（`erpnext.vilavi.cn`）与**测试系统**（`ensh.vilavi.cn`）之间物料组数据的一致性。

## 三、业务数据模型

### 3.1 ERPNext Item Group 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | str | 物料组编码（唯一标识） |
| `item_group_name` | str | 物料组显示名称 |
| `parent_item_group` | str | 父级物料组（树结构） |
| `is_group` | int(0/1) | 1=组节点(可含子节点), 0=叶子节点 |
| `custom_model_id` | str | 自定义字段，关联赛狐 SPU/款式ID |
| `image` | str | 主图 URL（本地 /files/xxx 路径） |

### 3.2 树结构示例

```
产品 (根节点)
├── 家居类
│   ├── 客厅
│   │   ├── 三角靠枕 (custom_model_id=KS0030)
│   │   ├── 方形靠枕 (custom_model_id=KS0031)
│   │   └── ...
│   ├── 卧室
│   ├── 儿童
│   └── 庭院/户外
├── 宠物类
│   ├── 狗床 (custom_model_id=KS0020)
│   └── ...
├── 车用
├── 其他
└── (叶子节点: 创意方抱枕、圆形坐垫、圆柱小枕...)
```

### 3.3 数据流

```
赛狐 Commodities 导出 (Excel)
  列: SKU, 品名, 赛狐分类路径, SPU(款式ID)
  │
  │ SPU ↔ custom_model_id 关联 EN 物料组
  │ 赛狐分类路径 ↔ EN 树中的位置
  ▼
ERPNext Item Group 树结构
  ├── 生产系统 (erpnext.vilavi.cn)  ← 数据源
  └── 测试系统 (ensh.vilavi.cn)     ← 同步目标
```

## 四、各脚本功能逻辑详解

### 4.1 `backup_prod.py` — 生产系统备份

**运行**: `python backup_prod.py`

**功能流程**:
1. **获取核心字段**: 拉取所有 Item Group 的 name/item_group_name/parent_item_group/is_group/image/custom_model_id
2. **分批获取扩展字段**: 多批次请求（icon/color/route/description/taxes 等），避免 URL 超长；某批次失败则降级跳过
3. **合并写入 JSON**: 核心+扩展字段合并，写入 `out/生产系统备份_全量_{ts}.json`
4. **生成树结构报告**: Excel 多 Sheet（汇总/节点清单含完整路径/深度分布/父级分组）
5. **归档备份**: 复制到 `out/备份归档/`
6. **生成 RESTORE 脚本**: 将备份 JSON 内嵌到独立 Python 脚本中，`python restore_prod_to_test_*.py` 可直接恢复

**关键设计**:
- 支持 `--restore-script <path>` 从已有备份生成恢复脚本
- 恢复脚本内嵌 JSON 数据，无需外部文件

### 4.2 `compare_item_groups.py` — 生产 vs 测试对比

**运行**: `python compare_item_groups.py [--root 产品] [--root-all] [--backup-only]`

**6 个对比维度**:

| 维度 | 检测条件 | 影响 |
|------|---------|------|
| 缺失节点 | 生产有 name 但测试无 | 需同步到测试 |
| 多余节点 | 测试有 name 但生产无 | 保留不删（安全策略） |
| 树结构不一致 | 相同 name, parent_item_group 不同 | 需修正 parent |
| 名称不一致 | 相同 name, item_group_name 不同 | 需修正 name |
| 类型不一致 | is_group 标志不同 | 需修正 is_group |
| custom_model_id 不一致 | 相同 name, custom_model_id 不同 | 需修正 custom_model_id |

**功能流程**:
1. 同时连接生产/测试系统，获取全部 Item Group
2. 按根节点（默认"产品"）筛选子树
3. 多维对比，生成操作清单
4. 备份测试系统全量数据（JSON）
5. 输出 Excel 报告（汇总 + 各维度明细 + 测试子树完整备份）

**支持的运行模式**:
- `--root 产品` — 对比"产品"子树（默认）
- `--root-all` — 不限根节点，全量对比
- `--backup-only` — 仅备份测试系统，不做对比

### 4.3 `sync_item_groups.py` — 生产→测试移植

**运行**: `python sync_item_groups.py [--dry-run]`

**安全设计**:
- `--dry-run` 预览全部操作，不下发修改
- 自动校验父节点存在性
- 每个操作记录 undo 信息
- **冲突检测**: 测试中"多余"节点若占用了缺失节点的 custom_model_id → 从创建清单移除

**执行阶段**:
```
阶段 0: 分析
  → 对比生产/测试子树
  → 生成创建清单 + 修正清单 + 冲突清单
阶段 1: 修正字段 (PUT custom_model_id) — 先改字段再改树
阶段 2: 创建组节点 (POST is_group=1) — 先创建父节点保证依赖
阶段 3: 修正树结构 (PUT parent_item_group)
阶段 4: 创建叶子节点 (POST is_group=0)
阶段 5: 验证 — 重新对比生成验证报告
```

**输出报告**: Excel（汇总 + 操作日志 + 冲突跳过 + 验证结果）

### 4.4 `restructure_item_groups.py` — 测试系统重构

**运行**: `python restructure_item_groups.py [--dry-run]`

**输入**: `数据源/Commodities*.xlsx`（赛狐商品导出）

**功能流程**:
1. 读取 Commodities → 建立 `{SPU → 赛狐分类路径}` 映射
2. 从分类路径提取分类树节点（去重、带层级）
3. 获取 EN 测试系统当前 Item Group
4. 遍历所有有 custom_model_id 的 EN 节点 → 建立**移动清单**
5. **自引用保护**: 若目标分类名与产品自身名称相同（如"三角靠枕"既是分类名又是产品名）→ 上移一级
6. 创建不存在的赛狐分类节点（POST is_group=1）
7. 移动产品节点（PUT parent_item_group）
8. **异常处理**: 若目标节点是叶子节点，"不能是一个叶节点"错误 → 设 is_group=1 后重试
9. 验证并生成报告

### 4.5 `restructure_prod.py` — 生产系统重构

- 逻辑与 `restructure_item_groups.py` **完全相同**
- 唯一区别: 连接 `erpnext.vilavi.cn`（生产）而非 `ensh.vilavi.cn`（测试）
- 使用 `PROD_ERP_API_KEY` 而非 `TEST_ERP_API_KEY`

### 4.6 `restructure_prod_full.py` — 生产系统重构（增强版）

在 `restructure_prod.py` 基础上增加了以下增强：

1. **集成备份**: 执行前自动备份生产系统（复用 `backup_prod.py` 的备份逻辑）
2. **赛狐叶子节点智能识别与跳过**:
   - `find_leaf_nodes()` 分析赛狐分类树 → 找出叶子节点
   - 叶子节点在 EN 中不存在时**不创建**分类节点
   - 产品目标为不存在的叶子节点时**重路由**到父级分类
3. **增强重试策略**: 对 500/502/503/504/417/408 使用递增延迟重试（`delay × (attempt+1) × 2`）
4. **更长的超时**: `(60, 180)` 而非其他脚本的 `(30, 60)`
5. **综合报告**: 多 Sheet 报告（执行摘要/赛狐结构/操作日志/移动清单/重路由明细/验证结果/错误记录）
6. **urllib3 全局补丁**: 在连接池层面移除 Expect 头（`HTTPConnectionPool._make_request`），更彻底地解决 nginx 417 问题

### 4.7 `generate_comparison_report.py` — 重构后对比报告

**运行**: `python generate_comparison_report.py`

**4 个对比维度**:

| 维度 | 检测内容 | 覆盖范围 |
|------|---------|---------|
| 分类结构对比 | 赛狐分类节点在 EN 中的存在性、类型(is_group)匹配、祖先路径完整性 | 所有赛狐分类节点 |
| SPU 产品映射对比 | 每个赛狐 SPU 在 EN 中是否有对应节点、位置是否正确 | 所有 Commodities SPU |
| custom_model_id 覆盖率 | 覆盖率统计、赛狐有EN无、EN有赛狐无 | 全体 SPU 集合 |
| SKU 变体级映射 | 逐行比对 Commodities SKU 的 EN 匹配状态 | 所有 Commodities SKU 行 |

**特殊处理**: "产品即分类"例外 — 当产品名等于分类名时（如"三角靠枕"），不视为位置不对

### 4.8 `upload_item_images.py` — 图片上传

**运行**: `python upload_item_images.py [--spu KS0001] [--dry-run] [--env prod]`

**功能流程**:
1. 读取赛狐图片链接 Excel（列: SKU, 品名, 图片链接, spu）
2. 逐行处理（同 SPU 缓存，后续行跳过）
3. 按 custom_model_id 查询 EN Item Group
4. 查询已挂载的 File 记录，按 content_hash 清理重复文件
5. 下载图片 → 真实文件上传（POST upload_file）→ PUT Item Group.image
6. 生成结果报告

**为什么需要下载再上传？**: COS 腾讯云对象存储开启了防盗链（Referer 校验），直接设置 URL 会 403；以真实文件存入 ERPNext 使用本地 /files/xxx 路径，无跨域问题。

每个脚本都包含以下自实现组件（**严重重复**）:

```

_NoExpectAdapter        ← 8 个脚本各有一份
ErpnextClient           ← 8 个脚本各有一份（方法各异）
```

### 安全与错误处理

- `--dry-run` 预览模式（每个写操作脚本都支持）
- HTTP 重试（各脚本策略不一致: 2-4 次重试，延迟 0.3-5 秒）
- `_NoExpectAdapter` 移除 Expect: 100-continue 头（nginx/1.18 返回 417）
- Token 认证（API Key + API Secret）
- 可执行 RESTORE 脚本（备份 → 恢复，独立可执行）

| 其他异常 | 固定延迟重试 2 次 |
| 最大重试次数 | 4 次 |

## 九、已知问题与边界条件

1. **nginx 417 问题**: nginx/1.18.0 对 `Expect: 100-continue` 返回 417。通过自定义 `HTTPAdapter` 移除 Expect 头解决；`restructure_prod_full.py` 更进一步做了 urllib3 连接池级别的全局补丁
2. **文件名编码**: ERPNext API 对特殊字符的 URL 编码敏感，使用 `urllib.parse.quote(name, safe="")`
3. **文件附件上限**: 每个文档最多 3 个附件；`upload_item_images.py` 按 content_hash 清理重复附件
4. **COS 防盗链**: 腾讯云 COS 开启了防盗链，必须下载图片后以真实文件上传 ERPNext
5. **URL 长度限制**: 获取扩展字段时分多批请求，避免 GET 请求 URL 超长
6. **树结构依赖**: 创建物料组必须先创建父节点，`sync_item_groups.py` 按 is_group=1 优先创建
7. **"不能是一个叶节点"**: 移动产品到叶子节点时 ERPNext 会拒绝；restructure 脚本检测此错误后设 is_group=1 重试
