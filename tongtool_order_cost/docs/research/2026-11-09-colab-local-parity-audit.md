## 2. build-order-tabs 评估

**需要做**，否则不能停 Colab。现有本地引擎的输入是：

- `out/wb_fresh_<月>.csv`（166 列，Colab 产出）
- `out/wb_fba_<月>.csv`（95 列，Colab 产出）
- `out/merged_<月>.csv`（78 列，Colab 产出）

`fill-tables` 只填这 29 个成本/系数列，不生成行集合/列结构。

### 2.1 行集合差异（必须先解决）

- 202608 raw 10,912 → 特殊订单删除后 10,910 → 合并吸收 91 → Phase1 detail 10,821。
- 但 Colab self 表 10,870 行；差 49 行（invalid 原单/非商品/未解析等），不是 writeback_new 的 10,821 能直接替代。
- FBA：Colab 95 列 1,966 行；本地 fba_shadow 是 78 列，95 列模板仍来自 Colab。
- 结论：build-order-tabs 不能只做 `concat`，要把 Colab 的**行全集**（含 invalid/非商品/未解析）与**列合同**都实现，或明确改为本地新口径并让财务接受行数变化。

### 2.1.1 旧 self 表行全集可复现，但语义审计不通过（不采用）

旧 Colab self 表的行集合（键 = 订单号+通途SKU）可以复现到 202608 **10,870/10,870，0 差异**，但**逐键一致不等于语义正确**。按用户要求重审后确认这是 2 年前不成熟代码，存在真实错误：

1. raw 先删特殊订单（10,910）。
2. `订单号_公共部分`：非 TikTok 用 `order_common_part`；TikTok 用数字主体 + `-1`。
3. 产品名补充：`松饼大沙发-放大版` 按皮壳/海绵块/纸箱补 `包裹1/2/3`。
4. `包含包裹` = 同（公共单号, 平台SKU）组内任一产品名含“包裹”。
5. **合并行**：`包含包裹=TRUE` 且公共单号行数 ≥2 → 按公共单号合并；202608 命中 23 组/46 行。**合并本身按公共单号（未限平台SKU/产品），且对 `运费` 直接求和**，多包裹同运费数据有重复风险。
6. **通用填充物**：`Curve-Pillow-50-PPCotton/Foam` 在单皮壳组被删除（17 行）。**其中多行有非零售价/售价(人民币)**，旧表只留 Cover 行，导致销售额丢失：
   - 202608：9 个组，Lost 售价 **254.79**，Lost `售价*汇率` **1,729.98**
   - 202609：7 个组，Lost 售价 **188.27**，Lost `售价*汇率` **1,278.13**
7. 其余 raw 行原样保留。

**结论：不采用旧 Colab 的 self 展示规则**。它只是旧的展示口径，不是成本/合并规则；会低记销售额。`build-order-tabs` 的 self 166 应使用本地成熟算法的行视图（合并组一行、销售额/运费守恒），并把旧表的行数/销售额差异作为“旧表 bug 修正”记录；不再做 legacy display adapter。

### 2.2 建议的实现

新增 CLI `build-order-tabs --month`，分三个 builder：

1. **self 166**：raw（先过滤特殊订单）→ 成熟合并组视图（`split_merge`）→ 成本/系数 + 关键列 → 写 `wb_fresh_<月>.csv`。**不复刻旧 Colab 的 23 组合并/17 行删除**；行数与旧表差异按上面的销售额修正解释。
2. **fba 95**：FBA 销量表 → 订单数量 UUID 展开作为格式适配；EN 明细/BOM 成本 → 95 列 → 写 `wb_fba_<月>.csv`。
3. **merged 78**：self + FBA concat → 78 列 → 写 `merged_<月>.csv`；复用 `phase36` 的 95↔78 对账。

先做 parity 对拍：每月与 Colab 三表比行数、订单/SKU 集合、销售额、四列成本、29 列逐格；三个月全过再停 Colab。
