# 排他式分层发布吃光细层，使部分渠道覆盖率归零且月份门槛实际失效

## Problem

分层发布采用「排他阶梯」：细层发布后把命中的样本从池子里移除，再发下一层。
对非美国而言，`美国ZIP3` 是空的，于是 `L1`（SKU×分区×重量）退化成
「SKU×重量」，把样本在 L1 就吃光；到 L2/L5 时池子已空，**PL 一行都没有**，
只好整体落到很粗的「仓库×渠道」层。

同时发现第二个缺陷：分组统计里的 `覆盖月份数` 误取了**被聚合列**（费用）的去重数，
而不是 `月份` 的去重数，使月份门槛 `>= 2` 几乎恒真——门槛形同不存在。

## Symptoms

- 非美国命中层级全部为空，预测值等于「仓库×渠道」层的整体中位数
- 发布层表里 `L2_SKU_重量` / `L5_重量` 对 PL 的样本数为 0（不该为 0）
- 月份门槛 1 与 2 的扫掠结果逐位相同——这是缺陷的指纹，不是「数据恰好如此」
- 覆盖率在部分国家为 0%，而不是「预测不准」

## What Didn't Work

- **调大/调小样本门槛**：门槛只改「发不发」，不改「谁先吃样本」，覆盖率空洞依旧。
- **归因于「波兰是低方差一口价」**：早期结论认为波兰线是一口价、不值得细分。
  实际上那只是错费用列 + 排他阶梯叠加出的假象（见相关条目）。
- **加可信度加权**：在排他阶梯之上加加权，增益≈0——因为问题出在候选集为空，
  不是「细层估计不稳」。

## Solution

两处修正：

1. **改为独立发布（非排他）**：各层各自从全量训练数据统计，互不吃样本，
   由解析器按由细到粗的顺序取首个命中。
2. **修正月份门槛的统计口径**：

```python
# 错误写法：覆盖月份数 = 被聚合列的去重数
data.groupby(cols)["观察费用"].agg(覆盖月份数="nunique")

# 正确写法：对 `月份` 列做 nunique
grouped.agg(样本数=("观察费用", "size"), 覆盖月份数=("月份", "nunique"))
```

并在分组后补重量维度为空的层（`L5b_国家重量` 等），让非美国链有落点。

## Why This Works

非排他发布保证「细层存在时用细层，不存在时用粗层」，而不是「细层把数据吃光后
粗层也没数据」。覆盖率从 0% 恢复到 100%，且精度同时提升：

| | 排他 + 门槛 30 | 独立 + 门槛 10 |
|---|---|---|
| Holdout MAE | 18.07 | **15.03** |
| Holdout 覆盖率 | 99.6% | **99.9%** |
| 月初工件 202605 MAE | 21.37 | **17.64** |
| 波兰仓各欧洲国家 | 10 国覆盖率 0% | 全部 100% |

细节：波兰仓单国改善幅度 DE 21.3→19.8、ES 23.9→17.3、NL 32.5→17.0；
此前覆盖率为 0 的国家（HU/PT/DK 等）从「无估值」变为可用。

## Prevention

- **扫掠参数时把「结果完全相同」当作可疑信号**：连续参数扫掠却给出逐位相同的结果，
  通常意味着该参数没有真正生效（本例正是如此）。
- **统计聚合要检查被聚合的到底是哪一列**：`groupby(...)[col].agg(nunique=...)`
  取的是 `col` 的去重数，不是其他列。
- **覆盖率是独立指标**：报告 MAE 时必须同时报告覆盖率与「未覆盖计数」，
  否则「不产出估值」会被算成「没有误差」而隐形。
- 为「层级被上一级吃光」写防回归测试：构造「细层样本充足」的数据，
  断言粗层仍可发布。
