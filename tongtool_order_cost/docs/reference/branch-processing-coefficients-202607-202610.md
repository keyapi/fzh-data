## GS 写回：基础列 vs 系数列

订单成本表（self 166 / FBA 95 / merged 78）里有 **3 个系数输入列** 和 **15 个 `*系数` 派生列**：

### 系数输入列

| 列 | 作用 | 202607-202610 建议值 |
|---|---|---|
| `绍兴成本系数` | 乘 `皮壳成本` / `皮壳含/不含包装成本` | 保持历史值（多数 1；少数 0.9764333333），本期不动 |
| `二次加工成本系数` | 乘 `二次加工成本`（国外加工） | **按分公司**：USNJ 0.775581852、USTX 1.184762040、PL 1.902793322；FBA 行 1 |
| `绍兴二次加工成本系数` | 乘 `绍兴二次加工成本` | 本期保持 1（绍兴工厂费用以后另行标定） |

### 派生列（由基础成本 × 系数计算）

`皮壳不含包装成本*系数`、`皮壳含包装成本*系数`、`皮壳成本*系数`、`皮壳成本*系数*数量`、
`二次加工成本*系数`、`二次加工成本*系数*数量`、`绍兴二次加工成本*系数`、`绍兴二次加工成本*系数*数量`、
`1件产品成本*系数`、`产品成本*系数*数量`、`订单总成本*系数`、`订单利润*系数`。

公式（与 `phase36_fill._fill_cells` 一致）：

```
1件产品成本*系数 = 皮壳×绍兴成本系数 + 绍兴二次×绍兴二次系数 + 二次加工×二次加工系数
产品成本*系数*数量 = 1件产品成本*系数 × 数量
订单总成本*系数 = 产品成本*系数*数量 + 头程*数量 + 运费 + 海外仓*数量
订单利润*系数 = 售价*汇率 − 订单总成本*系数
```

**不带 `*系数` 的列是 BOM 理论值**（用于对账/审计）；**带 `*系数` 的列是财务校准后的口径**（建议用于定价/利润分析）。尾程运费、头程、海外仓不乘系数。

## 使用与维护

- 本期实际写入的是 `branch_processing_coefficient_policy.csv` 的 1.0/1.2/1.6；计算比例（0.7756/1.1848/1.9028）只作下一轮调整参考。周期固定后，运营定价看 `*系数` 列。
- 系数变化（新周期/新实际费用）时：更新 `config/branch_processing_coefficients.csv` 与本文件，注明生效月份、来源文件、BOM 版本、审批人。
- 不要覆盖 1104 BOM 原表；棉包等新增行单独登记。
- FBA 行不套分公司系数；若以后需要 FBA 校准，另设 `二次加工成本系数`=1、单独体系。
