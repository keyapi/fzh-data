# 交接书 C：国外工时/PP棉 重算（EN 口径优先）

> **新对话/子Agent 直接执行本页。** 这是对前一版（`_labor_detail.py`）的**修正**——前一版有两个硬错。

## 0. 前一版的两个硬错（必须修）
1. **没按「绍兴发货方式」过滤**：`= 成品` 表示**绍兴发成品、国外不加工** ⇒ **工时=0、PP棉=0**，必须**排除**。`绍兴发货方式` 为**空**的主体骨架等部件同理。**前一版把成品行也算了进去 ⇒ 高估。**
2. **分公司成品编号只用了 gsheet 的列**：已发现错例 —— `KS0340-DM-50-IVORY` 被映射到 `USTXBZCP#KS0342-50`（疑似 gsheet 错），而 **EN 的关联是 `PLBZCP#KS0340-50`**。⇒ **必须同时跑「gsheet 映射」与「EN 映射」两套并对比**。

## 1. 拆包裹是**前置**，不是并列
用户原话：**"拆包裹 和 成本获取 是 2 个相对独立的逻辑，而且是成本获取的前置条件"**。
⇒ 顺序必须是：**先合并/判定哪行算成品 → 再算工时/PP**。

**判定口径（不限 Colab）**：
- 用 EN `Tongtool Order`：**原始单 + 拆分子单**（项目有记录；`order_items` 带 `erp_item_code / quantity / shipping_method / split_package_cost_factor`）。
- 或保留拆解行，但**按 `绍兴发货方式` 判定该行是否国外加工**（成品/空 ⇒ 不加工；皮壳/半成品 ⇒ 加工）。
- **不得重复计**：同一成品的多包裹行，工时/PP **只算一次**（件数 = Σ皮壳行数量）。

## 2. 计算口径（修正版）
```
对每条 通途自发货订单行：
  ① 合并/去重（拆包裹）→ 得到"一件成品"
  ② 取该成品的 绍兴发货方式（EN `custom_shipment_type_to_branch` 或 BOM 成本表列）
     - 成品 / 空 ⇒ 该件 国外不加工 ⇒ 工时=0, PP=0（排除）
     - 皮壳 / 半成品 ⇒ 继续
  ③ 乘数：H += 件数 × (Σ BOM Operation.time_in_mins / 60)
          PP += 件数 × (BOM 内 item_group='PP棉' 行 qty)
```
BOM 条件：`is_active=1 AND is_default=1 AND docstatus=1`；USTX 工时系数已是 1.5（写入 BOM 时乘过）。

## 3. 双逻辑对比（用户明确要求）
| 逻辑 | 映射来源 | 用途 |
|---|---|---|
| **A（当前生产）** | gsheet `importBOMCostList` 的三列「美中/美东/波兰 包装成品 编号」 | 与现状对齐 |
| **B（EN 真值）** | EN 侧：产品↔分公司成品的实际关联（BOM 成本表 / `Item` 关系） | 找 A 的错登记 |

**输出**：两套各自的 3家×3月 工时/PP + **差异清单**（哪些行 A/B 指向不同成品、差多少）。

## 4. 必查的错例（用户点名）
- `KS0342-HLR-50-DEEPBLUE` —— 绍兴发货方式=**成品** ⇒ 不加工（前一版误算）。
- `KS0121-KQC-138-WHITE`、`KS0156-NYBDSFH-52x52x5-BLACK` —— 同上，**成品**。
- `KS0340-DM-50-IVORY` —— A 映射 `USTXBZCP#KS0342-50`（疑错）；**B = `PLBZCP#KS0340-50`**。
- `ZTGJ5525-SOFALSHAPEDBRACKET-IRON-55x45x45` —— 主体骨架、绍兴发货方式**空**；是成品的一部分，**不需要国外加工**。

## 5. 交付
- **Excel（不是 CSV）**，sheet：`汇总_双逻辑对比`、`明细_已计入`、`明细_排除(成品/空)`、`明细_关联缺失(分原因)`、`拆包裹组`。
- 每行可核验：月/分公司/通途SKU/数量/绍兴发货方式/产品编号/A映射/B映射/单件工时/PP单件/工时×数量/PP×数量/状态。
- **只读 EN**；不改 gsheet/Colab；不打印凭证；`uv run python`。
- 完成后 ≤400 字回报：两套口径的 3×3 工时/PP、差异行数、仍缺什么。
