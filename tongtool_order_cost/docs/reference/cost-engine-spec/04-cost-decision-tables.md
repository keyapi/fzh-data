# 成本决策表 · 按 目的地 × 绍兴发货方式

> 这是本 bundle 的**核心页**。所有「某列怎么来的」都应能在这里查到；细节下钻见括号里的文件。

## 0. 一句话模型

对**每一行订单**，成本 = **皮壳成本 + 头程 + 目的地加工成本 +（绍兴侧加成）**，
其中「绍兴侧加成」= 绍兴发货成本里**超出皮壳的那部分**（见 §4）。
目的地类型（分公司 / FBA / 海外仓）决定「目的地加工成本」是否存在；绍兴发货方式决定「绍兴侧加成」取哪一档。

## 1. 主决策表：目的地加工成本

| 目的地 | 目的地加工成本 | 依据 |
|---|---|---|
| **美东 USNJ** | `USNJBZCP#` 物料 active+default BOM 的 `total_cost`；无 BOM → `Item.valuation_rate`；`disabled=1` → `None` | `bom_cost_list_v2.py:541`（`get_item_valuation_rate`）、`:1552` |
| **美中 USTX** | `USTXBZCP#` 同上 | 同上 |
| **波兰 PL** | `PLBZCP#` 同上 | 同上 |
| **FBA**（美/欧/日/英，19 行配置） | **= 0**（`processing_cost_name` **全为空**，根本不写加工成本） | `Tongtu Shipping Warehouse` 40 行配置 |
| **海外仓**（美国海外仓 2 行） | **复用「美中加工成本 USTX」**（配置非空） | 同上 |
| 欧洲/加拿大海外仓 / 绍兴自发货 | 配置表**有分类选项但无配置行**（未证实行为） | [09](09-known-issues-register.md) |

> ⚠️ **不存在**「`HEAD-USFBA` 之类的加工成本列」——`HEAD-*` 是**头程**编码，不是加工成本。曾有「国外加工**成品** BOM」的说法是**口误**，实际只有「国外**包装**成品」。

## 2. 主决策表：头程

头程来自**价目表** `头程-CNSX-<目的地>`，按绍兴发货方式落到三列之一：

| 目的地 | 头程来源取法 |
|---|---|
| 分公司（USNJ / USTX / PL） | 皮壳件→`头程皮壳运费<n>`；半成品→`头程半成品运费<n>`；成品→`头程成品运费<n>` |
| FBA | 一律用**成品头程**（FBA 必发成品） |
| 海外仓 | 走**非 FBA**（按发货方式），但报表侧其成本列配置**映射到美中 USTX** |

**特例**：`-COVER` → 一律用**皮壳头程**；`-FOAM` → 用**差额**（成品头程 − 皮壳头程；半成品则 半成品头程 − 皮壳头程）。

### 2.1 「为什么 A/B1/B2/B3 的头程完全一样」（已核实）

- **A 的头程 = EN 按绍兴发货方式取的值**（Colab 的 EN 覆盖层）。7 月 4379 行**逐行与 B2 相等，Δ 恰好 0**（`head_src` 非空 4328 行，确实生效）。
- 验证方式：`FZH-DANEEY-皮壳仓库`（编码 `HEAD-USTX-PK`）里一个**成品件**，A 取的是**成品头程 104.55**，而不是皮壳头程 6.8 → **仓库编码被 EN 覆盖层接管**。

### 2.2 `HEAD-USTX` vs `HEAD-USTX-PK` 的真实区别

| 编码 | 含义 | 7 月实测 |
|---|---|---|
| `HEAD-USTX-PK` | 固定用**皮壳头程** | 命中皮壳头程 3853 行 |
| `HEAD-USTX` | 按**物料**发货方式（成品→成品头程、半成品→半成品头程、皮壳→皮壳头程） | 命中成品 322 / 半成品 115 / 皮壳 23 |

GS `头程运费来源编码-EN成本列名对照表` 的两行（`HEAD-USTX`→`en头程成品运费美中USTX`、`HEAD-USTX-PK`→`en头程皮壳运费美中USTX`）**确实在用**（Colab 非 EN 路径），但**对美中这些行已被 EN 覆盖层绕过**。

### 2.3 头程口径的「量级」敏感度（同一份 7 月数据）

| 若全部按 X 头程 | 合计（￥加权） | vs 现状 A |
|---|---:|---:|
| **现状 A** | **51,099**（可比行）/ 52,666（全量） | — |
| 皮壳头程 | 34,563 | −12,174 |
| 半成品头程 | 4,893（仅 120 行可比） | — |
| **成品头程** | **175,953** | **+124,854** |

→ 若「美中按发成品口径」，头程应取**成品头程**，7 月要**再加约 12.5 万**。**这是唯一真正会动头程的杠杆**（改仓库编码**不会**）。

## 4. 主决策表：绍兴侧加成（= 绍兴发货成本 − 皮壳）

EN 里有**两处**按发货方式组合「绍兴成本」，口径**不同**：

| 发货方式 | **① 报表列 `绍兴总成本`（`sx_cost_all`）** | **② 订单同步字段 `绍兴发货成本`（`sx_shipping_cost`）** |
|---|---|---|
| 皮壳 | `皮壳成本 + 绍兴包装成品成本` | `皮壳成本` |
| 半成品 | `皮壳成本 + (绍兴包装成品成本 − 剔除额)`（**从不加半成品成本**，只剔除） | `皮壳成本 + 绍兴包装半成品成本` |
| 成品 | 自采购特例→`皮壳成本`；否则 `皮壳成本 + 绍兴包装成品成本` | `绍兴总成本`（= 皮壳+绍兴包装成品成本） |
| **FBA 仓** | — | `绍兴总成本`（**不看发货方式**） |
| 空 | `皮壳成本 + 绍兴包装成品成本` | 同皮壳 |

→ **「绍兴发货成本 = 按发货方式三档组合」只在 ②订单同步里成立**（= 用户回忆的那套）。①报表是另一套（半成品走「成品成本 − 剔除」）。
→ 因此「绍兴侧加成（超出皮壳部分）」= 半成品→`绍兴包装半成品成本`；成品→`绍兴包装成品成本`；皮壳→0。

**剔除额**（Jack，2026-10-10）：`= 绍兴包装半成品 BOM 的 operating_cost + 其「包装箱/包装袋」子树物料 amount`，再 ×「绍兴包装成品 BOM 引用半成品整件那行的 qty」。
👉 **只影响**：报表 `绍兴包装成品成本` / `绍兴总成本` / `发成品尾程前成本`；订单同步 `cost_sxbzcp` / `sx_cost_all` / **FBA 仓的 `sx_shipping_cost`**。
👉 **不影响**：皮壳成本、绍兴包装半成品成本、加工成本三列、头程三列、`pllc_cover`、**非 FBA 的 `sx_shipping_cost`**。
→ **故：非 FBA 的「半成品发货成本 = 皮壳 + 绍兴包装半成品成本」不受剔除额影响（用户判断 ✓）**；唯一例外是 **FBA 仓**（走 `sx_cost_all`，会间接变小）。
详见 [deduction-and-sxbzcp-adjustments.md](deduction-and-sxbzcp-adjustments.md)。
