# 【重大建议】改用「通途SKU → EN 客户物料号」直连

> ## ⛔ 【2026-10-16 第三轮 Codex 复核：本页结论**不予通过**】
> **「更准 / 严格占优 / 零损失 / 四类问题消失」——全部撤回。** 必须与 [20-codex-round3-corrections.md](20-codex-round3-corrections.md) 同读。
> 主要更正：
> ① **4372 是「候选命中」不是「可唯一可靠取成本」**；阻断歧义后唯一数 **4369**，另有 **3 行多产品/多值歧义**；
> ② **本页 §1.3 的样例本身是登记冲突**：`TT0031187K0063920-Cover` 同时指向 PP 件（85.75843）**与**海绵件（0）——
>    我原脚本**对客户码取 max**，**正好掩盖了冲突**（这正是我批评别人的反模式）；
> ③ **23 处差异的正确拆解**是「3 客户码歧义 + 3 旧WT歧义 + 17 其余」；17 行涉弧形皮壳/光磨砂绒/鹅卵石6件套/脚蹬，**并非都是填充物问题**；
> ④ 「7 行未命中」真实是 2 针线扣 + 1 棉包 + **4 五件套**，**不是尾缀问题**；
> ⑤ 「0」来自**无默认 BOM 的估值回退**，不等于 BOM 已证明加工费为 0；
> ⑥ **7 月历史不可直接回算**（反例：五件套客户码 `creation=5/21` 但 Version 显示 `8/11` 才 added）。
> **→ 本页降级为「待验证的方向」**；下一步按 [20](20-codex-round3-corrections.md) §9 的 6 条修订方案走，**先出离线证据表、不先建表**。
> 仍有价值的部分：**「通途SKU ↔ 客户物料号」确实是一条可用的「身份解析候选路径」**，值得优先验证（但必须带**歧义阻断**）。

> 起因：用户指出「**EN BOM 成本表里有 `客户物料号`，通途订单里有 `通途SKU`，两者本可直接对上；
> 而我们 Colab 仍在用『几年前没有 EN 系统时、从产品名称解析品类-尺寸-面料』的土办法**」。
> 实测**成立**，且效果远好于现路径。**本页可能推翻 [11](11-plan-new-ustx-processing-table.md) 的一部分设计前提。**

## 1. 实测结论（2026-07 数据，美中 4379 行）

### 1.1 直连可行性

```
通途订单.通途SKU  ──→  importBOMCostList.客户物料号  ──→  美中加工成本, USTX
```

| 指标 | 值 |
|---|---:|
| 订单表不同 `通途SKU` | 825 |
| `importBOMCostList.客户物料号` 不同值 | 3315 |
| **两者交集** | **801 / 825 = 97%** |
| `通途SKU` ∩ `产品编号` | **0**（对不上，**必须走客户物料号**） |
| **美中行命中（含 `-Cover` 去尾）** | **4372 / 4379 = 99.8%** |

### 1.2 与现路径（品类尺寸面料编码 → 重量模板）逐行对比

| 对比 | 行数 |
|---|---:|
| 两条都有一致 | **4308（98.4%）** |
| 两条都有**不一致** | 23 |
| **只有「客户物料号」路径有** | **41** |
| 只有「重量模板」路径有 | **0** |
| 两条都没有 | 7 |

**→ 「客户物料号」路径 *严格占优*：零损失、多覆盖 41 行。**

### 1.3 那 23 处不一致说明了什么

样例（均为 `LM-HS-001-*` 族）：

| 通途SKU | 品类尺寸面料编码 | 重量模板 | 客户物料号路径 | 重量模板路径 |
|---|---|---|---|---:|
| `TT0031187K0063920-Cover` | `…-FOAM-50-DM` | `ZLMB#KS0342-DM-50` | **85.75843** | 0.0 |
| `TT0031179K0063904-Cover` | `…-PP-50-HLR` | `ZLMB#KS0340-HLR-50` | **0.0** | 85.75843 |

→ **重量模板是「模板级」的（组内取 max），会把 FOAM / PP棉 这类**同尺寸不同填充**的变体抹平**；
**客户物料号是「件级」的，能区分**。所以不一致处**大概率是客户物料号更准**（需业务抽验确认，见 §4）。

## 2. 为什么这很重要：它一次绕开四座山

现路径的困难，全都来自「品类尺寸面料编码 ↔ 重量模板」这一跳：

| 现路径的困难 | 直连后 |
|---|---|
| 尺寸档归并（90→100 等，**EN 里无规则**） | **不存在** |
| **161 个键的 `EN重量模板物料号` 为空**（断链、逐月扩大） | **不存在** |
| 3 个同键双模板歧义（`KS0423-*`） | **不存在**（客户物料号近乎唯一：3315 中仅 7 个一物多行） |
| 品类/尺寸/面料 三段拼接 + 硬编码 + 海绵特例（[14](14-colab-key-derivation-chain.md)） | **不需要** |
| 覆盖率不全、需人工补行（用户长期痛点） | 提成 **99.8%**，且**随 EN 自动更新** |

## 3. 对既有方案的影响（**重要**）

| 既有内容 | 影响 |
|---|---|
| [11](11-plan-new-ustx-processing-table.md)「骨架 = 四表并集 922、按 `品类尺寸面料编码`」 | **应改为按 `客户物料号`（通途SKU）建表**，骨架 = `importBOMCostList` 的 `客户物料号`（3315 个），或仅取订单用到的 |
| [11](11-plan-new-ustx-processing-table.md) §3.2 的嵌套 VLOOKUP 公式 | **弃用**（不再需要两跳） |
| [12](12-weight-template-mapping-spec.md)「重量模板映射 / 尺寸档不在 EN」 | **不再是阻塞**（只是在「仍要走重量模板」时才相关） |
| [15](15-exception-rows-monthly-impact.md) 的「161 空键 / 断链扩大」 | **对新路径不构成风险**（新路径不读 wt） |
| 「让 EN 落一个 `重量模板 ↔ 品类尺寸面料编码` 映射字段」的长期建议 | **可降级/推迟**：改走客户物料号后**不再需要**这张映射 |

## 4. 待确认（**这几条需要业务/财务拍板，我给出建议**）

| # | 问题 | 我的建议 |
|---|---|---|
| Q1 | 「客户物料号」路径与「重量模板」路径**不一致的 23 行**，以谁为准？ | **建议以客户物料号为准**（件级 > 模板级；`LM-HS-001-*` 的 FOAM/PP 差异正是被模板抹掉的）。**请抽验 3~5 行实物**确认 |
| Q2 | 未命中的 **7 行** | 逐行列原因（多为 SKU 未登记客户码 / 新 SKU）；**不要猜**，留 `unmatched` |
| Q3 | `客户物料号` 有 **7 个一物多行** | 建表时**必须断言唯一**（多行且值不同 → 判歧义，不取首/末） |
| Q4 | 「客户物料号」在 EN 里是 `Item Customer Detail`（**按客户**登记），换客户/换登记口径会不会漂？ | 需**确认 7 月当时**的登记状态；历史回算要注意时点（见 [01](01-overview-and-glossary.md) §4） |

## 5. 建议的新表形态（供拍板）

| 项 | 建议 |
|---|---|
| **键** | `客户物料号`（= 订单 `通途SKU`，去 `-Cover` 等尾缀）**而不是** `品类尺寸面料编码` |
| 骨架 | `importBOMCostList.客户物料号` 全量（3315）∪ 订单用到的 |
| 值 | `美中加工成本, USTX`（同一客户物料号多行时**断言唯一**） |
| 标记列 | `en_ustx` / `zero_literal` / `unmatched` / `ambiguous_customer_sku` |
| **隔离** | ⚠️ **不能放回 `二次加工成本2022` 主工作簿**（notebook 会按名自动读；见 [17](17-codex-round2-corrections.md) §2）→ 放**独立工作簿**，或先用加载器明确排除的测算表名 |
| 列结构 | **不需要**月份的「多月列」，只要一列当前值（或按月一列），因为源是 EN |

## 6. 一句话

**「通途SKU → 客户物料号」是更短、更准、几乎全覆盖的路径；它把「品类-尺寸-面料 / 重量模板 / 尺寸档 / 161 空键」这一整块历史包袱绕开了。** 建议以它为主路径重做新表设计。
