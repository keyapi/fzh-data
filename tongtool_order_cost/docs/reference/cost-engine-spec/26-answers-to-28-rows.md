## 1. `TT0031054K0062974` 的 **27.04** 从哪来

**来自旧路径**（Colab 用「产品名称解析」得到的键所指的模板）：

```
订单行 品类尺寸面料编码 = RD-YM-pet-006-45-WGMSR
   → import皮壳成本.EN重量模板物料号 = ZLMB#KS0234-KJB-45
      → EN 表 美中加工成本 = 27.04276
```
而 **10/16 的 BOM 成本表**里 `TT0031054K0062974` 直接给 **18.86**。
→ 两者差 **= 旧 parser 把它归到了 `KS0234-KJB`（另一款）**。**是否属「历史成本代理」，需业务确认**（Codex 也要求「先核实旧映射是否刻意代理」）。

## 3. 五件套 `TT0031102-zuhe-all`（**已实测**）

拉到了 Product Bundle `TJ#KS0238x1_KS0240x1_KS0241x1_KS0242x1_KS0243x1-001`：

| 子件 | qty | 10/16 美中加工成本 |
|---|---:|---:|
| `KS0238-KJB-45-BLUE` | 1 | 0 |
| `KS0240-KJB-45-BLUEPURPLEPINKCOMB` | 1 | 0 |

- **套件本身无价**（Bundle 的 `rate=0`、`amount` 空）→ **只能累加孩子**（本次 5 个 qty 都是 1）。

- → **处置**：五件套的二次加工成本 = **Σ(子件成本 × 数量)**，**不为套件造 BOM**（与 Codex 一致）。

## 4. `TT0031187K0063920-Cover`：**「取有值的第一行」会取错** ⚠️（你点出的真问题）

- 该客户码在 BOM 表里有 **2 行**：一行空、一行 **85.758**（PP 件）。
- **但**该 SKU 是**纯皮壳**，同一皮壳可配两种填充：**弧形海绵靠枕**（`…-Foam-…`）与 **弧形PP棉靠枕**。
- **海绵填充不能在国外操作** → 海绵款**从绍兴发成品** → **国外二次加工 = 0**。
- **所以「取有值的第一行」→ 85.758 只对 PP 款；若是海绵款就错了。**

**实测（7 月该 SKU 的合并结果）**：合并后那一行带的是 `LM-HS-001-FOAM-50-DM`（**FOAM 键**）→ **旧路径 = 0** ✓，**取对了**。

**✅ 解决方案（推荐）**：**按「填充物」分流**，信号取**订单侧已有字段**：

| 信号 | 海绵（Foam） | PP棉 |
|---|---|---|
| `品类尺寸面料编码` 含 `FOAM`/`HM` | ✔ | 否 |
| `平台SKU` / `解析后SKU` 含 `Foam`/`sponge` | ✔ | 含 `PPCotton`/`PP` |

**规则**：**是海绵 → 二次加工 = 0**（国外不操作填充）；**是 PP棉 → 取 USTX 包装成品成本**。
**⚠️ 必须给「客户码直连」路径加这道闸**，否则它会取到 85.758（跨填充物取错）。

**实测覆盖**：7 月美中里「键含 FOAM/HM」共 **27 行**，两条路径**都给了 0** → **现状没错**；但**换直连路径必须加闸**。
（平台SKU 带 `Foam` 的仅 **10 行**——**标记不全**，故**优先用「键里的 FOAM/HM」，平台SKU 作补充**。）

## 6. `TT0312576K0064149` / KS0423 —— **⚠️ 本节的「删/改 637 行」结论已作废，见 [27](27-gsheet-source-root-cause.md)**
