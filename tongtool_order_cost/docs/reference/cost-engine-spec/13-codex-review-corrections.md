## 3. ⚠️ 新表提案的公式**搜错列**（本 bundle [11](11-plan-new-ustx-processing-table.md) §3.2 更正）

**原写法（错）**：`VLOOKUP( <wt>, importBOMCostList!$A:$Y, 21, FALSE )` —— 搜的是 **A 列（产品编号）**，不是 wt。

**已按冻结表列序自证**：`importBOMCostList` 中 **`产品编号`=A、`重量模板, 编号`=Y、`美中加工成本, USTX`=U**。

**正确写法**：
```
=IFERROR( IF( MATCH(<wt>, importBOMCostList!$Y:$Y, 0)=0, "",
   INDEX(importBOMCostList!$U:$U, MATCH(<wt>, importBOMCostList!$Y:$Y, 0)) ), "" )
```
且**不要用 IFNA 空白掩盖状态** —— 必须先区分 `缺失 / 歧义 / 字面 0` 再取数（与 [11](11-plan-new-ustx-processing-table.md) §3.4 的「取数来源」列配套）。

**附带更正（Codex §8.1）**：当前 `二次加工成本2022` **没有**正式的「美中USTX二次加工成本」表（只有测算表，且 cell108 排除含「测算/import」的页）；
本次捕获范围内的现行公式**没有**该错公式（即**错公式尚未部署**）；现行 `import皮壳成本` C/D/E 用 `INDEX/MATCH` 指向 `importBOMCostList` 的 **N/R/X**，以 **Y** 匹配 **B 列 wt**，**方向正确**。

## 4. ⚠️ 「改来源码无影响」**是错误归因**（本 bundle [07](07-colab-vs-en.md) 与 [11](11-plan-new-ustx-processing-table.md) R7 更正）

Codex 追到最终消费点的主加工成本链：

```
importBOMCostList(N=绍兴成品包装 / R=美国加工 / X=波兰加工；Y=WT)
  → import皮壳成本 C/D/E（INDEX/MATCH）
  → 绍兴二次加工成本表（按旧 key 查 C 列，含历史月回退）
  → cell108 的 df_cost_2prod_nodups（来源码 + 旧 key）
  → cell125 先 drop 原列、再双键 merge      ← ★ 这里会按来源码重新取数
  → 主「二次加工成本」
```

→ 因为 **cell125 会按 `二次加工成本来源编码` 重新取数**，所以「改来源码无影响」**不成立**。
→ **该结论只对「头程」成立**（头程确由 EN 覆盖层接管）；**对「二次加工成本」不成立**。

**新表真正生效还需要（Codex §8.2）**：可被 loader 读取的表名 + **明确来源码** + **正常生产仓库路由切换** + 完整且唯一的对象关联 + 整件/分件的成本分项规则。**只建表加公式不够。**
