# 7–9月「订单解析 vs EN 真值」体检

> **方法（只读）**：EN `Item Customer Detail.ref_code`（通途SKU→EN 物料的权威登记，**REST 该字段 403，须 SSH 查 DB**）作真值；对 7/8/9 月美中(`USTX分公司`)订单逐行比「订单解析出的 `品类`」与「EN 物料的 `item_group`」。
> **产物**：`out/ustx_wage_sim/parse_vs_en_7to9.csv`（12817 行明细，gitignore）。

## 0. 总览：**成本基本算能用** ✅

- 美中订单 7/8/9 月合计 **12817 行**、**443** 个通途SKU。
- **键覆盖：订单键 99.98% 都在皮壳表里**（仅 **2 行**缺键 `SX-KZSJ-55-HLR`）⇒ **取值链不断**。
- 不一致分两类：**品类名不符（88 行 / 7 类）**、**面料码与 EN 不同（85 行 / 18 类）**。后者**两侧都在用内部码**（订单解析与皮壳表一致），故**不破坏取值**。

## 2. 面料码不一致（85 行 / 18 类）—— **不破坏取值**

> **根因**：`材料价格明细` 里的面料码与 EN 物料名里的面料段**命名不统一**（如「雪尼尔欧式腰果提花」在本表 `ML-XNEOSTH`、在 EN 是 `XNEOSYGTH`）。但**订单解析与皮壳表两侧用的是同一套内部码 ⇒ 能对上 ⇒ 成本不受影响**。**故按你"成本基本能用"的判据，这类可不动。**

## 3. 待办 / 建议

## 4. 通途侧产品名核对（用户要求）—— **工具可用，但这些 SKU 查不到**

- **工具**：`erp2_product_goodsquery`（通途官方 MCP，经 `tongtool_api/mcp_http.py`；凭证在父仓库 `tongtool_api/.env`；**限流 5 次/分、主/副 App 共用一个桶**）。
- **可用性已验证**：`productType='3'` 能返回 CEN/石头族商品（如 `TT0009000K0009051` = `深灰纯色六件套 石头抱枕 CEN PureStone Dark Gray 6pcs`）⇒ **接口通、SKU 形如 `TT########K#######`**。
- **但这批查不到**：`skus=['TT0312588K0064179','TT0031179K0063904',…]` 在 `productType=1/2/3` 全返回空；productType 1/3 逐页（1-5 页×100）也搜不到 `TT0312588…`/`TT0031179…`。
  ⇒ **该 API 账号（PRIMARY）里没有这些商品** —— 很可能它们在**另一个通途账号**，或用的是另一个 `productType`/需要别的过滤。
- **结论**：**通途侧产品名核对暂无法完成**，需用户指认「这些 SKU 属于哪个通途账号 / 怎么查」。

## 5. 直角床头板 —— 真因与影响（2026-10-17 定案）

**通途侧产品名（用户实测）**：`TT0312588K0064179-Foam` = **「直角床头板(海绵) 100\*60\*10cm」**；且它是别的 SKU（`TT0031248K0064096-100`、`TT0031249K0064104-100`）的**子货品**（通途的组合/组装/捆绑商品，类似 EN 套件）。

**真因链**：
```
通途产品名「直角床头板(海绵)」（统称，不分方格/菱形）
  → Colab 解析 品类=直角床头板
  → 品类使用面料: 直角床头板 → KS0397
  → 订单键 KS0397-<size>-HM
  → 皮壳表 → ZLMB#KS0397-…（菱形）
但 EN ref_code: TT0312588K0064179-Foam → KS0396-…（【方格】）
```

**影响（两款成本略不同）**：`ZLMB#KS0396(方格)` vs `KS0397(菱形)` 同面料同尺寸差 **≈1.5 元/件**（100x60x10：方格皮壳 49.34 / 菱形 47.84）⇒ 现状把方格单按菱形算，**少算约 1.5/件**。7-9 月共 **5 个 SKU**（100/140/153/183/194）受影响。

**EN 侧建模缺口**：Product Bundle / BOM 子件 反查**均查不到**「KS0423 是 KS0364 的部件」「XXX 是 XXX 的子货品」这类通途组合关系 ⇒ **EN 没登记这些套件**。

**修法（用户定 C：两者都做；**gsheet 侧已执行 2026-10-17**）**：
- **gsheet（已执行，25 格，回读 ✔）**：`品类使用面料` C334「直角床头板」`KS0397 → KS0396`；`皮壳表` 行 838–845 的 D/E/F 由 `KS0397-*` → **`KS0396-*`**（EN 8 个 `ZLMB#KS0396-FHXRBFJPR-<size>x60x10` 模板已验证存在）。行 763-770（绗缝**菱形**扣子床头板）保持 `KS0397` 不动。⇒ 键不再撞车，直角床头板单取**方格**模板。
- **通途侧（待你在 UI 做）**：把产品名改精确（区分方格/菱形）；**新旧都登记**以兼容老订单。

## 6. 通途 API 复查补充（2026-10-17）

- 单一账号、官方 MCP `erp2_product_goodsquery`；已试 `skus` / `skuAliases` / `productType=1,2,3` / 逐页 —— **翻不到 `TT0312588…`**。
- 该账号返回的多是 **Centrade/石头族** 商品（`productType=2` 一页 100 条多为 `Centrade …`；`=3` 是石头六件套），且**很多记录 `sku` 字段为空**（无法按 SKU 命中）。
- ⇒ **这些 SKU 大概率在被该 API key 覆盖的商户/范围之外**（或需其它参数）。**结论：产品名以用户实测为准。**
