# 可行性方案 · 新建「美中USTX二次加工成本」worksheet

> **结论先给**：**可行**，而且「行怎么建全」有现成答案——**以 `绍兴二次加工成本` ws 的行集为骨架**（它覆盖 7 月美中订单 **177/177 = 100%**），
> 只把**取值**换成 EN 的 USTX 成本即可。
> 本方案**只读测算**，不改任何表；实施需用户确认。

## 1. 目标与口径

| 项 | 内容 |
|---|---|
| 目标 | 让美中（USTX）行的「二次加工成本」取**目的地实际加工成本**，而不是借用绍兴 |
| 口径 | = EN `USTXBZCP#` 物料 active+default BOM 的 `total_cost`（即 GS 列 `美中加工成本, USTX`） |
| 现状 | 美中行取的是 `绍兴包装成品成本`（理由：EN 早年没有国外 BOM，用绍兴拟合） |
| 影响 | 7 月美中：**+225,982（￥加权）**，占 A→B2 差异的 85% |

## 2. 数据源与匹配链

```
订单 品类尺寸面料编码
   └─(1) import皮壳成本[品类尺寸面料编码 → EN重量模板物料号]        ← 工作簿「二次加工成本2022」内
        └─(2) importBOMCostList[重量模板,编号 → 美中加工成本, USTX]  ← 同一工作簿内
```

- 两跳**都在同一个 Google 工作簿 `二次加工成本2022` 内** → **可以用嵌套 VLOOKUP 写公式**，不需要跨工作簿引用。
- 参照：现存 `绍兴二次加工成本` ws 的公式就是同款一跳（`VLOOKUP(键, import皮壳成本!A:E, 3)`），新表把第 3 列换成嵌套即可。

## 3. 「行怎么建全」——骨架与取值（**核心**）

### 3.1 骨架（行的来源）——**不要只用绍兴表**

| 源 | 唯一键数 | 行数 |
|---|---:|---:|
| `绍兴二次加工成本` | 881 | 903 |
| `import皮壳成本` | 868 | 902 |
| `皮壳成本平均202409-202410-202411（用于通途订单202502）` | 868 | 902 |
| **`头程运费合并`** | **893** | 9994 |
| **四表并集** | **922** | — |
| 7 月美中订单用到的键 | 177 | — |
| 其中被 `绍兴二次加工成本` 覆盖 | 177 / 177（100%） | — |

**结论（修正）**：
- **`绍兴二次加工成本` 是「7 月全」，但相对四表并集缺 41 个键**（样例：`SX-CYCPBT-*`、`BYJ-HS-007-218-CTTM`、`RD-YM-kid-001-5-KJB`…）。
- 因此**骨架应取「四表并集（922）」**，不能只抄绍兴表；否则 8/9 月及新品会漏。
- 用户口述「更全的是 `皮壳成本平均…`」——实测它与 `import皮壳成本` **键数相同（各 868）且结构一致（都含 `EN重量模板物料号`）**，两者基本互为镜像；**最大的是 `头程运费合并`（893）**。

### 3.1b ⚠️ 真正的断链点：`EN重量模板物料号` 为空

**这是用户「手工补行」痛点的直接后果**：新增/补录的行，**键填了、重量模板号没填**。

| 表 | 行数 | 其中「键非空但 `EN重量模板物料号` 为空」 |
|---|---:|---:|
| `import皮壳成本` | 902 | **161**（例：整个 `SX-KZSJ-*-CMYH` 面料族） |
| `绍兴二次加工成本`（按 903 行草案统计） | 903 | 160 |

> **【2026-10-16 按 Codex 复核改写】** 上一版此处记 `import皮壳成本` 为 **160**；经 2026-10-16 实测（冻结快照与线上 GS 逐键一致）应为 **161 行 / 161 个键**（902 数据行中 `EN重量模板物料号` 为空者共 178 行，其中 17 行 `品类尺寸面料编码` 亦空 → 键非空者 **161**）。差异原因未证实，**以 161 为准**。
> **注意**：这 161 个键中，**7 月订单只命中 10 个键 / 41 行**；且这 41 行只是「51 行需专门处理」中的一类（另 3 类见 §3.3）。

**用户问的「B 组 10 个键」（现已改称「源映射空值」类）正是这一类**——**行在表里、不是缺行**，断在重量模板号为空。
→ **修法是「补 `EN重量模板物料号`」**（不是补行）。而重量模板的推导**不是纯字符串变换**：
`SX-KZSJ-90-DM → ZLMB#KS0001-DM-100`、`186-138-DM → …-DM-140`、`123 → 120` —— **尺寸会被归并到标准档**，
所以要么补一张「品类编码→KS 组 + 尺寸改写」规则表，要么人工补录。


### 3.2 列结构（沿用绍兴表）

`品类 / 面料 / 尺寸 / 品类编码 / 尺寸编码 / 品类尺寸编码 / 品类尺寸面料编码 / <月度值列> / 材料名称 / 材料编码 / 品类统一名 / 品类别名`

**取值列**建议新增一列（例如 `美中加工成本USTX`），公式（**已按 2026-10-16 Codex 复核更正，见 [13](13-codex-review-corrections.md) §3**）：

```
=IFERROR( IF( MATCH( VLOOKUP(G2, import皮壳成本!$A:$B, 2, FALSE),
                    importBOMCostList!$Y:$Y, 0 ) = 0, "",
   INDEX( importBOMCostList!$U:$U,
          MATCH( VLOOKUP(G2, import皮壳成本!$A:$B, 2, FALSE),
                 importBOMCostList!$Y:$Y, 0 ) ) ), "" )
```

**列号已自证**（冻结表实测）：`importBOMCostList` 中 **`产品编号`=A、`重量模板, 编号`=Y、`美中加工成本, USTX`=U**。

> ⚠️ **上一版写法是错的**：`VLOOKUP(<wt>, importBOMCostList!$A:$Y, 21, FALSE)` 搜的是 **A 列（产品编号）**，不是 wt —— 因为它把「返回第 21 列」（对）和「在 A 列查找」（错）混在一起了。
> ⚠️ **不要用 `IFNA` 空白掩盖状态** —— 必须先区分 `缺失 / 歧义 / 字面 0`，再取数（与 §3.4「取数来源」列配套）。

### 3.3b 双模板冲突（3 个真歧义键）【2026-10-16 按 Codex 复核改写】

`import皮壳成本` 里**同键指向不同重量模板**的键全表共 **3 个**（与 `ustx_cost_compare` 的 `ambiguous` 排除口径一致，不取首/末行）：
`YM-HS-018-153-HLR`、`KS0423-140-XNEOSTH`、`KS0423-153-XNEOSTH`。

其中 **7 月订单命中的是 `KS0423-153-XNEOSTH`，共 3 行**（源 CSV 物理行 7068 / 7942 / 8075）：该键同时指 `KS0364` 与 `KS0423` 两个候选模板，**皮壳、加工、头程一起取错**。Codex §5.1 指出**当前对象支持 702（指 `KS0423`）那条**，须撤下错误候选并**重算**。
月度数（含 `YM-HS-018-153-HLR`）：**7 月 3 行 / 8 月 1 行 / 9 月 2 行**——**非 7 月独有**，详见 [15](15-exception-rows-monthly-impact.md) §3。


### 3.4 用一个「备注/来源」列把每行的取数状态写死

建议加列 `取数来源`，取值：`en_ustx`（正常） / `zero_literal`（EN 值为字面 0） / `no_weight_template`（源映射空值，即原「B 组」） / `no_ustx_bom`（wt 无 EN 成本）。**【2026-10-16 按 Codex 复核改写】** 但**光记取数状态不够**——白名单 / 五件套 / 双模板冲突这三类**不是「取不到数」，而是「要按其类别特殊处置」**，须另有标记（`business_exempt_zero` / `product_bundle` / `ambiguous_shell_key`），不能与 `no_weight_template` 混为一谈（见 §3.3）。
→ **任何一行都能自证它为什么是这个数**，避免「静默为 0」。

## 4. 风险与前置

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| R1 | **表不全比借用更糟** | 借用绍兴至少有个数；若新表留空，订单成本会变 0。→ 用 §3.3 的分类**逐行标注**，缺的显式记原因，**不要静默 0** |
| R2 | **时点错配** | GS `importBOMCostList` 是快照；EN 线上持续变（含 2026-10-10 剔除额）。→ 建表时**明确写「取哪一天的值」**，并在备注列记时点 |
| R3 | **命名坑** | `import皮壳成本` 的列名叫「绍兴/美国/波兰二次加工成本」，实际装的是各地**包装成品成本**（见 [01](01-overview-and-glossary.md) §5）——写公式时别被列名误导 |
| R4 | **`importBOMCostList` 列序变动** | 嵌套 VLOOKUP 的列号是**硬编码**（第 21 列）→ 每次重建表都要复核列序 |
| R5 | **同名歧义键** | **【2026-10-16 按 Codex 复核改写】** `import皮壳成本` 有 **3 个**「同键指向**不同**重量模板」的真歧义键（`YM-HS-018-153-HLR` / `KS0423-140-XNEOSTH` / `KS0423-153-XNEOSTH`）；7 月订单命中 **3 行**（键 `KS0423-153-XNEOSTH`，物理行 7068/7942/8075），8 月 1 行 / 9 月 2 行。→ 新表对这些键要么取唯一、要么标 `ambiguous`（**不猜**）；其中 `KS0423-*` 须撤下错误候选（637→KS0364）**重算皮壳/加工/头程**（[13](13-codex-review-corrections.md) §5.1） |
| R6 | **只解决「二次加工」一项** | 「绍兴二次加工成本」也是借用（现为 0），需另行处理；本方案**不覆盖**它 |
| R7 | ~~不能只改 `订单发货仓库对应成本来源`~~ **【2026-10-16 更正】** | **原判「改来源码无影响」是错误归因**（Codex 追到 cell125：主「二次加工成本」链会**按来源码重新取数**）。<br>**该结论只对「头程」成立**（头程确由 EN 覆盖层接管）。<br>→ **新表真正生效还需要：可被 loader 读取的表名 + 明确来源码 + 正常生产仓库路由切换 + 完整唯一的对象关联 + 整件/分件分项规则**。只建表加公式**不够**。详见 [13](13-codex-review-corrections.md) §4 |

## 5. 分步实施（建议）

| 步 | 动作 | 谁能做 | 产出 |
|---|---|---|---|
| S1 | **只读产出**「新表内容草案」（CSV：键 + 面料 + USTX 值 + 取数来源） | Agent（本仓库脚本可做） | 一份 CSV 供人工复核 |
| S2 | 人工复核：**4 类缺口逐类定处置**（源映射空 10 键怎么补 / 白名单是否维持归零 / 五件套不建 BOM / 双模板冲突撤哪条）；A1 组 45 个 0 是否认可 | **用户 / 财务** | 确认或修正 |
| S3 | 在 GS `二次加工成本2022` **新建 ws**（骨架照抄绍兴表），填入公式列 + 来源列 | 用户（或授权 Agent） | 新 ws（**不启用**） |
| S4 | **dry-run 对拍**：新 ws 的值 × 发货数量 与 B2 的 `二次加工成本` 对账（应逐行一致） | Agent | 对账报告 |
| S5 | 用户确认后再谈「是否启用 / 怎么并入核算」 | **用户主权** | — |

> ⚠️ **S3 之后不改任何现有表的取值**；新 ws 建出来先**并列放着**，不动老链路。

## 6. 验证方法（S4 的对账口径）

- 单位：**逐行**（美中 4379 行）比 `新表值` vs `B2 的二次加工成本`（= `importBOMCostList.美中加工成本, USTX`）。
- 期望：**除 B/C 组外逐行相等**（浮点容差 ≤0.005）；B/C 组显式列出。
- 汇总：`Σ(新值 × 发货数量)` 应等于 B2 瀑布里的 `二次加工成本`（7 月 = **468,011**），容差 ≤1 元。
