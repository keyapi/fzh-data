# E 供给线架构原则（2026-11-11 修正版）

> 用户明确纠正后的口径。之后 E 的设计、实现、交付都按这份来。

## 1. 术语对齐

- **SKU = 产品 = EN 物料**，日常混用；不制造第四个概念。
- **仓池 = 客户**：波兰 / 美东 USNJ / 美中 USTX。EN SO 的 customer 就是按这个填的。
- EN 物料通过 **客户物料号（customer_items.ref_code）** 对应通途 SKU。
- **一个 EN 产品可以对应多个通途/平台 SKU**：拆包裹、套件、套装、渠道别名都是特例；必须保留映射表，不假设 1:1。
- 因此“产品×仓池”就是“SKU×客户”，之前说“不是一回事”是错的。

## 2. 最低要求：SKU×客户×节点（单据可选）

- **必须能回答**：某 SKU 给某客户（波兰/USNJ/USTX）在已有供给线的每个节点上，现在有多少、什么状态。
- **单据是增强，不是门槛**：SO↔DN 不完美关联是已知事实；不能因为没有单号就把数量从最小视图里删掉。
- 每个节点行至少保留：`sku, customer, warehouse, node, qty, uom, as_of, source, linkage_status`。
- 输出两个总量，禁止混用：
  - `observed_total`：观测合计；标注“可能重复，不可直接相加”。
  - `confirmed_total`：单号互斥、非重叠、可安全叠加的部分。
- 单据能查到就附 `voucher_type/voucher_no`；查不到就写 `linkage_status=unlinked`，数量仍保留。

## 3. 生命周期按客户，不按全局 disabled

- **EN `disabled` 不是“停售”事实**：它可能是美国不卖，而波兰还在卖。
- 已有证据：
  - `KS0307-KQC-26-WHITE`（TT0031109K0063731）：2024–2026 **只有波兰销售**（2026 年 126 件），美国 0；EN 禁用不能推出波兰停售。
  - `KS0198-DRKQC-116-GREY`（TT0031078K0063328）：2024 年美国有量，2025 起只有波兰（2025 年 233、2026 年 93）；美国停售 ≠ 波兰停售。
- 新增 `lifecycle_status` 按 **SKU×客户**：`active / seasonal / clearance / discontinued / blocked`。
- E 必须展示每个客户的 lifecycle；D6 只对 `active`（或季节窗口内的 `seasonal`）补货；`clearance` 不进补货；`discontinued/blocked` 排除。
- EN `disabled` 只做技术开关；禁用/启用要同时写 lifecycle 和原因。

## 4. UOM、套件、套装

- **一个 EN 产品可对应多个通途/平台 SKU**，平台 SKU 后缀常表示套件规格（1/4/6/9/12 件套）。
- 通途订单的 `qty` 是**件数**（6 件套的订单行 qty=6；12 件套=12），不是套数；但业务沟通里的“请求 200”可能是 200 件，也可能是 200 套，必须确认单位。
- E 的节点表必须保留：`uom`、`pcs_per_set`、`set_sku`、`base_sku`。
- **个和套不能直接相加**。C 波兰 11,529 就是反例：866 行“个”合计 11,521，1 行“套”=8（`TJ#KS0334x1_KS0335x1_KS0336x1-001`，三件套），11,529 = 11,521 个 + 8 套；8 套不是 8 件，不能直接和个相加。
- 软包墙围（TT0031084/85/86）：平台 SKU 有 `-1PCS / -4PCS / -6PCS / -9PCS / -12PCS` 等后缀，2026 年波兰销售以 6/9/12 件套为主；需求序列可按件建模，但补货/下单必须同时看套数，不能只报件数。

## 5. “何时”的问题

- 必须明确回答：E 是否必须支撑“何时下单/何时催单”。
- 如果必须，ETA 的最小来源：
  - DN/发运：实际发运日 + 承运商/路线 + 历史运输段分布；
  - PO：未收数量 + 预计到货日；
  - 在途/待发：通途 `intransit/waiting` + 仓库/路线，但货龄未知要标情景；
  - SO：承诺交付日不等于 ETA，不能冒充预计到仓。
- 每个 ETA 必须带 `eta_basis`（实测/历史分布/情景）和置信度；没有依据就标 `unknown`，不编日期。
- 时间是否“必须”解决，由业务目标决定：如果补货动作只分“下/不下”，ETA 是增强；如果要分“今天下/下周下/空运/催”，ETA 是必需。

## 6. 落地顺序

1. 先出 **SKU×客户×节点** 最小表（观测合计 + 可叠加合计 + linkage 标记）。
2. 再补单据级证据（SO/DN/PO/发运）和互斥规则。
3. 再接 lifecycle（按客户）与 UOM/套件换算。
4. 最后做 ETA 与“何时”动作；每一步都可单独验收，不要求前一步完美。
