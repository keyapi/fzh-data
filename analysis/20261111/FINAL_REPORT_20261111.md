## 2. E 已有供给线（Codex 已交付节点账；架构按用户修正）

**先纠正我的说法**：“产品×仓池”就是“SKU×客户”，仓池=客户（波兰/USNJ/USTX），SKU=产品=EN 物料，日常混用；EN 物料通过客户物料号对应通途 SKU，一个 EN 产品可对应多个通途/平台 SKU（拆包裹、套件、渠道别名）。

之前两周没弄明白的根因不是“产品×仓池不对”，而是：**E 只有汇总列，没有 SKU×客户×节点的账；没有单号/UOM/生命周期/观测与可叠加的区分**，所以任何加总都会重复或漏，交付压力下只能反复重汇。

Codex 这次交付：
- 设计：`supply_netting/docs/E_DESIGN.md`、`E_IMPLEMENTATION_PLAN.md`
- 实现：`supply_netting/e_nodes.py`、`e_node_history.py`、`e_node_artifacts.py`
- 产物：`E_nodes_20261111.parquet`（**21,432 个当前节点**）、`E_inventory_history_20261111.parquet`（**239,022 行历史证据**）、`E_nodes_20261111_报告.md`
- 校验：153 项测试通过；EN/C 原始库存逐 SKU 对差 **0**；C 波兰 11,529 = **11,521 个 + 8 套**；SO 3,674 **只登记一次**；未用 MCP、未写生产。
- **能回答**：某 SKU 在某客户/仓有哪些节点、各多少、来自哪张单（SO 能找到 3 张波兰 SO）。
- **还不能回答“何时”**：缺已证 ETA；`waiting` 是否已扣 `available` 未确认；波兰已售未扣未接入；WIP/CG 授权/退货转可售也缺。
- **下一步按修正后的架构重做**（已发给 Codex）：最低要求是 **SKU×客户×节点**，单据可选；`observed_total` 与 `confirmed_total` 分开；lifecycle 按客户；UOM/套件换算；再判断“何时”是否必须解决。
- 代码在 Orca worktree 分支 `feature/e-nodes-20261111`，**已提交并推送**。

### 2b. C 波兰 11,529 = 11,521 个 + 8 套 是什么意思

C14 `4_可发供给` 的波兰池 867 行里，866 行 UOM=个、合计 **11,521**；1 行 UOM=套、**8 套**，产品是 `TJ#KS0334x1_KS0335x1_KS0336x1-001`（三件套），C 已把它标成“套件单列、不进个净额”。11,529 是把“个”和“套”直接相加的展示值；8 套不是 8 件，不能参与个的净额比较。E 必须分 UOM 输出，先换算再比较。

- **支持**：52% 件数在合理区间。
- **软包墙围必须先确认单位**：这组产品按 **1/4/6/9/12 件套**销售，平台 SKU 后缀（`-1PCS/-4PCS/-6PCS/-9PCS/-12PCS`、`SUK-...-6`）就是套件规格；通途订单的 `qty` 是**件数**（6 件套订单行 qty=6）。2026 年波兰销售里 6/9/12 件套占大头。**按件 200 与 D6 对比**：四个 SKU 的 D6 新补分别是 124 / 260 / 456 / 66，请求 800 件 vs D6 合计 906 件，**总量基本匹配**；但 `TT0031086K0063343`（涤麻深灰 60）请求 200、D6 只 66，单个偏高；`TT0031085K0063342` 请求 200、D6 456，反而偏低。**若 200 指 200 套（6 件套=1,200 件），则明显过量。结论：按件理解，总量合理、两个单 SKU 需调；按套理解，明显偏高。单位必须由波兰确认。**
- 另：`TT0031151`（30 件，12.5 个月）、`TT0001323K0010505`（100 件，9.1 个月，D6 观察）按件仍偏高。
- **偏低**：`TT0031087K0063345`（带孔耳枕）请求 40，D6 新补 97；另 2 个三角靠枕各 20 件也低于 D6。先记录，不展开具体补不补。
- **无今年动销**：`TT0031244K0064084`（圆沙发，45 件）；备注已说明皮壳/海绵配套，45 件是组件约束下的量。

**结论：波兰这份请求总体方向合理（一半以上件数在 2–6 个月），不是拍脑袋。软包墙围按件理解：总量 800 vs D6 906，基本合理；`KS0211-DM-60-DEEPGREY` 偏高、`KS0211-KJB-90-BEIGE` 偏低，逐 SKU 调即可。按套理解则明显偏高。单位由波兰确认后即可定稿。架构上套件后缀、pcs_per_set、set_sku→base_sku 已纳入 orders v2 / D3b v3.10 / E v2。**
