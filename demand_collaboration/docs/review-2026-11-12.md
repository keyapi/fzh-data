# 复核结论

Codex 的本地首版在**核心业务语义**上是成立的：四种输入语义、同范围冲突阻断、自批拒绝、基准哈希不可变、期中整期量标记、撤销/过期都通过测试与本地 HTTP 流程。但**不能直接接 EN 多用户上线**：缺少行级范围，且发布快照/状态对所有已登录角色可见；真实 D5 基准也因适配器把 185 条范围外行当拒收而无法生成。

**Go/no-go：No-go（P0 未关闭）。** P0 关闭后可进入测试站试点；P1 建议在试点前完成。

## P0（未关闭不得开放给多运营）

### P0-1 行级范围缺失 + 状态/发布泄露

**问题**：`frappe_bridge.gateway` 的 `/api/state` 返回整个台账；`/api/publications/{id}` 只调用 `_identity()`，**任何 Demand Contributor 都能读取全量快照**。README 与 `AGENT_HANDOFF.md` 已自认“尚无按运营商品/分公司的行级隔离”。

**证据**：
- `frappe_bridge.py` 的 `gateway`：`publication` 分支无角色判断；`state` 分支无范围过滤。
- 本地 HTTP：运营实例对 `/api/publications/{id}/download?format=json` 返回 **200**（本地单身份模式下也证明端点无角色门禁）。
- `store.state()` 返回全部 `proposals`、`publications`、`audit`。

**修复**：新增 `scope.py`，在 bridge 层按 `(product_id, branch)` 过滤 baseline rows / proposals / publications / audit；`submit` 二次校验范围；发布下载收紧为 Reviewer / System Manager；**默认拒绝**，禁止用历史仓归属推断。范围来源先落站点私有 JSON（SM 通过 RPC 维护，带审计），后续可换 DocType。

### P0-2 真实 D5 基准无法生成

**问题**：`adapter.make_baseline` 只要 `rejected_count > 0` 就整批失败；真实 D5 的 236 条拒收中 **185 条是范围外池（CG/CG-USNJ/CG-USTX/其他）**，不是数据错误。实际执行：

```
uv run python -m demand_collaboration.adapter --source ...D5_v6_8... --forecast-start 2026-11-02 --as-of 2026-11-11
→ 输入存在拒收行或没有可用行；请先检查inspect报告
```

**修复**：把范围外 pool 记为 `out_of_scope`（仍进报告、仍参与对账），不再算拒绝；仅范围内缺数/非法值算拒绝。保持 `input = selected + skipped`、`selected = accepted + rejected + out_of_scope`。
