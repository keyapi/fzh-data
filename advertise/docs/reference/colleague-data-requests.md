# 向运营同事要数据的沟通模板

> 何时读：需要向运营同事（YX 等）索取新的 Amazon 广告报表或第三方工具数据时。
> 每条请求都可以直接复制粘贴发给同事，或让同事发给她的 Agent。

## 告诉同事：对 Agent 说这句话

同事打开 Codex (fzh-data 目录) 后，对 Agent 说：

> **帮我导出 Amazon 广告数据**

Agent 会自动读取本文件，根据当前需要引导同事去具体位置下载。

---

## 当前需要的 6 种新报表

### 第一批（高优先级 — 立即可以下载）

同事在 Amazon 广告后台的操作路径：
**广告活动管理 → 左侧"报告"→ 创建报告 → 选择对应报告类型**

配置：Sponsored Products（商品推广）、最近 30 天、每日、CSV 或 XLSX 均可。

**对 Agent 说：**

> 帮我下载这 4 份 Amazon 广告报告，放到 advertise/数据源/ 下面：
> 1. 已购买的商品报告（Purchased Product）— 在报告类型里选"已购买的商品"
> 2. 搜索词展示份额报告（Search Term Impression Share）— 在报告中心里找"搜索词展示份额"
> 3. 按时间查看效果（Performance Over Time）— 在报告中心里找"按时间查看效果"
> 4. 已推广的商品报告（Advertised Product）— 在报告类型里选"已推广的商品"
>
> 全部选最近30天、每日粒度、商品推广。

### 第二批（低优先级 — 需要前提条件）

> 对 Agent 说：

> 帮我检查能不能下载这 2 份报告：
> 1. 总流量和无效流量报告 — 在报告类型里找"总流量和无效流量"
> 2. 受众报告 — 需要先在广告活动里开启"受众竞价调整"才能有数据
>
> 如果能下载就下，不能的话告诉我原因。

## 优麦云数据（在用）

> 优麦云：YX 团队在用的 ERP+广告管理工具，保存全量历史数据，但只有 Excel 导出没有 API。

**需要时对 Agent 说：**

> 帮我从优麦云导出以下数据：
> 1. 全量广告历史数据（广告活动/搜索词/投放，最近 90 天）
> 2. 销售/库存数据（如果能导出的话）
>
> 导出后放到 advertise/数据源/优麦云/ 下面

YX 自己在优麦云后台的路径：登录 → 报表中心 → 选择时间范围 → 导出 Excel

---

## 卖家精灵数据（按需）

> 卖家精灵：竞品关键词情报工具，有 MCP 接口 (`open.sellersprite.com/mcp/22`)

**需要时对 Agent 说：**

> 帮我在卖家精灵里查一下这件商品的竞品关键词，ASIN 是 [填具体 ASIN]

---

## Seller Central 数据（自然流量）

> 这些数据在 Seller Central（卖家中心），和广告后台是不同入口。需要 YX 有 Brand Registry 权限才能拿到 Brand Analytics。

**需要时对 Agent 说：**

> 帮我从 Amazon Seller Central 导出业务报告：
> 1. 进入 Seller Central → 业务报告 → 按ASIN查看详细页面流量
> 2. 选择最近30天 → 下载CSV
> 3. 如果有 Brand Registry，再进入 Brand Analytics → Search Query Performance → 下载
>
> 放到 advertise/数据源/SellerCentral/ 下面

## 给运营同事的完整开局脚本

> 以下脚本可以一次性发给 YX，让她对 Agent 粘贴。

```
我要开始分析 Amazon 广告数据了，请帮我按顺序做完以下事情：

第一步：下载已有功能需要的 4 份报告
1. 打开 Amazon 广告后台 → 报告 → 创建报告
2. 分别下载这4种（都用商品推广、最近30天、每日）：
   - 广告活动报告
   - 投放报告
   - 搜索词报告
   - 广告位报告
3. 下载的文件放到 advertise/数据源/ 下面

第二步：运行分析
运行 uv run python -m advertise.analyze_campaign
然后继续跑完其余 3 个分析脚本，最后 generate_report
把生成的 Excel 路径告诉我

第三步（如果能做的话）：下载新报告
再去 Amazon 后台下载"已购买的商品"和"已推广的商品"这两份新报告，也放到 数据源/

第四步：检查优麦云
登录优麦云，看看能不能导出最近90天的广告历史数据
```

## 沟通原则

1. **一次只要一件事** — 不要一次扔 6 个需求给运营同事
2. **给具体路径** — 不假设对方知道在哪里点。本文每条都有导航路径
3. **不问技术问题** — 不说 API、report type、列名。只说"选 XX 报告、下载"
4. **优先已有功能** — 先让同事跑通 4 报告分析流程，再看新报告
5. **截图优先于文字** — 如果同事找不到某个按钮，让她截图发你，而不是用文字描述
