AEM 为什么把 Assets 和 Collections 分开？

🗄️ Folders = 仓库货架
  • 物理存储层，永久结构
  • 权限控制 (ACL) 绑定在文件夹
  • 元数据 Schema 按文件夹继承
  • 处理规则 (水印/压缩) 按文件夹
  • 资产只能在一个文件夹
  • 谁在用：摄影师、管理员
📋 Collections = 相册/播放列表
  • 逻辑引用层，存指针不存文件
  • 删除 Collection ≠ 删除资产
  • 一个资产可在多个 Collection
  • Smart Collection = 保存的搜索结果
  • Public (共享) 或 Private (个人)
  • 谁在用：运营、品牌、市场
核心理念（Adobe 官方文档原话）：
"A collection holds references to each asset, and any change made to an asset inside a collection reflects on the original asset as well."
— Adobe Experience League, Files and Collections
"Folder structure is the most permanent decision you make in a DAM. Collections are ad-hoc, shareable, and cross-folder."
— Adobe AEM Community Experts

这个分离解决了什么真实问题？

问题 只有 Folders 只有 Collections Folders + Collections
摄影师按拍摄日期建文件夹 ✅ 天然支持 ❌ 需要手动建 Collection ✅ 上传即存储
同一张图用在多个上贴批次 ❌ 需要复制文件 ✅ 引用即可 ✅ 引用即可
权限管理（谁能删图） ✅ 文件夹级 ACL ❌ 引用无权限边界 ✅ 文件夹级 ACL
运营按上贴批次找图 ❌ 要翻文件夹 ✅ 天然支持 ✅ 天然支持
多团队共享 ❌ 串文件夹结构 ✅ Public/Private ✅ 最佳

Asset 的上传和管理（Flat storage）当前已可用。文件夹结构是 Phase 6+ 的事。现在聚焦 Collection 编辑器和多 SKU 导出。

关于"每个人是否允许不一样"

AEM 的做法：Collections 支持 Public（所有人可见可编辑）和 Private（仅创建者+管理员）。

对我们：默认 Public。因为电商运营团队共享上贴任务，小王建的"6月Amazon上贴"小李也需要看到和编辑。不需要 Private 的复杂度。

但 Collection 列表可以按创建者过滤，降低列表噪音。

确认后的设计方向

  1. Collection = 上贴批次：一个 Collection 内含多个 SKU，每个 SKU 有自己的有序图片列表
  2. Collection 引用 Asset（已经是）：删除 Collection 不删 Asset，同一张图可出现在多个 Collection
  3. AEM 替换视图：点 Collection → 主区域切换为编辑器，不再用侧边栏
  4. 导出 = 多行 Excel：N 个 SKU → N 行，每行列数 = 平台图片槽位数
  5. 文件夹上传：Phase 6 再做，现在 flat storage 够用
