关键发现：Collection 的本质是什么？

研究了 AEM、TESSA、Shopify、Amazon 后，发现当前方案有一个根本性问题需要先澄清

问题：现在导出 1 个 Collection = 1 行 Excel（1 个 SKU）

当前 export.py 行为
SKUmain_image_urlother_image_url1other_image_url2
KS0001/files/xxx.jpg/files/yyy.jpg/files/zzz.jpg

只有 1 行。Collection.context.product_sku 是单个值。

但你的实际场景是 Amazon Inventory Template：一个 Excel 里 N 个 SKU，每个 SKU 一行图片 URL。

三种 Collection 模型

🅰️ 单产品 Collection

当前方案

1 Collection = 1 个 SKU 的图片组

导出时聚合多个 Collection → 1 个 Excel

例：
Collection "KS0001 Amazon US" → 7张图
Collection "KS0002 Amazon US" → 5张图
导出：选 20 个 Collection → 1 个 Excel 20 行
✅ 简单清晰 ❌ 每次上贴要建 N 个 Collection ❌ 导入导出需"批量"概念 ❌ 没有"批次"概念

🅱️ 上贴批次 Collection 推荐

匹配 Amazon Inventory Template

1 Collection = 1 个上贴批次，内含多个 SKU

每个 SKU 有自己的有序图片列表

例：
Collection "6月上贴-家居纺织 Amazon US"
├ KS0001 → [主图, 场景图, 细节图]
├ KS0002 → [主图, 场景图]
└ KS0015 → [主图, 场景图, 细节图, A+图]
✅ 1 个 Excel = 1 个 Collection ✅ 有"批次"概念，匹配运营心智模型 ✅ 导出简单直接 ❌ 数据模型更复杂 ❌ 内部 SKU 间图片不共享

🅲 AEM 风格 Collection

Collection 只管分组，导出是独立操作

Collection = 资产文件夹（类似 NAS 文件夹）

"上贴任务"是独立概念，引用 Collection + SKU

例：
Collection "枕头白底图" = 20张图片
Listing Job "6月 Amazon 上贴" →
选 KS0001 从枕头白底图挑3张 →
选 KS0002 从枕头白底图挑2张 → 导出
✅ 最灵活，AEM/Bynder 标准模式 ✅ Collection 可复用（不同 Listing Job 引用） ❌ 两个新概念，实现量大 ❌ 对运营来说太抽象

关于 AEM "替换视图"

研究结论：AEM 打开 Collection 后，主视图切换为只显示该 Collection 内的资产（搜索范围也限定在里面）。不是侧边栏、不是弹窗——是导航进入了一个"子目录"。

这个模式有道理，因为：

  • AEM 的 Collection 是一个浏览单元（像文件夹），不是编辑工具
  • 替换视图 = "我进入了这个 Collection" 的明确信号
  • 和 🅱️ 上贴批次模型最匹配：点进批次 → 看到所有 SKU 的图片 → 编辑 → 导出

如果选 🅱️ 模型，推荐用 AEM 替换视图 而非侧边栏。
