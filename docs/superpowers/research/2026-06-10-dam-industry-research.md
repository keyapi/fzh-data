# DAM/PIM 行业调研 — 功能细节记录

> 调研日期: 2026-06-10 | 范围: AEM Assets + 12+ PIM/DAM/ecommerce 系统
> 用途: DAM Prototype 功能设计参考，持续更新

---

## 一、Adobe AEM Assets

### 1.1 文件夹上传（多层结构保留）

**经典管理视图（旧版 UI）**:
- 原生不支持拖拽文件夹上传
- 解决方案：压缩为 `.zip` → 上传 → DAM 更新资产工作流中自动解压
- 在 workflow 中添加 Unarchiver 步骤可自动处理

**Assets View（新版 UI）**:
- 直接支持拖拽文件夹（含多层子文件夹），结构完整保留
- 无需压缩

**桌面应用**:
- Adobe 桌面应用支持文件夹拖放（含子文件夹保留）
- DamPy (Python CLI) 提供 `uploadFolder()` 递归上传

**启示**: ZIP + 自动解压最稳健，即使浏览器 UI 在处理大量文件时出问题也能可靠处理深层嵌套。不要仅依赖拖放 — 始终提供基于 ZIP 的批量上传作为备选。

### 1.2 三种 Collection 类型

| 类型 | 描述 | 关键属性 |
|------|------|---------|
| **Static Collections** | 手动精选的资产、文件夹及其他 Collection 的固定列表 | 可共享、可设权限(Owner/Editor/Viewer)、可设为公开或私有 |
| **Smart Collections** | 基于已保存搜索条件的动态关联，内容随新资产自动更新 | 使用 OmniSearch 创建、自动更新、适合持续进行的活动 |
| **Lightbox** | 用户首次登录时自动创建的个人私有 Collection | 独属个人、不可删除/共享/重命名、临时暂存区 |

**Lightbox 细节**:
- 每个用户首次登录自动创建
- 不可删除、共享或重命名
- 界面顶部有 "拖放到 Lightbox" 目标区域
- 可将 Lightbox 内容复制到命名 Collection 以共享

**共享与协作**:
- Collection 可与特定用户/组共享
- 权限级别: Owner / Editor / Viewer
- 公开 Collection 对所有 DAM 用户可见
- Content Hub 提供额外安全资产分发方式

### 1.3 文件夹缩略图预览

- 导航到包含图片的文件夹 → 切换到卡片视图
- AEM 显示**合成缩略图**，拼贴展示文件夹中若干图片
- 提高资产可发现性 — 无需深入即可看到内容
- 卡片视图专为大型可视化预览设计
- 列视图和列表视图使用较小缩略图

**缩略图生成**:
- AEM 为每个资产生成多种呈现(rendition)，包括缩略图呈现（如 `cq5dam.thumbnail.48.48.png`）
- DAM 更新资产工作流负责缩略图生成
- ACS AEM Commons 提供 "刷新资产文件夹缩略图" 工具用于重新生成

**启示**: 文件夹级别的缩略图拼贴是最有影响力的功能之一。扫描大量文件夹时能节省大量时间。按需生成（折叠/展开时或加载文件夹时）优于预先批量生成。

### 1.4 AI 智能标签 (Adobe Sensei)

**支持的资产类型**:
- 图片 — 物体、场景、属性、标志、颜色 (JPG/PNG/TIFF/BMP/GIF/PSD 等)
- 视频 — 物体、场景、动作（如 "跑步"、"喝水"）
- 文本类资产 — 关键词和实体提取

**处理流程**:
1. 资产上传到 AEM
2. 工作流向智能内容服务 (Adobe Sensei) 发送请求
3. AI 分析内容并生成候选标签
4. 每个标签获得**置信度分数**
5. 标签按置信度排序后添加到资产元数据

**三种智能标签**:

| 类型 | 描述 |
|------|------|
| **标准智能标签** | 通用 AI 标签（如 "汽车"、"树木"、"海滩"） |
| **增强型智能标签** | 根据业务分类法自定义训练（如 "Sedan LX"、"Roadster GT"） |
| **颜色标签** | 自动识别主色（可配置 1-40 种颜色），支持名称/RGB/Hex 显示 |

**增强型智能标签（自定义训练）**:
- 通过策展资产、应用相关标签并运行训练工作流来教 AI 识别专有产品名称
- 训练无法撤销，策展很重要

**启示**: AI 自动标签是原型中影响力最大的单一功能。支持自定义训练会将其提升到全新水平。使用置信度分数对搜索结果排序（手动标签 > AI 标签 > 无标签）。

### 1.5 版本历史

- 每项资产维护完整版本历史
- 通过**时间轴**界面查看

**版本创建触发**:
- 重新上传文件时（勾选"创建版本"）
- 编辑元数据时
- 手动创建，可选标签和描述

**版本操作**:
- 版本预览 — 在时间轴中选择版本预览
- 版本比较工具 (ACS AEM Commons) — 当前版本和之前版本之间逐属性差异比较，显示新增/更改/移除指示器
- 还原 — 恢复到早期版本（替换当前版本，包括原始文件、呈现和元数据）

**启示**: 每次上传和每次元数据编辑时自动创建版本非常有价值。时间轴式 UI 是最佳选择。属性级 diff 是高质量功能。

### 1.6 资产关系 / 链接

- 通过 `AssetRelation` API 创建关系
- 关系类型包括 "派生"、"相关" 等
- 可按类型筛选关系
- **引用追踪**: 可追踪资产被引用的位置（如在哪些 AEM Sites 页面中使用）
- 防止在仍有依赖关系时删除资产

**启示**: 资产关系用于链接相关内容（如 "这个产品有三个角度视图"）或表示派生关系。引用追踪对大规模治理至关重要。

### 1.7 搜索与筛选

**全搜索**: 关键词搜索，不区分大小写，跨元数据字段全文搜索，默认 AND 运算符

**筛选器面板**: 按文件类型、大小、修改日期、状态、洞察数据、Adobe Stock 许可等组合筛选

**GQL 搜索**: 精确值查询，如 `title:"Scott Reynolds"`、`type:"image/png"`、`title:Scott*`

**搜索排名**: 元数据匹配优先于智能标签匹配；可通过 "提升搜索关键词" 功能进行权重提升

**查找相似图片**: 拖放参考图片找到视觉相似匹配（使用智能标签）

**动态搜索分面**: 在应用筛选器前显示近似结果计数

### 1.8 元数据管理

**支持标准**: XMP（默认）、EXIF（数码摄影）、IPTC/IPTC扩展（新闻媒体）、ID3（音频/视频）

**元数据模式**: 定义附加到资产的字段集

**级联/上下文元数据**: 根据其他字段值定义字段依赖关系和显示/隐藏行为

**批量元数据**: 支持 CSV 导入/导出

**元数据配置文件**: 分配给文件夹，上传到该文件夹的资产自动继承默认元数据值（如版权声明）

### 1.9 双界面

**管理视图**: 完整 + 技术性，面向专业 DAM 管理员

**Assets View**: 轻量级、以搜索为中心，面向内容消费者

同一存储库上两种 UI，服务两种用户类型，降低学习难度同时保持功能深度。

### 1.10 其他独特功能

- **Creative Cloud 集成**: 设计师可直接在 Photoshop/Illustrator 中签入/签出 AEM Assets
- **Dynamic Media + OpenAPI**: API 优先的内容分发，每项资产访问控制、自适应流媒体、智能裁剪、CDN
- **Adobe Stock 集成**: 直接在 DAM 工作流内购买和导入库存资产
- **Experience Cloud 集成**: 连接 Journey Optimizer、Target (A/B测试)、Analytics、Workfront、Marketo

## 二、Akeneo PIM

### 2.1 资产管理

- 移除传统文件夹层级，转为 **Asset Families**（资产家族）
- Asset Family = 一组共享相同属性模板的资产
- 标签现在是 Asset Family 上的单选/多选属性，有专门管理界面
- **资产过滤器**: 2025年12月更新支持通过 API 进行 AND/OR 运算符的智能资产筛选

### 2.2 产品-资产关联

- 通过 Asset Family 属性和产品属性关联
- Shopify 集成支持: 每个产品最多 **30 个图片属性** + **5 个 Asset Collection**（250 图片/视频/3D 混合）
- 变体级媒体: 最多 2 个图片属性或 Asset Collection，支持回退
- Asset Collection 作为 Shopify 文件 metafield（同步 PDF、用户手册等）

### 2.3 AI 能力 (2025)

- **AI 关键词标签**: 基于视觉内容自动标记资产
- **可定制 AI 自动标签配置** (2025年12月): 自定义 prompt 引导标签（如 "关注材料和颜色，排除品牌"）
- **AI 信息提取**: 从产品图片和 PDF 中提取颜色、材料、品类，自动填充 PIM 属性
- **资产转换**: 每个 Asset Family 最多 **10 种可配置转换**（自动调整大小、缩略图、按渠道优化）
- 内置 CDN 提供转换后的资产

### 2.4 全局搜索

- 主搜索栏 (Ctrl+K) 支持全局资产搜索
- 搜索跨所有 Asset Family

## 三、Pimcore DAM

### 3.1 组织模式

- **树状文件夹层级** + **类别/分类法** + **标签** 三重组织
- 标签集中定义，跨资产、对象、文档可重用
- 自定义视图和布局
- 自定义元数据模式（类似数据类），支持高级数据类型

### 3.2 核心功能

- **200+ 文件格式** 平台内预览（图片用 ImageMagick、视频用 FFmpeg）
- **3D/AR 资产** 支持
- **无限版本管理** — 每次更改创建新版本
- **可配置工作流状态机** — 手动和自动转换（由事件、webhook 或 API 触发）
- **Pimcore Copilot** (AI/ML) — 自动标签和分类
- 基于规则的资产处理自动化
- 批量元数据编辑和导出 (JSON/XML/CSV)
- **Brand Portals / Asset Experience Portals** — 安全外部共享
- 基于角色的权限 + 2FA
- 许可证/版权管理作为结构化元数据

### 3.3 架构

- 统一平台: PIM + DAM + CMS + MDM 合一
- 产品-资产关联原生双向
- 开源 (GPLv3)，无许可费

## 四、Shopify (产品媒体管理)

### 4.1 现状

- **无原生 DAM** — 媒体管理完全是产品附件模式
- 无文件夹层级
- 媒体直接附加到产品和变体
- 每个产品: 1 张主图 + 多张附加图片/视频
- 变体图片可分配给特定变体组合
- 最近新增 **3D 模型** (GLB/USDZ) 和视频支持

### 4.2 第三方填补

- **版本历史**: Loggr Product History & Revert ($13.99/mo)、Singleton Product Tracker ($3.99/mo)
- **批量管理**: Akeneo、Plytix 等第三方 PIM 提供外部 DAM 的批量媒体映射
- **AI 功能**: Shopify Magic（产品描述、图片生成），但不包括自动标签

### 4.3 评价

- 少于 500 个产品的商店: 简单快速
- 规模大后: 变得痛苦
- 依赖第三方生态填补 DAM 缺口

## 五、Amazon Seller Central

### 5.1 图片管理

- 无文件夹系统，按 ASIN 上传
- 每个 Listing: 1 主图 + 最多 9 张辅图
- **严格合规规则**: 纯白背景 RGB(255,255,255)、产品占画面 85%+、最短边 ≥1000px
- 无水印/logo/促销标识

### 5.2 最新更新

- **Smarter Bulk Image Upload** (2025年7月): 多文件上传 + 部分错误恢复 — 之前单错误停止整个批次，现在有效图片继续处理，生成详细错误报告
- **AI 图片生成**: A+ Content Manager 内创建生活方式场景和产品可视化 (2025年5月)

### 5.3 限制

- 无版本历史 — 替换图片即覆盖
- 无批量下载
- 无自动化标签

## 六、Salsify

### 6.1 核心理念

- **Product Experience Management (PXM)** — 管理完整产品内容体验，不只是数据
- 刻意**从文件夹结构转向分类法驱动**的数据库方法
- 资产通过元数据标签组织 (season, brand, product line, style, dates, features, benefits)

### 6.2 产品-资产关联（4 种方式）

1. 直接在产品详情页上传和关联
2. 上传到数字资产后添加关联产品
3. **链接电子表格** — 批量操作（数百产品、数千图片）
4. **Linking Assets Lab** — 自动化关联

### 6.3 AI 能力 (Salsify Intelligence Suite)

- **AI Image Editor** — GenAI 编辑生活照和产品图
- **AI Image Analysis** — 从图片提取产品详情、文字或属性，映射到数据模型
- **AI Metadata** — 自动添加图片元数据以提升可搜索性
- **AI Text Generation** — 从图片创建产品文案

### 6.4 渠道分发

- **Syndication Engine** — 将资产和产品数据直接推送到 950+ 零售渠道 (Amazon, Walmart 等)
- 自动转码 — 存储一个高质量版本，平台按渠道处理转换
- 内置 CDN 交付
- 渠道特定优化 + 实时同步

## 七、Plytix

### 7.1 架构

- **集成式 PIM+DAM**（非模块化/分离）
- 灵活分类组织 + 无限子类别树
- 自定义资产分类法
- **Smart Lists**（按条件自动更新）和 **Static Lists**（手动选择）
- 自定义资产属性

### 7.2 特色功能

- **无限免费席位** — 所有计划无按用户定价
- **表格视图** — 像电子表格一样编辑资产，无需下载/重新上传
- **即时格式化** — 导出时调整大小/重命名/重新格式化图片，不复制原图
- 文件类型转换和重命名（导出时）
- 按需导出产品+资产数据
- **AI Autofill** (OpenAI 驱动) — 产品描述和属性文本生成
- 图片背景移除 + 放大

### 7.3 定位

- 最佳 SMB (500-10,000 SKU)
- 快速实施 (~1 周 vs 企业 PIM 6-9 月)
- G2 评分 4.7/5 (357+ 评论)
- AI 功能需附加定价 ($10K-$90K)

## 八、inriver

### 8.1 定位

- **PIM 而非 DAM** — 与 Bynder/KeyShot Dock/Canto/Kontainer/Acquia DAM 集成
- Inriver 管理结构化产品数据，DAM 伙伴管理非结构化资产
- 双向 PIM-DAM 同步作为核心架构原则

### 8.2 特色

- **嵌入式 AI Agent** (Inspire Generate, Translate) — 自动丰富、翻译、数据转换
- GPT-5 直接在平台内集成
- **MCP (Model Context Protocol) Server** — 允许外部 AI 应用连接产品数据
- **Content Onboarding** + 自动映射 — AI 驱动清洗导入数据
- **Brand Store** — CDN 门户，开放店铺能力（无需登录）、批量下载、可配置模板
- **Syndicate Advance** — 灵活分发引擎 + 直接 API 连接 Best Buy 和 950+ 渠道
- **Inriver Evaluate** — 分发后数字货架监控

## 十、Brandfolder（by Smartsheet / 纯 DAM）

### 10.1 组织

- 文件夹/Collection 结构 + **AI 智能 Collection**（按标签和元数据自动填充）
- 自定义元数据字段
- **无限访客用户** — 外部伙伴访问

### 10.2 AI: "Brand Intelligence" 引擎

- 计算机视觉 + NLP
- 自动元数据标签
- 视频场景检测 + 音频转录
- **可训练 AI** — 品牌特定分类法
- **人脸识别** (People Tagging) — 隐私/权限管理
- **视觉相似度搜索** — 按参考图片查找相似资产
- 自然语言搜索（即将推出）
- 报告: ~90% 减少手动标签时间，复杂类别 ~15% 误分类率

### 10.3 批量操作

- 最多 **100,000 资产** 同时操作
- Brand Portals + 下载控制
- 自定义 CDN 链接 (2025 路线图)
- 智能去重 (2025 路线图)

### 10.4 定价

- Premium: ~$25K-$100K/yr
- Enterprise: $250K+/yr

## 十一、Google Drive

### 11.1 文件管理

- 标准层级文件夹结构
- 上传保留文件夹结构（Drive for Desktop 或拖放）
- 图片、PDF、视频缩略图预览
- **文件流** (虚拟驱动器) — 无需完整下载即可访问文件
- Shared Drive 模式（团队拥有，非个人拥有）

### 11.2 版本管理

- 内置版本历史（所有文件类型）
- 可查看、还原或制作先前版本副本
- 30 天或 90 天版本保留（取决于 Workspace 计划）

### 11.3 AI (2025年12月)

- **Gemini 驱动搜索** (付费版) — 文件夹内容摘要
- "Explore with Gemini" 侧面板 — 跨文件夹询问文件相关问题
- 仅 Web、仅英文

### 11.4 不是 DAM

- 无资产特定功能（无水印、无权限管理、无审批工作流）
- 版本管理是系统级，非工作流感知

## 十二、Dropbox

### 12.1 最新更新 (2025)

- 统一团队空间 — 所有团队文件夹在共享协作空间中
- 权限从顶级文件夹级联
- 无根级文件（所有内容必须在文件夹中）

### 12.2 特色

- **DocSend** 集成 — 专业内容分享 + 分析 + 水印 + 访问控制
- **共享文件自定义缩略图** (1:1 JPEG/PNG)
- **Rewind** — 文件夹级回滚
- 扩展版本历史 (30-180 天取决于计划)
- Dropbox Dash — AI 通用搜索（跨 Dropbox + Google Workspace + Microsoft + Salesforce + Notion）

### 12.3 不是 DAM

- 无资产特定功能
- 文件夹遍历权限 — 共享子文件夹显示父路径但不显示父内容

## 十三、Airtable

### 13.1 文件管理

- 附件字段在数据库记录中
- 每条记录可有多文件附件
- Gallery View 以卡片形式显示记录预览
- Interface Designer 允许自定义视图
- 关系数据库结构 — 可在 Airtable 上构建简单 DAM

### 13.2 Airtable Proofing (2025年7月 新功能)

- 附件字段内完整创意审阅:
  - **版本自动编号** — 上传新文件时自动增加
  - **并排比较** — 两个版本对比（PDF 自动检测文本变更）
  - **富标注工具** — 评论、矩形、自由手绘、文本高亮
  - **外部利益相关者审阅** — 无需 base 访问权限
- 附件字段可切换为"单文件 + 版本管理"模式
- 每个文件附件限制 5GB
- 存储计入计划限制（每个版本单独计算）
- 不支持视频校对

### 13.3 限制

- 附件 URL 有过期时间（最少 2 小时）
- 非过期附件查看器 URL 需要登录
- 不是专业 DAM — 但校对功能是独特差异化

## 十四、Notion

### 14.1 文件管理

- 文件是数据库属性的附件
- 无层级文件夹系统
- Gallery/Table/Board/List/Calendar 视图

### 14.2 限制

- **文件 URL 1 小时后过期** — 需重新获取才能永久预览
- 外部文件链接用于稳定引用
- 最好用作**轻量级资产注册表**（跟踪有什么、在哪里）而非 DAM
- 可作为实际 DAM 之上的协作层

## 十五、行业趋势总结

### 趋势 1: 从文件夹转向元数据/分类法

现代 PIM/DAM 系统 (Akeneo, Salsify, Brandfolder, Pimcore) 都在弱化深层文件夹层级，转向元数据驱动组织。Akeneo 直接移除了文件夹分类改为 Asset Families。Salsify 明确将去文件夹化作为最佳实践。

### 趋势 2: PIM-DAM 融合

Plytix 和 Pimcore 提供真正的集成式 PIM+DAM。Salsify 用 PXM 方法模糊了界限。其他系统 (Akeneo, inriver) 有强双向集成。电商产品图片的成功方法是紧密的产品-资产关联，而非独立 DAM。

### 趋势 3: AI 是标配

所有主流系统现在都有某种形式的 AI 自动标签。Brandfolder 声称减少 90% 手动标签时间，但评论指出复杂类别 ~15% 误分类。Salsify 和 Akeneo 现在提供 **AI 富化** — 读取产品图片自动填充 PIM 属性，电商高价值功能。

### 趋势 4: 版本管理参差不齐

Pimcore 提供无限版本。Airtable 刚引入 Proofing（版本+标注）。Shopify 和 Amazon 对产品图片**无原生版本历史** — 需要第三方应用。电商 DAM 原型的版本管理是明显差异化优势。

### 趋势 5: 渠道分发是壁垒

Salsify、inriver、Akeneo 通过分发引擎差异化 — 将同一产品图片推送到 Amazon、Shopify、Walmart 等渠道，按渠道特定转换。这是企业级功能，值得长远规划。

## 十六、纳斯达克 Browse NAS 功能（vilavi_pim Phase 6）

### 16.1 需求背景

来自 `docs/ux-workflow.md` 用户访谈:
- NAS 按运营需求组织（如 `2025年10月/视觉-SJ01/运营-YY01/主图/`），非按 SKU
- 文件名无一致模式，视觉同事随意命名
- 运营人员在 NAS 中手动找文件夹 → 浏览器逐个打开文件 → 人眼检查挑选图片 → 填入 Excel URL
- 当前耗时: **10-40 分钟**/次

### 16.2 设计模式

三层存储模型 (来自 AEM):
```
Folder (物理位置) → Asset (单个资源) → Collection (虚拟分组)
    1:N                  N:N                   用途驱动
```

### 16.3 计划实现

**后端 API**:
- `GET /api/nas/browse?path=` — 列出目录内容（安全校验 `Path.resolve()` 在 NAS_ROOT 内）
- `GET /api/nas/thumbnail?path=` — 即时生成缩略图（Pillow，缓存）
- `POST /api/nas/import` — 复制文件到 DAM + 创建 DB 记录 + 从路径推断标签

**前端组件**:
- 侧边栏 "BROWSE NAS" 入口
- 树状文件浏览器（展开/折叠 + 面包屑）
- 图片网格预览 + 选择复选框
- "导入选中 (N)" 按钮

**元数据推断** (来自 `docs/industry-research.md` §6.2):
- 从文件夹路径段推断: `NAS/三角靠枕/PP棉/xxx.jpg` → style="三角靠枕", fabric="PP棉"

**安全**:
- 防路径遍历: `Path.resolve()` 校验
- 不暴露 NAS 绝对路径给前端
- 导入时 SHA256 去重
