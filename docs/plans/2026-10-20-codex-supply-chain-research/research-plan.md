# 供应链整合独立调研执行计划

## 1. 任务与已定边界

回答：怎样把销售分析、未来数月需求预测、库存、下单、生产、出库、头程在途连接成可追溯的补货与排产建议，帮助老板审批；哪些已有资产应复用，哪些成熟产品或开源方案更合适。

用户已明确：Claude、Codex、Cursor 各自独立覆盖完整问题，各自分支与 PR；不按软件分配 A/B/C 研究线。Codex 内部允许使用便宜模型的子 Agent。先规划，再深度调研；额度耗尽前阶段提交。Astra 可由用户在关键节点手动切换。

本轮仅规划、核对调查起点并提交文档。后续研究阶段不改业务行为，不自动下单、排产或扩大数据写入范围。不把 Claude 的架构假设、V1 粒度、事实源选择或八个业务问题的预设答案当作用户决定。

## 2. 独立性与综合方法

1. 把用户原始需求作为主输入；Claude 交接包用作线索库，其断言逐项复核。
2. Codex 的首轮证据表、候选排序和架构备选形成独立提交后，再阅读其他软件的深度调研结论。已经看到的交接假设登记在案，主动找反证。
3. 不以三家共识代替证据；分歧保留，按一手来源、代码、实验和业务条件裁决。少数意见可能正确。
4. Codex 内按领域分工，每个子 Agent 同时调查方法、现成实现、适用性和反例。最终由主 Agent 检查跨领域接口与遗漏，不直接拼接三篇综述。
5. 不预先锁定“确定性内核 + AI 外层”。比较规则/统计与优化、集成计划产品、Agent 主导或混合方案；统一评估可复现性、约束满足、维护与审批成本。

## 3. 能力覆盖表：先找能力，再找产品

以下是搜索范围，不是已验证结论或实施承诺。

| 范围 | 必须回答的问题 | 证据/验证重点 |
|---|---|---|
| 销售与需求事实 | 订单、支付、发货、退货、取消、促销、断货各如何影响需求？ | 原始订单行到业务件数守恒；销售不等于未受约束需求 |
| SKU、BOM、仓库与包裹 | 成品、Cover/Foam、套件、拆包裹、仓库更名如何归一？ | 去重键、父子行、时间生效映射；合并不重复计数 |
| 库存与供应 | 账面、可售、预留、在制、采购未交、头程、到仓未上架如何区分？ | 同一货物跨状态不能多算；快照时间与事件时间 |
| 预测 | 稀疏/间歇、季节性、促销、新品、层级、多仓如何处理？ | 滚动回测、断货删失、信息泄漏、预测区间与基线 |
| 补货 | 服务水平、资金、MOQ、箱规、运输和提前期不确定性如何权衡？ | 预测误差不替代缺货、资金、库存等业务结果 |
| 生产与排产 | MRP、物料齐套、产能、换型、工序、节假日、交期如何衔接？ | 理论计划、可行排程与真实工单进度分别验证 |
| 头程 | 订单行如何对应批次、柜、分批装运、ETA 变更和签收上架？ | PJ/Jack 接口、数据结构、历史覆盖、更新频率与异常 |
| 审批与预警 | 老板要批准什么？建议怎样解释、比较情景、跟踪执行？ | 一页结论可回溯；阈值与负责人待业务确认 |
| 数据与 Agent 架构 | 数据契约、语义层、工作流、记忆、工具、权限怎样组合？ | 重跑、迟到修正、失败恢复、证据引用、人工审批 |
| 维护与采购 | 复用现有系统、整套产品或组件组合哪个适合？ | 许可、版本、安装证据、团队维护、迁移与退出成本 |

研究 S&OP/IBP、MRP/DDMRP、APS、库存策略/多级库存优化及控制塔的适用条件，而非默认全部建设。分别检索开源的整套计划系统和组件，避免只比较预测库/Agent 框架而遗漏成熟计划引擎。

## 4. 搜索与证据纪律

### 仓库先行

先读模块索引、相关 AGENT_HANDOFF、CONCEPTS 与经验库；随后检索 main、开放 PR、远端分支与相关历史。主 Agent 负责资产账本，字段至少包括：能力、路径、ref、提交 SHA、PR、设计状态、实现状态、测试证据、合并状态、运行/部署状态、复用建议及限制。

覆盖所有开放 PR 的标题与变更文件；对不相关 PR 写排除理由。继续按路径/关键词扫描远端分支与历史，覆盖未开 PR 的工作。关闭 PR、历史原型和本地未提交资料登记为独立线索；不混入当前可用资产。未定位到的预测对比/网页 demo 记录查过哪里，不宣称“不存在”。

### 外部调查

中英文检索；以截至调研日可访问的一手文档、源代码、发布记录、原始论文、基准仓库与可复现案例支撑结论。用户评价和二手文章用于发现线索及风险，再回查原始 issue/材料；厂商宣传标为主张。记录发表/更新日及访问日，旧材料可用于方法论，不能冒充当前 SOTA。

每条重要主张记录：claim_id、能力、结论、URL/ref+SHA、位置、短摘要、证据类型、支持/反驳、适用条件、局限、核实状态。全文/付费材料取不到就标记，不由摘要补写结论。许可证从对应版本 LICENSE 核查，代码与模型权重分别记录；安装成本和效果数字只写实际测量或有来源的区间及假设。

每个重要能力至少搜索“整套方案、组件、已有项目复用”三种路径；保留被淘汰候选及理由。候选项目名称只是搜索起点，不等于推荐。不能用 stars、最近提交时间或厂商声称的提升单独证明成熟度。

### 把湖煮干的验收方式

- 每轮报告检索/候选总数、已核实、待核实、排除、访问失败及原因；分类互斥、数量可对账。
- 能力表每一格必须有证据、条件性判断或明确缺口，不能空白或静默丢弃。
- 每个关键推荐至少有可定位的一手证据，并完成反例/局限搜索；找不到可运行证据就降低结论等级。
- 连续两轮扩展搜索未产生改变候选排序或架构判断的新证据，可暂停该方向并记录覆盖范围；这代表当前搜索饱和，不代表全球穷尽。
- 结束时交付剩余未知清单、已查边界和继续搜索的价值排序。资料数量本身不作为完成标准。

## 5. Codex 子 Agent 安排

深度调研启动时最多主 Agent + 3 个子 Agent；当前规划阶段不启动研究子 Agent。

| 角色 | 研究责任 | 独占输出 |
|---|---|---|
| 主 Agent | 仓库资产、事实口径、覆盖矩阵、证据审查、架构与路线综合 | assets.md、coverage.md、synthesis.md、checkpoint.md、索引/日志 |
| A | 成熟供应链规划、补货、产能/排产、审批与真实适用案例 | industry.md、sources-industry.md |
| B | 预测统计基线/基础模型、Agent SOTA、评测、可靠性及反证 | forecasting-agents.md、sources-ai.md |
| C | 整套开源计划产品与组件、ERPNext 复用、维护/许可/TCO、复现条件 | open-source.md、sources-oss.md |

先采用当前工具可用的便宜模型 gpt-6-luna，fork_turns=none，仅传原始需求、任务边界和必要仓库事实；避免整段对话传给每个子 Agent。名称代表本次执行配置，不声称固定计费或未来可用性。遇到证据冲突、建模判断或持续检索失败，主 Agent 接手；不在便宜模型上反复空转。

子 Agent 仅写负责文件，不提交/推送、不改共享索引，不读凭证，不改他人文件。第一轮完成后轮换审阅另一路的关键断言，审阅只反馈；作者修正，主 Agent 核实。这样同时控制费用、文件冲突和单一路径的偏差。

## 6. 阶段与交付

| 阶段 | 交付与完成门槛 | 提交节点 |
|---|---|---|
| P0 规划 | 本计划、起点纠偏、独立分支与 PR | 本轮提交规划 |
| P1 资产与问题地图 | 分支/PR 快照、资产账本、覆盖表；全部“未找到”给检索边界 | 第一批可审查资产即提交并更新同一 PR |
| P2 广搜与收敛 | 三路证据、短名单/淘汰表、已知缺口；先独立固化结果 | 每一路首轮成果可单独提交 |
| P3 深核与验证设计 | 核实关键版本、许可、接口；拟定 1–2 个最小对照实验 | 有结论即提交，未运行项明确标记 |
| P4 综合与交叉审阅 | 2–3 条可选路线，复用/替换/新增矩阵、风险、成本假设、试点路线 | 独立结论固化后才比较 Claude/Cursor 结果 |

最终应能回答“推荐什么、为什么、复用什么、为何不用其他方案、还缺什么证据、下一步怎样验证”。不在研究阶段承诺大型平台建设。

实验设计至少包括：同一冻结数据集上的预测基线与候选对照；库存/补货策略在相同需求和提前期情景中的业务结果；订单拆包裹/BOM 合并的数量对账；Agent 正常/缺数据/冲突/重跑时是否引用正确证据及停在审批边界。实际运行是后续节点，不能把实验设计写成实验结果。公开 PR 只放脱敏摘要，不提交客户数据、CSV、PDF、图片或凭证。

## 7. 额度、保存与 Astra 节点

额度以账户工具返回为准，是共享窗口，不是本任务独享，也不是可精确兑换的 token 预算。便宜模型是否节省该账户额度以实际消耗观察，不据模型名承诺。窗口可能被其他会话消耗，不能保证自动预知硬中断。

- 开始、每批子任务结束、重要检索扩展前、提交前查看 5 小时/周额度与重置时间；工具不可用时更保守地保存。
- 每个完整子成果或约 30–45 分钟工作后落盘 checkpoint；可审查成果及时 commit、push，不能只留在子 Agent 上下文。该间隔是执行检查点，不创建后台定时器。
- 任一窗口已用达到 60%：提交当前证据与未决项；达到 75%：不再扩充低价值候选，收敛现有结果；达到 85%：停止派发，保存子任务局部结果，完成扫描、推送和接续说明。若启动时已超过阈值，立即执行对应动作；不等下一阶段。
- checkpoint 必须包含：已完成/未完成、关键 ref/SHA、未解决冲突、精确下一步、各子 Agent 文件、扫描状态、最近提交/PR、额度读数及时间。额度不足时阶段成果可保持 Draft PR，不声称最终完成。
- Astra 可选节点：P1 后审视事实模型与遗漏；P2/P3 后裁决架构、预测/补货取舍；P4 前审查推荐证据。每次先提交，再给用户一段可复制的审查问题；不自动改主对话模型，不把手动换模当作继续研究的必要条件。

## 8. 业务问题与外部交接

决策粒度、计划周期、目标函数、事实源、产能、审批边界与老板一页纸偏好，均不在研究中擅自定案。先用现有材料列出选项与影响，必要时集中提问，不阻塞不依赖答案的调查。先前被批准的 PB 计划可作为真实样例线索，不能自动推成全公司范围。

PJ/Jack 头程工作：查询 GitHub 与用户指定 Gitee 仓库的 PR/分支差异，不能假设镜像已同步。请其后续交付字段字典、关联键、状态/事件定义、更新频率、历史覆盖、样例结构、失败重试与授权方式；不要求向公开仓库提供真实客户记录或密钥。未获得材料前登记接口缺口，不重复搭建一套头程大屏。

本研究的隔离分支为 feature/codex-supply-chain-research；基于 main 独立开 PR，阶段成果优先更新同一 PR，范围过大再拆关联 PR。Claude 交接包无需先合并；用 ref+SHA 阅读，不 cherry-pick 其结论。所有修改按 OKF 更新本目录索引/日志并生成根索引，提交前检查凭证与变更范围。
