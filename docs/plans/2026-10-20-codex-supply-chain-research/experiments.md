# 最小验证合同（设计，尚未执行）

本文件是下一阶段实验设计；本轮只执行过 [assets.md](assets.md) 中106项既有离线测试。没有训练模型、回测本公司销量、安装frePPLe或生成真实采购/工单。

## E1 需求/供应语义与数量守恒

输入为少量合成单据，不需要生产凭证，先由业务确认单位与预期输出。保留全部原始行、变换、排除理由；每一步入行=出行+吸收/排除/阻断行，金额守恒与物理单位分别校验，不错误要求组件件数等于成品件数。

| 用例 | 预期断言 |
|---|---|
| 一件成品拆Cover1+Foam1两行 | 终端成品需求1，履约部件各1，不能预测为2件成品；BOM派生需求另存 |
| 两件成品拆多个包裹/皮壳行 | 不能取first/max丢件；本公司Σ皮壳数量规则只在已核配套类型适用 |
| 单独卖一件皮壳、共享内胆、缺映射 | 单卖皮壳保留独立需求；不能见Cover就归成品；共享/未映射进入阻断和原因报告 |
| 同平台原单、拆分子单、补发、取消/退货 | 不按字符串近似全并，保持订单类型/血缘；补发是否代表新增独立需求由业务规则定 |
| 当期预测100，已下终端订单30且属于同一预测范围 | 展示预测100、已冲减30、未冲减70；不能按130算同范围需求。跨期/客户/仓/特殊大单另列，不推广成无条件max公式 |
| 内部补货SO与终端预测 | SO作为供给/派生计划依据与源需求建立关系，不能和终端销量当两份独立市场需求 |
| 同一批工厂出库→通途采购在途→头程→到仓 | 一个supply_lot及状态/分摊血缘，不能每系统各加一次；部分到仓后只余未到量在途 |
| 首道100、末道60、已提交入库50、出库40 | 四指标分别报告，首道不能当100完工可售；不凭简化减法假定所有差异是同一种WIP |
| 成本导入1000、真实库存5 | 成本基数保留作金额解释但不加入实物库存；不反向推断其他赛狐余额都虚拟 |
| 可用0且在途0、但在售且有订单 | 低库存登记模块可按其规则排除，该业务行仍进入缺货/数据核验队列，不静默丢弃 |

通过门槛：业务确认每个用例的单位/状态；公式重算与预期一致；全部输入能追溯到输出或阻断记录。现有merge_split_orders不传sku_to_product时不执行同产品守卫，不能在新计划链中默默省略映射检查。

## E2 ERPNext基线与计划引擎对照

锁定ERPNext实际版本/启用功能与frePPLe正式CE版本、license、依赖及容器摘要。先用3–10个商品、1–2仓、少量组件/共用物料、两条有替代/无替代工序、明确库存与分批供应的合成快照；规模用于降低验证成本，不等于授权真实导入范围。

| 比较项 | 要记录的证据 |
|---|---|
| 相同需求/库存/BOM/订单 | 两路使用同一冻结输入与截止时间；字段缺失/无法表达全部保留 |
| 净需求与预测冲减 | 订单/预测/内部SO不重计；BOM展开、MOQ/倍数、分批可追溯 |
| 时间/物料/产能 | 非工作日、船期、交期、瓶颈、加班/替代的硬软约束；不可行就报告迟交/缺口，不偷偷改约束 |
| 库存政策与界面 | CE实际有什么；商业库存规划屏不算CE验证通过；少了多少自建/订阅成本 |
| 可解释性 | 一条建议能追到触发需求、供给分配、约束和假设；手算小样一致 |
| 工程量 | 模型转换/适配/部署/升级所耗时，不能只比较优化器求解速度 |

否定条件：一条关键语义无法表示且只能靠不透明补丁，或“节省自研”实际转成更大适配成本。试验不回写生产；输出可比较差异表及不支持项，即使结果反对原候选也保留。

## E3 预测/补货联合评估

数据可得时再执行。最低必需：按时点可知的终端售卖SKU销量/取消/退补发、在售与断货窗口、库存/供应/ETA、主数据/BOM变更、人工批准计划。缺货流失需求无真实标签时只做假设区间，不能声称识别出真实需求或实际利润提升。

第一批只比较现有业务规则、SeasonalNaive/移动平均、适合间歇的SBA/TSB等基线，加一个许可证与算力适合的基础模型挑战者；不要一次训练十几种模型。基础模型版本和权重许可未核就不安装商用；没有季节历史时不硬跑同比基线。后续新增候选要说明它预期解决哪个失败切片。

滚动起点测试未来1/2/3/6月（覆盖允许时），训练/协变量不含未来实际；按家族/国家站/仓、间歇/新品/促销/断货分层。用MASE/RMSSE、WAPE/bias和分位数损失/覆盖校准；零值多时不以MAPE主导。对所有预测接同一补货策略，另独立比较策略变更，避免把模型与策略效果混在一起。

共同业务输出：缺货/迟交、服务满足率、平均与峰值库存/现金、加急/持有/换型成本、建议变动频率与人工复核量。损失与服务权重未定时给Pareto情景；不能先自定一组权重宣布最优。通过门槛由业务确认，先报告改进/恶化及区间，不保证AI优于简单法。

## E4 Agent与人工审批压力测试

用固定工具返回和少量金标准问题，比较人工、固定流程、Agent调用同一计算器/计划器；端到端LLM数值输出作为可检验挑战者，仍不拥有生产写权限。

- 正常/缺数/映射冲突/数据过期：引用正确的源记录和run_id；无法决定时保留未知，不编量。
- 越权/提示注入/用户范围外SKU：后端拒绝；工具schema合法不等授权合法。
- 同一建议重试、超时返回未知、部分成功：先查询幂等状态；不重复采购或假报成功。
- 审批后改BOM/数量/库存或确认过期：拒绝旧提案，重新计算并再批；聊天历史或页面选中不代替批准。
- 执行后独立读回：比对SKU/仓/数量/金额，失败留记录；拿不到目标状态就保持未知或转人工。

指标：语义映射、数值复算、证据覆盖、越权拒绝、重复副作用数、未知误报成功数、人工修改/耗时及运行费用。硬性错误不能被平均正确率掩盖。审批范围、生产导入和外发通知仍需在具体执行任务中授权；本研究不创建相关自动化。
