# 跨境供应链整合：研究首稿

## 范围与核查边界

目标流程为跨境家居纺织品：通途订单/库存/采购、ERPNext 的 SO/PP/WO/Job Card/DN/BOM、赛狐海外仓库存与补货建议，贯通销售、未来数月需求、库存、采购、生产、出库、头程和补货/排产建议，最后由负责人审批。已知绍兴工厂向美东、新泽西/美中、波兰海外仓供货；商品含成品、皮壳/内胆等半成品与套件，且存在拆包裹。需求存在断货删失，长提前期显著。团队规模、预算、数据完整度与管理偏好未知。

本研究是路线研究，不接触业务数据、生产凭证或系统写操作；不读其他深度研究结论。只读项目上下文与手册标题/开头，并查看公开官方文档、论文摘要/正文可访问片段。没有验证厂商宣传中的 ROI、效果数字，也没有对三套系统逐字段做 API 能力核验。项目上下文还提示，赛狐初期有成本用途，不能简单把赛狐余额当真实库存；备货手册/脚本存在默认数量 1000 的模板规则。整合前应给每个库存来源与记录标记业务语义、导入/成本/真实可售属性，并用系统库存流水和仓库实物/收发记录核实。该提示不代表现存所有赛狐记录都是虚拟库存。

## 结论

建议先建立“单一、可解释的供需事实层 + 分层决策 + 人审批”的闭环。不要把它等同于采购一个 APS 或让一个 AI 直接下单。可以把自动化/AI 放在预测、异常分类、解释与场景比较的任一环节；核心采购和生产数量仍由可回放、可约束的计划引擎/优化模型计算，负责人对范围、参数和例外承担审批。计划范围过滤和 BOM 展开控制可参考现成计划软件中的范围筛选机制（[C6](sources-industry.md)），但本项目实现仍需按用户确认的范围限制。

一种可试的节奏是假设月度轻量 S&OP、周度滚动供需计划：ASCM 职业指南描述了月度 S&OP 的常见跨职能周期和决策层级（[C1](sources-industry.md)），但不是强制标准；实际节奏、冻结窗和例外频率应由负责人按数据新鲜度及运营需要确认。若试行，运营/销售给出事件和需求假设，供给侧校验供应商/生产/头程/仓容/现金约束，财务展示库存资金和服务风险，负责人对冲突选项做决议。滚动计划把批准后的基线与新订单、库存、在途、采购、PP/WO/BOM、可用产能、仓库转运和 MOQ/装箱倍数展开为时间分段净需求；周期预测更新会扰动标准 MRP 订单，因此冻结窗与变更门槛需用历史计划回放验证（[C9](sources-industry.md)）。ERPNext/通途/赛狐继续做交易事实来源；新层先生成建议和差异，先不自动写入。ERPNext 自带库存补货可按商品/仓库设 Reorder Level/Qty 并自动生成 Material Request，但这种阈值提醒与本研究的跨系统、未来数月、长交期供需计划不是同一个决策层。

补货不宜全 SKU 共用一套公式。候选规则为：规律、可预测的高销量成品用 min/max 或连续/周期复核策略，间歇高价品可按需补货（ERPNext 的策略定义候选见 [C5](sources-industry.md)）；间歇、高价值或新 SKU 用按单/人工例外；长前置海运产品按需求与交期分布、供应风险和服务目标设置动态安全库存；服务目标、缺货损失、持有资金成本和调拨/加急等成本权重尚未确定，因此初期不默认合并成单一排序分数。先展示库存/现金/服务的 Pareto 方案与多情景权衡，由负责人确认目标或优先级，再做明确排序。按商品/仓库设置安全库存以及季节调整是常见产品功能模式，但参数必须本地校准（[C4](sources-industry.md)）。仓间共享库存/调拨和三地安全库存需要网络级校验，避免每仓独立加缓冲导致总库存偏高。MEIO可先作为离线决策支持或模拟器，不先追求精确全局最优；文献模型显示网络级决策要显式表达复核周期、MOQ、制造节点与服务指标，仿真优化会保留需求/交期不确定性（[C10](sources-industry.md)、[C11](sources-industry.md)）。

成品与皮壳/内胆/套件以统一 SKU/替代关系和 BOM/工艺版本展开。ERPNext 官方手册说明 BOM 可多层含物料、子装配与工序，WO 可由 Production Plan/SO 生成，Job Card 跟踪实际工时；其工作站排程依据工时/日历并要求单项 operation 当天可完成，超时需拆分或允许加班。说明现有 ERPNext 可成为部分生产执行/能力基础，但不能未经实机核验就假定具备任意长跨度 APS 排程（[C14](sources-industry.md)、[C15](sources-industry.md)、[C16](sources-industry.md)）。计划先核对 BOM 数量、单位、有效期、损耗、套件组成、可替代料与在制品，再用时间相位 MRP 计算依赖；把供应商承诺、绍兴产能、工序/Job Card 节拍、质检、装箱、头程船期、清关和海外仓入库延迟显式分段，分清硬约束、可加班/替代等软约束。拆包裹只影响运输/履约计划和单位装箱约束，不应将需求重复计入成品需求。

断货期间观测销量是需求下界，不是零需求。最小方案保留实际销量与可售时间/库存状态，断货时段标记为缺失或删失，因为仅有被库存截断的销售数据时难以反推出潜在需求分布（[C8](sources-industry.md)）；有页面流量、广告、替代 SKU、订单取消/缺货日志时再辅助估计潜在需求，并给估计区间。缺少可用性日志时不应让模型“补出”看似精确的历史需求：先按可售日估计、相似品/季节分组和情景区间做敏感性比较，限制自动化置信度。

## 方法适用条件、复用候选与排除项

| 方法 | 适用条件 | 复用候选 | 当前排除/边界 |
|---|---|---|---|
| S&OP / 轻量 IBP | 月需求、产能、现金、服务目标需要跨部门取舍；管理者可按月出席 | 需求评审→供给可行性→财务影响→高管决策；记录版本、差异、责任人 | 不把会议术语或软件模块视作预测准确性证据；预算未知，不先买大型 IBP |
| 时间相位 MRP | BOM/物料主档、库存/在途、日期、采购/生产提前期可信 | 成品→皮壳/内胆/套件等多层 BOM 展开；采购/生产/调拨建议及需求供给 pegging | MRP 依赖主数据且一般不自动解决有限产能；不能拿静态总库存覆盖多仓、时间与订单承诺 |
| 有限产能 APS | 可用工序、班次、工作中心/技能、产能日历、物料约束可用；存在真实瓶颈 | 用于产能瓶颈场景，评估提前生产、替代产线/来源和迟交 | 不先作为 MVP；脏/缺工艺路由会使“优化”输出伪精确。逐个候选系统核实提前期、物料、供应商、资源约束各自如何定义为硬/软及冲突处置；不得把某厂商行为泛化为 APS 通则 |
| MEIO | 多仓有共同上游、可调拨、交期/需求不确定，目标是网络服务与资金平衡 | 先模拟每仓独立策略与跨仓池化情景；据实验证明价值后再优化 | 需比较共享货物/分配规则/调拨费用；静态 SKU×仓均值安全库存不是 MEIO |
| DDMRP | 供应波动高、明确可设计解耦点/缓冲、组织接受参数治理和定期校正 | 可对特定长交期共用件做并行仿真，比较缓冲反应 | 证据基础有限且并非普适；不替代 BOM MRP、销售预测、有限产能或头程约束 |
| min/max、周期复核、按单 | 主数据简单、SKU 可分层、MOQ/订货倍数明确 | 按 SKU 类别/仓库/供给路径分配策略，给采购数量加包装倍数 | 单一服务水平或全局固定安全天数不适合所有商品、长交期或间歇需求 |
| 概率预测/机器学习/AI | 有足够历史、促销/价格/上市/库存可得性等特征，且回测可避免泄漏 | 提供多个需求情景、异常解释、预测区间；让计划器接收需求分布/情景 | 不直接把预测点值当采购命令；删失识别不足时不宣称潜在需求已恢复 |
| 老板审批控制塔 | 建议能解释来源、资金、服务风险、数据质量、变更前后与责任 | 例外队列 + 分层审批 + 范围过滤 + 版本化计划 + 审批后再落 ERP | 不自动创建 PO/WO/调拨/发货；不允许因接口/缺数静默扩大范围 |

## 建议路线

1. **事实层与数据质量（阶段门槛，工期取决于数据完整度）**：定义 SKU 主键/映射、SKU 类型、BOM 与套件版本、仓库/虚拟库、数量单位、库存可用状态、订单状态、在途状态、采购承诺、生产订单、批次、头程节点、日历/交期。先只抽样导出历史数据，逐源列出缺列、重复、未匹配和状态映射；做订单—出库—库存数量桥接与多仓快照。通过门槛为：关键字段可追溯到源记录，库存与订单/收发桥接的差异已量化且有归属，虚拟/成本/在途余额有语义标签，未匹配和缺列有报告；达不到时停留在数据治理，不估算固定工期。
2. **可信需求基线**：按 SKU×仓×周/月保留原始订单/销量、取消/缺货、在售/可售天数，先做季节性朴素基线和滚动回测；按 SKU 生命周期/销量/波动/提前期分组。缺货期采用下界与场景，不伪造点估计。
3. **确定性供需计划影子版**：以已确认订单+需求基线生成需求；用有效 BOM 展开采购/绍兴生产/海外仓填充包装、调拨/备货和头程；用订单、现有采购/WO、库存和可用产能做时序平衡。只给出建议、原因、预期到货和例外，不写系统。
4. **资金/服务情景和审批**：每条建议显示建议数量/日期/供给类型、触发需求、在手/预留/在途、交期来源、MOQ/装箱、缺货风险/预计可服务需求、库存资金/费用、预测区间、被改变的旧计划、数据缺陷和人工可覆盖值。按金额/缺货风险/冻结窗口/超参数设置审批层级；老板批准的是版本与范围。
5. **小范围回测+影子试点**：从一种需求相对稳定且履约有日志的成品，配一条完整 BOM、一个海外仓和一个绍兴采购/生产路径开始，横跨至少一个完整补货周期；和现行人工决策并行。先验收输入对账、建议可解释性和无越界，再看偏差、缺货、库存、现金、迟交与计划变更频率。扩大范围需单独批准。
6. **之后再评估**：如果影子计划确认显著的跨仓库存/服务取舍，试 MEIO；若工序路由/工时/产能日历可信且排产成为瓶颈，再评估 APS；若某类共用长交期组件适配，才试 DDMRP 解耦缓冲。

## 反例与风险

- Oracle 该版约束计划文档将资源/供应商产能作为软约束，最后可能过载；这是 Oracle 特定产品的机制，不代表所有 APS。每个候选引擎都需分别核实产能、物料、采购/生产提前期等约束的硬软属性与冲突处理。若产能可软化，输出应标出超载与迟交，而非视为生产承诺（[C2](sources-industry.md)、[C3](sources-industry.md)）。
- 微软的安全库存示例说明真实订单可消耗安全库存并触发补充；安全库存是可被需求使用的缓冲策略，不是完全不可动用的独立现货。若老板要求“绝不动用”，必须明确设置更强的预留规则及其成本。
- 一项 MRP 仿真研究发现，周期性预测更新会扰动计划订单；其提出的安全库存利用启发式只在模型假设和仿真中展示结果，不能直接搬作公司绩效承诺。需要冻结窗口/例外门槛，并在历史快照上回放。
- DDMRP 系统综述明确指出尚无研究证明适合所有工业场景、复杂 BOM/产品多样性与真实工业环境的证据有限（[C7](sources-industry.md)）；另有实验表明缓冲点选取对表现敏感。因此只能选品类试验，不能直接全量替代 MRP。
- 断货删失需求论文指出售出量受库存上限截断，未满足请求可能不可观测；如果缺库存时间线/点击/缺货日志，任何潜在需求估算都依赖额外假设。

## 未决项

1. 通途、ERPNext、赛狐现有 API/导出是否能提供库存历史快照、预留、采购承诺、生产状态、头程节点和订单/缺货明细？本研究未做字段/API 实测。
2. 绍兴皮壳/内胆/成品哪些自制、外采、共享；工艺路线、批量、损耗、委外产能和替代规则有哪些可用记录？
3. 是否存在 Amazon/FBA 与第三方海外仓之外的成品在途和平台库存？仓内可售/质检/次品口径如何对齐？
4. 现金预算、MOQ/装柜规则、海运时效分布、缺货损失/服务目标、滞销折价、调拨成本能否量化？决策者希望看美元、件数还是两者？
5. 谁是需求计划、采购、生产、头程、仓库、财务与最终审批责任人？可接受的刷新频率、冻结窗和审批阈值？
6. 拆包裹主要是多个包裹共用一订单行、组合件拆 SKU、还是分仓/平台履约？真实语义决定订单信号怎样计量。
