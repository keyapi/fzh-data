# 02 — 能力地图（先定能力，再选技术）

> 用法：新对话先拿这张表跟老板/业务对齐「V1 要哪些格子」，
> 再去做 03 的调研。**不要先选框架再找问题。**

## 1. 全链路（数据流）

```text
销售事实 ──► 需求预测 ──► 净需求 ──► 补货/下单建议 ──► 生产/排产建议
   ▲            ▲           ▲              │                  │
   │            │           │              ▼                  ▼
   └─ 平台/ERP   └─ 历史+异常  └─ 库存/在途   审批 ──► 执行（EN/通途/工厂）
                                   ▲
                      采购在途 ◄── 头程在途 ◄── 工厂出库
```

## 2. 能力清单

优先级：**P0 = V1 必须有；P1 = 第二批；P2 = 以后**。

| # | 能力 | 具体内容 | 现有资产 | 缺口 | 优先级 |
|---|---|---|---|---|---|
| C1 | **数据接入** | 通途订单/库存/采购、EN SO/PP/WO/DN/BOM、赛狐库存/结算、钉钉头程表、平台账单 | `tongtool_api`、`EN_API`、`SELLFOX_API`、`dingtalk_sheet`、`pb_orders` | 统一连接器层与增量同步；失败重试与水位 | P0 |
| C2 | **主数据归一** | SKU 三系统映射、仓库、供应商、BOM、客户/渠道 | `missing_products`、`multi_attr_saihu`、成本引擎映射、`channel_account_sync` | 一张权威映射表 + 未匹配报告 | P0 |
| C3 | **事实层与数量对账** | 订单行、采购、生产、出库、在途、库存快照；四组数量等式 | 履约蓝图 §3/§5、`item_shipment_status.py` | 统一事实模型（未合并分支里已有雏形） | P0 |
| C4 | **销售分析** | 按 SKU×仓库×渠道×月；剔除断货/促销/一次性大单；PB 与非 PB 分列 | `pb-replenishment-sizing-from-sales.md`、`sellfox_settlement`、GSheet 月度订单 | 通用化到全品类；口径配置化 | P0 |
| C5 | **需求预测** | 基线（naive/MA/季节）、断货删失、新品冷启动、层级汇总、误差评估 | **无**（只有方法文档；`demand_forecast` 待确认） | **最大缺口** | P0 |
| C6 | **库存与覆盖期** | 可用库存、在途、覆盖月数、安全库存、服务水平 | `warehouse_restock`、通途库存、EN 库存 | 安全库存策略；多仓分配 | P0 |
| C7 | **补货/下单建议** | 净需求、MOQ、装箱/柜、提前期、资金约束、分批到货 | `warehouse_restock`、PB 补货方法 | 优化与约束；情景对比 | P0 |
| C8 | **生产/排产建议** | 产能、工序瓶颈、齐套、节假日、交期倒排 | `erpnext` WO 审计、EN PP/WO | 排产算法与产能模型 | P1 |
| C9 | **头程在途** | 批次、装柜、ETD/ETA、清关、到仓、异常 | 钉钉表只读；履约蓝图 §5/§6；Jack/PJ 大屏 | 接入、事件模型、ETA 变更留痕 | P0（识别）/ P1（自动化） |
| C10 | **异常与预警** | 断货、低于安全库存、在途延误、生产停滞、超期未发 | `pb_orders` 断货闭环、`parcel_track` | 统一告警规则与去噪 | P0 |
| C11 | **建议解释** | 每个数字的来源、公式、数据新鲜度、置信度 | 履约蓝图证据模型 | 通用证据结构 | P0 |
| C12 | **审批与执行** | 草稿、审批记录、执行回写、审计 | Notion 台账（PB） | 通用工作流；权限 | P0（审批）/ P1（回写） |
| C13 | **交互层** | 一页纸结论、下钻明细、自然语言问答 | `ai_access_poc`、PB 网页版 | 面向老板的视图；Agent 取数工具 | P1 |
| C14 | **治理与评测** | 口径版本、回测、预测准确率、数据质量分、回归测试 | 各模块测试、`check_solutions_health` | 端到端评测集 | P1 |

## 3. 能力依赖关系（做事的顺序）

```text
C1 接入 ─► C2 主数据 ─► C3 事实与对账 ─► C4 销售分析 ─► C5 预测
                                              │              │
                                              ▼              ▼
                                          C6 库存/覆盖 ◄── C7 补货建议 ─► C12 审批
                                              │
                                              ├─► C9 头程在途 ─► C10 预警
                                              └─► C8 排产建议（依赖 C3 生产事实）
C11 解释 / C13 交互 / C14 评测：贯穿每一层
```

**没有 C1–C3，后面的预测和优化都是沙上建塔。** 新对话应先用一个小品类验证 C1–C3 的可行性，
再决定是否投入 C5/C7。

## 4. 数据源与事实源（必须先裁定）

| 数据 | 候选来源 | 当前倾向 | 待裁定 |
|---|---|---|---|
| 销量 | 通途订单 / 赛狐订单 / 平台结算 | 通途订单（含渠道字段） | PB 等渠道是否以平台账单为准 |
| 库存 | 通途 `stocks` / EN Bin / 赛狐 | **按仓分别裁定**（EN 不扣减通途，2026-10 确认） | 海外仓以谁为准 |
| 采购在途 | 通途采购单 / EN PO | 通途采购单（PB 补货已验证） | EN PO 是否同步 |
| 生产 | EN PP/WO/Job Card | EN | 工单状态可信度规则沿用 `erpnext` |
| 工厂出库 | EN DN | EN | 部分出库/退货净额 |
| 头程 | 钉钉表 / 智美通 / Jack 大屏 | 钉钉表（可机器读） | 智美通是否权威、更新频率 |
| 成本 | EN BOM 成本 / 成本引擎 | 成本引擎（Colab 口径） | 新 USTX 表是否上线 |
| 客户/渠道 | 平台 / EN Channel Account | EN Channel Account | Amazon 按国家站 |

> **铁律（来自既有经验）**：EN **不扣减**通途库存 → EN Bin 不能当可用库存；
> SO「未交量」≠ 在途；赛狐库存有安全冗余，不能反推「某批头程已签收」。

## 5. 决策对象（建议的输出结构）

每条建议至少包含：

```json
{
  "scope": {"sku": "...", "warehouse": "...", "channel": "..."},
  "horizon": {"from": "2026-11", "to": "2027-04"},
  "recommendation": {"order_qty": 110, "order_by": "2026-11-01", "coverage_months": 6},
  "evidence": [
    {"value": 18.2, "kind": "derived", "source": "sales_fact", "period": "2026-03..2026-09"},
    {"value": 6.0,  "kind": "estimate", "source": "forecast_model_v1", "confidence": "medium"}
  ],
  "constraints": [{"type": "moq", "value": 50}, {"type": "capital", "value": "..."}],
  "risks": [{"code": "stockout_before_arrival", "probability": "high", "impact_qty": 12}],
  "alternatives": [{"order_qty": 88, "coverage_months": 5, "why_not": "..."}],
  "owner": "WX",
  "approval": {"required": true, "approver": "老板"}
}
```

## 6. V1 纵向切片建议

选 **一个品类家族 × 一个海外仓 × 一个渠道**（例如 PB 楔形枕 × 美中 Daneey × PB），
跑通：

1. 销售事实（3 年历史，剔除断货月）；
2. 预测（至少两种方法 + 基线对比）；
3. 库存/在途/覆盖期；
4. 下单建议（含 MOQ/资金/到货日）；
5. 排产建议（EN PP/WO 可行性）；
6. 一页纸老板视图 + 证据下钻；
7. 审批记录与执行状态。

**验收**：与 2026-10-16 已交付的楔形枕决策包对比，数字能解释差异；
下一次同类需求能在半天内复跑。
