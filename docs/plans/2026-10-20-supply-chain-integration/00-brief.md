# 00 — 项目简报

## 1. 触发事件（用户陈述，未逐条核实）

- **2026-10-16（周五）**：把 PB 楔形枕/三角靠枕的**下单计划**（含销量分析、库存、在途、覆盖期、
  建议下单量）交给老板，**老板审批通过**。
- **2026-10-19（周一）**：老板反馈：以后这类下单申请，他**没有精力也缺少抓手**去逐项分析。
- **老板要的东西**：不是更多 Excel，而是一套**整体供应链整合**：
  - 从**销售数据**出发；
  - 用**历史 + 工具/模型**预估接下来几个月销量；
  - 结合**库存、下单、生产、出库、头程在途**数据；
  - **自动给出下单建议**；
  - 再给**排产建议**；
  - 最终让他能**快速判断、审批**，而不是从零核对。

> 以上是用户的一家之词，可能有遗漏或偏差。新对话应把「老板到底要看什么」列成问题，
> 用一页纸的样例输出反向确认，而不是直接假设。

## 2. 要解决的问题

把「每次由一个人手工拉数、拼 Excel、拍脑袋」变成：

1. **同一套口径**：销售额、销量、库存、在途、覆盖率全公司只算一次；
2. **可重复**：每月/每周跑一次，结果可复现、可对比上期；
3. **可解释**：每个建议都能回答「依据是什么、数据多新、哪一步是估算」；
4. **可审批**：老板看到的是**结论 + 风险 + 待决策项**，不是原始明细；
5. **可执行**：审批后能生成 EN 采购/生产建议、通途下单草稿（**人工确认后**才写）。

## 3. 范围

### 3.1 在范围内（V1 目标）

- 销售事实与需求分析（按 SKU × 仓库 × 渠道 × 月）；
- 需求预测（含**断货期销量删失**处理、季节性、新品冷启动）；
- 库存与在途快照（通途库存、EN 事实、采购在途、头程在途）；
- 补货/下单建议（覆盖期、安全库存、MOQ、资金约束）；
- 生产/排产建议（与 EN PP/WO/工序能力衔接）；
- 断货与延迟预警；
- 给老板的一页纸结论 + 可下钻的证据链；
- 审批记录与执行状态回写。

### 3.2 不在 V1（先别做）

- 全自动下单/自动排产（**必须有人批**）；
- 全公司所有品类一次性铺开（先选 1 个品类家族 × 1~2 个仓做纵向切片）；
- 替代 ERP/通途/赛狐（它们是事实源，本项目是**决策层**）；
- 复杂数字孪生、实时优化、容器级装载优化（等基础数据对了再说）；
- 直接改现有业务脚本的行为（研究阶段只读、只出文档）。

## 4. 成功标准（建议，待老板确认）

V1 做完时，应能：

1. 对一个选定品类，**每月 1 次**、**半天内**产出可审批的下单与排产建议；
2. 每个数字都能点回来源（系统 + 单据/表格 + 抓取时间）；
3. 预测误差有基线（naive/移动平均）对比，且**断货月不被当成真实需求**；
4. 建议里明确区分 **事实 / 推导 / 估算 / 人工判断**；
5. 老板能在一页内看到：建议下单量、金额、覆盖到几月、主要风险、需要他决定什么；
6. 同一个问题，两个人/两个 Agent 跑出的数字一致（可复现）。

## 5. 约束（已知）

| 约束 | 含义 |
|---|---|
| 三套系统并存 | 通途（订单/库存/采购）、EN ERPNext（SO/PP/WO/DN/BOM）、赛狐（库存/备货/结算） |
| 数据权威性不一致 | 同一指标三处都有，但口径不同；必须先定「谁是事实源」 |
| 头程是拼图缺口 | 当前只能读钉钉表；智美通/WorkBuddy 大屏在 PJ/Jack 手里，代码未进本仓库 |
| 凭证不进仓库 | 一律读父仓库 `.env` / `secrets/`，文档不写明文 |
| 写操作要确认 | 任何下单/排产/改状态的动作，默认只生成草稿，人工确认后执行 |
| 现有代码风格 | Python + `uv run`；OKF 文档；分支 → PR，不直接推 main |
| 多 Agent 并存 | Claude / Codex / Cursor 同时改同一仓库，必须按文件分工 |

## 6. 设计假设（待调研验证，不要当结论）

1. **确定性内核 + AI 外层**：算数、对账、优化用可测试的 Python/OR 工具；LLM 负责取数编排、
   归因、写解释、生成待办。**不让 LLM 直接算关键数字。**
2. **事实/推导/估算/人工判断四层标注**：与 `en-end-to-end-supply-chain-fulfillment-visibility.md`
   的证据模型一致，避免把估算冒充事实。
3. **先纵向切片，再横向铺开**：选一个品类家族跑通「销售→预测→补货→排产→审批」，
   而不是先建大平台。
4. **控制塔不是新 ERP**：优先复用 EN/通途/赛狐的既有事实，不再造一套库存或订单主数据。
5. **Agent 的价值在「异常处理与解释」**，不在于替代 MRP 计算。

## 7. 待老板/业务确认的问题（新对话第一件事）

1. **决策粒度**：按 SKU × 仓库？还是 SKU × 渠道？哪些品类先做？
2. **计划周期**：月度滚动、双周滚动，还是周度？提前期多长？
3. **目标函数**：优先保交付（服务水平）、优先压资金，还是两者加权？目标服务水平是多少？
4. **审批边界**：多大金额/多少数量以内可自动？哪些必须老板批？
5. **事实源裁定**：库存以通途还是 EN 为准？销量以哪个系统为准？头程以钉钉表还是智美通为准？
6. **产能约束**：工厂产能、工序瓶颈、节假日（如 2027 春节停机）如何进入排产建议？
7. **现有手工流程**：现在谁在做什么表、花多久、最容易错在哪（找 2~3 个一线同事访谈）。
8. **老板的一页纸长什么样**：先做 3 个样例页给他选，再定系统输出格式。
