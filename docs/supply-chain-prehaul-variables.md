# 交期四段与 pre-haul 变量

当前模型把交期拆为：

1. 生产 SO→DN（按池，已有）
2. **DN→头程物流商仓入仓（pre-haul）**
3. 头程仓→目的仓签收（按区域×方式，已有 ZMT 样本；即 55/30/14）
4. 目的仓上架（`shelving_days`，默认 0；见下，1–2 天是未经验证的假设）

> 第 2 段只到“入仓”，不含“入仓→开船”。后者已在第 3 段里，见下。

## pre-haul 变量

当前口径：**pre-haul 固定记 2 天**，之后直接接 55/30/14：

| 变量 | 默认 | 含义 |
|---|---:|---|
| `prehaul_days` | 2 | DN 出库 → 头程物流商仓入仓的固定天数（决策值；实测 p50=0/p90=2） |
| `prehaul_pool_adj` | {} | 按池/分公司调整，如 USNJ/USTX/PL |
| `prehaul_port_adj` | {} | 按发货港口调整（宁波/上海/义乌等） |
| `prehaul_distance_days` | 0 | 与绍兴距离相关的附加天数 |
| `prehaul_scenario` | "decision_2d" | 当前决策口径；实测值为 p50=0/p90=2 |
| `shelving_days` | 0 | 目的仓签收 → 可售上架的附加天数；未实测，默认 0 |

规则：**总交期 = 生产 + prehaul(2) + 55/30/14 + shelving(0)**。不要把“入仓→开船”当成 pre-haul 塞进 55/30/14（那 12 天已在 55/30/14 内）。

关于 `shelving_days`：之前写的“1–2 天”是**假设，不是实测**。可测口径是 Shipment 签收 → 通途 PO 入库，但当前 PO 靠人工操作，入库时间会被人工延迟污染，所以暂不纳入，默认 0；等自动化后再用实测替换。

## 已有实测（2026-11-06，EN Shipment 字段直读）

不再用事件文本猜，直接取 Shipment 上的 ZMT 字段：

| 段 | 字段 | n | p50 | p90 | max |
|---|---|---:|---:|---:|---:|
| DN 过账 → 货代仓入仓（pre-haul） | `posting_date` → `custom_zmt_wms_in_time` | 50 | 0 | 2 | 6 |
| 入仓 → 实际开船 | `custom_zmt_wms_in_time` → `custom_zmt_atd` | 48 | 12 | 17 | 28 |
| 开船 → 到港 | `custom_zmt_atd` → `custom_zmt_ata` | 37 | 21 | 37 | 41 |
| 入仓 → 派送预约 | `custom_zmt_wms_in_time` → `custom_zmt_appt` | 49 | 53 | 65 | 73 |

关键结论：

- **pre-haul（DN→入仓）实测 p50=0、p90=2、max=6**；当前按决策口径记 **2 天**。
- 55/30/14（实测 p50 50/31/13，p90 64/32/14）是 **入仓→签收**，已经包含“入仓→开船→到港→派送”整段。
- **不能把 9–13 天的 DN→开船再加到 55/30/14 上**：DN→开船 = DN→入仓（0）+ 入仓→开船（12），后半段已在 55/30/14 里，再加就是重复计算。
- 因此总交期 = 生产 + prehaul（2）+ 55/30/14（入仓→签收）+ shelving（0）。

> 负值是 DN 过账晚于入仓（货先到货代仓、后补 DN），按 0 处理即可。
