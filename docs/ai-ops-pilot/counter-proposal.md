# AI 运营试点计划 — 三处修改建议

> 针对《FZH AI运营试点计划 1.0》| 2026-09-16 面谈用 | 详细依据见 [assessment.md](assessment.md)

**总体判断：框架扎实，建议保留。** 30 天、6–8 人、人机共判、明确暂不做、G1–G4 关口——方向都对。以下三处是把**不可验收的表述**改成**可验收的表述**。

## 一、三处修改

### 第 03 节 ·「4 个标准 AI 助手」先定义载体

| | |
|---|---|
| **问题** | 全文只给了 4 个助手的名称，没定义「助手」是什么。第 04 节 G2 却要求「4 个助手 V1 发布，知识关键事实抽测通过」——**没有定义就无法验收** |
| **建议** | 每个助手先写清四要素：**载体 + 输入输出边界 + 业务 Owner + 验收口径**。**首批只做 2 个**：广告复盘、产品表达；第 3–4 周视情况加 |
| **暂缓** | 「市场与竞品研究」——它是 4 个里唯一需要新增采购的（见下） |

### 第 07 节 ·「暂不做集成」细化粒度

| | |
|---|---|
| **问题** | 现写「ERPNext 深度集成 / 复杂接口开发」暂不做。表述过粗，会连**只读导出**一起排除，导致两个数据侧助手（广告复盘、经营）无数据可用 |
| **建议** | 改为「**不做写回、不做复杂集成；允许只读、单店铺、最小范围的数据导出**」 |
| **补充** | 写回本来也做不了：**赛狐广告目前没有写 API**（拉报告、读实体可以，否词下发/改竞价预算不行）。且项目里已有跑通的只读实现可复用 |

### 第 04 / 08 节 · 资料交付物 与 成功案例判据

| | |
|---|---|
| **问题（资料）** | W1 要求交「30–50 份资料清单」、W2「导入并校验」。NAS `/产品信息/` 已有 404 个 ERPNext 物料组目录及「调研报告/设计稿/图片/视频」子目录，历史资料**可能已有**；但格式、Owner、时效、重复、可解析性和事实可信度均未盘点。**有文件不等于知识已就绪** |
| **建议（资料）** | W1 改交「**资料资产与缺口表**」：只抽样 1–2 个产品族，记录路径、类型、Owner、最后更新、可解析性、敏感性与知识库准入；不做 NAS 全盘 OCR |
| **问题（案例）** | 第 08 节「至少一半人员形成稳定习惯」「管理层明确感受到提升」——是感觉，不是证据 |
| **建议（案例）** | 增加一条硬判据：**至少 1 个助手产生可量化的业务变化**（ACOS / CTR / CVR 前后对比）。哪怕只有一个 |

## 二、五个问题

1. **「助手」是哪一成熟度、用什么载体？** L1 知识助手、L2 工具助手，还是 L3 业务 Agent？
   - ChatGPT Workspace Agent 可调用远程 MCP/API，但仓库脚本**不能直接上传即运行**，需封装为只读窄工具；Git 继续保留 instructions、代码、schema 与测试真源。
2. **「市场与竞品研究助手」的数据从哪来？谁出钱？怎么证明必要性？**
   - 现状：内部数据源（ERPNext/赛狐/通途）已通，但**外部市场与竞品数据一条都没有**。卖家精灵 MCP 未开通（较贵），Sorftime 仅同事个人试用一个月已到期。预算表里没有「数据源」这一行。
3. **我作为 AI 负责人是兼职还是专职？若是兼职，助手能否从 4 个降到 2 个？**
4. **是否知道项目里已有 `ai_access_poc/`（壳 + 板 + 门户三个 PoC），技术验收已绿，卡在运营审？**
   - 若是：这是**最大的合并机会**——计划的 W3「实战与纠偏」与既有的「运营审」是同一件事，一次做完即可拿到第 30 天最容易的那个成功案例。
5. **第 30 天的成功案例，是否接受绑定可量化业务指标？**

## 三、我的角色边界

**认领**：ChatGPT Workspace Agent 平台与发布机制、FZH 只读 MCP/API 薄适配层、只读数据导出、Git 技术真源、工具培训；协助设计 NAS 盘点字段。
**不认领**：Agent 的业务事实与内容确认、周度评分、第 30 天业务质量签字。
**需要明确**：「助手维护 Owner」由谁接——否则 AI 负责人会变成 4 个助手的长期保姆。
