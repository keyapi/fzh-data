# AI 运营试点计划 — 落地配套建议

> **给黄总**：第 1 节是人看的结论，两分钟读完。
> **给 Agent**：第 2 节起是编号条目，可按第 3 节的回执协议逐条回复。
> **本文不改变计划的范围、目标与时间表**，只是把启动前需要定下来的几个口径先理一理。

## 1. 给黄总的一页

计划框架没问题，可以照跑：30 天、6–8 人、一个 ChatGPT 工作区、小范围真实业务、人机共判、明确暂不做、四道检查关口（计划里叫 G1–G4，分别在第 5、10、20、30 天）——这几条都建议原样保留。

下面 3 件事都不涉及改计划，只是启动前把口径定一下，会上十分钟能定完。

**一、4 个助手的「形态」先定一下。**

计划已经定好了 4 个助手的名字、主要任务、标准输出和业务 Owner。还差一件：这些助手具体长什么样——是 ChatGPT 工作区里的助手，还是仓库里的技能加文档。

这件事定下来，第 10 天那道检查（计划里叫 G2）就有明确判据。因为**形态不同，能读到的数据、由谁维护、怎么验收，完全不一样**。建议我这边先出方案，会上过一下。

**二、「市场与竞品研究助手」的外部数据，可能是个缺口。**

内部数据（ERPNext / 赛狐 / 通途 / 物流）都已经接通；但外部市场与竞品数据目前还没有来源：卖家精灵只用了网页版，MCP 未开通；Sorftime 是同事个人试用一个月，已到期。这类外部数据能力通常需要单独开通，并有一定费用。

建议先把它列为一个待确认项。在开通之前，这个助手可以先做成「研究流程模板」，不承诺市场容量这类数据结论。

**三、资料这块，建议把「格式」和「内容」分开看。**

计划第一周要盘点现有知识资料，交一份 30–50 份的清单（含 Owner 和版本）；第二周导入并校验。

我把这 6 类过了一遍，它们性质其实不一样：

- **写一份就成型的（规范类）**：③ 市场调研模板、④ 关键词/广告复盘方法、⑤ 图片与页面表达原则、⑥ 新品冷启动 SOP。这四类的验收要点本身就是「字段统一」「口径一致」「含正反例」「阈值清楚」——说明它们要的是**格式和规则**，一份就行。
- **会随产品增长的（内容类）**：① 产品资料、② 优秀 Listing 案例。

**这里想先跟你确认一下**：① 产品资料，是先定一份**产品资料的格式模板**（之后按模板逐个产品补），还是**30 天内要把产品资料整理出来**？前者第二周就能完成；后者要看产品数量，可能要分批。

另外，NAS 上已经按 ERPNext 物料组建了 404 个目录，历史的产品设计稿、调研报告可能就在里面。第一周盘点时顺手看一眼，有能用的就不用重写。

一句话：**这三条定完不影响框架和排期，第二周就能正常推进。**

## 2. 补充条目（供 Agent 逐条核对）

### R1 · 助手形态先定，四要素写清楚

| | |
|---|---|
| **现状** | 计划已定 4 个助手的名称、主要任务、标准输出与业务 Owner。载体形态待定。 |
| **建议** | 启动前为每个助手补四要素：**载体 / 输入输出边界 / 业务 Owner（落到人名）/ 验收口径**。发布可分两批：先跑通 2 个，第 3–4 周补齐另外 2 个。 |
| **说明** | 载体决定能力边界。2026-09 官方资料复核：ChatGPT Business 现已支持 Workspace Agents、Company Knowledge 和管理员发布**远程 MCP app**，所以「工作区内的助手」并非天生读不到赛狐数据——但必须先把手上的脚本封装成**远程只读工具**，**仓库脚本不能原样上传运行**。这个区别写清楚，第 10 天的抽测才有判据。 |

### R2 · 「暂不做集成」的粒度要细化

| | |
|---|---|
| **现状** | 计划把「ERPNext 深度集成 / 复杂接口开发」列入暂不做。方向正确，但表述偏粗。 |
| **建议** | 细化为「**不做写回、不做复杂集成；允许只读、单店铺、最小范围的数据导出**」。 |
| **说明** | 写回本来也做不了：**赛狐广告目前没有写 API**——拉报告、读实体可以；否词下发、改竞价预算不行。所以「不做写回」是当前技术条件下的必然，不是取舍。把这条写进计划，第 30 天就不会被追问「为什么没有自动执行」。 |

### R3 · 资料清单里区分「格式类」与「内容类」，并确认 ① 的意图

| | |
|---|---|
| **现状** | 第 1 周交付「30–50 份资料清单含 Owner/版本」；第 2 周「导入并校验知识」。6 类如下： |
| **① 产品资料** | 规格、材料、功能、使用场景、限制、差异点 —— 产品负责人 —— 事实准确，有版本与日期 |
| **② 优秀 Listing 案例** | 标题、五点、A+、图片、评论表达案例 —— 运营负责人 —— 说明「为什么优秀」 |
| **③ 市场调研模板** | 容量、价格带、人群、竞品、评论、机会点 —— 运营负责人 —— 字段统一，可复用 |
| **④ 关键词/广告复盘方法** | 搜索词、ACOS/TACOS、结构与异常诊断 —— 广告负责人 —— 指标口径一致 |
| **⑤ 图片与页面表达原则** | 品牌、卖点优先级、场景与视觉规范 —— 视觉/品牌 —— 含正反例与禁区 |
| **⑥ 新品冷启动 SOP** | 定价、库存、节奏、广告与复盘节点 —— 运营负责人 —— 动作、阈值、责任清楚 |
| **建议** | ③④⑤⑥ 属**规范类**，写一份即成型，第 2 周可完成；①② 属**内容类**，建议先做 1–2 个产品族作为样板，其余按模板后续补。**需向黄总确认：① 要的是格式模板，还是 30 天内整理完内容？** |
| **说明** | 「关键事实抽测通过」建议设计成**每次使用时的持续校验**，而不是一次性的放行测试（与第 03 节的红线是一回事，建议合并表述）。另外，先做样板再铺开，可以让第 20 天（G3）的实战闭环先跑起来，而不必等内容全部就位。 |

### R4 · 业务 Owner 从角色落到具体人名

| | |
|---|---|
| **现状** | 计划已为 6 类资料和 4 个助手指定了责任角色（产品 / 运营 / 广告 / 视觉负责人），并在第 03 节写明「AI 负责人维护核心指令与知识版本，业务 Owner 负责专业口径验收」。 |
| **建议** | 启动会上把这四个责任角色**落到具体的人名**，并明确每类资料的首次交付时间。 |
| **说明** | 计划第 01 节把「人才：哪些运营具备 AI + 经营思维，能判断、修正并落地 AI 建议」列为三大验证问题之一。**责任落到人名，第 30 天才能分清是「工具不好用」还是「内容还没跟上」**——两个验证问题才能分别测出来。 |
