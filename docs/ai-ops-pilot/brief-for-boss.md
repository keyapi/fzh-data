# AI 运营试点计划 — 落地配套建议

> **给黄总**：第 1 节是人看的结论，两三分钟读完。
> **给 Agent**：第 2 节起是编号条目，可按第 4 节的回执协议逐条回复。
> **本文不改变计划的范围、目标与时间表**，只是把启动前需要定下来的几个口径先理一理。

## 1. 给黄总的一页

计划框架没问题，可以照跑：30 天、6–8 人、一个 ChatGPT Business 工作区、小范围真实业务、人机共判、明确暂不做、四道检查关口（计划里叫 G1–G4，分别在第 5、10、20、30 天）——这几条都建议原样保留。

下面 4 件事都不涉及改计划，只是启动前把口径定一下。

**一、4 个助手的「形态」先定一下。**

计划第 02 节已经定了载体：一个公司级 ChatGPT Business 工作区，每人独立账号。4 个助手是：

- **FZH 市场与竞品研究助手**（运营负责人）
- **FZH 产品表达助手**（产品/视觉负责人）
- **FZH Amazon 广告复盘助手**（广告负责人）
- **FZH 运营经营助手**（运营负责人）

还差一件：这些助手在工作区里以什么形式存在，以及它们和工作区外的数据、脚本怎么配合。

我的初判是：这四个会是工作区里的「Workspace Agent（工作区智能体）」；其中广告复盘和经营这两个要吃实时数据，还需要在工作区外把现有脚本包成**只读接口**。**但这部分能力我还在核实**——工作区助手支持接哪些接口、能不能接我们自己的、怎么编辑、怎么留版本，等我出一份对比调研再定。会上先确认方向就行。

**二、「市场与竞品研究助手」的外部数据，可能是个缺口。**

内部数据（ERPNext / 赛狐 / 通途 / 物流）都已经接通；但外部市场与竞品数据目前还没有来源：卖家精灵只用了网页版，MCP（一种让 AI 调用外部工具的标准接口）未开通；Sorftime 是同事个人试用一个月，已到期。这类外部数据能力通常需要单独开通，并有一定费用。

计划第 07 节自己有一条「费用审批原则」：任何新增投入都要回答「解决哪个已验证的问题、谁使用、如何验收」。建议就按这条办——要么在第 30 天前把这几个答案拿出来，要么这个助手先做成「研究流程模板」，不承诺市场容量这类数据结论。

**三、资料这块，建议把「格式」和「内容」分开看。**

计划第一周要盘点现有知识资料，交一份 30–50 份的清单（含 Owner 和版本）；第二周导入并校验。我把 6 类过了一遍，性质其实不一样：

- **写一份就成型的（规范类）**：③ 市场调研模板、④ 关键词/广告复盘方法、⑤ 图片与页面表达原则、⑥ 新品冷启动 SOP。这四类的验收要点本身就是「字段统一」「口径一致」「含正反例」「阈值清楚」——说明要的是**格式和规则**，一份就行。
- **会随产品增长的（内容类）**：① 产品资料、② 优秀 Listing 案例。

**这里想先跟你确认**：① 产品资料，是先定一份**产品资料的格式模板**（之后按模板逐个产品补），还是**30 天内要把产品资料整理出来**？前者第二周就能完成；后者要看产品数量，可能要分批。

另外，NAS 上已经按 ERPNext 物料组建了 404 个目录，历史的产品设计稿、调研报告可能就在里面。第一周盘点时顺手看一眼，有能用的就不用重写。

**四、另外 2 处小口径，想一并对一下。**

1. **席位算几个人？** 计划是 6–8 名试点运营，另有「按需 1–2 名产品/视觉协同」，而预算按 6–8 个席位算。协同的 1–2 人要不要占席位？（要占，人数不变但要留名额；不占，他们怎么接收和回传资料。）

2. **「运营经营助手」要用成本数据吗？** 这个助手做新品冷启动、定价、库存、周月复盘，大多要碰成本；而计划第 02 节的资料边界里写了「暂不纳入完整财务与未经授权的完整成本数据」。想确认：定价和利润这块用什么口径、由谁授权。

一句话：**这几条定完不影响框架和排期，第二周就能正常推进。**

## 2. 补充条目（供 Agent 逐条核对）

### R1 · 助手形态先定，四要素写清楚

| | |
|---|---|
| **现状** | 计划第 02 节已定载体（ChatGPT Business 工作区）；第 03 节已定 4 个助手的名称、主要任务、标准输出与业务 Owner（业务负责人）。工作区内以什么形式存在、如何与外部数据配合，待定。 |
| **建议** | 启动前为每个助手补四要素：**载体形式 / 输入输出边界 / 业务 Owner（业务负责人，落到人名）/ 验收口径**。发布可分两批：先跑通 2 个，第 3–4 周补齐另外 2 个。 |
| **说明** | 载体决定能力边界。初步判断是工作区内的 Workspace Agent，但**具体能力（能接哪些接口、能否接自有接口、编辑与版本管理方式）需先出一份对比调研**，暂不展开。调研需同时对比现有 Git 仓库方式的运维影响——重点看后期可维护性、可编辑性与版本控制，而不只是上手门槛。第 10 天（G2）的抽测判据依赖这一条。 |

### R2 · 只读数据的时点要提前到第 2 周

| | |
|---|---|
| **现状** | 计划第 07 节把「ERPNext 深度集成 / 复杂接口开发」列为暂不做，重新评估时点写的是「**第 30 天后**；优先评估只读、小范围接口」。但第 3 周的实战阶段，「广告复盘」和「运营经营」两个助手就要吃真实数据。 |
| **建议** | 把「**只读、单店铺、最小范围的数据导出**」从「第 30 天后」提前到第 2 周准备，在暂不做条款里明确列为例外。 |
| **说明** | 两点理由：一是写回本来也做不了——**赛狐广告目前没有写 API**（拉报告、读实体可以；否词下发、改竞价预算不行），所以不存在「先做系统后找需求」的风险；二是只读导出属于确定性脚本，不需要接口开发。把它提前，第 3 周才有真实数据可实战。 |

### R3 · 资料清单区分「格式类」与「内容类」，并确认 ① 的意图

| | |
|---|---|
| **现状** | 第 1 周交付「30–50 份资料清单含 Owner/版本」；第 2 周「导入并校验知识」。6 类如下： |
| **① 产品资料** | 规格、材料、功能、使用场景、限制、差异点 —— 产品负责人 —— 事实准确，有版本与日期 |
| **② 优秀 Listing 案例** | 标题、五点、A+、图片、评论表达案例 —— 运营负责人 —— 说明「为什么优秀」 |
| **③ 市场调研模板** | 容量、价格带、人群、竞品、评论、机会点 —— 运营负责人 —— 字段统一，可复用 |
| **④ 关键词/广告复盘方法** | 搜索词、ACOS/TACOS、结构与异常诊断 —— 广告负责人 —— 指标口径一致 |
| **⑤ 图片与页面表达原则** | 品牌、卖点优先级、场景与视觉规范 —— 视觉/品牌 —— 含正反例与禁区 |
| **⑥ 新品冷启动 SOP** | 定价、库存、节奏、广告与复盘节点 —— 运营负责人 —— 动作、阈值、责任清楚 |
| **建议** | ③④⑤⑥ 属**规范类**，写一份即成型，第 2 周可完成；①② 属**内容类**，建议先做 1–2 个产品族样板，其余按模板后续补。**需确认：① 要的是格式模板，还是 30 天内整理完内容？** |
| **说明** | 计划第 09 节启动会确认页已预留「首批资料 目录 Owner + 目标数量」一栏，本条即按该栏填写。另：「关键事实抽测通过」建议设计成**每次使用时的持续校验**，而非一次性放行测试（与第 03 节红线是一回事，建议合并表述）。先做样板再铺开，也能让第 20 天（G3）的实战闭环先跑起来。 |

### R4 · 业务 Owner（业务负责人）从角色落到具体人名

| | |
|---|---|
| **现状** | 计划第 03 节已为 6 类资料和 4 个助手指定责任角色，并写明「AI 负责人维护核心指令与知识版本；业务 Owner（业务负责人）负责专业口径验收」。第 09 节启动会确认页已预留「4 个 AI 助手 业务 Owner（业务负责人）分别为 ____」。 |
| **建议** | 启动会上把这四个责任角色**落到具体人名**，并明确每类资料的首次交付时间。 |
| **说明** | 计划第 01 节把「人才：哪些运营具备 AI + 经营思维，能判断、修正并落地 AI 建议」列为三大验证问题之一。**责任落到人名，第 30 天才能分清是「工具不好用」还是「内容还没跟上」**，两个验证问题才能分别测出来。 |
