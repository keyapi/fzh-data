# 同事通途报表备份（20261026）可用性评审

> 一句话：**能用作 2026-04→10 的稀疏“有货库存检查点”，不能当作完整库存或断货依据**——导出时勾了“隐藏所有库存为0的货品”，最需要的零库存 SKU 大部分被隐藏了。

## 1. 文件构成

`D:/Work/彭建/通途库存记录 彭建下载备份 20261026.zip`（19.3 MB）→ 117 个嵌套 zip：

| 类型 | 数量 | 日期范围 | 内容 |
|---|---:|---|---|
| `销售及库存报表YYYYMMDDHHMM.zip` | 70 | 2026-04-14 → 2026-10-09 | 库存 + 7/15/30/90 天销量；按仓导出 |
| `商品销量分析报表(起~止).zip` | 47 | 2025-01-01 → 2026-09-30 | 周期销量/销售额/成本/利润汇总 |

- 外层的“库存报告”实际是**销售及库存报表**；不是每日全量，也不是 14 仓一次导出。
- 47 个销量分析报表是**销售汇总**，与订单历史重复，主要用于成本/利润交叉校验；**不含库存**。

## 3. 关键限制：零库存 SKU 被大量隐藏

导出条件里有 **`隐藏所有库存为0的货品 = 是`**（70 个文件里 68 个为“是”）。

以美东为例（日期相差 11 天，近似对比）：

| 指标 | 报表 2026-10-09 | EN 快照 2026-10-20 |
|---|---:|---:|
| SKU 总数 | 370 | 2,072 |
| 可用 > 0 | 283 | 302 |
| 可用 = 0 | 87 | 1,770 |

- **有货 SKU 覆盖约 94%**（283 / 302）——库存水平、结构、趋势可用。
- **零库存 SKU 只覆盖约 5%**（87 / 1,770）——**缺的正是断货判定最需要的部分**。
- 因此：**报表里没有某个 SKU，不能当作它库存为 0**；只能当作“这份导出没包含它”。

## 4. 其他数据质量注意

- `Buttonkit-pl`（售后针线扣子）在 10/09 的可用库存是 **9,999,866**，是占位/虚拟数量；**不要对全表 `sum(available)` 做趋势或对账**，应按 SKU 过滤。
- 7/15/30/90 天销量是导出时点的滚动汇总，不是日销量；不能直接当日需求。
- 47 个销量分析报表的 SKU 销量/销售额/成本/利润是周期汇总，和订单历史重复；仅建议做交叉校验。
- 内层 xlsx 文件名有 GBK 乱码（外层 zip 名正常），不影响内容解析。

## 5. 结论与用法

**可用，但定位要准确：**

| 用途 | 是否可行 |
|---|---|
| 2026-04→10 的**有货库存检查点**（美东/波兰/美中各子仓） | ✅ 可用，约 22 个日期 |
| 看某 SKU 的库存水平/7-30-90 天销量趋势 | ✅ 可用（仅限报表中出现的 SKU） |
| 判断某 SKU **断货**（库存=0） | ❌ 不可单独使用；零库存 SKU 大量被隐藏 |
| 日级库存/断货窗口 | ❌ 稀疏且不连续 |
| 销售/成本/利润交叉校验 | ✅ 47 个销量分析报表可辅助 |

**建议：**

1. 如果同事还能重新导出，把 **`隐藏所有库存为0的货品` 改为 `否`**，并按固定频率（每天或每周）导出；这样零库存 SKU 才会出现，才能真正用于断货。
2. 现有文件保留作**有货库存检查点**，已入 `pengjian_inventory` schema；不要覆盖每日 `stock_history`。
3. 断货判定仍以 **EN 每日快照 + WX 检查点 + PB `checked0stock`** 为主；这份报表只作补充。
4. 需要时按仓过滤：美东 `美东-CENTRADE`；美中成品 `美中-FZH-DANEEY`；波兰 `波兰-FZHPoland-covers`；不要把皮壳/半成品/退货仓算进可售。
