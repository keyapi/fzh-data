## 3. 零库存怎么用：**曾出现过、后来消失 = 该仓 0 库存**

导出条件里有 **`隐藏所有库存为0的货品 = 是`**（70 个文件里 68 个为“是”）。这看起来让零库存 SKU 消失，但正因为这份报表是**按仓**导出的，**“消失”本身就是仓库级 0 库存的负证据**——前提是这个 SKU 以前在该仓出现过。

### 3.1 先看规模：报表确实是子集

以美东为例（日期相差 11 天，近似对比）：

| 指标 | 报表 2026-10-09 | EN 快照 2026-10-20 |
|---|---:|---:|
| SKU 总数 | 370 | 2,072 |
| 可用 > 0 | 283 | 302 |
| 可用 = 0 | 87 | 1,770 |

- 有货 SKU 覆盖约 **94%**（283 / 302）——库存水平、结构、趋势可用。
- 零库存 SKU 只显式出现约 **5%**（87 / 1,770）——**大部分零库存 SKU 是“消失”的**。
- 但报表**并非只含有货 SKU**：它确实保留了部分显式 0 行（美东 10/09 有 87 行可用=0，其中 21 行有待发/在途，25 行是停售/清仓）。

### 3.2 消失的 SKU 是什么状态

对“以前在该仓出现过、2026-10-09 不再出现”的 SKU 做追溯：

| 仓 | 曾出现 | 10/09 出现 | 消失 | 消失前状态 |
|---|---:|---:|---:|---|
| 美东-CENTRADE | 523 | 370 | 153 | 在售 139、清仓 14 |
| 波兰-FZHPoland-covers | 1,369 | 750 | 619 | 在售 604、清仓 14、停售 1 |
| 美中-FZH-DANEEY | 725 | 602 | 123 | 在售 121、停售 2 |

美东消失的 153 个 SKU 中：**55 个最后出现时仍有正库存，41 个最后 7 天还有销量**，绝大多数是在售品——这与“卖完/转仓后 0 库存被隐藏”一致，而不是随机漏报。

同日再看这 153 个消失 SKU 的其它仓：
- **119 个在所有仓都没有任何记录**（全局 0 库存）；
- **30 个在美中-FZH-DANEEY 仍有正库存**（可能是转仓/只在美中卖），但对**美东 Listing** 来说仍然是美东不可售；
- 4 个在其它仓也是 0。

**结论：对“以前出现过”的 SKU，在某个仓的报表里消失，可以按该仓 0 库存/断货处理；但不能按“全局 0 库存”处理。**

### 3.3 判定规则（可直接进模型）

对每个 `(日期, 仓, SKU)`：

| 状态 | 条件 | 用法 |
|---|---|---|
| `present_positive` | 报表有行且 `可用库存数量 > 0` | 可售；库存水平可信 |
| `present_zero` | 报表有行且 `可用库存数量 = 0` | 该仓显式 0；可作断货证据 |
| `absent_after_presence` | 该 SKU 以前在该仓出现过，本日无行 | **该仓 likely 0**；再看 `prior_status` |
| `never_present` | 该 SKU 从未在该仓出现过 | `not_carried` / unknown，不参与断货 |

`absent_after_presence` 再分：
- `prior_status = 在售` → `likely_stockout_or_transfer`（可作删失候选）；
- `prior_status = 清仓/停售` → `delisted`（不算断货，需求也不拟合）；
- 如果同日其它仓有正库存 → 对当前渠道仓仍是不可售，但对全局 SKU 不是 0。

### 3.4 已落地的表

- `pengjian_inventory.sku_status_daily`（59,559 行）：逐日 × 仓 × SKU 的 `present_positive` / `present_zero` / `absent_after_presence`，带 `prior_status`、`sales_7d`、`sales_30d`。
- 2026-10-09 示例：美东 283 正 / 87 显式 0 / 153 消失（139 在售 + 14 清仓）；波兰 732 / 18 / 619；美中 573 / 29 / 123。

### 3.5 两个必须注意的坑

1. **美中 2026-09 仓库合并**：之前是皮壳/退货/成品/半成品 4 个仓，之后合并成一个 `美中-FZH-DANEEY`。因此 9 月后旧的 4 个子仓会全部显示“消失”，这是**改名/合并**，不是断货。分析美中时要按时期分开，或把 9 月前的成品仓映射到 `美中-FZH-DANEEY`。
2. **从未出现过的 SKU 不能当 0**：报表只覆盖一部分 SKU；一个从未在该仓出现的新 SKU，缺失不代表 0 库存。

## 4. 其他数据质量注意

- `Buttonkit-pl`（售后针线扣子）在 10/09 的可用库存是 **9,999,866**，是占位/虚拟数量；**不要对全表 `sum(available)` 做趋势或对账**，应按 SKU 过滤。
- 7/15/30/90 天销量是导出时点的滚动汇总，不是日销量；不能直接当日需求。
- 47 个销量分析报表的 SKU 销量/销售额/成本/利润是周期汇总，和订单历史重复；仅建议做交叉校验。
- 内层 xlsx 文件名有 GBK 乱码（外层 zip 名正常），不影响内容解析。

## 5. 结论与用法

**可用，但定位要准确：**

| 用途 | 是否可行 |
|---|---|
| 2026-04→10 的**有货库存检查点**（美东/波兰/美中各子仓） | ✅ 可用，约 22 个日期 |
| 看某 SKU 的库存水平/7-30-90 天销量趋势 | ✅ 可用（仅限报表中出现的 SKU） |
| 判断某 SKU **在某个仓断货**（可用=0） | ✅ 可用：显式 0 + **以前出现过、后来消失**；排除清仓/停售和“从未出现” |
| 判断某 SKU **全局断货** | ⚠️ 部分可用：消失的 SKU 里约 20% 仍在其它仓有货，要按仓/渠道看 |
| 日级库存/连续断货窗口 | ❌ 稀疏且不连续；只能给检查点 |
| 销售/成本/利润交叉校验 | ✅ 47 个销量分析报表可辅助 |

**建议：**

1. **不要求 PJ 重导**。现有 22 个日期按 §3.3 的规则用：显式 0、`absent_after_presence`（在售）、排除清仓/停售。
2. 如果以后有新导出，仍建议把 **`隐藏所有库存为0的货品` 改为 `否`**；这样零库存行会显式出现，少一层推断。
3. 现有文件保留作**仓级库存/断货检查点**，已入 `pengjian_inventory` schema；不要覆盖每日 `stock_history`。
4. 断货判定以 **EN 每日快照 + 本报表检查点 + PB `checked0stock`** 为主；美中 9 月合并前后要分开。
5. 需要时按仓过滤：美东 `美东-CENTRADE`；美中成品 `美中-FZH-DANEEY`；波兰 `波兰-FZHPoland-covers`；不要把皮壳/半成品/退货仓算进可售。
