# 赛狐成本核算口径调研

调研动机：做「按仓库+SKU 改激励成本」的工具时，需要知道改一笔成本到底影响哪些口径。

## 1. 两套口径并存，不要混用

| 口径 | 方法 | 在哪看 |
|---|---|---|
| **库存报表** | **移动加权平均** | 【仓库】>【库存明细】的 `采购单价(￥)` / `单位费用(￥)` / `单位库存成本(￥)` |
| **出库结转** | **先进先出（FIFO，按店铺站点维度）** | 【财务】>【利润报表】的商品成本；【财务】>【批次成本】按批次核对 |

证据：`SELLFOX_API/docs/api-reference/仓库/库存明细/查询库存明细.md:302` 字段说明原文
「采购单价,移动加权平均计算」；而利润报表 API 里是一系列 FIFO 字段
（`orderMCFIFO` / `buyerReturnFIFOFee` / `inventoryAdjFIFOFee` / `inventoryRemovalFIFOFee` …）。

> 库存报表显示加权平均，是 ERP 报表的通用做法，**不能**据此推断出库结转也是加权平均。

## 2. 官方帮助：批次成本（先进先出）

来源：<https://www.sellfox.com/help/features/batch-cost-fifo>

- **启用入口**：【设置】>【业务设置】>【先进先出】。开启后「批次成本影响【财务】>【利润报表】的商品成本」。
- **出库成本取值优先级**：
  **关联发货单的成本 > 导入库存成本（重置成本）> 商品模块固定成本**
- **成本来源字段**：`发货单（FH****）` / `重置成本` / `固定成本` / 空（未取到成本）。
- **页面划分**：【财务】>【批次成本】分「批次入库」「批次出库」。
  - 入库类型：初始化库存、月初库存、货件入库、退货入库、盘点入库、转移入库、差异入库、负库存调整。
  - 出库类型：货件出库、订单出库、盘点出库、库存移除、转移出库、差异出库。
  - 「负库存调整」月末自动生成，**只做记录，不参与先进先出计算**。
- **更新频率**：初始化后前 3 个月+本月，批次成本 1 天更新 1 次；
  成本来源为「发货单/重置成本」时实时更新，为「固定成本」时每天中午 12 点与晚上更新（本月+上月）。
- **未提及移动加权平均**——官方只描述了 FIFO 这一种计价；是否可选移动加权需向客服确认。
- 欧洲共享库存可能跨站扣减（如德国仓发货扣到英国店铺的货件成本）。

### 其他官方页

- 发货单（FBA 发货管理）：<https://www.sellfox.com/help/features/delivery-note>
- 功能总览（财务）：<https://m.sellfox.com/function.html?target=finance>

> 搜索里出现的「移动加权平均」设置路径（金蝶/用友/S1S3）来自**其他 ERP**，不能套用到赛狐。

## 3. 实测：「改头程 → 库存成本」到底传不传

测试对象：`test001-white` @ POLAND（测试品）。同仓同 SKU，逐笔叠加。

| 步骤 | 库存 采购单价 | 库存 单位费用 | 在库总费用 |
|---|---|---|---|
| 初始（无库存） | 0.0000 | – | 0.00 |
| 收货 `OWS294A9T700030`（采购 1.5 / 头程 0.20 ×1000） | 1.5000 | 0.2000 | 200.00 |
| 收货 `OWS294A9T700029`（采购 1.5 / 头程 4.08 ×1000） | 1.5000 | **2.1400** =(0.2+4.08)/2 | 4,280.00 |
| **改「已完成」单 029 的头程 4.08→1.00** | 1.5000 | **0.6000** =(0.2+1.00)/2 | 1,200.00 |

**结论：**

1. **「单个头程费用」→ 库存 `单位费用(￥)`；「指定采购单价」→ 库存 `采购单价(￥)`。**
2. **改已完成（已入库）单的头程，库存成本会按加权平均实时重算** —— 事后修正是可行的。
   收货前改同样有效（收货时按当时值计入）。
3. **「在途」口径不跟**：改**待收货**单的头程，库存明细的「在途总费用」保持不变
   （实测在途期间把 0.20 改成 4.08，在途总费用仍是 400）。在途是快照值。
4. 出库结转另走 FIFO（见 §2），与上面这条加权平均**互不影响**。

**踩坑教训**：第一次验证时挑了一张「库存已被调整单清零」的单去改头程，看到库存不动就错判成
「改完不回写」。实际是那批货已不在仓库、没有可重算的库存。
→ **验证成本传导必须选「当前确实有库存」的单。**
另：改备货单头程保存时会弹警告「将改动该批次商品的头程费用，若其他单据使用该批次商品也将同步修改」
—— 头程按**批次**生效。

## 4. 成本补录单实测：海外仓的限制

同一批测试（`test001-white` @ POLAND）走「成本补录单」的完整实测，三条硬规则均来自导入报错原文：

| # | 规则 | 原文/依据 |
|---|---|---|
| 1 | **按SKU导入不支持海外仓** | `成本补录单中创建类型为按sku时,不能为海外仓` |
| 2 | 海外仓走**按单据导入**，`单据类型` 选「海外仓备货单」，`单据号` 填备货单号 | 模板 `batch_import_adjustment_by_order.xlsx` 的 data validation：`发货单,采购单,其他入库单,调拨单,海外仓备货单,移除入库单,多平台发货单` |
| 3 | **发货单/海外仓备货单/多平台发货单 不许填 `单位费用`/`总费用`** | `发货单、海外仓备货单、多平台发货单填写单位费用、总费用无效，导入失败` |
| 4 | 补录单需**审核通过**才生效 | 状态 `待审核` → 详情页「审核通过」→ `已通过` |

**生效效果实测**（补录单 `CA26091800001`，关联 `OWS294A9T700029`，把 1000 件的采购单价 1.5→1.2）：

```
库存 采购单价(￥)   1.5000 → 1.3500     = (1000×1.5 + 1000×1.2)/2000
库存 单位费用(￥)   0.6000 → 0.6000     不受影响
在库总货值(￥)     3,000.00 → 2,700.00
```

→ **只重算受影响的批次份额，按加权平均合并。**

## 5. 对「按仓库+SKU 改成本」工具的结论

| 成本项 | 入库前 | 入库后（无需清零重入） |
|---|---|---|
| 采购成本 | 备货单 `指定采购单价` | **成本补录单 按单据导入**（类型=海外仓备货单，**需审核**） |
| 头程 | 备货单 `单个头程费用` | **改备货单 `单个头程费用`**（成本补录单不支持改它） |

两条路都会让库存明细的 `采购单价(￥)` / `单位费用(￥)` 按加权平均重算。
