# 赛狐成本核算口径调研

调研动机：做「按仓库+SKU 改激励成本」的工具时，需要知道改一笔成本到底影响哪些口径。

## 1. 两套口径并存，不要混用

| 口径 | 方法 | 在哪看 |
|---|---|---|
| **库存报表** | **移动加权平均** | 【仓库】>【库存明细】的 `采购单价(￥)` / `单位费用(￥)` / `单位库存成本(￥)` |
| **出库结转** | **先进先出（FIFO，按店铺站点维度）** | 【财务】>【利润报表】的商品成本；【财务】>【批次成本】按批次核对 |

证据：`SELLFOX_API/docs/api-reference/仓库/库存明细/查询库存明细.md:302` 字段说明原文
「采购单价,移动加权平均计算」；而利润报表 API 里是一系列 FIFO 字段
（`orderMCFIFO` / `buyerReturnFIFOFee` / `inventoryAdjFIFOFee` / `inventoryRemovalFIFOFee` …）。

> 库存报表显示加权平均，是 ERP 报表的通用做法，**不能**据此推断出库结转也是加权平均。

## 2. 官方帮助：批次成本（先进先出）

来源：<https://www.sellfox.com/help/features/batch-cost-fifo>

- **启用入口**：【设置】>【业务设置】>【先进先出】。开启后「批次成本影响【财务】>【利润报表】的商品成本」。
- **出库成本取值优先级**：
  **关联发货单的成本 > 导入库存成本（重置成本）> 商品模块固定成本**
- **成本来源字段**：`发货单（FH****）` / `重置成本` / `固定成本` / 空（未取到成本）。
- **页面划分**：【财务】>【批次成本】分「批次入库」「批次出库」。
  - 入库类型：初始化库存、月初库存、货件入库、退货入库、盘点入库、转移入库、差异入库、负库存调整。
  - 出库类型：货件出库、订单出库、盘点出库、库存移除、转移出库、差异出库。
  - 「负库存调整」月末自动生成，**只做记录，不参与先进先出计算**。
- **更新频率**：初始化后前 3 个月+本月，批次成本 1 天更新 1 次；
  成本来源为「发货单/重置成本」时实时更新，为「固定成本」时每天中午 12 点与晚上更新（本月+上月）。
- **未提及移动加权平均**——官方只描述了 FIFO 这一种计价；是否可选移动加权需向客服确认。
- 欧洲共享库存可能跨站扣减（如德国仓发货扣到英国店铺的货件成本）。

### 其他官方页

- 发货单（FBA 发货管理）：<https://www.sellfox.com/help/features/delivery-note>
- 功能总览（财务）：<https://m.sellfox.com/function.html?target=finance>

> 搜索里出现的「移动加权平均」设置路径（金蝶/用友/S1S3）来自**其他 ERP**，不能套用到赛狐。

## 3. 实测：「改头程 → 库存成本」到底传不传

测试对象：`test001-white` @ POLAND（测试品）。同仓同 SKU，逐笔叠加。

| 步骤 | 库存 采购单价 | 库存 单位费用 | 在库总费用 |
|---|---|---|---|
| 初始（无库存） | 0.0000 | – | 0.00 |
| 收货 `OWS294A9T700030`（采购 1.5 / 头程 0.20 ×1000） | 1.5000 | 0.2000 | 200.00 |
| 收货 `OWS294A9T700029`（采购 1.5 / 头程 4.08 ×1000） | 1.5000 | **2.1400** =(0.2+4.08)/2 | 4,280.00 |
| **改「已完成」单 029 的头程 4.08→1.00** | 1.5000 | **0.6000** =(0.2+1.00)/2 | 1,200.00 |

**结论：**

1. **「单个头程费用」→ 库存 `单位费用(￥)`；「指定采购单价」→ 库存 `采购单价(￥)`。**
2. **改已完成（已入库）单的头程，库存成本会按加权平均实时重算** —— 事后修正是可行的。
   收货前改同样有效（收货时按当时值计入）。
3. **「在途」口径不跟**：改**待收货**单的头程，库存明细的「在途总费用」保持不变
   （实测在途期间把 0.20 改成 4.08，在途总费用仍是 400）。在途是快照值。
4. 出库结转另走 FIFO（见 §2），与上面这条加权平均**互不影响**。

**踩坑教训**：第一次验证时挑了一张「库存已被调整单清零」的单去改头程，看到库存不动就错判成
「改完不回写」。实际是那批货已不在仓库、没有可重算的库存。
→ **验证成本传导必须选「当前确实有库存」的单。**
另：改备货单头程保存时会弹警告「将改动该批次商品的头程费用，若其他单据使用该批次商品也将同步修改」
—— 头程按**批次**生效。

## 4. 成本补录单实测：海外仓的限制

同一批测试（`test001-white` @ POLAND）走「成本补录单」的完整实测，三条硬规则均来自导入报错原文：

| # | 规则 | 原文/依据 |
|---|---|---|
| 1 | **按SKU导入不支持海外仓** | `成本补录单中创建类型为按sku时,不能为海外仓` |
| 2 | 海外仓走**按单据导入**，`单据类型` 选「海外仓备货单」，`单据号` 填备货单号 | 模板 `batch_import_adjustment_by_order.xlsx` 的 data validation：`发货单,采购单,其他入库单,调拨单,海外仓备货单,移除入库单,多平台发货单` |
| 3 | **发货单/海外仓备货单/多平台发货单 不许填 `单位费用`/`总费用`** | `发货单、海外仓备货单、多平台发货单填写单位费用、总费用无效，导入失败` |
| 4 | 补录单需**审核通过**才生效 | 状态 `待审核` → 详情页「审核通过」→ `已通过` |

**生效效果实测**（补录单 `CA26091800001`，关联 `OWS294A9T700029`，把 1000 件的采购单价 1.5→1.2）：

```
库存 采购单价(￥)   1.5000 → 1.3500     = (1000×1.5 + 1000×1.2)/2000
库存 单位费用(￥)   0.6000 → 0.6000     不受影响
在库总货值(￥)     3,000.00 → 2,700.00
```

→ **只重算受影响的批次份额，按加权平均合并。**

## 5. 库存调整单不涉及成本（实测）

用 `test001-white` 核实调整单 `AD2608140016`（`type=0 数量调整`，POLAND）：**三处都没有成本字段**。

| 来源 | 字段实况 |
|---|---|
| OpenAPI `POST /api/ware/adjust/create.json` | `type`(0数量调整/1换标调整)、`availableNum`、`defectiveNum`、货架位 —— 无成本 |
| 内部 `POST /api/gw/sellfox/sellfox-warehouse/sellfox/api/warehouse/adjust/pageList` 主表 | `adjustNo/type/adjustStatus/sum/remark/adjustmentReason/...` —— 无成本（`sum` 只是数量合计） |
| 同上 `itemList[]` | `available/defective/newAvailable/newDefective/targetAvailable/targetDefective` + 货架位 —— **成本字段 0 个** |

→ **赛狐的库存调整单是纯数量调整，不碰成本。**
调整单产生的批次的 `inventoryCost`/`transportCost` 来自其来源批次，**且会跟随来源备货单更新**：

> **实测**：把 `OWS294A9T700024` 的 `单个头程费用` 从 4.08 改成 7.77 后，
> 由它产生的调整单批次 `20260529002385` 的 `transportCost` 同步 `4.08 → 7.77`
> （`updateTime` 即改动时刻）。20 个 AD 批次里有且只有这 1 个被更新。

→ 所以**不存在「调整单批次钉住成本」的问题**：改备货单会连带覆盖它派生的调整单批次。

> 对比：ERPNext 的库存调账可同单同时改数量与成本；赛狐不是（调整单只管数量）。

## 6. 定位「该改哪些单据」：海外仓批次

改成本必须落到**具体单据**，但一个 (仓库,SKU) 常有几十上百张历史单。
`POST /api/overseaBatch/page.json`（页面 仓库 → 海外仓 → 海外仓批次）给出**批次级库存**：

- 筛 SKU 用 **`searchType=commoditySku` + `searchContent`**（传 `commoditySku` 参数不过滤）
- `goodsAva > 0` = 还在库；`oriNo` = 来源单号；`inventoryCost`/`transportCost` = 该批次采购成本/头程
- `type=5` 且 `oriNo=OWS…` → 海外仓备货单（可改头程）；`AD…` → 库存调整单
- 加权后可**反算**【库存明细】的 `采购单价(￥)`/`单位费用(￥)`

实测：

| SKU | 批次总数 | 有货批次 | 可用量 | 加权(采购/单位费用) | 来源 |
|---|---|---|---|---|---|
| test001-white @POLAND | 83 | 2 | 2000 | 1.375 / 0.6 | 全部备货单（029/030） |
| KS0248-DM-60-WHITE @DANEEY | 128 | 4 | 150 | 104.38 / 8.12 | 139 件备货单 007 + 11 件 3 张调整单 |

→ **库存常是混合来源**。但 `AD…`（调整单）批次的成本**会跟随其来源备货单更新**（见 §5 实测），
所以改备货单通常能连带覆盖它派生的调整单批次。需要用 `probe_batches.py` 先确认来源构成，
尤其是「非备货单派生」的调整单批次（如外部 API 写回数量产生的批次），
它们的成本不随备货单走，需单独确认来源。
工具：`cost_adjust/probe_batches.py`。

## 8. 出库/调整按 FIFO 吃批次（实测钉死）

2026-09-18 受控实验：`test001-white` @ POLAND 有两个在库批次各 1000，建调整单
`AD2609180004` 扣 **-3**：

| batchNo | 来源 | 入库时间 | 扣前 | 扣后 |
|---|---|---|---|---|
| `20260918000123` | OWS294A9T700030 | 12:18（**更老**） | 1000 | **997** ← 全从这扣 |
| `20260918000124` | OWS294A9T700029 | 12:25 | 1000 | 1000（没动） |

调整单自己的批次行 `batchNo=20260918000123, goods=3`，成本 `1.5/0.2` 原样继承。
库存反推只有 FIFO 对得上：

```
采购单价 = (997×1.5 + 1000×1.25) / 1997 = 1.3748   ← 实际 1.3748 ✓
单位费用 = (997×0.2 + 1000×1.0)  / 1997 = 0.6006   ← 实际 0.6006 ✓
```

→ **所有出库（含调整单）先扣光最老的批次，不够再扣次老的。**
「10 张备货单各 1 件、调整单 -3」会扣**最老的 3 个批次各 1 件**。

**对成本工具的直接影响**：出库先吃老批次 = 先把老批次那份成本从加权平均里拿走。
排激励价时必须把「老批次会被先扣走」算进去，否则改完新批次成本，一次出库就把均价带偏。

## 9. 对「按仓库+SKU 改成本」工具的结论

| 成本项 | 入库前 | 入库后（无需清零重入） |
|---|---|---|
| 采购成本 | 备货单 `指定采购单价` | **成本补录单 按单据导入**（类型=海外仓备货单，**需审核**） |
| 头程 | 备货单 `单个头程费用` | **改备货单 `单个头程费用`**（成本补录单不支持改它） |
| 数量 | — | 库存调整单（**只改数量，不涉及成本**） |

两条链路都会让库存明细的 `采购单价(￥)` / `单位费用(￥)` 按加权平均重算。
**调整单不需要纳入改成本的工具**；但用 `probe_batches.py` 看来源构成时要区分它。
