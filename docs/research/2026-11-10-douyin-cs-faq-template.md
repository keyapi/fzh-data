# 抖店飞鸽客服话术表（模板）

> 2026-11-10。配套阅读：[生态调研 §4](2026-11-10-douyin-live-commerce-ecosystem.md)（客服三条路线与官方机器人边界）。
> **用途**：今天就能填进抖店后台「智能机器人」；将来换 ISV 或自研飞鸽插件时，这张表原样复用，不用重做。

---

## 一、三条硬纪律（先看，再填）

1. **不承诺做不到的事** —— 不写"保证 48 小时到"、不写"绝对不掉色"。平台考核按**真实揽收**，承诺越满，投诉越多。
2. **不做站外导流** —— 不出现微信号、手机号、二维码、"加我""私聊下单"。抖音对站外导流处罚很重。
3. **不用绝对化用语** —— "最好""第一""100%""国家级"违反《广告法》，AI 自动回复同样受约束。

> 另：**不要让机器人碰个人信息**。买家报手机号/地址时，回复统一为"请您在订单里填写，客服这边不需要您的地址哦"。

---

## 二、字段定义（9 列，缺一列以后迁移都会痛）

| 字段 | 说明 | 示例 |
|---|---|---|
| `id` | 唯一编号，不要复用 | `A-01` |
| `category` | 分类，便于统计命中率 | 发货物流 |
| `triggers` | 触发词，用 `|` 分隔（越具体越好） | 什么时候发\|几天到\|发货时间 |
| `answer` | 标准回复，口语化，不超过 80 字 | 亲，现货订单 48 小时内发出… |
| `auto` | 是否允许机器人直接答 | `Y` / `N` |
| `handoff` | 转人工条件（命中即转） | 买家追问具体到货日 |
| `scope` | 适用商品/类目，`*` 表示全部 | `*` / 靠枕类 |
| `owner` | 谁负责维护 | 客服主管 |
| `updated` | 最后修改日期 | 2026-11-10 |

## 四、转人工规则（建议直接照此配置）

| 触发条件 | 处理 |
|---|---|
| 命中 `handoff` 非空 | 立即转人工，机器人不再追问 |
| 出现"退款/投诉/起诉/曝光/12315" | 最高优先级转人工 |
| 买家连续 2 次表达不满（负面情绪词） | 转人工 |
| 涉及定制、改址、加急 | 转人工 |
| 机器人连续 2 次答非所问（买家重复问） | 转人工 |
| 非营业时间 | 机器人先接，留言 + 次日优先回 |

## 五、维护流程（不做这步，三个月后表就废了）

1. **每周**：导出飞鸽会话，统计「机器人回答后买家仍转人工」的 top 10 问题 → 补话术或改判定。
2. **每两周**：把新出现的高频问题加进表，`owner` 与 `updated` 必须填。
3. **每月**：复核 `auto=Y` 的条目，凡是近 30 天引发过投诉或退款的，降级为 `N`。
4. **每次平台规则变更**（发货时效、售后政策）：同步改 A、E 两类。

## 六、三处复用（这张表的真正价值）

| 阶段 | 怎么用 |
|---|---|
| 现在（官方机器人） | 按 `triggers` + `answer` 逐条录入，`auto=N` 的设为"不自动回复" |
| 换 ISV | 让 ISV 导入这张表，要求他们**不改 answer 文案**，只做意图匹配 |
| 将来自研 | 直接做 `FAQ` 表 + 向量检索，`handoff` 字段就是"低置信度转人工"的开关 |

> 每一行都是**结构化数据**，不是一段自然语言——这就是为什么现在填它，将来能直接复用。
