# 麻将沙发「1 个 SKU = 3 个垫子」跨系统现状盘点

## 1. 背景

麻将沙发实际是 **3 个垫子拼成 1 个沙发**，运营按「1 个沙发」卖，EN 下 SO 和生产也按这个方式。现在要把其中 **1 个垫子单独销售/下单**。

此前最大的误解是：物料名里的 `70x70x25cm` 看起来像单个垫子的尺寸，容易被当成「这个 SKU = 1 个垫子」。**实测证明不是**——EN 全链路都按「1 个 SKU = 1 套 3 垫」定义，只是名称没写清楚。本文把 EN / 通途 / 赛狐三套系统的现状逐项记录，再判断套件有没有问题、该改还是该新建。

## 2. 取证方法（可复现）

| 系统 | 入口 | 关键过滤条件 |
|---|---|---|
| EN 生产 | `https://erpnext.vilavi.cn` REST，凭证读 `EN_API/.env` 的 `ERP_API_KEY/SECRET` | `Item Group.item_group_name like %麻将沙发%`；`Item.item_group like %麻将沙发%`；`BOM.item in [...]`（每批 ≤30 个，URL 过长会 400）；BOM 子表不能直接 list，须逐份 `GET /api/resource/BOM/<name>` |
| 通途 ERP2 | 生产机 `~/frappe-bench` 上的 `tongtool_integration.api.client.TongToolClient`（直连 `open.tongtool.com/api-service`，自签 MD5） | `POST /openapi/tongtool/goodsQuery`，必填 `productType`；`skus` 每批 ≤10；**`productName` 参数不生效**，只能按 `categoryCode` 或 SKU 取 |
| 赛狐 | `SELLFOX_API/client.py` 代理模式（`SELLFOX_PROXY_API_KEY`） | `POST /api/commodity/pageList.json`；`skus` 精确查、**名称类参数全部不生效**，只能全量翻页（3,518 个 SKU，36 页）后本地筛 |

> 通途 MCP（`mcp.tongtool.com`）在本机实测 **HTTP 403**，且 MCP 403/524 不代表 App 未授权；本次全部走直连 API。通途限流「每商户 5 次/分钟」被所有 App/作业共享，查询必须分批缓存。

### 3.1 「1 个 SKU = 3 个垫子」的四条硬证据

| 证据 | 实测值 | 折算单垫 |
|---|---|---|
| 皮壳默认 BOM（41/41 个变体完全一致） | 隐形拉链 **3** 条、扣胚 **60** 个、面料 **4.8m**、喷胶棉 **4.8m** | 1 拉链 / 20 扣胚 / 1.6m |
| 绍兴包装成品 BOM | 内包装纸箱 **×3**、真空袋 **×3**、外包装纸箱 **×1**、PP棉 8.4 | 一箱 3 件 |
| 重量模板 `ZLMB#KS0443-DM-70x70x25` | 成品 **13.5kg**、皮壳 **2.7kg**、外箱 60×32×46cm | 4.5kg / 0.9kg |
| 绍兴工厂 GCK 确认 | 该皮壳 BOM 实际对应 3 个垫子 | — |

成品 BOM = 1× 对应皮壳（无内胆行）；皮壳 BOM = 面料 + 拉链 + 喷胶棉 + 扣胚 + 8 道工序。

### 3.3 EN 的「N 件」表达：152 个套件

5 个产品组下没有任何「套件」物料组；套件都挂在通用组 `套件#`（`所有物料组/套件#`）。名称含麻将的套件 SKU 共 **152 个**，单位「套」、`is_stock_item=0`、无 BOM，`Product Bundle` 组件 = **N × 成品 SKU**。

| 型号 | 颜色数 | x2 / x3 / x4 / x5 | 小计 |
|---|---|---|---|
| KS0454 BOHO | 17 | 17 / 17 / 17 / 17 | 68 |
| KS0319 衍生款 | 13 | 13 / 13 / 13 / 13 | 52 |
| KS0385 优化款 | 6（1 色缺） | 5 / 5 / 5 / 5 | 20 |
| KS0443 纯色版 | 3 | 3 / 3 / 3 / 3 | 12 |
| KS0531 纹理款 | 2 | 0 / 0 / 0 / 0 | 0 |

**因成品本身已是一套 3 垫，`TJ#…x3` = 3 套 = 9 个垫子。** 例：`TJ#KS0443x3-001` 的组件是 `KS0443-DM-70x70x25-GRASSGREEN` × 3。

## 4. 通途现状：41 个普通商品，无任何组合表达

按类目 `自产-客厅产品-沙发`（`categoryCode=6464013595202411070000803172`）全量拉取：类目内 **437 个商品**，其中名称含「麻将沙发」**41 个**。

- 类型：**全部 `productType=0` 普通商品，0 个捆绑/组合**
- 类目内确实有 12 个捆绑商品（产品类型 2），但**没有一个包含麻将沙发 SKU**（如「松饼大沙发-放大版」「可组合扶手沙发」「沙发支撑垫 2个」）
- 名称写「3个」的 24 个（优化款 6、纹理款 2、衍生款 16）；**BOHO 风格 17 个全部没写「3个」**
- 与 EN 的绑定：EN 40 个成品变体登记了通途码（`customer_items.ref_code`），通途侧对应 40 个；另有 `TT0312710K0064602-Offwhite`（优化款米白条纹）**未绑定到 EN**
- **命名错位**：EN 的「纯色版」3 个 SKU（`TT0312584/85/86`）在通途叫「**麻将沙发衍生款**」
- **重量/尺寸口径混乱**（41 个商品）：
  - 重量：12000g ×26、10650g ×5、11000g ×1、**3000g ×3、2000g ×6**（一套 3 垫不可能 2–3kg，疑似只填了单垫或漏填）
  - 包装：76×67×20cm ×36、62×40×55cm ×2（纹理款）、**0×0×0 ×3**、**全空 ×1**
  - 与 EN 重量模板（13.5kg / 60×32×46）**不一致**

## 5. 赛狐现状：38 个底层 SKU + 152 个组合商品

全量翻页 3,518 个 SKU，名称含「麻将」**190 个** = 底层 38 + 组合 152。

- **底层 38 个**（`isGroup=0`）：KS0454 17、KS0319 13、KS0385 5、KS0443 3；**缺 KS0531 的 2 个、KS0385-OFFWHITESTRIPE 1 个**（与 EN「无 BOM 的 3 个变体」完全对应）
- 底层名称：`麻将沙发BOHO风格-丽丝绒印花-70x70x25cm-土耳其游牧文化` —— **全部 38 个都没写「3个」/「3件」**
- 分类：`家具类/坐垫`；`state=1`
- **重尺全 0**：38 个底层 SKU 的 `weight = 0`、`length/width/height = 0`；152 个组合同样全 0
- **组合 152 个**（`isGroup=1`）：机型×档位与 EN 完全一致（17/13/5/3 × x2–x5），名称形如
  `套件#麻将沙发BOHO风格-丽丝绒印花-70x70x25cm-土耳其游牧文化x3件-017`，`childSkus = [{sku: KS0454-…, num: "3"}]`
  → **赛狐把它定义为「3 个底层 SKU」，即 9 个垫子**
- **成本与 EN 不一致**（底层 `purchaseCost`）：
  | 型号 | 赛狐 | EN |
  |---|---|---|
  | KS0454 | 138.178 | 137.88 |
  | KS0385 | 140.219 | 139.92 |
  | KS0443 | 137.819 / 152.219（仅 2 个值） | 139.92 / 151.92 / 156.72（3 个值） |
  | KS0319 | 138.178 / 213.875 / 223.475 / 226.275 / 228.275 | 137.16–153.96（最高仅 153.96） |

## 6. 三系统对照

| 维度 | EN | 通途 | 赛狐 |
|---|---|---|---|
| 单件数 | 41 个成品变体 | 41 个普通商品 | 38 个底层 SKU |
| 每个 SKU 实际内容 | **1 套 3 垫** | **1 套 3 垫** | **1 套 3 垫** |
| 名称是否写明「3 个」 | 否（只有 70x70x25cm） | 24/41 写、17 个 BOHO 不写 | 否 |
| N 件组合表达 | 152 个 `TJ#…xN` 套件 | **无** | 152 个组合（`num=N`） |
| 组合语义 | N 套 = 3N 垫 | — | N 套 = 3N 垫 |
| 重量口径 | 13.5kg / 外箱 60×32×46 | 12kg/10.65kg 为主，**10 个异常 2–3kg**；76×67×20 | **全 0** |
| 成本 | 137–157 | 有 `productGuideCost`（未逐项核） | 多为近似，KS0319 部分高 60–75 |
| 覆盖一致 | 基准 | 40/41 绑定，1 个未绑 | 38/41，缺 3 个 |

**结论：三系统在「1 个 SKU = 3 个垫子」这一点上是一致的**（通途名称、EN BOM/包装/重量、赛狐组合粒度）。不一致的是**表达方式**：EN 和赛狐都额外建了 152 个「N 件」组合，而通途完全没建。

## 7. 套件到底有没有问题

**有问题，而且是语义重复。**

- 既然底层 SKU 已经是「3 垫/套」，`TJ#…x3` / 赛狐「x3件」表达的是 **3 套 = 9 垫**。
- 如果当初建套件的本意是「3 个垫子 = 1 个沙发」，那么 152 个套件的语义整体错位 3 倍——按它下单会发出 3 倍货。
- 反过来，如果本意是「买 2/3/4/5 套沙发」，那套件本身没问题，但**它们跟「单件垫子」这个需求完全无关**，且通途没有对应组合，三系统对不上。

判定需要一条事实：这 152 个套件是否已有实际订单/配单。目前 EN 这些成品几乎没有库存流水（KS0454/0443/0531/0319 的 Stock Ledger 行数为 0 或 1），说明它们基本没在 EN 实际出货；赛狐/通途侧是否在售需再按渠道确认。

## 8. 单件销售的三条路径

单件销售在 EN 需要补齐的东西是确定的：单垫皮壳 BOM（1 拉链 / 1.6m 面料 / 20 扣胚）+ 单件包装 BOM（1 内箱 + 1 真空袋 + PP棉÷3）+ 单垫重量模板。差别只在挂在哪里。

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A 增量**（建议先做） | 新增「单垫」物料族（新 KS 编号，或同款加 `-1PC` 变体），完整走属性→模板→变体→皮壳→包装→重量模板→BOM，再登记通途/赛狐 | 中；存量完全不动，可先拿 KS0443 单型号灰度 | 只有少量 SKU 需要单卖 |
| **B 重构** | 底层改成「单垫为原子 SKU」，3 垫一律用套件表达（现有 `TJ#x3` 语义随之变正确） | 高；要重建 41 个变体的皮壳/包装/成本 BOM、重算 152 个套件、历史单据与库存口径断档 | 单件销售是长期常态 |
| **C 不改 EN** | 只在赛狐/通途侧做单品链接 | 低；但 EN 无法按单垫下 SO/工单，绍兴工厂拿不到单件生产指令 | 仅渠道试销 |

**建议**：先做 A（KS0443 灰度）+ 立即澄清并处置 152 个套件（P1，影响在售/发货数量）；B 作为中期评估项，最终口径由项目主拍板。

## 9. 问题清单

| 编号 | 问题 | 影响 | 优先级 |
|---|---|---|---|
| P1 | 152 个 `TJ#xN`（EN）与 152 个「xN件」组合（赛狐）语义 = N 套 = 3N 垫 | 若按「1 沙发」理解，发货量错 3 倍 | 高 |
| P2 | 三系统都没在物料名/属性里写明「1 套 3 垫」；通途只有 24/41 写了「3个」 | 新建物料、选品、配对都可能再犯同样的错 | 高 |
| P3 | 通途完全没有对应组合，与 EN/赛狐 152 个套件对不上 | 三方对账缺一条腿 | 中 |
| P4 | 单件销售能力缺失（无单垫物料/BOM/包装/重量） | 当前无法按单垫下单生产 | 中 |
| P5 | 重量/尺寸口径三处不一致：EN 13.5kg/60×32×46、通途 12kg/76×67×20 且有 10 个异常、赛狐全 0 | 运费与账期成本失真 | 中 |
| P6 | 赛狐成本与 EN 不一致（KS0319 部分高 60–75 元；KS0443 少一个值） | 毛利与成本核算偏差 | 中 |
| P7 | 配套缺漏：内胆 5 款里 4 款只有模板无变体；绍兴包装半成品# 缺 2 款；KS0531 挂错分类分支；3 个变体无 BOM | 后续补齐或重算时会漏 | 低 |
| P8 | EN 客户物料号重复登记（多数 SKU 同一 `ref_code` 登记两次） | 匹配时可产生重复行 | 低 |

## 10. 未完成 / 限制

- **通途 `goodsQuery` 不支持名称检索**（`productName` 参数被忽略），本次只用「沙发类目全量 + EN 绑定的 40 个 SKU」覆盖；若有麻将沙发商品挂在其他类目，需要通途网页导出补全。
- 通途**按 SKU 查询时只有 `productType=0` 能命中**（`1/2/3` 合法但返回 0 行，2026-09-15 实测）；因此「通途没有麻将组合」的依据是**类目全量**（含 12 个 `productType=2` 捆绑，均不含麻将 SKU），而不是 SKU 查询结果。
- 152 个套件是否已有真实订单/配单未核实（EN 无库存流水；赛狐/通途订单侧未查）。
- EN `BOM Cost List V2` 报表口径未逐行复核，本文成本取自 BOM `total_cost`。
- 赛狐 `purchaseCost` 的取数时点未知（可能是历史批次成本）。
