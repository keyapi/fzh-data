# G1 三角靠枕匹配过程（按公司架构）

> **更正**：G1a v1 用“品类/产品名含三角”做主筛选，口径不对；`EN Tongtool Cost Review` 只借代码逻辑，不用其数据。
> 本文件按 `docs/company-context.md` / `CONCEPTS.md` 的公司架构重写。

## 0. 公司架构（先对齐）

`docs/company-context.md:14-29`：

```text
绍兴工厂
 ├─ 生产皮壳、内胆、半成品
 ├─ 部分成品直接生产 → FBA / 直接发货
 └─ → 海外分公司仓库：
      ├── USNJ (美东, NJ) → CENTRADE：填充/压缩/包装/仓储/发货(2C+2B)
      ├── USTX (美中, TX) → DANEEY：同上
      └── POLAND (波兰)   → 同上
```

- 三角靠枕类：绍兴只发**皮壳**给分公司；分公司填充 PP 棉、压缩、包装，最终卖给顾客的**多数是成品**。
- 个别订单只卖皮壳 → 发皮壳；这是例外，不是主需求。
- 因此：**终端成品销售 1:1 消耗皮壳**；补货需求应由分公司销售驱动，皮壳仓是库存/缓冲节点，不是需求本身。

## 1. 匹配步骤（可复核）

1. 从 `EN产品BOM成本列表20261016.xlsx` 取 `产品编号` 前缀 `KS0001`/`KS0248` 的行：**1,739 行**。
2. 取 `客户物料号` 建精确索引；**不用品类文本做纳入**。
3. 每月 `订单_order_cost` 的 `通途SKU` 精确匹配客户码。
4. 按公司架构解释结果：
   - base 码订单 = 分公司成品销售（多数），1:1 对应皮壳需求；
   - `-Cover` 码订单 = 只卖皮壳的例外，也计入皮壳需求；
   - `绍兴发货方式=皮壳` 说明绍兴发的是皮壳，不代表订单行卖的是皮壳。
5. 皮壳仓（如 `FZH-DANEEY-皮壳仓库`）是分公司仓，不是“皮壳产品”；其销售行产品名也是「三角有扣…靠枕」。

## 5. 需要确认的剩余问题（只问业务，不问常识）

1. **WayfairCG / 其他 3PL 的销售是否计入分公司补货需求？**
   - 建议：作为单独渠道计入总需求，但分公司补货只按对应仓的库存/在途净算。
2. **分公司皮壳库存用哪些仓的当前快照？**
   - USNJ/CENTRADE、USTX/DANEEY（含 `FZH-DANEEY-皮壳仓库`）、PL（`FZHPoland-covers`）；
     这些是分公司仓，不是“皮壳产品仓”。
3. **`-out` / `-Foam` 排除**：建议排除；本次订单 0 命中。

## 6. 下一步（确认后）

- 以 33,719 件/6 个月为**皮壳需求基线**（成品 1:1 + 皮壳例外）；
- 用分公司皮壳**当前库存 + 在途**净算补货；
- 再进入 G1b：EN 生产只读 API（SO/PP/WO/JC/SE/DN）+ 数量守恒；
- 拆包裹对原始订单销量的影响另记，不混入本步骤。
