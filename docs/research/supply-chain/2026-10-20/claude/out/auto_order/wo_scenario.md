# WO 无完工日敏感性

> **这是情景，不是结论。** 假设“无完工日的 open WO 在某个窗口内可到货”后重算净需求，
> 仅用于看数量级；假设未证时**不可执行**、不改 V0.2 建议表。

## 1. 输入与口径

- 对象：V0.2 外部视图 **81 条 target×仓建议行**（其中 55 行库存未取得、净需求 null，不参与合计）。
- 当前建议（V0.2，不假设）：L15/L30/L60 均为 **5,492.0**（外部 open 行交期均已落在 15 天内）。
- 无日期 open WO（来自只读 WO 查询，按 item 匹配、无 warehouse 维度）：
  - 外部目标物料共 **797 张 open WO**，**全部无 `planned_end_date`**；
  - 落在有建议量的行上：**23 行**、**3,803 件**（T35 同一口径）；
  - 其余行无建议量或库存未取得，不参与减法。

## 2. 三档情景（只改“无日期 WO 何时可用”）

| 情景 | L30 建议合计 | L60 建议合计 | 说明 |
|---|---:|---:|---|
| **不假设**（当前 V0.2） | **5,492.0** | **5,492.0** | 无日期 WO 不计入供给 |
| **假设 L30 内可到货** | **3,294.0** | **3,294.0** | 23 行共减 2,198；L30/L60 同时受益 |
| **假设仅 L60 内可到货** | **5,492.0** | **3,294.0** | L30 内不可用，故 L30 建议不变；L60 减 2,198 |

- 三档针对 **L30 建议量**：5,492 → 3,294 → 5,492（L60-only 不降 L30）。
- 三档针对 **L60 建议量**：5,492 → 3,294 → 3,294。
- 减少额 2,198 = 23 行上无日期 WO 的 3,803 件与各行建议量的截断后合计
  （逐行 `max(0, suggest_H − undated_WO)`，不是简单相减）。

## 3. 假设与限制

1. WO 无 warehouse 字段；同一 WO 在多个仓行上可能被重复使用（本轮按行扣减，可能高估
   供给、低估建议量）。若要执行，必须先取得 WO 的目标仓。
2. “L30/L60 内可到货”**未证**；797 张 WO 全部无完工日，无法判断是否落入窗口。
3. 55 行库存未取得（net null）不参与；即使 WO 可到货，这些行仍无法给出建议量。
4. 本表不改 V0.2 的 `external_view.csv` 或 V0.1 任何数字；V0.2 建议仍为 5,492/5,492/5,492。

## 4. 复现

```bash
# 读取 existing artifacts；WO 张数为一次只读查询（prod REST）
uv run python scripts/check_secrets.py
```

- 数据：`external_view.csv`（建议量、库存）、`overdue_backlog.csv`（`wo_any/wo_dated`）、
  只读 WO 列表（张数/日期缺失）。
- 计算：逐行 `suggest_H' = max(0, suggest_H − (wo_any − wo_dated))`，再按非空行求和。
