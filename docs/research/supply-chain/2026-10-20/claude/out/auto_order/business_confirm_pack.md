# 自动下单确认包（一页）

## 1. 一句话结论

**外部需求已经能算出“条件建议”（22 单 / 81 行 / L15·L30·L60 各 5,492），但还不能下单**：
3 个数据缺口会直接造成漏下或重复下单，必须先由业务/生产/主数据确认。

## 2. 现在就能看到的（带数字）

| 项 | 数字 |
|---|---|
| 外部需求（`is_internal_customer=false`） | **22 单 / 81 条 target×仓建议 / 建议量 L15·L30·L60 = 5,492 / 5,492 / 5,492** |
| 外部建议分类 | **A 2 / B 78 / C 1** |
| 外部逾期 | **71 / 81 行**已逾期；其中 **>90 天 48 行** |
| 内部需求 | **75 单已隔离**（原账保留，不生成替代单、不从外部扣减） |
| 出库单据（外部 22 单） | **13 单有已提交 DN**；**8 单无任何 DP/DN**；**1 单仅 DP** |
| 已提交 DN 的对照 | 13 单 `per_delivered` 全部 <100（4 单 ≥99、9 单 <99）；164 行中 54 行仍显示未履约 |

> “无 DN”不等于真缺货（可能线下发货）；“有 DN”也不等于 `per_delivered` 已回写。

## 3. 三个缺口与影响

1. **在产 WO 无完工日**
   - 23 条建议行 / L30 建议 4,283，与既有 **3,803 件**无日期 WO 并存。
   - 情景测算：若假设这些 WO 在 L30 内可到货，L30 建议量 **5,492 → 3,294**；
     若只假设 L60 内可到货，L30 仍为 5,492、L60 降至 3,294。
   - **这是情景，不是结论；日期未证时不可执行。**

2. **目标仓 Bin 缺记录**
   - 外部 **55 条建议行 / 51 个目标物料**在该仓无 Bin 记录（V0.1 全量 252 行 / 211 物料）。
   - 处理：库存记“未取得”，净需求留空，**没有按 0 计算**。

3. **需求去重键缺失 / 疑似重复**
   - `po_no` 缺失：V0.1 全量 **25 个 SO**；外部 **11 条建议行 / 11 个目标物料**。
   - 疑似重复需求：V0.1 全量 **16 条建议行**；外部 **0 条**。
   - 处理：重复疑点保留不删，标“待人工确认是否重复补货”。

## 5. 我们不会做什么

- **不在 EN 写任何单据**（SO/DN/PO/WO 一律不动）；
- **不自动提交**任何建议；
- **不把条件量当采购批准**，也不把“五口径一致”当正确；
- 不删除任何内部 SO 或重复疑点，不从外部需求里扣减内部单。
