# 证据索取包

> 这是**证据索取清单**，不是审批、不是下单、不是排产请求。所有条目只用于把
> `replenishment_v2.csv` 里的“待核实”变成可核对的事实；收到前，相关行保持待核实。
> 口径：WAPE 是加权绝对百分比误差，不是“错 SKU 比例”或“准确率”，也没有通用阈值。

## 1. 按责任方分表

| 责任方 | 要什么字段 | 格式 | 用途 | 影响哪些行 | 缺失时的当前处理 |
|---|---|---|---|---|---|
| **采购/供应链** | 每条未结 PO 的 `ponum / goods_sku / warehouse / open_qty / will_arrive_date`，以及 PO↔在途的逐笔关单键 | Excel/CSV，一行一条 PO 行 | 判定到货是否在窗口内、在途是否与 PO 重复 | **169 行 / 161 SKU**（有未结 PO 的行） | ETA 全表缺失（248 条 open 行 0 条有日期）→ 按“窗口内到货”作假设，标 `unproven` |
| **生产/PMC** | 每张开放 WO 的 `name / production_item / remaining_qty / planned_end_date / status`；Stopped/Draft WO 是否释放；PK# 皮壳→KS 成品的 1:1 依据 | Excel/CSV，一行一张 WO | 计算在产供给与完工时点；确认单位换算 | **2,218 行 / 1,237 SKU**（全部合格行） | 在产不在快照 → 按 0 计入并标 `work_order_not_in_snapshot`；不得表述为“真实无在产” |

| **采购/财务** | 每个物料的 MOQ、包装倍数、单件成本（含币种与生效日期） | 一个物料一行 | 把条件区间转成可执行的采购约束 | **2,218 行 / 1,237 SKU**（全部合格行） | 三列均为 null，标「采购约束待定」，**不进建议量** |

| **数据/系统** | PO↔在途↔在产的逐笔重叠键；SO/WO 快照与库存快照的时点对齐说明 | 键值表 + 时点说明 | 消除重复计数；桥接 1–2 天时点差 | **267 行 / 259 SKU**（去重状态非 `none_recorded` 的行） | 只发 `B_min/B_max` 边界，去重状态标 `unproven` |

合计覆盖：**2,309 行 / 1,328 SKU**（2,218 合格 SKU×仓 + 91 范围外）。

## 2. 使用方式

1. 各责任方按上表交付；**不需要**提供原始订单明细，只要表头对应的字段。
2. 数据到齐后，由数据分析 worker 用同一脚本重跑 `replenishment_v2.csv`，并记录：
   哪些行的状态由 B/待核实变为可判定、哪些仍未变、原因是什么。
3. 任何一条证据只影响上述“影响行数”范围内的行；不得据此扩大范围或直接下单。

## 3. 明确不是

- 不是审批请求：本清单不请求任何人批准数量或预算。
- 不是下单/排产请求：没有数量被提交为订单或工单。
- 不是对现有结论的确认：收到证据前，主表所有数量仍是条件区间。
