## 2. G1：脱敏快照本地回放

**目标**：用一份脱敏真实快照，在本地验证 08 的契约能否端到端闭合；不接生产写、不先搭 BI/计划平台。

### 2.1 输入（最小）— G1 候选范围（待业务确认）

| 项 | 候选取值 | 说明 |
|---|---|---|
| 品类 | **三角靠枕 family** | EN 叶子物料组 **KS0001 三角靠枕** + **KS0248 三角靠枕无扣**；两者差异很小，规划层按 family 聚合，事实层保留 leaf group 与 SKU |
| 通途品类 | GSheet 品类为「**自产-三角靠枕-<面料>**」 | 只作候选线索；不能拿中文名直接当键；以 SKU/客户码精确匹配为准 |
| 仓 | **美中-FZH-DANEEY 或 美东-CENTRADE** | 2026-09「三角」品类发货：CENTRADE 1,631 件、DANEEY 1,586 件；**Daneey 只是候选之一，不是已确认范围** |
| 窗口 | **2026-07..09（最新 3 个可用月）或 2026-04..06** | 2026-04..09 月表均存在且日期覆盖整月；**2026-10 缺失，但 2026-08/09 不缺失**。由业务确认，不称「最近 3 个完整月」 |
| 粒度 | SKU × 仓 × 月（规划层 family × 仓 × 月） | 订单/包裹行保留行级血缘 |

2026-09「三角」品类仓库分布（发货件）：美东-CENTRADE 1,631；美中-FZH-DANEEY 1,586；
波兰-FZHPoland-covers 554；WayfairCG-Cranbury 137；美中-FZH-DANEEY-退货产品仓 55。

**三角靠枕映射规则**：

- `KS0001` 与 `KS0248` 是同一 family 的两个 leaf group；**不能把两者当同一 SKU**，也不能在 family 聚合时重复计数。
- **从 EN leaf group/KS item_code 出发**映射到变体、客户物料号、通途 SKU；GSheet 品类「自产-三角靠枕-*」只作候选线索。
  2026-09 的 SKU 前缀包含 `C/Linen`、`C/Velvet`、`C/Cord`、`CEN…` 等多种，**不能把「三角」直接等同 KS0001+KS0248**。
- 先按完整 EN `item_code` / 通途 SKU / 客户物料号精确匹配；`-Cover/-Foam` 等后缀只生成候选，不直接合并。
- 一个通途订单行只归一个 leaf group；若同时命中 KS0001/KS0248，标 `ambiguous` 进异常，不取 max/平均。
- family 级只用于预测/补货汇总；成本、BOM、库存仍按 leaf group/SKU。

### 2.2 脱敏快照来源（需业务确认）

| 选项 | 谁提供 | 优点 | 前提/限制 |
|---|---|---|---|
| A. 业务导出 | 计划/仓库/财务导出脱敏文件 | 不碰生产；责任清晰 | 需定义字段、cutoff、脱敏规则 |
| B. 授权只读拉取 | 技术用现有客户端拉取 | 可复现、字段全 | 需书面授权范围；不写；EN 生产只读需单独批准 |
| C. 本地已有导出 | 复用已有文件 | 零接入 | 三角靠枕可能没有现成导出 |

**默认建议**：优先 A；若选 B，先列字段与 cutoff，明确不写、不导出客户信息，EN 生产只读另行批准。
**没有实际输入时，只报告合成测试结果，不声称真实回放。**

### 2.3 输入清单（最小）

- 三角靠枕 family × 1–2 个仓 × 3 个月（候选窗口待确认）：
  - 通途库存快照（含快照时间）；
  - 通途订单/包裹行（品类「三角」只作候选线索）；
  - EN SO/PP/WO/Job Card/已提交 SE/已提交 DN；
  - 采购单/在途；
  - 头程批次/事件（如能取到；没有则标 `unknown`，不阻塞）；
  - SKU/仓/渠道映射与未匹配清单（区分 KS0001 / KS0248）。

### 2.4 步骤

1. 只读抽取 → Parquet/CSV 脱敏快照（保留 source_row_id/revision/observed_at）。
2. 建本地 DuckDB/Parquet 查询层；按 08 的实体/键落表。
3. 按 08 §2 跑守恒：
   - 需求冲减（含桶内已发订单）；
   - 生产四量（首道/末道/已提交 SE/已提交 DN）；
   - 同 cutoff 互斥供应余额；
   - 收货 gross/accepted/available；
   - 采购与头程在途经 crosswalk 的单一余额。
4. 每个输入行必须有处置结果：`used / blocked / unmatched / conflict / unknown`；
   不得静默丢弃。
5. 输出回放报告与异常清单（脱敏、聚合；不提交原始明细）。

### 2.5 验收门槛（G1）

- [ ] 每个输入行有处置结果；未匹配/冲突单列，数量可追溯。
- [ ] 需求冲减：桶内已发订单继续冲减预测，交付不使需求复活；内部补货 SO 不重复。
- [ ] 生产四量分开；无 JC 标 `unknown` 而非 0；四量非单调不被强加等式。
- [ ] 供应余额同 cutoff 互斥；新收不与可用重复；采购/头程在途只保留一个 crosswalk 余额。
- [ ] 收货 revision 替换不累计；accepted ≠ available。
- [ ] 坏/缺数量不转 0；隔离原因可查。
- [ ] 同一快照重跑结果一致（可复现）。
- [ ] 所有输出带 `kind/source/source_row_id/observed_at/confidence`。

> 未通过门槛的项进入异常清单；不得为了“跑通”而改口径或补 0。

## 3. 保留的备选与裁决条件

| 备选 | 当前不锁定 | 裁决条件 |
|---|---|---|
| 存储 | DuckDB/Parquet / Postgres / EN 只读快照 | G2 并发/权限/备份实测 |
| 计划引擎 | 轻量组件 / EN 原生 / FrePPLe | 同一事实快照先跑轻量+EN；需重造 MRP 或资源/BOM 约束时做最小影子例 |
| 预测 | TSB / ens5 / 其他 | 同标签窗口、独立测试；当前不引入 TSFM |
| 预算 | 件数 / 金额 / 多目标 | 业务给成本/币种/服务目标；C10 为反例 |
| 头程 | 钉钉 / 货代 API / 第三方 | adapter 逐个验证；无到货源标 unknown |
| 呈现 | 一页纸 / EN 报表 / 轻 Web | G4 同一建议包试读 |
| Agent | 规则路由 / 受控单 Agent / 执行 Agent | 真实权限/回读/并发验证后影子试用 |
