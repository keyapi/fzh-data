# 00 — 调研执行计划（Claude 路）

## 1. 要回答的三个决策问题

1. **业界成熟架构里哪些该抄？** 哪些是「大公司才能用」的方法论，哪些能落到 5 人团队。
2. **AI / Agent 现在到底能承担哪一段？** 哪些环节是真增益，哪些是把不确定性引进来。
3. **哪条路能用开源拼出来、成本多少？** 自研 / 开源 / 采购的比例，以及年度 TCO。

最终服务于：老板能在**一页纸**内判断「为什么建议下这么多、风险在哪、要我批什么」。

## 2. 约束（已确认）

- **不写业务代码**，不改现有模块行为；调研阶段只读业务系统。
- **允许**在项目 uv 环境或临时目录安装研究依赖（`statsforecast`、`OR-Tools` 等），
  用现有客户端**只读**拉少量真实数据做画像。
- **最小验证切片**：PB 楔形枕/三角靠枕 × 美中 Daneey × PB 渠道。
- 文档提交到本目录，独立分支 `research/supply-chain-claude`，独立 PR。
- 不读取 Codex / Cursor 的中间结论；三家完成后另开对比会话。

## 3. 三系统与已知铁律（调研的前提）

| 系统 | 角色 | 已知铁律 |
|---|---|---|
| 通途 ERP2 | 订单 / 库存 / 采购 | 在途只认通途采购单；「标记发货/报溢」不等于真实发货；库存按仓分别裁定 |
| ERPNext (EN) | SO / PP / WO / DN / BOM | **EN 不扣减通途库存**（Bin 不能当可用库存）；`Closed` ≠ 已发完；WO 头状态不可信 |
| 赛狐 | 库存 / 备货 / 结算 | 库存有安全冗余，不能反推「某批头程已签收」；调拨同步会带来成本漂移 |

其他：断货月必须删失；仓名是别名族；SKU 完整码精确匹配；头程 join key 是 EN 销售订单编号。

## 7. 证据协议

`sources.md` 每行：

| 字段 | 说明 |
|---|---|
| ID | `S-###`；找不到的记 `N-###` |
| 主张 | 一句话，可判定真假 |
| 来源 | 标题 + URL / 仓库路径 / PR |
| 类型 | `P` 论文、`V` 厂商主张、`I` 独立证据、`C` 可复现代码/实验 |
| 日期 | 发布日 / 访问日（本项目时间基准 2026-10） |
| 原文 | 关键句摘录（不是转述） |
| 强度 | A 一手/同行评审；B 独立机构/可复核方法；C 厂商文档/案例；D 博客/轶事 |
| 用于 | 章节编号 |

规则：

- 厂商主张（`V`）不得与独立证据（`I`）混算；正文用 `[S-012, B]` 引用。
- 每个数字要么有来源，要么由提交的实验代码生成。
- 「未找到」必须写检索词、库、日期、范围，结论写「在上述范围内未发现」，不写「不存在」。
- 技术时效：AI 类资料优先 2026 年；开源项目最近 6 个月无 release/commit 必须标注。

## 8. 最小验证（详见 `experiments/`）

### E1 预测基线对拍

20–50 个 SKU、12–24 个月；断货月删失；滚动回测。
方法：M1 运行率 / M2 同比窗口 / M3 线性趋势 / M3b 季节平均 + naive / seasonal naive / Croston。
指标：WAPE、bias、聚合稳定性、排序稳定性。
**Pass**：简单方法在高价值 SKU 聚合上比 naive 低 ≥10% WAPE 且排名稳定。
**Falsify**：无方法稳定胜 naive，或结论随窗口翻转。

### E2 OR-Tools 补货 LP

20 SKU；最小化持有 + 缺货惩罚；约束 MOQ、交期、在途、预算；与启发式对比。
**Pass**：5 分钟内可行、约束可解释、回测成本/服务优于启发式。
**Falsify**：关键字段缺失或无可复现改进。

### E3 只读 Agent 原型

15 个标准问题；工具注册表 + 指标定义 + prepare→确认→执行→独立回读；禁止写。
**Pass**：≥90% 正确选工具/口径，0 越权写，答案附证据。
**Falsify**：SKU/仓库语义歧义 >20%，或无法统一口径。
