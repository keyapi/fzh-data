# T6 可用性核对

> 对 `replenishment_v2.csv` 的 2,309 行逐行核对（2,218 合格 + 91 C）。
> **未修改主表任何数量**；发现的口径问题只在本审计与建议中标注。
> DB 只读、未扩样、未下单；不改 T2/T3/T4/T5 与 V1 产物。

## 1. 同仓库存核验

| 项 | 值 |
|---|---:|
| 核对行数 | 2,218（合格行） |
| `可用` 与**同仓** `stock_latest.available` 完全一致 | **2,058** |
| 主表有 `可用` 但同仓无库存行 | **0**（无“分摊值混入”） |
| 主表无库存行（库存未知，null） | **160** |
| 库存跨仓摊派行 | **0** |

**结论**：主表“可用”是**逐仓库存快照值**，不是 SKU 跨仓汇总后摊派。
`该SKU主表仓数 > 有库存行仓数` 的 **534 行 / 160 个 SKU**，全部是“有销售、但该仓无库存行”
的待核实仓（`可用` 为 null），**不是摊派值**。

**但需求是摊派的**：需求 = SKU 级 AutoETS/MA3 预测 × 该仓近 3 月销量占比。
**1,415 行 / 742 个 SKU** 发生了跨仓分配，逐行 `需求摊派比例` 给出占比（如
`C/Cord-Black-100-707-wow` 在 `美东-CENTRADE` 占 0.5261、另两仓 0）。
**这部分是假设，不是同仓实测需求。**

## 3. lead_days 适用范围

| 项 | 值 |
|---|---:|
| `item_attr` 有 lead_days>0 的物料 | 3,344 |
| 主表覆盖 SKU 中有 lead_days 的 | **518 / 1,328**（其中合格 501 / 1,237） |
| 主表合格行中有 lead_days 的 | **824 / 2,218** |
| lead_days 取值范围 | **3–30 天** |
| 无 lead_days 的合格行 | **1,394**（不填默认值） |

**与 L60/L90/L120 的关系**：
- 主表三情景是**固定的日历窗口**（提前期+复核 60/90/120 天），**不是由 lead_days 推导**；
- lead_days 最大 30 天 < 60 天，**不能当端到端提前期实测**（不含生产、运输、清关、入库）；
- 没有 lead_days 的行**不使用默认值**，仍给三情景，但只能读作情景，不能当实测提前期。
- 518 这个数与用户提到的“518 项”一致：它是**全部 1,328 个 SKU** 中有 lead_days 的数量；
  只算映射合格的 1,237 个则是 **501**。

## 4. 主表哪些列可当事实、哪些是分配/假设

| 类型 | 列 |
|---|---|
| **事实（同仓快照/单据）** | `可用`（同仓 stock_latest）、`在途`（同仓快照）、`PO未结`（tongtool_po 按行汇总，去重状态另列）、`状态`/`SKU`/`仓`、`lead_days`（主数据配置，不是实测到货） |
| **分配/假设** | `月需求率`→`历史率(T3)`、`新预测等效率(T5)`（SKU 预测 × 仓销量占比）、`需求P50(冲减前/后)`、`压力情景(MA3残差系数×,截顶3×)`、`建议上限L90(压力情景)`、`去重情景批`、`PR297_*`（基线）、`L60/L90/L120`（固定窗口） |
| **派生（由事实+假设算得）** | `缺口L60/L90/L120`、`建议下限L90`、`与PR297差异L90` |

**使用建议**：可用/在途/PO 可作同仓事实引用；需求与上限必须带“分配/压力情景”限定语；
缺口与建议量只能作为情景，不可当已审批数量。
