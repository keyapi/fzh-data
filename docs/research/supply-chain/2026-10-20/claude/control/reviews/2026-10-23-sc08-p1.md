## 1. 手算对照（断言精确到 1e-9，11/11 通过）

| 场景 | 手算 | 仿真 |
|---|---|---|
| 单周期确定需求 10、在手 10 | β=1、α=1、closing=0 | ✅ |
| 单周期缺货 10 vs 在手 4（lost-sales） | β=4/10=**0.4**、α=0、lost=6 | ✅ |
| 单周期随机（需求 10/20 等概率、在手 15） | β=(10+15)/(10+20)=**25/30=0.8333…**、α=1/2 | ✅ |
| 两期 lost-sales（需求 10,10；到货 0,15；期初 5） | β=15/20=**0.75** | ✅ |
| 两期 **backorder**（同一输入） | p1 欠 5 → p2 需求 15 全满足 → β=**20/20=1.0**；lost=0 | ✅ |
| backorder 不重复算失销 | 欠交滚入下一期只服务一次，β=1 | ✅ |
| 零需求周期 | demand=[0,10]、在手 10 → β=1、**α=1（零需求不进分母）**、zero_cycles=1 | ✅ |
| 全零需求 | β=None、α=None（**零分母不填 100%**） | ✅ |
| **β ≠ α 反例** | 需求 10、在手 8 → β=**0.8**、α=**0** | ✅ |
| **P90 ≠ Fill rate 90%** | 需求 U{0..10}：P90=**9**；存货到 9 时 β=54/55=**0.9818…** | ✅ |

## 2. 最小仿真器（`inventory_policy.py`）

- **政策**：order-up-to（参照政策，不是最优）+ 复核周期 R + 提前期 L；每 R 期按
  `S − 库存位置` 下单，L 期后到货。
- **口径**：`semantics` 是显式参数，只能是 `lost_sales` **或** `backorder`，不混用。
- **逐期输出**：opening / receipts / demand / need / fulfilled / lost / backlog / closing。
- **恒等式**：`opening + receipts − fulfilled = closing` 在**每个周期**断言；
  本轮前沿网格 **identity_failures = 0**。
- **指标**：β（单位满足率）、α（有需求周期的无缺货比例）、需求周期/零需求周期数、
  平均期末库存、超额暴露（期末库存超过下一期需求的部分）。
- 前 `L+R` 期为**预热期**（t=0 管道为空），不计入 β/α——网格结果已按此剔除。

## 4. 边界

- **不接真实 SKU、不接模型、不出补货量**；需求是合成序列，成本/预算未建模（D40：缺成本不编预算）。
- order-up-to 只是**参照政策**；未加 MOQ/箱规（后续才加已证约束，未知约束做显式敏感性）。
- 保护期 L+R 最大 150 天，**超出多数真实预测窗**——真实接入时必须按 D40 标「未覆盖」。
- 本轮只证明：评估器算术正确、恒等式成立、前沿可复现；**不构成任何服务水平政策批准**。
