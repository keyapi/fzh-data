# EN 自动下单 V0.1

> 按 D25 章程实现“建议草稿”生成器：只读、不写单据、不自动提交。
> 预算 ≤150 GET；单线程、200 ms、page_length ≤100；超时/5xx 即停。

## 1. 预算与范围

| 项 | 值 |
|---|---|
| 请求 | **135** / 150 |
| 耗时 | **27.1 s** |
| 停止 / 错误 | 无 / 0 |
| 写入 | 无（全部 GET） |
| 范围 | docstatus=1、status 非 Closed/Cancelled、transaction_date ≥ 2026-01-01 |
| 结果 | **97 个 open SO**（106 个头部，其中 9 个全部行已交付）、**1,090 请求行**、**483 条 target×仓建议** |

## 2. 三闸门（逐项可见）

### 2.1 SO 有效性

- 只取 docstatus=1 且 status 非 Cancelled/Closed；closed/cancelled 不产生需求。
- `is_internal_customer`：**75 / 97 个 open SO 为 true**。按 D25 单列
  `internal_customer_confirm`（B 类），**未自行判为非需求、未删除**；涉及 412 条建议。
- `po_no` 作为需求去重键：72 个 SO 有键、25 个无键（`dedupe_key_missing`，B）；
  16 条建议命中 `duplicate_demand_suspect`（同 po_no+物料+交期+仓），**保留不删**。

### 2.2 Bin（目标仓）

- 库存按 **EN Bin actual_qty** 查询；该仓无记录 → `stock=null`、`bin_missing`，
  **不按 0**。影响 **252 条建议**（多为 PK#/ND# 组件在成品/半成品仓无 Bin 记录）。

### 2.3 PO / WO 去重与归窗

- PO：按 `(po, item, warehouse, schedule_date)` 去重；`schedule_date` 空 → 不归窗，
  记 `supply_date_missing`。
- WO：按 `(wo, item, planned_end_date)` 去重；`planned_end_date` 空 → 不归窗。
- **WO 缺日期是最普遍阻塞**：`supply_date_missing` 命中 **357 条建议**
  （实测缺日期的 item 列表见 JSON `gates.wo_missing_date_items`）。
- 三 H（15/30/60）分别按各自日期窗口计算，**不相加**。

## 3. 分时净算与分类

- `due_H = 未履约 × qty_per`（交期 ≤ today+H）；`net_H = max(0, due_H − 同仓库存 −
  PO_due_H − WO_due_H)`；H=15/30/60 **三列独立**。
- need-by 保留**原交期**；`overdue_days` 记录逾期天数，日期不改写为今天。
- UOM/换算：直接物料需 `uom == stock_uom`；BOM 拆解还需组件 UOM 与 SO UOM 一致、
  qty_per>0；否则 **C**。
- BOM 唯一**本身不作证明**：只有“BOM 唯一 + UOM 换算已证”才拆 PK#/ND#；
  否则 `bom_rule_unproven`（B），不拆。

| 分类 | 条数 | 含义 |
|---|---:|---|
| **A** | **1** | SO 有效 + 需求去重键 + UOM/库存/供给时点均证 |
| **B** | **481** | 缺日期 / 缺库存 / 内部 SO 待确认 / 去重疑点 / BOM 规则未证 |
| **C** | **1** | UOM 或映射未证 |

## 7. 三条阻塞（必须人工/补证）

1. **内部 SO 待确认**：75/97 open SO 的 `is_internal_customer=true`，412 条建议为 B；
   需业务确认是否重复补货，**不得自行判为非需求**。
2. **在产 WO 缺完工日**：357 条建议无法把 WO 归入 15/30/60 窗口，供给时点未证。
3. **目标仓 Bin 缺失**：252 条建议的 target 在该仓无 Bin 记录，库存“未取得”、净需求 null；
   另有 274 条缺少 `po_no` 去重键。
