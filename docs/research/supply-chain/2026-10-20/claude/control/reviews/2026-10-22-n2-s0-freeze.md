## 2. 主类别判定（防重复占位）

判定顺序（D16）：**紧急 → 重叠 → 在产 → PO → 零库存 → 普通**。
一个 SKU 只按它命中的**第一个**类别占一个名额；其它属性写进 `cross_labels`，只作交叉标签。

候选域里的主类别分布（`ten_sample_freeze.json → universe_counts`）：

| 主类别 | 数量 |
|---|---:|
| urgent | 75 |
| overlap | 18 |
| PO | 8 |
| zero_stock | 3 |
| normal | 18 |
| in_production | 0（无数据源） |

- `overlap` 的操作定义：`open_po_qty > 0 ∧ intransit > 0 ∧ intransit == open_po_qty`
  —— 同一批货被「采购」与「在途」两个阶段重复记录，31 个有 PO 的 SKU 里 **23 个**符合。
- 因此 PO 名额只能从「有 PO 但不构成重复嫌疑」的 8 个里取（S5）；
  S4 的「ETA 可验证」全库无样本。
- 例：`TT0031038K0062927` 同时有 waiting=5、PO 201、在途 201，但主类别是 **urgent**，
  只占 S1 一个名额，其余写成交叉标签。
