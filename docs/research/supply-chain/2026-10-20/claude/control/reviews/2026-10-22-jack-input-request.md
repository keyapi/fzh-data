# Jack 头程跟踪数据接入 — 最小输入清单

## 背景

`delivery_plan` 已上线新的头程物流跟踪代码（生产已重启），但数据仍需：
1. Jack 的爬取/推送任务写入测试与生产；
2. 部分 DN 缺头程单号，需要 PJ 或 YYS 补齐。

没有这些数据，B 的 ETA/在途只能保持 blocker，不能估填。

## 需要 Jack 提供（最小集）

1. **字段说明**：新跟踪数据落在哪个 DocType/表、字段名与含义，特别是：
   - DN / 出货计划行 / SO 的关联键；
   - 头程单号（tracking number）与承运商；
   - 状态（已交运/在途/到港/清关/入库/异常）；
   - 日期：计划离港/到港、确认到港、可售日期；
   - 数量与**部分到货**记录；
   - 来源与抓取时间（用于判断新鲜度）。
2. **一条脱敏样例**：每个主要状态各一条，含上述字段（可隐去客户名/地址）。
3. **推送状态**：爬取任务是否已写入测试/生产；写入表名、频率、最近一次成功时间。
4. **缺失清单**：当前缺头程单号的 DN 列表（DN 号 + 仓 + 物料/数量），供 PJ/YYS 补齐。
5. **口径**：ETA 是计划、确认还是可售日期；部分到货如何拆分；承运商单号复用如何处理。

## 我们拿到后会做

- 只读核对：DN ↔ 头程单号 ↔ 承运商 ↔ 日期/数量，逐条可追溯；
- 更新 B 的 ETA/在途判定：`evidence_present` / `scenario` / `blocker`；
- 不写生产、不估填、不把计划日期当确认日期。
