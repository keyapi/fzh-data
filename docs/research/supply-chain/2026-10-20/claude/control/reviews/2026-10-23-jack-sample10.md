| 主类别 | 判定式 | 证据来源 |
|---|---|---|
| 紧急 | `waiting_shipment > 0`（待发货） | `stock_latest` |
| 重叠 | `open_po_qty > 0 ∧ intransit > 0 ∧ open_po_qty == intransit`（同仓同量的同批重复） | `stock_latest` + `tongtool_po` |
| 在产 | 存在开放 WO 且 `qty − produced_qty > 0` | `wo_dn_coverage.json` ＋ `g1b_en_*.json` 原始 WO 行 |
| PO | `open_po_qty > 0`（且未落入上述更高优先级） | `tongtool_po.open_qty > 0` |
| 零库存 | `available == 0` 且 `net_qty_6m > 0` | `stock_latest` + `ranking.json` |
| 普通 | `available > 0`（其余属性均不命中） | `stock_latest` |

**关于「重叠」的第二个分支（SO / 已出库履约重叠）**：本轮**未使用**。理由是可判定的 SKU 级未履约 SO 序列不存在——

## 4. 缺额：有 PO · ETA 可验证

**结论：无合格样本。** 不是"没找到合适的 SKU"，而是**本地快照没有任何一条带 ETA 的未结 PO 行**。四项核查：

| # | 核查 | 结果 | 证据 |
|---:|---|---|---|
| 1 | 通途采购单是否有到货日 | `tongtool_po` **524 行**，未结 **248 行**，`will_arrive_date` **非空 0 行**（全 NULL） | `select count(*) from tongtool_po where open_qty>0 and will_arrive_date is not null` → 0 |
| 2 | 能否用"部分到货日"反推 | 未结行中 `in_quantity > 0` 的 **0 行**（未结行全部未收） | `open_qty>0 and in_quantity>0` → 0 |
| 3 | 能否用 DN / Shipment 的 ETA 反推 | **无 PO→DN/Shipment 键**：WO↔PO 有键 **0/214**；DN 行只带 SO 键（DN↔WO 有键 0/507） | `wo_dn_coverage.json → linkage` |
| 4 | EN 采购单口径是否可替代 | 不成立：EN 抽取物不含 PO 行；`auto_order` 469 条 SO 行的 `po_L15/L30/L60` **非零 0 行**（同期 `wo_L*` 有 325 行非零） | `out/auto_order/order_examples.csv` |

**补证路径（给 Jack / 业务，不是本轮结论）**

1. 业务按 PO 行给预计到货日（最小成本，248 行里只需先给 10 SKU 命中的行）。
2. 或实测通途 `purchaseOrderQuery` 是否返回到货日字段——官方文档未列出该字段，且**同一商户 5 次/分钟共享限流**，
   需与现有 MCP 错峰；**不要把"下单日 + 假设交期"算成 ETA**，那属于 W2 的 assumed 档，必须标 `source=assumed`。

> 本条与 D17 一致：ETA 缺失属外部数据缺失，**记准确阻塞，不替换已选样本、不放宽定义**。
