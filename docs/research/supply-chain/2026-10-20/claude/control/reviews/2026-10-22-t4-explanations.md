## 3. 需求 / 供给 / 公式列

- 需求：`需求P50(冲减前)` 与 `(冲减后)` 两列（相等，原因见 T3：SO 不冲减）；
  `需求P90` 指向 T3 的推导列。
- 供给：`可用 / PO / 在途 / 在产` 与 **各自去重状态**（PO/在途/在产分列）。
- 缺口公式（每行同文）：`缺口_L = 需求_P50_L − (可用 + 去重情景批)`；
  去重情景批 = 重复 PO 按一笔 / 在途=PO 按同批 / 否则两批相加。
- 建议量公式：`下限 = max(0, P50_L90 − (可用 + 去重批))`、`上限 = max(0, P90_L90 − 可用)`。
- 假设引用：逐行带上 T3 的 `assumptions` 原文。

## 4. 八类异常标签的覆盖统计与处理说明

| 标签 | 命中行数 | 命中 SKU 数 | 为何这样处理 / 为何没处理 |
|---|---:|---:|---|
| `short_history` | 943 | 538（合格 463 + 范围外 75） | 历史 <24 月：改用仓级 MA3，而非长周期模型；短历史本身不剔除 |
| `missing_inventory` | 160 | 160 | 该仓无库存行 → 库存未知，建议数量留空（**未按 0 计算**） |
| `zero_sales` | 875 | 564 | 该仓近 3 月无销量 → 月需求率 0；这是观测事实，不是“需求不存在” |
| `returns_unobservable` | 2,309 | 1,328 | 全局口径边界：`gs_orders` 无状态字段、窗口内 0 条负数量 → 净=已发货，退货/取消未校正 |
| `duplicate_mapping` | **0** | 0 | P1A 的四项检查命中 0（两张映射表键空间一致、无多物料）；**别名聚集**（一个物料被多个通途键引用）是正常现象，不是重复映射 |
| `promo_spike` | 252 | 117 | 存在月份 ≥3× 正销量中位 → 尖峰原样进入均值，**未剔除、未做促销校正**（无促销日历证据） |
| `operational_change` | 1,046 | 586 | 近 3 月/前 3 月均值 ≥2× 或 ≤0.5× → 可能为运营/渠道变化；按原样计入均值，**未做结构突变校正** |
| `stockout_censoring` | 1,472 | 670 | 有断货观测或待发订单 → 历史销量可能被压制；**未校正**（快照只有 3 天库存历史） |

> 每个命中行的 `异常处理说明` 都写明具体数字（窗口、倍数、断货行数等），
> 没有“只打标签不解释”的行。八类标签的词汇表在脚本中固定，未命中的类别也保留在词汇表中。

## 8. 已知边界

1. T4 不改变任何决策数值；它只解释 T3 的每一行。
2. AutoETS 探针在**当前全历史**上做一次可用性测试，不等同于 T2 在 12 个切点上的完整评估。
3. T2 未存逐 SKU 指标，`该序列验证表现` 只能给模型级 WAPE 与“是否在 774 条内”。
4. 促销尖峰、运营变化、断货删失三类都是**检出未校正**：没有促销日历、渠道变更记录
   与足够长的库存历史。
