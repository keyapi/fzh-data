## 2. 五条边界语义（规格正文）

### 2.1 一 DN 多运单号（且无分号数量）

**规格**：一个 DN 多号 → **一行**。

```json
{"doc_name":"DN-26-00069","doc_line":"1","qty":1475,"uom":"个",
 "tracking_numbers":["1Z1","1Z2","1Z3","1Z4","1Z5"],
 "allocation_known": false, "tracking_qty": null}
```

- `qty` 是**批次总量**，不是每号数量。
- `allocation_known=false` 时**必须** `tracking_qty=null`；给了 `allocation_known=true` 却不给 `tracking_qty` → `E_TRACKING_ALLOC`。
- **禁止**把同一 DN 行按运单号展开成 N 行、每行都写批次总量（`E_DUPLICATED_QTY`）。
- 我方下游只按 `qty` 计一次，运单号只用于展示与轨迹。

### 2.2 部分到货

**规格**：部分签收必须**拆成两行**，且两行之和 = 单据总量。

```json
{"stage":"received","qty":40,"received_qty":40,"remaining_qty":60,"doc_qty":100}
{"stage":"shipped_in_transit","qty":60,"received_qty":40,"remaining_qty":60,"doc_qty":100}
```

- `received_qty + remaining_qty == doc_qty`（`E_PARTIAL_SUM`）。
- `stage='received'` 行的 `qty` 必须等于 `received_qty`；`stage='shipped_in_transit'` 行的 `qty` 必须等于 `remaining_qty`（`E_PARTIAL_STAGE_QTY`）。
- **禁止**：已部分签收却仍整单记在途（`E_PARTIAL_AS_FULL`）；只写 `partial=true` 不给拆分（`E_PARTIAL_UNALLOCATED`）。
- 分配确实未知时（多号部分签收、不知道是哪号的货）：**不允许**把整单记在途；在 Jack 补齐
  `partially_received` 状态并给出该行的 `allocation_unknown` 标记前，我方**一律拒收该行**，
  并把它记进 `supply_unknown`（宁可少算，不可多算）。

### 2.3 未知数量

- `qty=null` ⇔ `qty_status='unknown'`，双向强制。
- **0 不等于未知**：`qty=0` 表示确实为零；`qty_status='unknown'` 时写任何数字都是错（`E_UNKNOWN_AS_NUMBER`）。
- 未知数量的行**不参与**任何合计，只在 `supply_unknown.qty_null_rows` 里计数。

### 2.4 未证 ETA

| `date_confidence` | 含义 | 进哪一列 | 能否进判决 |
|---|---|---|---|
| `confirmed` | 有单据/节点证明（需 `date_proof`） | `supply_confirmed` | 可以 |
| `estimated` | 有日期但未证（Shipment ETA、供应商承诺） | `supply_expected` | **只能做敏感性，不作及时到货** |
| `unknown` | 无日期 | `supply_unknown` | **不可以** |

- `date_confidence='unknown'` 却给了 `available_date` → `E_UNKNOWN_HAS_DATE`（防止"填了日期就变成到货"）。
- `confirmed` 但无 `date_proof` → 降级为 `estimated` 并告警（`W_CONFIRMED_WITHOUT_PROOF`）。
- **`gap` 只能对 `confirmed` 计算**；`demand` 未知时 `gap` 必须 null（`E_GAP_WITHOUT_DEMAND`）。

### 2.5 外部 FBA 已签收

- `scope='external_fba'` 的 `received` 行：**既不算我方在手（on_hand），也不算在途**，只登记到 `excluded_external_fba`。
- 缺 `scope` → 告警 `W_SCOPE_MISSING`，我方默认按 `in_house` 处理**并标注未证**（不是静默）。

## 4. 真实数据预演（现有 SC04，不是 Jack 的数据）

`uv run python experiments/sc14/dry_run_sc04.py`——把 39 张 DN / 4,279 行物料按 §2 规则映射成 W1 行再校验：

| 结果 | 数量 | 说明 |
|---|---:|---|
| 总行数 | 4,279 | 39 张 DN |
| `E_REQUIRED_NULL`（sku 为空） | **2,347** | 组件 `PK#/ND#` 没有父 SKU → **W1 的 SKU 粒度问题**，见下 |
| `E_PARTIAL_UNALLOCATED` | **452** | DN-26-00069 部分签收但未拆行（正是 §2.2 要拦的） |
| `E_STAGE`（unknown） | **169** | DN-26-00112 状态缺失 → 枚举缺口（§1.2） |
| 外部 FBA 排除 | **1,745 行** | 两边都不算，符合预期 |
| 汇总（仅 in_house） | 在手 个 12,098 / 套 580；在途-有 ETA 个 56,961 / 套 30,701；未知 212 行 | 未证 ETA 没有进 confirmed |

**三条从真实数据里得到的规格修正**（已写回 §1–§2）：

1. **SKU 粒度**：DN 行大量是组件（皮壳/内胆），W1 若以销售 SKU 为键，必须给**父 SKU 归属**或单独的 `scope='component'`，否则 2,347 行无法入表。
2. **`doc_line` 必须是稳定行号**：预演第一次用物料码当 `doc_line`，同一 DN 内同一物料多行 → 误报 3,675 条"source_key 重复"。规格明确 `source_key = doc_type|doc_name|doc_line|uom`。
3. **unknown 状态必须显式**：不能靠"状态缺失就归在途"。
