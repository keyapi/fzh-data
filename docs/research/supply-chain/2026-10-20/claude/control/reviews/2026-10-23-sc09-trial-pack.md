## 1. 条件清单（`sc09_trial_rows.csv`，2,309 行）

每行 = 一个 **SKU × 仓**，列含义：

| 列 | 说明 |
|---|---|
| `suggested_qty_or_range` | **建议量或区间**：按**数值升序** `最小 ~ 最大`；两值相等时给单值；**HOLD 行写「不可算（证据不足）」**，绝不写 0 |
| `qty_min` / `qty_max` | 升序后的两端（可直接参与业务判断）；`gap_low_raw`/`gap_high_raw` 保留上游原字段 |
| `need_time` | **需要时间**：首个出现未履约的月桶（2026-10 剩余 / 2026-11 / 2026-12），或"窗口内无缺口"/"不可算" |
| `can_make_it` | **能否赶上**：全部为「无法判断（无 ETA/在途证据，WO not_observed）」——本批没有任何一张单能证明赶得上 |
| `forecast_basis` / `rate_clamped` / `fallback_reason` | **依据哪档预测**：T5 等效率，逐行标 AutoETS 或 MA3 回退，含版本与钳零标记 |
| `forecast_rate` | 预测率（件/月）。**上游为空时保持 null（空字符串），绝不写 0**；真正的 0 只有 829 行，是真·零预测 |
| `forecast_rate_status` | `ok` / `null · 缺库存证据` / `null · 缺需求依据`——null 的**原因逐行可查** |
| `stock_basis` | **哪套库存口径**：physical / net / unknown（unknown 时缺口是两端并列的区间） |
| `so_unfulfilled` / `so_allocation` | 未履约 SO 与分配模式（earliest / proportional） |
| `scenario_id` | **哪个情景**：条件行 = `S_phys_overlap0_onhand`；HOLD 行 = `S0_证据不足` |
| `assumptions` | 该行成立所依赖的假设 |
| `missing_evidence` | **缺证项**（自动从字段派生：**预测率缺失** / 库存口径未证 / 无 WO 证据 / SO 重叠未证 / 去重无记录 / 负率已钳 0） |
| `readiness` | 条件 / HOLD |
| `reviewer` / `reviewer_note` | **复核人空栏**（留空给业务填） |

> **251 行 HOLD 的正确读法**：缺口字段为空 → 清单显示「不可算（证据不足）」。
> 这是**有意的**：把不可算写成 0 会让业务以为"不缺货"。

## 2. 三个代表算例（预测 → 库存 → 供应 → 建议）

### 例 1 · 最大缺口 `TT0312614K0064238` @ 美中-FZH-DANEEY（条件）

| 环节 | 值 | 来源 |
|---|---|---|
| 预测 | 10 月剩余 **51.85** / 11 月 **155.55** / 12 月 **160.73**（件/月） | T5 等效率，AutoETS，statsforecast 2.1.1 |
| 库存 | 期初 **112**（口径 `unknown`：available 112 = physical 112，**net 端未证**） | `stock_available/physical` |
| 供应 | 在手情景 **0 收货**；另两个情景：同批次到货 **129**、跨批次 **258** | `receipts` 字段 |
| 推演 | 10 月用掉 51.85 → 余 60.15；11 月需 155.55，只满足 60.15 → **未履约 95.40**；12 月需求 160.73 + 结转 95.40 = **256.13**，无可发 → **未履约 256.13** | `forward_net_buckets.csv` |
| **建议** | **256.1 件**（该行 `qty_min = qty_max = 256.13`：available 与 physical 都是 112，net 分支没拉开区间）；需要时间 **2026-11** | 本包 |
| 凭证 | 若同批次到货成立 → 缺口降到 **127.1**；若跨批次到货成立 → **0** | 三情景对比 |

> 读法：**256.1 是窗口期末累计未履约，不是"12 月要买 256 件"**；且它随"到货是否成立"在 256.1 / 127.1 / 0 之间跳。

> **区间口径提醒**：全表只有 **14 行**是真正的区间（`qty_min < qty_max`），其余 2,044 行两端相同。
> 上游字段名有陷阱：`gap_low` 其实是**悲观端（更大）**、`gap_high` 是**乐观端（更小）**，
> 本包已统一按数值升序展示，请勿按字段名直接拼区间。

### 例 2 · 无缺口 `C/Cord-Black-100-707-wow` @ WayfairCG-Cranbury仓（条件）

预测三个月均为 **0**、库存 18 恒定 → **缺口 0**，需要时间「窗口内无缺口」。
⚠️ 但 `forecast_rate = 0` 是 T5 对这个 SKU×仓的**等效率为 0**，**不等于"不会有需求"**；
这行仍保留在清单里供业务判断"这个仓是否真的没需求"。

### 例 3 · 不可算 `C/Cord-DKBlue-100-713-wow` @ 美中-FZH-DANEEY-退货产品仓（HOLD）

`scenario_id = S0_证据不足`；库存字段为空、WO `not_observed`、SO 重叠未证 → **建议量写「不可算」**。
业务能做的只有两件事：补齐库存/需求证据，或明确"这个 SKU×仓本期不评估"。

## 3. 假设清单与待确认清单

### 3.1 假设清单（逐行体现在 `assumptions` 列）

| 组 | 行数 | 该行成立所依赖的假设 |
|---|---:|---|
| 条件行 | **2,058** | 需求 = T5 等效率（实际方法见 `method`）；snapshot 锚定；库存口径 physical/net 并列；SO 按 `earliest` 分桶（零预测不回退丢单）；在途疑似同批 → same/diff 并列；WO 未观测 → 不计且不升级 |
| HOLD·缺库存 | **160** | 缺 库存 → `unknown`，**不填 0** |
| HOLD·缺需求 | **91** | 缺 需求 → `unknown`，**不填 0** |

### 3.2 待确认清单（每类都写明"补什么"）

| # | 待确认项 | 影响行数 | 需要谁做什么 |
|---|---|---:|---|
| 1 | **预测率缺失** | **251** | 按"缺库存证据(160) / 缺需求依据(91)"分开补证；补证前该行只能「不可算」 |
| 2 | 库存口径未证（physical / net） | 2,309 | 仓储确认可售/占用口径 |
| 3 | 无 WO / 在制证据 | 2,309 | 采购·生产补未结 PO/WO 与 ETA |
| 4 | SO 与预测重叠未证 | 2,309 | 运营确认内部 SO 冲减规则 |
| 5 | PO/WO/在途 去重无记录 | 1,888 | 主数据 / 采购提供去重键 |
| 6 | 负率已钳 0（原值保留在 `forecast_rate_raw`） | 27 | 运营确认负率是否真实（退货/冲销） |

> **「预测率缺失」是独立一类**，不与"库存口径未证"合并——前者是**这一行根本没有需求率**，
> 后者是**需求率有、库存单位/可售口径没证**，两者的补证责任人不同。

## 7. B 情景 ≠ 采购批准（必须随包传达）

- 本清单的每一行都是**条件情景**：依赖"需求量 = T5 等效率""库存口径 physical/net 未分""SO 与预测不重叠""无在途/WO"等假设。
- 即使业务在 `reviewer` 栏签字，**也只代表"依据被复核"**，不代表任何采购动作获批。
- 要变成可执行的采购依据，需要《补货测算依据确认单》（`control/templates/replenishment-basis-confirmation.md`）三侧确认人签字，
  且仍需另走采购审批——**确认单本身也不是采购订单批准**。

## 8. 边界

1. 只读汇总；未访问生产、未下单、未扩样。
2. 缺口是**窗口期末累计未履约**，不是单月采购量；且随供应情景（到货是否成立）大幅变化。
3. `can_make_it` 全为"无法判断"：本批没有 ETA/在途/WO 证据，任何"能赶上"的说法都无依据。
4. 销量覆盖用的是 `despatch` 口径的**发运量**，不是需求（被断货挡掉的单不在内）。
5. 271 个扩展候选只做评审准备，未并入、未合计。
