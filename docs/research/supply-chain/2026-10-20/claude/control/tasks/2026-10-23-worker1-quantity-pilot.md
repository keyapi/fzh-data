# 任务：数量衔接试点（只读离线）

## 依据

Codex2 D35 第 3 条原文要求：先从 790 个已评分 SKU 中挑出**同时满足**
「映射/UOM 已证 + 真实同仓库存及日期已证 + 需求来源可辨 + PO/WO/在途可去重且可用时间明确」
的**简单单仓 SKU**，先做**逐时段净需求**，再验复杂配套。**不得把 790 整体视为供需合格。**

## 第一步：四道门（逐 SKU、逐门给判定）

每门只能给三态之一：**已证 / 未证 / 无法判定**，并写明证据字段与来源。**不许"差不多"**。

| 门 | 判据 | 明确禁止 |
|---|---|---|
| **G1 映射与 UOM** | SKU↔物料↔仓 映射有来源；UOM 有明确定义 | 按名字相似当已映射；UOM 未证按 1:1 猜 |
| **G2 同仓库存与日期** | 该仓该时点可售库存有来源 + 日期 | 用 SKU 合计当单仓可发；人工宽表 scope 未证当可用库存 |
| **G3 需求来源可辨** | 需求来自哪类单据/预测，可与供给同桶消费 | 内部 SO 重复加需求；预测与 SO 重叠未处理 |
| **G4 供给可去重与可用时间** | PO/WO/在途 可去重、有可用时间 | ETA 全空却当"会到货"；共享组件（皮壳等）超分配 |

## 第二步：逐时段净需求（仅对四门全过的 SKU）

- 按**需求日期分桶**算净需求，**不得用月均单点替代**。
- 每个数给：可复算公式、输入值、需要日、成立条件。
- 时间未证的供给**单列**，不进净需求主表。

## 第三步：A / B / 拒绝 三分

- **A 批**：业务已批准的需求依据 + 供给完整（四门全过）。
- **B 批**：含**显式批准的假设**（例：该供应不计入 / 按指定时点到货）——假设必须写在行上。
- **拒绝**：逐条写**哪道门没过、缺什么证据**，**不得静默丢弃**。

## 硬约束

- DB `read_only=True`；不访问生产、不扩样、不下单。
- **不 commit、不 push**（工头唯一提交者）；不跑 `update_index.py`；不新增依赖。
- **不给"可下单量"**；MOQ / 包装倍数 / 预算**另列**，不混进净需求。
- 不默认"无货"，也不默认"及时到货"。
- 行级业务 CSV/JSON 留本地；报告里只放聚合数字与判定结论（提交清关用）。
