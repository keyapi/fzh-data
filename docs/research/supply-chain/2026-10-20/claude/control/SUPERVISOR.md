# 项目进度监督协议

## 角色

- **监督者：Codex2**。负责判断“继续 / 返工 / 局部暂停”，调整已授权范围内的顺序，
  否决无依据的全局停工；不扩大生产范围、不批准生产写入、不代替业务裁决。
- **协调者：Claude**。负责巡检、触发监督者、执行与收结果；不得自行新增全局门槛。
- **执行者：Claude worker**。按任务书交付；完成/异常主动上报。
- **审核者：Codex1**。审计算与证据，区分阻塞错误与可披露限制。

## 触发条件（必须）

1. 阶段完成（样例、V0、行动清单等）。
2. 协调者准备宣布阻塞。
3. 任务逾期。
4. 有 ready 任务闲置超过 10 分钟。
5. 范围变更。

常规步骤直接执行，不逐步审批。监督者不被调用时不会后台巡检；
触发责任在协调者，不得回推给用户。

## 输入包（固定）

```text
阶段：
产物路径：
验收证据：
缺数影响：
下一任务：
负责人：
截止：
```

## 输出（固定）

```text
结论：继续 / 返工 / 局部暂停
理由：
下一动作：
期限：
```

## 协调者纪律

- 局部缺数必须隔离到 SKU 或给出受限情景，不得升级为全局停工。
- 声称全局阻塞时，必须证明**全部可执行任务**都无法继续。
- 未匹配/ETA/Cover/UOM 等未知项：分开展示，不写 0、不合成精确采购量。
- 不以“等待外部数据”代替可交付的受限版本。

## 推进方式（事件驱动，不设固定等待节点）

- worker 完成（后台任务通知）→ 立即收结果、提交、派 Codex1；
- Codex1 返回 → 立即交 Codex2 验收（固定输入包）；
- 验收通过 → 立即派下一项（补货行动清单/下一商品组）；
- **时间只作失败告警上限**：任务逾期或卡住才触发监督者，不作为“等到某点再继续”的闸门。
- 15 分钟巡检只是兜底，防漏接通知；正常情况不等待巡检。
- 当前 V0 监督裁决：返工+局部暂停；受影响 SKU 等 V0.1，其余可先列“可准备/待核实/暂缓”。

## 四条硬约束（2026-10-22 采纳 Codex 建议）

1. **固定责任人，替换留记录**：Claude 调度；Claude worker 实施；Codex1/#301 主审并汇总子 Agent；Codex2 阶段决策。临时审核进程可存在，但不能静默替代 #301。
2. **状态必须附证据**：
   - 已派工 → 任务与启动回执；
   - 执行中 → 最新工具输出或产物；
   - 已完成 → 固定版本、测试/报告；
   - 已验收 → 对应审核结论。
   没有证据只能写“未核实”，不能写“我在盯”。
3. **完成触发下一步**：worker 完成 → 收报告 → 派审核 → 处理问题；心跳只查漏收、审批等待、进程退出、额度限制，不代替正常流转。
4. **不因安静重启，不因返工全线等待**：接管前确认原任务状态并解除编辑所有权；独立任务继续推进，避免双写与全局等待。
