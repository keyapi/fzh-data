# 项目进度监督协议

## 角色

- **监督者：Codex2**。负责判断“继续 / 返工 / 局部暂停”，调整已授权范围内的顺序，
  否决无依据的全局停工；不扩大生产范围、不批准生产写入、不代替业务裁决。
- **协调者：Claude**。负责巡检、触发监督者、执行与收结果；不得自行新增全局门槛。
- **执行者：Claude worker**。按任务书交付；完成/异常主动上报。
- **审核者：Codex1**。审计算与证据，区分阻塞错误与可披露限制。

## 触发条件（必须）

1. 阶段完成（样例、V0、行动清单等）。
2. 协调者准备宣布阻塞。
3. 任务逾期。
4. 有 ready 任务闲置超过 10 分钟。
5. 范围变更。

常规步骤直接执行，不逐步审批。监督者不被调用时不会后台巡检；
触发责任在协调者，不得回推给用户。

## 输入包（固定）

```text
阶段：
产物路径：
验收证据：
缺数影响：
下一任务：
负责人：
截止：
```

## 输出（固定）

```text
结论：继续 / 返工 / 局部暂停
理由：
下一动作：
期限：
```

## 协调者纪律

- 局部缺数必须隔离到 SKU 或给出受限情景，不得升级为全局停工。
- 声称全局阻塞时，必须证明**全部可执行任务**都无法继续。
- 未匹配/ETA/Cover/UOM 等未知项：分开展示，不写 0、不合成精确采购量。
- 不以“等待外部数据”代替可交付的受限版本。
