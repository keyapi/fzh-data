# 不以“准确率”决定补货：理论依据与本项目协议

## 1. 结论与目标

用户的方向是对的：**首先尽量保障供货，再在可接受风险下减少库存和资金占用**。预测是决策输入，不是项目的终点。

把目标写为：在各商品组约定的需求满足约束、预算与执行约束下，最小化期望库存相关成本；或者在成本尚未知时，展示“服务—库存”有效前沿，由业务选择。有限库存、随机需求和不确定提前期下一般不能承诺绝不缺货；必须说明风险水平、保护期与适用条件。

2010年的库存预测研究已明确指出统计误差与库存效率没有简单直接对应，要求同时评价库存量和服务水平；2022年的综述进一步主张比较整套库存操作，而不是孤立预测器。[S1][S2] 这不是为了复杂化项目，是纠正验收目标。

**项目决定**：所有长史/短史/PB候选既报预测诊断，也进入同政策的库存评价；在数据不完整时明确标模拟或部分观察。M1可先给条件建议与敏感性，不以“理论尚需完善”为全局阻塞。

## 2. WAPE不是准确率，Bias也不是库存风险的充分描述

当非负实际量总和>0时，WAPE = Σ|预测−实际| / Σ实际。

- 本批树WAPE=0.49386，表示聚合绝对误差相对实际总量的比例；**不能把1−WAPE称准确率50.61%**。WAPE可超过1，销量被断货压低时分母/标签也会受影响。
- 同样的误差，低估畅销高毛利SKU与高估长尾SKU的损失不等价；误差出现在新货可到前还是可到后也不同。
- 同月总量正确也可能在月中断货；只有月度标签时不能声称日级服务改善已验证。
- 项目统一Bias = Σ(预测−实际)/Σ实际；正为高估，负为低估。不同来源符号必须转换并记录。
- 保留WAPE、MASE或RMSSE、Bias、逐SKU/品类/切点的退化、销量覆盖、失败与回退。零分母/尺度为零标不可评，不默认为完美。

AWS官方把WAPE与分位数损失分列，也说明低估/高估成本不同时可选不同分位数。[S5] 文档是评价方法参考，不代表本项目决定采用Amazon Forecast服务。

## 3. 业务指标：四层仪表，不混用

| 层次/指标 | 定义及用途 | 项目数据边界 |
|---|---|---|
| **需求即时满足率 Fill rate（β）** | 固定评估窗口内即时满足的需求单位 / 总需求单位；本项目主报单位加权，不与订单完整满足率混用 | 缺货期间潜在需求不可见时，只能报已接订单口径或情景模拟，不能称全市场真实β |
| **周期服务水平 CSL（α）** | 无缺货补货周期 / 有效补货周期，或模型中的周期不缺货概率 | 周期定义和零需求周期处理须固定；不等于β，不是“SKU库存>0占比” |
| 缺货单位/积欠/失销 | 首次未满足需求、期内新增未满足量、积欠持续、失销分别列 | 选择lost-sales或backorder语义；不能逐期把同一欠单重复算作新增失销 |
| 可售覆盖/缺货持续 | 有效观测下的SKU×仓可售可用时间比例/连续受阻时长 | 快照稀疏时只能报信号与有证时长，不能用14天信号合并制造连续断货真值 |
| **平均库存与资金占用** | 时间加权实物库存、按可靠成本计值；在途/在产资金另列 | 不能把inventory position当在手库存；跨SKU件数不可当资金或体积 |
| 超额/滞销暴露 | 超过预先声明的覆盖天数/数量/库龄阈值的库存，及期末剩余 | 期末有余货不自动等于积压；阈值、生命周期、采购成本需明确 |
| 总相关成本/利润 | 持有、失销边际损失、延期、加急、订货、报废/折价等，按同一经济口径 | 缺参数先报敏感性与非货币前沿；不能编造毛利、缺货罚款或把销售额直接当利润损失 |
| 决策稳定性与执行 | 订单修改频率、MOQ/装箱偏差、预算/仓容、到货前不可挽救缺口 | 防止低WAPE靠频繁加急/不现实供给实现 |

Fill rate按需求单位定义有正式库存理论依据，CSL与Fill rate是不同服务概念。[S3][S4] 项目同时给全局加权值、逐SKU/品类分布及PB重点组，避免高销量聚合掩盖局部持续断货。

### 为什么不能只说“95%服务水平”

必须注明是α还是β。例如一个周期缺1件和缺100件，CSL都算该周期失败，但Fill rate影响不同。数值95%并不能在两个指标间直接转换。

业务尚未批准目标时，先展示若干**探索性目标/成本比**的结果，不默认所有SKU统一95%或99%。PB核心畅销品、季节品、可替代长尾品可不同；具体分层与阈值由甲方/业务选定，Agent负责提供代价对比，不用等批准才开始计算。

## 4. 需要什么“区间”：不是模型均值的置信区间

补货主要需要**未来保护期内累计需求的预测分布/分位数**，并把供给时间的不确定性纳入情景；不是仅给估计均值的置信区间。

- P90是累计需求分布的90%分位数；校准且模型假设成立时约90%的对应需求观测不超过它。**不保证90%订单/需求单位得到满足，也不保证跨全部SKU/全年90%不断货**。
- [P10,P90]是名义中央80%预测区间，不是90%区间。与“估计Fill rate的95%置信区间”是两回事。
- 每期P90一般不能直接相加得到累计P90，要保留跨期相关性；逐仓分配也不能破坏SKU总量与共享库存约束。
- 看分位数覆盖率、区间宽度/锐度、pinball或加权分位数损失；宽得无用的区间不能只凭覆盖率高称好。
- 按预测跨度、商品组、促销/正常期检查校准。已用过的回测不是全新留出；先锁规则做前向观察，回顾性比较继续如实标注。

**不能再称bootstrap固定预测差异的CI为未来需求区间**。现有树vs组合CI只回答特定重采样条件下的指标差异，不回答“该SKU未来最多卖多少”。

## 5. 理论桥梁：保护期、分位数与订货政策

### 5.1 需求要覆盖多久

连续复核的简单再订货点覆盖提前期L；周期复核的order-up-to策略通常要覆盖 **L+R**（提前期+复核周期）。安全库存取决于该保护期的需求及供给不确定性，而不是任意固定“未来三个月”。MIT库存课程明确区分这两种策略与保护期。[S4]

本项目L要包含采购/生产、头程、清关、到仓、可能的加工和可售上架，不把到港/签收直接等于可售。没有可信L先出情景网格，不捏造一个精确天数。

### 5.2 单周期报童模型：为什么不一定取平均值

在单周期、线性缺货/多余成本等经典假设下，设少一件的边际代价Cu、多一件的边际代价Co，目标分位数τ = Cu/(Cu+Co)，目标数量是需求分布的τ分位数。比如**纯示例**Cu=9、Co=1，对应τ=.9；不是本公司已批准参数。[S6]

这解释了为什么不对称风险下均值、P50与实际订货目标可以不同；**不能直接把单周期公式当跨月、多阶段、受预算约束的最终采购公式**。缺货代价可能含毛利损失和其他证据支持的项，多余代价可能含持有/折价；重复计值要避免。

### 5.3 本项目的实装路线（成熟薄政策，不先造优化平台）

先复用当前逐桶净需求/库存账，加入可版本化的order-up-to参照、提前期/复核周期、需求分布、MOQ/装箱和预算情景。简单同质模型可用目标库存减净库存位置生成候选；复杂多批次/交期/共享料必须通过时间账验证，不把所有晚到PO都立即减掉。

inventory position的在手、已订、积欠口径与需求账对齐；已扣占用的available不能再重复减同一SO。预测冲减消除的是“预测与真实订单的重叠”，不是消除未履约客户需求。

已有研究 `02-industry-practices.md` §3.7、§验证建议与 `05-synthesis.md` 已提服务/预算前沿；本次是把这些变成可执行验收，不另选第二套框架。若有用再适配已有仿真库，不因选平台拖延首批条件建议。

## 6. 如何公平比较模型和补货策略

### 两条试验，不能混成一张排行榜

**A：模型贡献。** 固定初始库存、同一可见需求路径、同一供应/提前期路径、同一补货政策/成本/MOQ/预算，只替换预测，比较服务与库存。模型各自独立模拟库存，不能随结果修改共同需求真值。

**B：整体决策贡献。** 政策参数在内层训练/校准，外层评整个“预测+政策”流程；每种方法获得相同调参预算。另与已有人工/固定覆盖政策比较，前提是旧政策能复现；不可凭同事换人时间归因。

统一给三种结果：同Fill rate谁库存少；同库存/资金谁Fill rate高；有可信成本时谁总成本低。展示非劣前沿，不拿一个WAPE冠军替老板选择所有风险偏好。

### 最小评估清单

1. 冻结SKU×仓、时间、预测跨度、训练可知信息、初始库存/欠单/在途、需求与供应来源、随机种子和政策版本。
2. 第一层用可手算的合成轨迹验证守恒、延迟到货、分批到货、失销/积欠、已承诺SO、MOQ/预算，先证明仿真器没错。
3. 历史库存/订单完整的片段做真实回放；不完整的做清楚标注的反事实情景。无可靠潜在需求时不称已验证真实失销。
4. 长史、短史、PB、品类、重要度分别报样本数、销量/金额覆盖、指标分布和退化；不能用790优势替538或PB背书。
5. 以SKU整簇/时间块的成对重采样保留依赖，必要时多次重训/参数敏感性；固定预测CI明确不含流程方差。
6. 事先登记最小业务改善、容忍退化和目标指标；未定时展示差值/区间/前沿，不事后挑能显著的一项称成功。
7. 锁定候选与政策做前向影子观察，反馈实际到货、有效缺货/未履约、库存资金；执行采购仍另行批准。

## 7. PB与缺货删失：为何重要、又如何不自证

PB重点组是**多年销售史**，有订单、发运、checked0stock、部分历史库存及促销资料，适合作需求受限分析；不是短史239组，也不代表全目录。

- 固定原28名单与映射，解释26/27差集。促销日期与折扣生效来源明确；分正常、促销、疑似受限、恢复期。
- 分开“下单需求/接单时间”和“履约发运量/时间”；补发和积欠会把发运峰推后。订单也可能缺失被断货挡掉的潜在需求。
- 稀疏库存/拒单信号不证明一整段连续断货，低库存与偶发退货可发不自动恢复正常供应。
- 真实受限段没有需求真值：可用独立订单/未履约等作有限证据；恢复值不能当本方法评分真值。
- 在可靠未受限片段人工截断并保留原真实需求，验证损失方向/恢复方法，再在真实缺货段报告范围及敏感性；模拟结果也明确其假设。
- 对照原始销量、透明缺货校正基线、成熟删失/层级方法；复用PyMC-Forecast示例先做最小同输入对照，不为了“高级”直接引入大模型。旧R2变差只否定该实验路线，不等于需求恢复无价值。[S9]

## 8. 数据不足时怎么交付，而不是停工

| 现实缺口 | 仍可继续的工作 | 不可声称 |
|---|---|---|
| 没有历史每天库存 | 从最新快照往未来测算；完整片段回放；透明模拟；开始前向观察 | 真实历史日级缺货率/全部失销量已知 |
| 提前期/ETA不全 | 接现有Shipment轨迹；延误/及时/无已证到货情景；不可赶上部分单列 | 无ETA的PO必然及时到 |
| 成本/目标未定 | Fill rate—平均库存/资金前沿、Cu/Co敏感性；未批准政策标探索 | 算法已经找到公司利润最优或获预算批准 |
| 短史/新品 | 简单可解释候选、全局/品类借力、宽区间及低证据标记、限额试点供选择 | 不够12月就不能产生任何条件预测，或790验证可外推 |
| 数据存在未知 | 保留全SKU去向，局部隔离/给条件范围 | 全部填0，或全项目因此无事可做 |
