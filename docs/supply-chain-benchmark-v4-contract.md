# v4 验收契约草案

> 目的：先冻结“怎么算、怎么比、什么算通过”，再让打工仔写代码；避免边跑边改口径。
> 本文件待 Codex gate 审后冻结。

## 1. 输入与样本

- 需求：D3b v3.8 current 日序列（`date,qty`）。
- 删失/未知：D2 v3 `2_删失`；**删失=缺货证据，不当需求覆盖**。
- 预测：D5 v6.6 `1_预测`（仅用于样本分层/当前基线）。
- 样本沿用 round13：66 零中位数中取 30、稳定 10、短历史 10；去重后 50。
- 数据日期：D5 截至 2026-11-02，库存 2026-11-05；不因文件名改变。

## 2. 日级评估规则

1. 只评估**真实观测日**：测试窗内任一天是删失/未知，整窗跳过并记原因。
2. 训练窗同样只接受真实观测日；任一天删失/未知，整窗跳过。
3. 连续日历补齐：缺失日不默认补 0，标 `unknown`；真实无订单日只有 D2 明确 `observed_zero_only` 才当 0。
4. 测试窗：97 天、157 天各两个 origin；所有模型必须在**同一 origin、同一测试窗**上成功，才进入汇总。
5. 模型：MA3、SeasonalNaive、AutoETS、CrostonSBA、TSB(0.2,0.2)、ADIDA。
6. 当前 D5：**同 cutoff 重拟合**该模型族后再比；不得拿 11-02 冻结预测比已结束历史。若无法重拟合，D5 单列“不可比”，不参与排名。
7. 指标：WAPE、MAE、bias；有区间的模型另报 q95 覆盖率；零中位数段单独报。
8. 全部跳过/失败原因逐条输出；禁止隐藏失败。

## 3. 补货库存指标（政策模拟，不是历史还原）

对每个“模型 × 样本 × origin”：

- 固定同一补货政策：按预测的 97/157 天需求 + 安全库存阈值下单；补货提前期用生产+prehaul2+运输（按池/方式）。
- 初始库存用该 origin 时点的 C 可发供给（历史不可得时明确标“固定库存政策模拟”）。
- 计算：
  - 缺货天数、缺货件数
  - 满足率（总满足/总需求）
  - 平均库存、期末库存
  - 资金占用（库存×成本，若成本缺失则只报数量）
- 不允许声称还原真实历史断货；只报“在该政策/库存假设下”的结果。
- 缺失成本、交期、库存时，标 `not_comparable`，不硬算。

## 4. 通过/不通过

- 只有同时满足以下才进入“可比较汇总”：
  - 测试窗全观测；
  - 6 个模型全部成功；
  - 同一 origin/窗口；
  - 库存模拟输入完整。
- 否则进 `skipped`，不计入分母。
- **不设“总冠军”**：按 segment（稳定/零中位数/短历史）×h 报告；样本不足只写方向，不排名。
