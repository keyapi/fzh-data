# 账期业绩月度报表（应收−通途成本−Tax±附加费）

## Context

老板/财务的基准从「通途发货月销售额」改成 **OA 钉钉收款确认单的账期应收**。需要按 **渠道账号** 产出月度 `账号-按应收`，放在每月 `通途订单YYYYMM` 工作簿的 `账号` 紧左边；7/8/9 月已落地普通簿与 `-特殊规则` 簿两套。

## Guidance

### 1. 数据源（只认这些）

| 用途 | GS / ws | 关键列 |
|---|---|---|
| 应收/销售/费用（按账号） | `钉钉OA收款费用Amazon多平台&附加费&Tax` / `YYYYMMDD-YYYYMMDD` | `渠道账号`、`应收金额_人民币`、`销售额_人民币`、`收款费用累加人民币` |
| Tax/附加费（按账号） | 同一 GS / `人民币{账期}` | `Tax amount人民币`、`附加费累加人民币`（= 四个分项之和） |
| 预留/应收账款 | 同一 GS / `{账期}原始` | `本期预留金额`、`返还上期预留金额`、`汇率` |
| 通途成本 | `通途订单YYYYMM` / `写回YYYY年M月FBA订单和非FBA订单` | 五段成本列；**不要**用 `账号` ws 当成本源 |
| 账号/别名/运营人员 | `和运营部共享` / `渠道账号（20260521起在此维护）` | `渠道账号`、`渠道账号别名`、`运营人员YYYYMM` |
| 1.7.0 规则 | `和财务部共享` / `黄-特殊规则-订单改销售额成本` | **只认黄表**；Jeck 已过时 |

交叉验证：`附加费&Tax / 附加费{ym}` 与 OA `人民币{账期}` 的 `附加费累加人民币` 逐账号一致；`Tax{ym}` 与 `Tax amount人民币` 一致（202607/08/09 均零差；AllegroHU 修复后 HUF 也一致）。

### 2. 公式与列序

```
应收业绩 = 应收金额_人民币 − 通途成本合计 − 附加费 − Tax
剔预留业绩 = 销售额_人民币 − 收款费用累加人民币 − 通途成本合计 − 附加费 − Tax

通途成本合计 = 皮壳成本*系数*数量 + 绍兴二次加工成本*系数*数量
             + 二次加工成本*系数*数量 + 头程运费*数量
             + 海外仓成本*数量 + 运费
```

恒等：`销售额 − 各项费用 ≡ 应收 + 应收账款`；`应收账款 = 本期预留 − 返还上期预留`。两套业绩差 = `−应收账款`。

实际 25 列（前两个业绩列是主看列）：

`渠道账号｜运营人员｜平台｜渠道｜收款归属｜应收金额_人民币｜销售额_人民币｜应收账款｜绍兴产品｜头程｜国外二次加工｜尾程｜海外仓｜通途成本合计｜Tax｜附加费｜账期业绩_应收_扣附加费_扣Tax｜账期业绩_剔预留_扣附加费_扣Tax｜账期业绩_应收_不含税｜账期业绩_应收_扣附加费｜账期业绩_剔预留_不含税｜账期业绩_剔预留_扣附加费｜标志｜备注｜口径说明`

### 3. 期间口径（沿用现有算法）

- 收入 = OA 账期 `YYYYMMDD-YYYYMMDD`（04 号~次月 03 号）；
- 成本 = 当月 `写回` 整月订单：**自发货按发货日、FBA 按付款/销售日**；
- 不对成本按 04–03 二次过滤；9/1–3 在 9 月成本里、不在 20260904–20261003 账期里，属固有差异（非 FBA 敏感性约成本 15.98% / 销售 17.16%）。

### 4. 1.7.0 特殊规则（2026-11 当前）

- **只读 `黄-特殊规则-订单改销售额成本`**；`Jeck特殊规则…` 已过时，旧 206 条/−120,366 不能当基准。
- Colab cell 22 只改内存 `df_order_pre`，不写表；需要 **另建** `特殊规则-写回YYYY年M月FBA订单和非FBA订单`，**原 `写回` 不动**。
- 本地复刻可执行 cell 22 原代码：重建 `df_order_pre`（当前 `写回` + 账号别名/运营人员 + `渠道账号不含国家`）→ 读取黄表/汇率 → exec。2026-11 实测应用 241/300/271 条执行记录；**先做 ISO+月份唯一汇率**后，规则重复执行被消除，成本逐列金额不变。
- 旧下划线 `特殊规则_写回…` 是过时快照（1,691 个订单键与当前原始表不一致），不得作为当前成本源。

### 5. 账号/币种两个硬坑

- **别名**：`WFUS-Daneey → WFDANEEYUS`（202607 有 3 行、成本约 681.98）；新别名必须进 OPS 主表，否则静默变 `null`。
- **币种名**：AllegroHU 原始值是 `‌匈牙利福林（HUF）`（零宽 U+200C + 全角括号），精确 join 失败 → 汇率/RMB 全 0。先 NFKC + 去 Cf + 去空白，再按 `收款币种` 取唯一汇率；HUF 202607=0.02182205424089802、202610=0.0205。

### 6. 尾差

逐账号 `round(2)` 后求和会与未舍入合计差 0.02–0.05；202609 成本差 56,431.88、业绩差 56,431.86、未舍入明细差 56,431.884276。财务目前不要求尾差说明；**同层比较**（明细对明细、账号对账号），不要混算（如 2,092,622.79 − 2,036,190.88 = 56,431.91 是混层，不是控制数）。

## Why This Matters

混用期间（打款/账期/发货月）、混用成本源（`账号` vs `写回`、旧特殊写回）、把预留当费用、把 `产品成本` 当四段、币种名不干净——都会让业绩忽高忽低或直接变 0。7 月在不含 1.7.0 时显著为负（−638,818.41），是真实结果，不是算错。

## When to Apply

每月出 `账号-按应收`、普通簿/特殊规则簿对比、运营业绩、财务对账、任何“应收−成本”口径设计。
