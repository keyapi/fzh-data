# Amazon 结算口径与成本的四个决策

## Context

Amazon 卖家常把"结算/回款/销售额"混在一起。实际上它们对应不同期间与用途；成本也有多个字段来源。这些问题不定死，指标就会忽高忽低、对不上税局。

## Guidance

1. **三种期间轴，别混**
   - **Settlement 结算组**：按放款/结算周期；`transferAmount`(打款) 已扣 Amazon 费用与**预留**。
   - **posted 记账日**：V2 明细的收入/费用口径；用于经营/会计。
   - **履约/发货日**：权责发生制、运营业绩的销售时点。
   - **预留金是资产负债表项**，不是费用；Deferred(DD+7) 在释放前不在结算报表里。
2. **退款/退货**
   - 可售退货：**冲回 COGS、库存恢复**；不可售/损坏：COGS 留损失。
   - **尾程/出库运费是沉没成本，不冲回**；Amazon 退佣金冲减费用；赔偿 = 其他收入。
   - 判可售靠 **FBA/FBM 退货报告的 `detailedDisposition` + `status`**（赛狐 API 有，实测 10 月 146 件中仅 52 件可售）。
3. **EN 成本字段**
   - 通途 Cost Review 回出的 `商品成本` 是**行合计**；`绍兴发货成本` 是**单价**。
   - 标准：**尾程前成本 = 绍兴发货成本 + 头程 + 加工**，再 + 尾程；别"商品成本 + 头程 + 加工"（可能重复）。
   - EN FBA 的 `item_cost` 实测全 0 → 用 **BOM 单价×数量**。
4. **中国报税与运营业绩**
   - 中国申报用 **Date Range / Transaction（订单/发货、全额销售额）**；Settlement 作**回款/费用凭证**；平台报送收入总额常含代收代缴税，差异要能解释。
   - 运营业绩可用**结算期贡献**：`accountNetIncome（剔除预留变动） − 订单明细匹配的产品/头程/尾程 − 其他`；**不要用打款 transferAmount**；退款回看原单成本。
   - 账户级费用/广告分摊：订阅按销售额、仓储按体积/库龄、广告按 SP SKU 报表；销售分成不改变公司总额。

## Why This Matters

口径混用会产生三种误导：把打款当销售额（月份错位）、把预留当费用（低估利润）、把行合计当单价（成本翻倍）。对税局，申报基数错会触发比对异常。

## When to Apply

月结、税务申报、运营考核、任何"收入 − 成本 = 利润"的口径设计。

## Examples

- 打款 ≠ 销售：DANEEY 美国 Summary income 16,925.95，而 totals（转账净额）只有 -40.64。
- 成本字段：`商品成本` 77.84 vs `绍兴发货成本` 55.71，乘数量会重复。
- 退款：10 月 2,190 行/393 单，约 55% 来自 8/9 月。

## 附：OA 多平台账期字段关系（钉钉收款确认单）

数据链：`原始`（审批明细）→ `YYYYMMDD-YYYYMMDD`（按账号，外币+汇率）→ `人民币YYYYMMDD-YYYYMMDD`（加 Tax/附加费）→ `YYYYMMDD-YYYYMMDD收款比例运营人员`（按人汇总）。

- **应收金额 = 销售额 − 各项费用 + 返还上期预留金额 − 本期预留金额**（实测多行成立）；`应收账款 = 本期预留 − 返还上期预留`；因此 **`销售额 − 费用 = 应收 + 应收账款`**。`应收_人民币 = 应收 × 汇率`。
- **数据来源**：`原始` 表里的 销售额/应收/各项费用/**返还上期预留/本期预留** 都是 **OA 销售收款确认单的运营提交字段**；人民币列（应收/销售额/各项费用）是流水线按汇率算的；`收款比例运营人员` 是按人汇总。Colab 实际只用"费用"。
- **Tax 不在 OA 表单**（运营拿不到/没要求填）→ **应收没有扣 Tax**。若运营提交的"销售额"是含税口径，业绩需要再减 Tax（须与 Amazon 结算/Date Range 核对确认是否含税）。
- `_比例 = 该费用 ÷ 销售额`；`应收比例 = 应收 ÷ 销售额`。
- **做运营业绩时**：用 **`销售额 − 费用`（= 应收 + 应收账款，已剔除预留变动）**，**不要直接用"应收"**（它含 返还上期预留−本期预留 的预留变动，是资产负债表项）；若销售额含税，再减 **Tax**；附加费另行处理。
- **财务提出"直接用应收(账期收款额)当基准"？** 财务只能对银行到账，用"应收"对账合理；但**预留并非每月对冲**：实测 2024-07 起各月，"返还上期预留"与"本期预留"合计**净差可达 ±10~16 万**，每月 **11–41 行只有一边**，单行最大差 **7.5 万**。故用应收做**单月考核**会把预留波动转嫁给运营（运营不可控）。建议：**对账用应收/银行；考核用 `销售额−费用`（剔预留）**，或对预留做"加回本期预留、扣掉上期返还"的调整；两套并列并标注口径。
- **Tax amount人民币 与 附加费（账号单独/销售费用/头程/尾程附加费）只出现在「人民币…」层，不进「收款比例运营人员」的应收**。
- 来源是 **OA 运营填报值（多平台）**，不是平台结算实际；用它做考核须标注"OA 账期口径"，并与 Amazon Settlement/Date Range 定期对平。
- 新方法（老板/财务）：**账期应收（销售额−费用）− 通途订单成本（绍兴产品/头程/国外二次加工/尾程）−（是否再扣 Tax/附加费）**；旧方法是"通途发货月销售额 − 通途成本 − 账期费用 − 附加费/Tax"。两者期间口径不同，不能混比。
