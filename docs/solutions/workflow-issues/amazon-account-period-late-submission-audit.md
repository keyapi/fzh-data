# Amazon&新平台账期「提交异常/迟交」审计方法与规则

## Context

财务每月靠运营在钉钉提交「销售收款确认单」（一行=一条账期），另一同事按**发起时间 4号~下月3号**归桶到 NAS，文件命名 `Amazon&新平台成本 YYYYMMDD-YYYYMMDD 销售收款确认单-<ts>[ _合并汇率&账号_<ts>].xlsx`。运营若错位/迟交（如把 7 月账期在 8 月 4 号后才提交），会混入下月桶、难过滤。需要一套可复用的审计口径去量化每个月「正常/迟交/遗档/早交」。

## Guidance（规则 + 方法）

### 判定口径（本项目规则）
- **账期归属** = `账期日期` 所在**自然月**（1号~月末）。
- **正常提交窗口** = [所属账期月 M的4号, (M+1)的3号]（原来是 8号~下月7号，后改 4号~3号；多留 3 天处理月底账期）。
- **提交时间** = 收款确认单的**发起时间**（钉钉按发起时间过滤导出）。
- **桶** = 文件名窗口 `YYYYMMDD-YYYYMMDD` = 导出的发起时间窗；**账期月 = 起始月的自然月**（如 20260704-20260803 = 7月账期桶）。
- 一行的归属月 Z vs 所在桶 B：
  - `Z == B` → 正常；`Z < B` → **迟交**（混入下月桶，未在自己窗口内发起）；年份更早 → **遗档**；`Z > B` → **早交**（下月账期提前混入本桶）。
- `发起时间` vs `账期月窗口`：`Z` 的窗口末日 = (Z+1)/3；`迟交天数 = 发起日 − (Z+1)/3`。

### 读取/去重
- 每月取一个定稿合并 `_合并汇率&账号_` 文件（Sheet1）为主行集；其余同桶为重复稿只计数（前缀「不能用/可以用 已补充都荣美表/需要剔除4月已提交部分/再次导出核对/账期日期在7月」= 返工原因）。
- 跨文件按 `审批编号 + 账期日期 + 渠道账号 + 应收金额` 去重，避免同批被多个桶重复计入。
- **钉钉文件 Amazon 与 新平台 混排** → 按 `选择平台==亚马逊` 分流。
- 日期解析要兼容 `2026-06-13` 和 `2026/6/13`（单数字月份）；`str(datetime)` 才可靠。

- 8 月桶内有 **40 行账期日期在 7 月**（=「7月账期 8月4号后才提交」错位）→ 用户已建 `...账期日期在7月.xlsx` 拆分。

## Why This Matters
- 让「运营是否按 4号-3号 按时提交」可量化；识别跨月混入/重复/遗档，财务才不会把不同期间的钱混算。
- 口径（账期月自然月、4号-3号窗口、发起时间=提交、钉钉 Amazon/新平台分流）是后续任何账期工具（含 `sellfox_settlement` 自动取回）的公共基础。

## When to Apply
- 每月账期扎帐/审核；对 `sellfox_settlement` 自动取回的口径做审计；排查「账期日期在7月」「剔除4月已提交部分」这类返工。
