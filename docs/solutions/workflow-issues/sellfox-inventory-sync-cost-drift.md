# 用库存调整单同步数量，会让成本越来越改不动

## 现状

发货仍在通途，但运营要在赛狐看到库存数量 —— 所以有人（下称「同步脚本」）读通途库存后，
在赛狐建**库存调整单**增减数量。只调数量、不带成本。

**这不是用错了工具。** 赛狐自己的三方仓模块里就有「生成调整单」这个正式功能
（i18n `main.warehouse.tripartite.warehouse.generate.adjustment.order`，权限
`MOD_OVERSEA_WAREHOUSE.CREATE_ADJUST`），说明官方对「外部库存同步」的建模本身就是生成调整单。

**问题出在成本，不在工具选择。**

## 为什么会积累出改不动的成本

### 1. 调整单创建时**不录成本**，但新批次**一定带成本**

库存调整单的明细只有 `originId` / `targetId` / `可用量调整` / `次品量调整` —— **零个成本字段**。
可它每建一张，就会在库存里产生一个新批次，而这个批次的成本是：

> **该 (仓库, SKU) 在创建那一刻的加权平均成本快照**（取库存明细的「采购单价 / 单位费用」）

实测：某 SKU 当时均价 4.3763，新建 `+1` 批次拿到的就是 `4.3763`；同一 SKU 的另一张来源备货单
批次是 4.08，**新批次没有跟它**——**快照，不是引用**。

### 2. 这些快照**不可修正、不可撤销**

| 操作 | 结果 |
|---|---|
| 建 `-N` 冲掉 `+N` | ❌ 扣减按 **FIFO 吃最老批次**，不会冲掉刚建的那批 |
| 删除已完成调整单 | ❌ 赛狐明确拒绝：`仅【待调整】、【待提交】状态的单据可删除` |
| 撤销/作废已完成单 | ❌ 详情页只有 `取消`（=返回）和 `打印`；端点族无 `antiAudit`/`revoke` |
| 改这个批次的成本 | ❌ 调整单没有头程/采购成本字段，**没有任何入口** |

唯一能对已完成调整单做的写操作是 **`editRemark`**（只能改备注）。

实测 `+1` 再 `-1` 的净效果：备货单批次 139 → **138**（被 FIFO 吃掉 1 件），
**新批次 1 件永久留下**，单位费用净漂移 +0.0019 且清不掉。

### 3. 长期结果是「可修正的越来越少，不可修正的越来越多」

| 批次来源 | 成本能改吗 | 同步脚本每跑一轮 |
|---|---|---|
| 备货单批次 | ✅ 改备货单「单个头程费用」 | **被 FIFO 慢慢吃掉** |
| 调整单-增加批次 | ❌ 无入口 | **不断新增** |

所以同一个 (仓库,SKU) 会有几十个**不同时点的成本快照**堆积在库存里参与加权平均。
改成本时改得动的部分在缩小、改不动的部分在变大 —— **越跑越难把均价改到位**，
而且**没有任何回退路径**。

## 三个选项

| | 做法 | 代价 |
|---|---|---|
| **A. 维持现状** | 继续只同步数量 | **成本持续漂移且不可修正**。只有在「成本确实完全不关心、也永远不会回头改」时才可接受 |
| **B. 改用**其他入库单**** | 同步时带上 `perPurchase`（采购单价）+ 可选 `shipFee`/`otherFee` | 需要同步方**提供成本数值**。好处：成本**显式、可追溯、每次可对齐** |
| **C. 保持调整单，但先修成本** | 同步前先把该 (仓库,SKU) 的成本改成目标值，新批次快照就取到正确值 | 治不了历史批次，但能保证**未来**产生的快照是对的。仍需同步方接受"成本按当下均价冻结" |

**「其他入库单」为什么更好**：它的明细 `perPurchase`（采购单价）是**必填**
（`其他入库单创建 2.0` `/api/warehouseInOut/inRecord/v2.json`），表头另有
`shipFee`/`otherFee`/`apportionType`。**必填这件事本身就在逼同步方给成本** ——
而调整单允许你什么都不给，于是把问题埋进库存里。

> 未验证：其他入库单产生的批次是否同样"独立不跟随"（大概率是）。
> 但它至少**显式携带成本**，每次入库都能对齐到目标值。

## 建议

**不要停在 A。** 要么让同步带上成本（B），要么至少保证同步前该 SKU 的成本是对的（C）。

如果同步方确实拿不到成本，**B 也可以用「当前库存明细的采购单价/单位费用」作为入参**
—— 从赛狐读回来再写回去，至少让每批快照与当时口径一致、可追溯。
