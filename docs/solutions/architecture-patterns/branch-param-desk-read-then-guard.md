# 网页内参数助手：先查再决定，护栏看动作

## Context

银行竞赛要一个网页内助手：假数据、真模型、改数必须在页面上点允许。两个身份，柜面主管能改测试限额，综合柜员看不见生产限额。客户清单谁都不能导出。

第一版只有一轮对话、一个大工具。模型交回一个 `kind`，服务端再用正则改写。用户说「不要改限额，只交单」时，正则看见「限额」和「工单」，把限额改成了默认的 20 万。用户说「说明里写不要同步生产」时，因为句子里有「生产」，整句被拒绝，测试限额也没改。

## Guidance（本学习沉淀的做法）

助手循环保持很小，不引入编码助手运行时。

1. 当前限额不写进系统提示。模型要先调用 `read_test_limit`，工具结果交回之后，才允许 `propose_change`。
2. 写操作的提案回到浏览器，人点允许才改页面。读操作不用点允许，因为读的是这个岗位已经能看见的数字。
3. 安全护栏检查的是即将执行的动作，不是用户原话里的词。提到「不要同步生产」不算申请改生产。导出客户清单单独拦截，同一句里的测试限额提案可以留下。
4. 目标金额和当前值相同：不改数，也不提交变更单，只记审计。没给出具体金额（「调高一点」）就追问，不默认 20 万。一句话里两个金额，只取最后一个。
5. 护栏结果用固定条目显示在对话里：岗位工具白名单、生产写保护、客户信息不出域、无差额不立项、人工确认。模型负责想，护栏负责拦。
6. 分享给外部时单独建仓库，公开名用能看懂的 `web-ai-assistant`，不要用直译或自造词。模型只认 OpenAI 兼容的 `OPENAI_API_BASE_URL`（以 `/v1` 结尾）和 `OPENAI_API_KEY`。仓库只留 `.env.example` 里的占位符。运行机器上的真实地址和密钥只写在该机器的 `.env`，文档不写主机地址、账号和私钥路径。
7. 需要点到事先没有专门工具的新字段时，借用网页内通用点击（阿里巴巴 page-agent），和腾讯云 KiKi 是同一类：在页面里找控件、移动、填写。KiKi 是闭源 Helix，能跨腾讯云自己的页面。page-agent 管当前页，默认会直接点；用 `onBeforeStep` 停住等人点允许。模型请求由本站 `/v1` 转发，密钥不到浏览器。
8. page-agent 的全屏遮罩层级很高，会盖住侧边栏的允许按钮，人点不了，看起来像卡死。侧边栏要压在遮罩上面。允许和跳过的点击不能从本地记忆恢复；刷新后把未完成的卡片标成已中断。
9. 允许按钮没有被真实点通过之前，不要把这一版放到对外演示。page-agent 自带弹窗和侧边栏、KiKi 的确认条不是同一套，统一体验以后再做。

对照：OWASP LLM06 要求工具白名单、在下游强制授权、高影响动作人工确认。NVIDIA NeMo Guardrails 的 execution rails 包在工具执行前后，工具名和参数在模型之外再验一次。这两条都不要做成「整句关键词一票否决」。

Pi 和 DeepSeek Harness 的可取之处只是「工具结果交回模型再决定」。它们默认的读文件、跑命令不要装进这个页面。网页里自己点控件，用 page-agent 这一类，不要装整套编码助手。

## Why This Matters

正则补在模型后面，看起来像模型没有判断。评审看到的应是：助手先读数，再提案，旁边的护栏逐条通过或拦截。敏感操作被拦住，是护栏的成绩，不是模型说错了话。

## When to Apply

- 页面内助手要操作本页控件，并且必须给人看过程。
- 同一句话里混有允许的修改和必须拒绝的导出或生产写入。
- 要把演示拆出去分享，仓库里不能出现网关密钥。

## Examples

柜面主管说「把测试限额改成 20 万，并提交工单，说明里写不要同步生产」：先读出当前 50 万，提案改为 20 万并交单。护栏里生产写保护是通过，人工确认是等待。

同一人再说「导出客户清单，同时把测试限额改成 20 万」：客户信息不出域拦截，测试限额提案仍在。

综合柜员说「改成 20 万」：岗位工具白名单拦截，页面不改。
