# 网页内参数助手：先查再决定，护栏看动作

## Context

银行竞赛要一个网页内助手：假数据、真模型、改数必须在页面上点允许。两个身份，柜面主管能改测试限额，综合柜员看不见生产限额。客户清单谁都不能导出。

第一版只有一轮对话、一个大工具。模型交回一个 `kind`，服务端再用正则改写。用户说「不要改限额，只交单」时，正则看见「限额」和「工单」，把限额改成了默认的 20 万。用户说「说明里写不要同步生产」时，因为句子里有「生产」，整句被拒绝，测试限额也没改。

## Guidance（本学习沉淀的做法）

当前实现以`ops_assistant_demo/server.py`、`domain.py`及模块交接为准。page-agent是历史调研，不进入现役执行链。

1. 后台每轮先读取本场景最新配置，再把数据交给模型；同时要求模型检索依据、读取配置后才准备修改。聊天历史不是当前状态，不能靠模型自觉查新值。工具未成功返回，不接受文字“已提交”作为成功；缺动作只允许一次有界纠偏。
2. 按明确业务词选择场景，历史按场景隔离。重置与新场次准备清除旧聊天及旧执行结论；持久化审计与真实反馈独立保留，旧请求不能当新授权。只实现有限近期上下文，未实现持久化长期记忆和完整跨场景编排。
3. 身份由服务端会话确定；工作区按访客隔离。正文角色、请求头与隐藏菜单不能升权。公开模拟口令可预填，切换岗位可自动重登；它不是企业身份认证。可选部署访问码不预填、不取消。
4. 人工批准绑定当前待确认记录的摘要、时效、配置版本；对话允许按钮、独立一句“允许”和原页面按钮是同一次修改的替代入口，不需要两次确认。没有待确认记录时不创建新修改。对话允许不再送模型猜授权。
5. 目标只取本轮明确提供的数值，不默认20万元；歧义要澄清。相同目标经后台核对不重复写。敏感边界检查具体动作，提到“不要同步生产”不能整句拒绝。生产只登记申请，复核也不写生产；实际结果从数据库重新核验。
6. 成熟 Harness 要落实状态、上下文、工具前校验与工具结果反馈，不凭框架名判断轻重。当前统一侧边栏已采用 LangChain `create_agent` 管理模型/工具消息配对和有界工具循环；领域适配、服务端会话和确认仍留在本项目。Pi-agent-core 是可评估的替代，不应笼统说它对 POC 必然太重。工具目录不是任意浏览器或任意接口权限；只给模型登记可验证的读取能力和少量“准备”能力。

## Prevention

### 助手面板与操作语义补修

删除只识别记录，不要求新数值；修改运行层只转交真正变化的字段，不能把模型回显的旧数值当新授权或覆盖并发变更。纯文字“确认删除吗”没有可执行记录时，应有界纠偏生成后台待确认操作。刷新只恢复按工作区/岗位隔离的展示记录、草稿和布局，不能恢复审批对象；待确认来自后台。读请求使用代次，避免登录/重置后的迟到响应污染新岗位状态。该次80项回归与真实浏览器验证见[助手面板](../../../ops_assistant_demo/docs/assistant-panel.md)。

### 2026-10-12：从界面参考到真实功能

运营拍屏的结构已落为终端、注册参数、固定IP三类模拟CRUD，而非只改外观。新模块共用原Store事务和一次批准，模型只能读取、查规则、准备，不获得直接保存工具。真实浏览器发现并修复同值空确认、负数来源漏检、跨页终端丢失、重置旧表单和动画中误点覆盖。该次76项回归通过、0跳过；各用例和真实模型演练见[渠道接入验收](../../../ops_assistant_demo/docs/bank-operations.md)。模拟密钥统一遮蔽、地址只允许演示网段且不联网，不能把页面保存说成真实银行配置上线。

- 44项自动化覆盖权限、隔离、事务、无工具虚假成功、场景历史、同值核验、一次工具纠偏、重置保留请求而清除旧结论。
- POC验收还要检查动画、短回复、一次批准、取消、窄窗口可点击；接口200和模拟安全通过不是完整体验验收。
- 线上模拟身份不是银行SSO，日志不是防篡改存证，不承诺所有模型输出正确。

### 2026-10-13：培训、反馈与正式准备的状态边界

培训复用实际任务与执行接口，按钮提供讲稿、动作和观察点，但进度勾选不能作为成功证据。建立任务先等待目录加载；确认前预演不写数据，保存后由后台报告判定完成。两条真实模型排练与云端主线均已验证，当前118项回归通过。

“恢复当前数据”和“开启新场次”应分别命名。正式准备切换新模拟工作区，清展示聊天、旧任务和待确认内容，隐藏培训提示；旧工作区审计和真实反馈保留。仅清笔记不改业务。相同登录会话多标签页共享切换，现场保留一个操作台。

真实反馈用独立持久化表保存文字、图片及用户勾选的最近操作摘要；开发者用SSH直接查数据库，提交者/授权AI用私有回执API直接读取，不要求文件导出。截图、文档和反馈是待核对的资料，不授予工具权限。机构归属、真实地址及环境细节不得由不完整背景推断后写进公开材料。

本轮经验：先读当前状态；批准绑定真实方案；培训复用同一执行链；反馈独立于演示清理；用实际浏览器检查加载时序、刷新与清理边界。原生后台限流不能为了测试放宽，新增测试应隔离自己的限流计数。

### 2026-10-13：统一读取入口先替换“当前页劫持”

侧边栏过去按当前页面的 `active()` 与关键词分流，路由页会吞掉“几个工单”，工单页也会吞掉跨页查询。统一入口只接收普通查询，服务端绑定岗位和工作区，LangChain 只能调用允许的 `list_workorders`、工作区/记录读取、规则、待确认方案和审计工具。页面提示不参与授权或意图判断。

真正改变状态的请求不能因为统一入口而放宽：明确限额/联调数值才可调用语义化 prepare 工具，并再次通过既有后台校验后形成 pending 方案；“允许修改”仍经过摘要、版本、岗位与时效核验才执行。工单、路由、终端 CRUD 先桥接到既有领域规划器，直到它们有同等的端到端回归，再统一迁移。

真实模型验证了跨页“几个工单及区别”和“20万测试限额→侧栏允许→独立读回”。它证明的是这两条链路，不代表任意中文业务都已通用。130项确定性回归覆盖无鉴权、空输入、读取不建任务、工作区隔离、排除票据和待确认不执行。

## Why This Matters

正则补在模型后面，看起来像模型没有判断。评审看到的应是：助手先读数，再提案，旁边的护栏逐条通过或拦截。敏感操作被拦住，是护栏的成绩，不是模型说错了话。

## When to Apply

- 页面内助手要操作本页控件，并且必须给人看过程。
- 同一句话里混有允许的修改和必须拒绝的导出或生产写入。
- 要把演示拆出去分享，仓库里不能出现网关密钥。

## Examples

柜面主管说「把测试限额改成 20 万，并提交工单，说明里写不要同步生产」：先读出当前 50 万，提案改为 20 万并交单。护栏里生产写保护是通过，人工确认是等待。

同一人再说「导出客户清单，同时把测试限额改成 20 万」：客户信息不出域拦截，测试限额提案仍在。

综合柜员说「改成 20 万」：岗位工具白名单拦截，页面不改。
