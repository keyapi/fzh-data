# 变更日志

## 2026-09-23
- **改造**: `reconcile_pb.py` 纳入范围改为**整月口径** —— 锚点(`Notes!B2`)之前的日文件夹跳过，
  其余全部纳入（不再「首个 0 付款即停」）。跳过的文件夹逐日校验其发票都已在表内，防止「跳过」变「漏数」。
  财务自本月起要整月；代价是未付张数变多（0831 等还没到账期的也计入）。
- **新增**: 扫描硬校验——`<日文件夹>/invoice/` 里有 csv 但无一匹配 `invoice*.csv` → 报错退出并列出目录下所有 csv。
  只看日文件夹的 `invoice/` 一层（`<日文件夹>/878/invoice/` 补充子目录不查，其内容与主导出重复）。
- **修正**: Notes 区块行号不再写死（旧代码把差额行钉在 R86）。未付 87 张时「异常」区块会被推到 R145，
  差额行改为 `he + 2 + len(abn_rows)` 动态定位，清空循环上界同步。
- **变更**: `UNPAID_NOTES` 内联字典 → `UNPAID_NOTES_FILE`（JSON 侧载，缺失视为无备注）。未付张数整月口径下常态几十张，内联太长。
- **成果**: 生成 `…20240430-20260922_20260923_164417.xlsx` —— 付款追加 377 行（08/17–09/22）、
  发票追加 930 行 / 459 张（202607 剩余 + 全部 202608 至 0831）；绿 5 张 / $179.94、黄 87 张 / $5,042.50；
  差额 `-227.50 + 5042.50 = 4815.00`（LibreOffice 重算核对 `=G2-H2` 一致）。
- **核查**: 87 张未付全部用 `ups_track` + UPS 官方 Track API 批量查（86 已交付 / 1 未交运）。
  `INV0580626000011890` 是**无货未发**（UPS 停在"建了标签但未收件"；11 月中到货，钉钉 8 月底已提交，暂不处理）。
- **修复数据**: `20260730\invoice\invocie x37 ….csv` → `invoice x37 ….csv`（拼写错误被 glob 静默漏掉 37 张 / $2,232.28）。
- **修复历史文件**: 重跑 `merge_invoices.py --month 202607 --write --force` → 230 张 / $13,182.52 变
  **267 张 / $15,414.80**（9 天小计与 `invoice/*.txt` 全对上）；旧文件留证 `PB invoice 合并 202607 缺37张作废.csv`，需重发财务。
- **文档**: 新增 workflow §3（整月口径）/§3b（扫码硬校验）/§10（UPS 批量核查）/§11（LibreOffice 重算核对）；
  补「核对 H2 别用 Python 裸加」陷阱——`I` 列有 2 个手写公式单元格（合计 386.86），无缓存值时裸加会正好少这个数。
