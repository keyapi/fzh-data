# DAM 用户工作流设计

> 基于 2025-2026 DAM UX 最佳实践研究 + FZH 电商运营场景
> 回答：运营同事在 DAM 里到底要干什么？完整操作路径是什么？

---

## 1. 用户角色

| 角色 | 谁 | 做什么 |
|------|-----|--------|
| **资产上传者** | 摄影师 / 运营助理 | 把拍好的产品图批量上传到 DAM，打上基本标签 |
| **资产审核者** | 运营主管 / 品牌负责人 | 检查图片质量、合规性、标签是否正确，通过或驳回 |
| **内容编辑者** | Listing 运营 | 为 Amazon/Wayfair/Shopify 上架找对应的图片，下载或复制链接 |
| **标签管理者** | DAM 管理员 | 维护标签体系、合并重复标签、清理无用标签 |
| **资产消费者** | 任何需要图片的人 | 搜索 → 找到 → 下载正确尺寸 |

---

## 2. 核心工作流

### 2.1 上传流程（资产上传者）

```
拍摄完成 (NAS 文件夹)
  │
  ▼
打开 DAM → 点击「+ 上传」
  │
  ▼
拖入整个文件夹（或者选择文件）
  │
  ▼
系统自动:
  • 生成缩略图
  • 读取文件名中的 SKU（如 KS0001-pillow-white-front.jpg）
  • 建议标签：pillow, white, front-view
  │
  ▼
用户确认/修正:
  • 关联 SKU: [KS0001 ✓]
  • 图片类型: [主图 / 场景图 / 细节图 / 包装图]
  • 平台: [Amazon ✓] [Wayfair] [Shopify]
  • 补充标签: [ ]...
  │
  ▼
点击「提交审核」
  → 状态变为"待审核"，审核者收到通知
```

**关键 UX 要求**:
- 上传进度条（单个文件 + 总体）
- 必填字段*号标记（SKU + 图片类型）
- 上传前就校验（文件格式、大小），不要上传完才报错
- 支持批量：整个文件夹拖入 → 统一打标签 → 一键提交

---

### 2.2 审核流程（资产审核者）

```
收到通知: "12 个新资产待审核"
  │
  ▼
打开 DAM → 审核队列（按上传时间排序）
  │
  ▼
逐张审核:
  • 点击图片 → 全屏预览 + 缩放
  • 检查: 白底是否纯白（Amazon 主图要求）
  • 检查: 产品是否占画面 85%+
  • 检查: 标签是否正确
  │
  ▼
操作:
  [✓ 通过] → 状态变为"已审核"，可被 Listing 运营使用
  [✗ 驳回] → 填写原因："白底不够纯，需要重新抠图" → 退回上传者
  │
  ▼
支持批量:
  • 多选 8 张 → 一键通过
  • 多选 3 张 → 一键驳回 + 统一理由
```

**关键 UX 要求**:
- 并排对比：新图 vs 同一 SKU 上次通过的图
- 快捷键: A=通过, R=驳回, →=下一张, ←=上一张
- 驳回必须填原因（防止无理由驳回）
- 支持手机端快速审核（运营主管可能不在电脑前）

---

### 2.3 查找使用流程（Listing 运营 / 内容编辑者）

```
在 Amazon Seller Central 准备上架 SKU "KS0001"
  │
  ▼
打开 DAM → 搜索框输入 "KS0001"
  │
  ▼
看到该 SKU 下的所有图片:
  ┌──────────┐ ┌──────────┐ ┌──────────┐
  │ 主图 ✓   │ │ 场景图 ✓  │ │ 细节图 ✓  │
  │ Amazon   │ │ All      │ │ All      │
  └──────────┘ └──────────┘ └──────────┘
  │
  ▼
点击第一张（主图）→ 详情面板展开
  • 标签: pillow, white, front-view, Amazon-ready
  • 已审核通过 ✓
  │
  ▼
选择需要的尺寸:
  [下载 Amazon 尺寸 (2000x2000, JPG, sRGB)]
  [复制链接] ← 直接贴到 Amazon 后台，不需要下载再上传
  │
  ▼
切换到 Wayfair 上架 → 筛选 "Wayfair 尺寸" → 下载对应版本
```

**关键 UX 要求**:
- 搜索框在最显眼位置（页面顶部，永远可见）
- 按 SKU 搜索必须即时（自动补全）
- 平台筛选：「只看 Amazon 可用的」「只看已审核的」
- 「复制链接」按钮（避免下载→重新上传的循环）
- 下载时自动选对格式（Amazon: JPEG+sRGB, Shopify: 可用 WebP）

---

### 2.4 渠道图片规格自动化（关键电商需求）

运营同事的长期痛点：不同平台要不同尺寸/格式。

| 要求 | Amazon 主图 | Wayfair | Shopify |
|------|------------|---------|---------|
| 背景 | 纯白 #FFF | 白或场景 | 不限 |
| 尺寸 | 2000-2560px | 2000+px | 2048px |
| 比例 | 1:1 | 按类目 | 1:1 |
| 格式 | JPEG | JPEG | JPEG/WebP |
| 色彩 | sRGB | sRGB | sRGB |
| 文件大小 | <10MB | — | <20MB |

**DAM 应该做的**: 存储一张「母版」（高分辨率原图），自动生成各平台的衍生版本。运营同事永远不需要手动改尺寸。

---

### 2.5 标签管理流程（DAM 管理员）

```
每月一次标签清理:
  │
  ▼
打开标签管理面板:
  • 所有标签按使用次数排列
  • 标记零使用标签（红色）→ 可安全删除
  • 发现重复: "hero" 和 "main" 都是主图 → 合并为 "hero"
  • 发现不规范: "front_view" 和 "front-view" → 统一命名
  │
  ▼
批量操作:
  • 选中 50 个未打标签的资产 → 补充标签
  • 导出标签报告
```

## 3. 资产状态机

```
[Draft 草稿] ──→ [Pending Review 待审核] ──→ [Approved 已通过] ──→ [Published 已发布]
                       │                           │
                       └──→ [Rejected 已驳回]      └──→ [Archived 已归档]
                              │
                              └──→ 重新编辑 → [Pending Review]
```

**每个状态的视觉标识**:
- 草稿: 灰色圆点
- 待审核: 黄色圆点 + "待审" 标签
- 已通过: 绿色圆点 + "✓" 标记
- 已驳回: 红色圆点 + 驳回原因
- 已发布: 蓝色圆点
- 已归档: 灰色 + 半透明

## 4. 设计到开发的流程（回答"之后应该做什么"）

### 推荐流程（针对内部工具，轻量版）

```
第 1 周: 用户调研
  • 跟 3-5 个运营同事做 15 分钟访谈（问题清单见下方）
  • 观察他们现在怎么在 NAS 上找图
  • 记录当前痛点 + 变通方法

第 2 周: 信息架构设计
  • 卡片分类法：让运营同事把"图片类型"分组
  • 确定标签体系（最多 10-15 个标签值/类别）
  • 确定文件夹结构

第 3 周: 交互原型
  • 在现有 DAM 原型上增加完整工作流
  • 上传 → 审核 → 搜索下载 全链路可走通
  • 给运营同事试用，收集反馈

第 4 周: 后端开发
  • FastAPI + SQLite 实现数据模型
  • NAS 文件读写
  • ERPNext Item API 对接（获取 SKU 列表）
```

### 用户访谈问题（可直接用）

> 以下问题可以直接拿去问运营同事，15 分钟就能完成一次访谈：

1. "上次你上传一批产品照片，从头到尾做了什么？先干嘛，然后干嘛？"
2. "当你需要给 Amazon 上架找一个产品的主图，你现在怎么做？"
3. "管理产品图片这件事，最让你头疼的是什么？"
4. "你有没有遇到过用错了图片版本（比如用了旧版而不是新版）的情况？"
5. "如果许一个愿望来改善现在的图片管理方式，你最想改变什么？"
6. "给我看看你们现在 NAS 上的文件夹结构。你决定把文件放哪里的时候怎么想？"
7. "图片审核是怎么做的？谁来审？怎么通知？"

## 5. MVP 优先级

### 必须有的 (Phase 1)
- [x] SKU 搜索（搜索框 + 自动补全）
- [x] 批量上传 + 基础标签
- [x] 缩略图网格浏览
- [x] 详情面板（标签编辑 + 产品关联）
- [x] 状态流转（待审核 → 通过 → 驳回）
- [x] 单张下载 + 复制链接

### 重要的 (Phase 2)
- [ ] 批量标签编辑
- [ ] 审核队列（并排对比 + 快捷键）
- [ ] 平台衍生版本（一键生成 Amazon/Wayfair/Shopify 尺寸）
- [ ] 版本历史（新旧图对比）
- [ ] 收藏夹/合辑

### 锦上添花 (Phase 3)
- [ ] AI 自动标签
- [ ] 使用统计（哪些图被下载最多）
- [ ] 外部分享链接（给供应商/合作伙伴）
- [ ] 直接推送到 Amazon/Wayfair/Shopify

## 6. 用户访谈记录

> 访谈对象: 项目主（有过 Amazon 运营上贴经验，多年前）
> 日期: 2026-06-09

### 访谈发现 #1: Amazon Excel 上贴流程

- 使用 Amazon Seller Central 的 Inventory Template（Excel）批量上传
- Excel 列: SKU | Title | Description | Bullet Points | main_image_url | other_image_url1-8
- 图片必须以 URL 填入 Excel，不能直接贴文件
- 手动在 Amazon 后台换图后 → Excel 信息不一致 → 下次不敢用旧 Excel
- 多人同时编辑 Excel → A 的修改可能被 B 覆盖

### 访谈发现 #2: 当前图片组织方式

- **NAS**: 按运营提需求的方式组织（`2025年10月/视觉-SJ01/运营-YY01/主图/`），非按 SKU 属性。文件名无规则，视觉同事随意命名
- **钉钉直传**: 部分图片不走 NAS，人传人
- **老系统 a.vilavi.cn**: 有"组ID"概念，颗粒度不到4属性。需先建组 → FTP上传 → 通用图需重复传2次（没人传）。已不维护
- **外包需求 (ZQ)**: 需要临时从 NAS 搜集图片，按 ERPNext 物料组名称手动建文件夹整理

### 访谈发现 #3: 图片归属的颗粒度

**核心发现**: 大部分图片是产品变体独有（4属性全锁定），少数是通用图。

| 图片类型 | 归属颗粒度 | 示例 |
|---------|-----------|------|
| 白底主图 | 款式-面料-尺寸-颜色 (4属性) | KS0001-PP棉-100x150-RED 专用 |
| 角度图 | 款式-面料-尺寸 (3属性) | 多种尺寸看上去一样，共用 |
| 细节图 | 款式-面料 (2属性) | 同面料不同颜色细节相同 |
| 场景图 | 款式 (1属性) | 整个款式通用 |
| A+图 | 运营提需求视觉制作，或复用已有 | 卖点相关 |

### 访谈发现 #4: 图片挑选决策过程

- **选择方式**: 肉眼挑、凭感觉。没有系统化的挑选标准
- **信息来源**: 自己的 Excel / 有经验同事的 Excel / NAS 文件夹 / 某个软件
- **主图选择**: 找符合平台规则的（如 Amazon 白底 85%），但靠人工判断
- **同角度多张**: 凭感觉选一张符合自己帖子描述的，没有客观标准
- **视觉部门对接**: 存在信息不对称
  - 运营以为有某张图，实际没有
  - 视觉拍的/修的不是运营要的角度
  - 解决方式: 重新拍 / 重新修图 / AI 重新生成图

**启示**: DAM 需要支持"图片类型完整性检查"——这个产品该有的 7 种图（白底主图/角度图/细节图/场景图/尺寸图/A+图）哪些有了、哪些缺失。

### 访谈发现 #6: 图片链接生成与分发（关键基础设施）

**老系统 a.vilavi.cn 的完整链路**:
1. 运营提需求 → 视觉拍摄修图
2. 同事（即将离职⚠️）在阿里云 FTP 上创建"组ID"（款式 + 可能面料/颜色）
3. 该同事 FTP 上传图片到组ID下
4. 系统针对不同 Amazon 账号，将图片分发到阿里云不同地域 OSS/CDN
   - **防关联**: 相同图片在不同账号的链接指向不同 IP
   - 文件名混淆加密
5. 上贴同事下载 Excel，里面包含对应组ID的图片链接
6. OSS 存储定期自动清理（节约成本），链接可能失效

**非 Amazon 平台的替代方案**:
- ERPNext File 上传获取链接 → 但操作繁琐 + 有压缩问题
- EN_API 图片上传前端（昨天做的）→ 适合单次上传排序下载 Excel，但缺少持久化管理

**当前方案的共同缺陷**:
| 工具 | 能用什么 | 缺什么 |
|------|---------|--------|
| a.vilavi.cn | 组ID管理 + 防关联分发 + Excel下载 | 无预览、无拖拽排序、无版本管理、关键人依赖 |
| EN_API 前端 | 拖拽上传 + 排序 + 下载Excel | 无持久化、无多人复用、无顺序历史、非管理系统 |
| ERPNext File | 获取链接 | 操作繁琐、图片压缩 |

**时间估算**（从 NAS 选定图片到 Excel 填好链接）:
- 有组ID: 下载 Excel → 10-20分钟
- 无组ID 用 EN_API: 上传 → 排序 → 下载 → 20-30分钟
- 用 ERPNext: 逐张上传 → 获取链接 → 手工填表 → 40+分钟
- 加上找人/沟通/确认: ×1.5-2倍

**关键风险**: 管理 a.vilavi.cn 组ID 和 FTP 上传的同事即将离职。这个功能需要被 DAM 接管。

- 图片数量: 与行业标准一致（Amazon 7张引用，Wayfair 6-7张）
- Amazon A+: 内部视觉部门制作
  - 方式A: 运营提需求，针对自己卖点专门做
  - 方式B: 用已有现成图拼凑
- 大部分图不是通用图，是产品变体独有图 → DAM 需要支持 4 属性级产品关联
