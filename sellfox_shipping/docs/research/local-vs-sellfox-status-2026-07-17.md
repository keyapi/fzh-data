# 赛狐包裹状态 vs 本地审核状态

## 两套状态，各管一边

| | 赛狐侧 `package_status` | 本地 `local_review_status` |
|--|-------------------------|----------------------------|
| 谁维护 | 赛狐 ERP（同步只读镜像） | **本系统** |
| 典型值 | 待处理 / 物流下单 / 待打单 / 已发货 / 已搁置 / 异常…（API 常为 `to_process`、`to_print`、`has_shipped` 等） | `pending` / `approved` / `rejected` |
| 通过/驳回会改它吗？ | **不会** | **会** |
| 作用 | 反映赛狐里订单处理到哪一步 | 本系统是否允许进入「导出蜴国际 Excel」 |

同步时我们**保存**赛狐状态供筛选展示，**不**在审核时回调赛狐改状态。

```
赛狐状态（镜像）          本地审核（闸门）
to_process / to_print  →  pending → approved  → 可 lizard-export
                       →  rejected            → 不进导出批次
has_shipped            →  一般不再导出（已发货）
```

## 「通过 / 驳回」到底表示什么

| 操作 | 含义 | 对赛狐的作用 |
|------|------|----------------|
| **通过** | 人确认：渠道是蜴国际、地址/重尺够用，可以进本系统导出批次 | **无**。不改赛狐状态，不提交追踪号 |
| **驳回** | 本系统先不做这单（缺资料/渠道不对/要人工另处理） | **无**。不搁置赛狐订单（除非人去赛狐网页自己操作） |

在赛狐网页改「已搁置 / 异常」等，是**赛狐自己的操作**；与我们本地通过/驳回**不是同一按钮**。

## 人在哪里操作？允许两边都操作吗？

| 事项 | 推荐操作面 |
|------|------------|
| 日常订单处理、赛狐自带物流 | 仍可在**赛狐**（过渡期） |
| 是否进本系统蜴国际导出批次 | **本系统网页**（本地审核） |
| 上传 Excel 到蜴国际网站 | **蜴国际**网页（永远人工） |
| 写回销售平台（Amazon 等） | **通途**负责；赛狐自动推送已关。本系统近期目标是赛狐可见 `trackNo`（`submitToPlatform` 为文档化填号入口，真调须确认；见 submit-vs-autopush） |

过渡期可以两边都看：赛狐看全局，本系统看「尾程打单队列」。**不要**指望本地驳回自动等于赛狐「已搁置」。

## 导出数据从哪来（不必人下赛狐 Excel）

人点「导出」时，系统自动汇总：

1. 赛狐包裹 API（地址、`packageSn`、SKU）  
2. 赛狐商品 pageList（carton 重尺）  
3. 不够再 ERPNext ZLMB  

这比「赛狐网页下 Excel」全；同事无需再走通途变格式（历史路径仅作对照）。

## 追踪号落库如何测（不写回平台）

1. 本地审核几单 `approved` → `lizard-export` 出 xlsx  
2. **不要**真上传蜴国际时：用同事样例返回表，或手改一列「物流单号」做成假返回文件  
3. `lizard-import-tracking` →（待做）写入本地 `tracking_number`  
4. **全程不调用** `submitToPlatform`  

用通途历史 P 号样例只能测「旧表可追溯订单」，**不能**当赛狐 `packageSn` 导出测试集（见 `pnumber-to-sellfox-trace-2026-07-17.md`）。
