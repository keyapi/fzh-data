## 1. 公司背景

来源：项目根目录 `docs/company-context.md`（Agent 应自行阅读全文）

**FZH** 是跨境电商公司，在北美和欧洲销售**家居纺织品**（填充物为 PP棉/海绵的靠枕、沙发等）。

销售平台：Amazon（北美+欧洲）、Wayfair、Home24、Shopify、Overstock、Pottery Barn 等。

供应链：
```
绍兴工厂 (中国)
  ├─ 生产皮壳、内胆、半成品
  ├─ 部分成品直接生产 → FBA / 直接发货
  └─ → 海外分公司仓库：
       ├── USNJ (美东, NJ州) → 填充/压缩/包装/仓储/发货(2C+2B)
       ├── USTX (美中, TX州) → 同上
       └── POLAND (波兰)     → 同上
```

赛狐仓库映射：CENTRADE(USNJ)、DANEEY(USTX)、POLAND(波兰仓)

三系统 SKU 定义不同（ERPNext、赛狐、通途），详见 `docs/company-context.md`。

公司同事分布在**中国 + 海外分公司**，一部分中国同事操作，一部分国外分公司操作。

## 2. 项目背景：为什么需要这个系统

### 2.1 当前状态

OMS（订单管理系统）正在从**通途**逐步迁移到**赛狐**。

当前尾程打单流程碎片化：
- 部分尾程物流商有 API，可直接对接打单
- 部分尾程必须用 Excel 导出订单 → 用之前几年开发的 Google Colab 小程序调整格式 → 上传到尾程物流商的软件或网页后台

之前从通途尾程打单的经验：一些尾程通过直接 API 对接，一些必须用 Excel 导出 + 格式转换工具。

用户之前在德国工作时用 **Plentymarkets（可能改名为 PlentyOne）**，经验包括：
- 尾程物流 API 接口有时不管用
- 仓库打单常用本地软件 polling 方式，读取软件"吐"出来的 CSV 文件打单
- Plentymarkets 有 `shipping_profile` 概念

## 3. 核心需求（按用户原意提炼）

### 3.1 订单获取
- 从**赛狐**获取订单数据
- 方式：API 优先，Excel 导出作为兜底
- 赛狐已有 API：订单列表、订单详情、包裹处理列表（详见 `SELLFOX_API/docs/api-reference/订单/`）
- 赛狐认证：OAuth 2.0 + HMAC 签名 + IP 白名单。已有 `sellfox-api-proxy` 封装

### 3.2 尾程打单
- 使用**自有尾程物流商**打单（公司自己找的、有合作关系的物流商）
- 方式：API 直连优先，Excel 上传兜底
- Excel 兜底：从赛狐导出订单 → 按物流商要求的表头格式调整 → 用户自己上物流商后台上传
- **不需要**系统自动上传 Excel 到物流商后台（用户手动上传即可）

### 3.3 标签/面单
- 生成运单标签（面单），获取追踪号
- 标签可能需要支持不同格式（ZPL 热敏打印、PDF 通用打印等）

### 3.4 追踪号回写
- 将获取的尾程追踪号写回赛狐
- 方式：API 优先，Excel 兜底

### 3.5 规则引擎（待定）
- 可能需要根据订单条件（目的国/州省/邮编、重量/体积、产品类型、平台、仓库等）自动选择承运人
- 不确定是否需要，赛狐/通途自带类似功能
- 同事不一定选最低价格（产品压缩发货容易涨包）

### 3.6 数据存储
- 需要存储订单和包裹信息
- 不确定是否需要完整订单信息（含财务数据）还是仅打单需要的字段

### 3.7 发货成本追踪
- 需要知道具体某个订单/包裹用了什么物流、花了多少钱
- 不需要宏观统计分析报表（那是之后的事）

### 3.8 用户界面
- **Web UI**：面向物流同事日常操作
- **AI Agent 友好**：新系统需要方便 AI Agent 操作（如通过 MCP 工具、结构化 CLI 等）
- 中英文支持

### 3.9 部署
- 可以考虑部署在 ERPNext 上海测试服务器上（已运行 new-api、钉钉 OIDC、赛狐 API 转发等服务）
- 或者作为 ERPNext app
- 不确定部署太多服务是否可行

## 4. 关键约束

1. **使用自有物流商**：不通过第三方打单平台
2. **API 优先，Excel 兜底**：Excel 只做格式转换，不自动上传
3. **CSV polling**（类似 DPD/DHL 官方软件扫码吐 CSV）：先记录方案，暂不开发
4. **不确定是否放 ERPNext**：可以作为独立服务，架构需预留后期移植到 ERPNext 的可能性
5. **项目位置**：在现有 `fzh-data` monorepo 下新建子目录（类似已有的 stock_init、warehouse_restock 等）
6. **遵循项目规范**：OKF 文档标准、AGENT_HANDOFF.md、SKILL.md、uv/pyproject.toml
